# 엑셀(xlsx) 시트 편집 — 엑셀 파일을 문서처럼 올려 고치기

관련: [spec_작업.md](spec_작업.md)(작업 폴더 · 작업 목록) · [spec_계정.md](spec_계정.md)(계정마다 따로인 작업) · 외부 지식 [references/xlsx_OOXML_편집.md](../references/xlsx_OOXML_편집.md) · 화면의 꼴 [design.md](../design.md) §34(원본 — 여기는 동작과 끝점만 적는다).

## ① 질의·요청 히스토리

- 2026-11-26 사용자: (상단 「HWPX·DOCX 웹 편집」 을 가리키며) "여기서 엑셀파일도 사용할 수 있게 가능할까?" → 에이전트가 지금 되는 것(자료로 올리기 · 표를 엑셀로 내보내기 · 엑셀 표 붙여 넣기)과 넓히는 길 셋(시트를 표로 가져오기 · 엑셀 값 매핑 · 문서처럼 열어 편집)을 답함.
- 같은 날 사용자: "참고문헌을 엑셀시트에 작성하는거거든" · "문서처럼 올려서 편집하기야" · "구현해줘".

## ② 확정 사양

아래는 사용자가 말한 것(「엑셀 파일을 문서처럼 올려서 편집 — 참고문헌을 엑셀 시트에 작성」)을 뺀 나머지 모두가 **에이전트 판단이다(사용자 확인 전)**.

### 0. 말

- **시트 편집기** = xlsx 작업을 여는 따로 선 페이지 `/sheet#w=<작업 id>`(화면 이름 「시트 편집」). hwpx · docx 의 문서 화면(문단 · 표 블록)과 다른 화면이다.
- **칸** = 엑셀의 셀(화면 글에 「셀」 대신 「칸」 — 표 도구의 말과 같게) · **행** · **열** · **시트**.

### 1. 들어오는 길

- 시작 화면의 「파일 열기」 · 끌어 놓기 · 작업 목록에서 **.xlsx** 를 고르면 작업(형식 `xlsx`) 하나가 생기고 시트 편집기가 열린다. 같은 파일(이름 · 바이트)로 만든 작업이 있으면 묻지 않고 그 작업을 이어 연다.
  서버는 `POST /api/docs` 가 xlsx 를 받으면 시트 작업으로 넘기고(`{docId, open}`), `GET /api/docs/{id}` 가 xlsx 작업이면 `{format: "xlsx", open}` 을 준다 — 문서 화면은 `open` 이 있으면 그 주소로 간다(`app.js load`).
- 워크플로우(TASK) 카드 · 원본 / 목적 문서 칸 · 문서 목록은 xlsx 를 받지 않는다(워크플로우의 단계가 문단 · 표 블록을 전제한다).
- .xls(옛 바이너리) · .xlsm(매크로) 은 받지 않는다 — 「엑셀에서 .xlsx 로 저장해 올려 주세요」.

### 2. 저장 — 원본 XML 을 그대로 두고 고친 곳만

- `app/xlsx_doc.py` 가 xlsx 의 XML 을 **직접** 읽고 고친다(openpyxl 로 다시 쓰지 않는다 — 그림 · 차트 · 조건부 서식 · 데이터 유효성 · 인쇄 설정 같은, 이 화면이 모르는 것이 그대로 남게). 고친 부분(시트 · 워크북 · 표 · 그림 자리 …)만 다시 쓰고 나머지 멤버는 바이트 그대로다.
- 고친 글 칸은 인라인 글(`t="inlineStr"`)로 쓴다(공유 문자열 표는 건드리지 않는다). 고친 문서는 `calcChain.xml` 을 빼고 `calcPr fullCalcOnLoad="1"` 을 건다 — 엑셀이 열 때 수식을 다시 계산한다(지운 수식 칸을 계산 차례가 가리켜 엑셀이 「복구」 하는 것을 막는다).
- 공유 수식(`t="shared"`)은 그 시트를 처음 고칠 때 칸마다의 수식으로 푼다(무리의 첫 칸을 고치거나 행을 옮겨도 남은 칸의 수식이 깨지지 않게).
- 작업 폴더: `original.xlsx`(올린 원본) · `current.xlsx`(지금 — 편집마다 바꿔 씀) · `work.json`(`format: "xlsx"`) · `log.jsonl`(편집 한 줄씩). 실행 취소는 메모리에만(50번까지 — 서버를 다시 켜면 지금 상태부터).

### 3. 편집

- **칸 글**: 칸을 고르고 바로 치거나(바꿔 쓰기) 두 번 누르거나 F2(이어 쓰기) · 위의 칸 입력 줄. Enter = 아래로 · Tab = 오른쪽으로 · Esc = 그만 · Alt+Enter = 칸 안 줄 바꿈 · Delete = 고른 칸들 비우기.
  - 넣는 값의 판정: `=` 로 시작 → 수식 · `'` 로 시작 → 글(앞의 `'` 는 뺌) · 숫자 꼴(천 단위 쉼표 · `%` 포함)이고 정수부가 11자리 이하이고 0 으로 시작하지 않음 → 숫자 · 칸의 표시 형식이 날짜이고 `YYYY-MM-DD` · `YYYY.MM.DD` · `YYYY/MM/DD`(+ 시각) → 날짜 일련번호 · 칸의 표시 형식이 글(`@`) → 글 · 그 밖 → 글.
    정수부가 긴 숫자(ISBN · 번호)를 글로 두는 것은 엑셀이 지수로 보이거나 끝자리를 잃지 않게다.
  - 병합된 칸은 왼쪽 위 칸만 고친다 · 배열 수식 칸은 고치지 않는다(「엑셀에서 고치세요」).
- **여러 칸 붙여 넣기**: 탭 · 줄 나눔으로 나뉜 글(엑셀 · 한글 표 · 웹 표를 복사한 것)을 고른 칸부터 펼쳐 넣는다 — 시트 끝을 넘으면 넘는 만큼 쓴다. **복사**(Ctrl+C) = 고른 칸들을 같은 꼴의 글로.
- **행 넣기 · 지우기**(행 번호나 칸에서 오른쪽 단추 · 위 단추): 넣은 행은 바로 위 행(맨 위면 아래 행)의 칸 서식 · 높이를 받는다(값은 비움). 행을 넣고 지우면 그 시트를 가리키는 것이 함께 옮겨진다 —
  칸 · 행 번호 · 병합 · 모든 시트의 수식과 이름 정의(그 시트를 가리키는 것) · 조건부 서식과 데이터 유효성의 범위와 수식 · 하이퍼링크 · 자동 필터 · 표(ListObject)의 범위 · 메모 · 그림 · 차트의 자리(행) · 쪽 나눔 · 고른 칸 · 차원.
  지운 행만 가리키던 수식 참조는 `#REF!` 가 되고(엑셀과 같음) 범위는 줄어든다 · 표(ListObject)의 머리 행을 지우는 것은 막는다. 1,048,576 행을 넘기지 않는다.
- **실행 취소**(Ctrl+Z · 위 단추) · **내려받기**(「xlsx 저장」 · Ctrl+S — 지금 상태의 xlsx, 이름은 올린 이름).
- 편집 요청은 화면이 아는 차례(`rev`)를 싣고, 서버의 차례와 다르면 409 — 화면은 다시 읽는다(다른 창에서 같은 작업을 고친 때).

### 4. 보이는 것

- 시트 탭(아래 · 숨긴 시트는 흐리게), 열 머리(A, B …) · 행 번호, 열 너비 · 행 높이(엑셀의 값 → px), 숨긴 행 · 열은 그리지 않음, 병합, 틀 고정(위 · 왼쪽)은 머리처럼 붙어 있게.
- 칸 서식의 일부: 글꼴 굵게 · 기울임 · 밑줄 · 취소선 · 크기 · 색 · 채움(RGB · 테마 색 + 밝기 · 옛 색 번호) · 가로 · 세로 맞춤 · 줄 바꿈 · 테두리(선 굵기는 두 가지로).
- 값의 표시: 일반 · `0` · `0.00` · `#,##0` 꼴의 자릿수와 천 단위 · 백분율 · 날짜 · 시각(그 밖의 형식은 일반으로). 수식 칸은 엑셀이 마지막으로 계산한 값을 보이고(위 입력 줄은 수식), 이 화면에서 고친 뒤의 값은 엑셀에서 열 때 다시 계산된다 — 한 번이라도 고친 작업에서는 **수식 칸 모두**를 흐린 표시(회색 · 점선 밑줄)로 「다시 계산 전」 이라 보인다(어느 칸이 어느 칸에 기대는지 이 화면은 셈하지 않는다).
- 시트 하나에 그리는 것은 2,000 행 · 200 열까지 — 넘으면 위에 알린다(파일의 나머지는 그대로 남는다).

### 5. 의존

- `app/xlsx_doc.py` = 순수(표준 라이브러리 + lxml — 웹 · 작업 폴더를 모름) · `app/xlsx_api.py` = 끝점(작업 폴더는 `works` 로만 · `app.server` 를 가져오지 않는다 — server.py 가 라우터를 include 하고 `_open` · `get_doc` 에서 xlsx 를 넘긴다) ·
  화면 `app/static/sheet/`(`index.html` · `sheet.js` · `sheet.css`) = `app.js` 를 읽지 않는다(`account/chip.js` 를 먼저 싣는다).
- 계정: 작업은 `works.folder` 로만 찾는다(남의 작업 = 없는 작업 — spec_계정 ② §3).

### 6. 끝점

| 끝점 | 일 |
|---|---|
| `GET /sheet` | 시트 편집기 페이지 |
| `POST /api/sheets` (multipart `file`, `?new=1`) | xlsx 올리기 → `{docId, name, reused, open}` |
| `GET /api/sheets/{id}?sheet=i` | `{docId, name, rev, undo, sheets[{name, hidden}], sheet: 보기}` |
| `PUT /api/sheets/{id}/cells` `{sheet, rev, cells[{r, c, text}]}` | 칸 글 → `{rev, undo, cells[…], stale[…]}` (붙여 넣기 · 비우기도) |
| `POST /api/sheets/{id}/rows` `{sheet, rev, op: insert｜delete, at, n ｜ r0, r1}` | 행 넣기 · 지우기 → 시트 보기 전체 |
| `POST /api/sheets/{id}/undo` `{sheet}` | 실행 취소 → 시트 보기 전체 |
| `GET /api/sheets/{id}/download` | 지금 xlsx |

## ④ 미결 / 후속

- **참고문헌 작성 에이전트**(사용자가 말한 쓰임): 자료(문서 라이브러리의 MD · 올린 문서)에서 참고문헌을 뽑아 시트의 열(번호 · 저자 · 제목 · 학술지 · 연도 …)에 맞춰 행으로 넣는 제안 → 고른 것만 반영. 시트의 머리 행을 읽는 법 · 문헌 꼴(APA 등)을 사용자와 정한 뒤 만든다.
- 열 넣기 · 지우기 · 칸 서식 바꾸기(굵게 · 채움 · 맞춤) · 열 너비 · 행 높이 끌기 · 시트 더하기 · 이름 바꾸기 · 찾기 · 바꾸기.
- 화면 안 수식 다시 계산(지금은 엑셀이 열 때) · 행 지우기 · 넣기의 그 밖 참조(행 전체 참조 `3:5` · 다른 파일 참조 · 확장 목록 `extLst` 의 범위 · 피벗 · 슬라이서) — 지금은 옮기지 않는다.
- 엑셀로 찍은 PDF 견주기(hwpx · docx 의 검증과 같은 것) · 공유(손님과 같이 쓰기).
- 워크플로우에 xlsx 를 원본 · 목적 문서로 쓰는 것(예: 참고문헌 시트를 연차보고서의 표로) — 단계들이 블록을 전제해 지금은 막는다.
