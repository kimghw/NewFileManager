앱(8114)에 사용자 계정을 두고, 계정마다 작업 · 프로젝트를 따로 쓰게 하는 것. 관련: [spec_배포.md](spec_배포.md)(바깥 주소 · Caddy 기본 인증 — 앱 로그인의 바깥 문) ·
[spec_포인터.md](spec_포인터.md)(같은 문서를 연 화면끼리 — 방은 문서 id) · [spec_공유.md](spec_공유.md)(손님 포트 8119 — 링크와 키: 계정과 따로).

## ① 질의 · 요청 히스토리

- 2026-11-24 질의 "현재 서버에서 계정 별로 작업할 수 있도록 되어 있나?" → 아니다(앱에 계정이 없다 — [spec_배포.md](spec_배포.md) ① 같은 날).
- 2026-11-24 사용자 **"앱에 계정별로 할 수 있게 해줘. 관리자 모드 sscb/sscb 로 하고 승인할 수 있도록 해줘,"** → ② 전부.
  사용자가 말한 것은 이 한 문장이다 — 「계정별로」 를 **작업 · 프로젝트를 계정마다 따로**로, 「승인」 을 **가입 신청을 관리자가 승인**으로 읽은 것과 ② 의 나머지 규칙은 에이전트 판단(사용자 확인 전).

## ② 확정 사양

### 1. 계정 · 가입 · 승인

- **계정** = 이름(영문 소문자 · 숫자 · `_` 2~20자 — 폴더 이름으로 쓴다) + 비밀번호(4자 이상). 상태 셋: **승인 대기**(`pending`) · **승인됨**(`approved`) · **막음**(`blocked`).
- **관리자** = `sscb`(처음 비밀번호 `sscb` — 계정 파일에 관리자가 없으면 서버가 만든다). 관리자는 하나다(관리자를 더 만드는 기능은 없다).
- **가입 신청**: 로그인 화면(`/login`)의 「가입 신청」 — 누구나 이름 · 비밀번호로 신청하고 **승인 대기**가 된다. 관리자가 승인하기 전에는 로그인할 수 없다(「승인을 기다리는 중」).
- **승인**: 관리자가 계정 화면(`/account`)에서 대기 중인 신청을 「승인」 · 「거절」(신청을 지움). 승인된 계정은 「막기」 · 「풀기」 · 「비밀번호 초기화」(관리자가 새 비밀번호를 정함) · 「지우기」.
  계정을 지워도 그 계정의 작업 폴더는 지우지 않는다(같은 이름으로 다시 가입 · 승인하면 이어진다).
- 누구나 제 비밀번호를 바꾼다(계정 화면 — 지금 비밀번호 확인). 비밀번호가 바뀌면 그 계정의 다른 로그인은 풀린다.
- 저장 = 이 PC 의 `%LOCALAPPDATA%\NewFileManager\accounts.json`(env `NFM_ACCOUNTS` — 시험은 임시 파일). 비밀번호는 소금 + PBKDF2-SHA256 해시만 남긴다.

### 2. 로그인 문

- **켜는 것은 env `NFM_AUTH=1`**(띄우개 [tools/start_8114.ps1](../tools/start_8114.ps1)가 건다) — 안 걸면 문이 없다(전과 같은 동작: 시험 · 화면 검사 · 임시 서버).
- 문 = 순수 ASGI 미들웨어 하나(`app/accounts_api.py` `Gate` — http · websocket 모두). 로그인 안 한 요청: 페이지(GET · `/api/` 밖)는 `/login?next=…` 으로 · API 는 **401** · 웹소켓은 닫음(1008).
  로그인 없이 열리는 것 = `/login` · `/api/account/login` · `join` · `me` · `/static/account/` 뿐.
- 로그인 = 쿠키 `nfm_auth`(HttpOnly · SameSite=Lax · https 면 Secure · 30일) — 값은 `이름.만료.서명`(서명 = 계정 파일의 비밀 값 + 그 계정의 비밀번호 해시로 HMAC: 서버를 다시 켜도 남고 비밀번호를 바꾸면 풀린다).
  요청마다 계정의 상태를 다시 본다(막으면 바로 풀린다).
- **이 PC 안에서 바로 온 요청은 관리자다**(상대가 127.0.0.1 이고 프록시 머리말 `X-Forwarded-For` 가 없음 — 바깥 요청은 Caddy 가 그 머리말을 늘 붙인다): 쿠키가 있으면 쿠키의 계정이 먼저.
  이 PC 의 도구 · 확인 절차(`GET /api/headings/llm` · `GET /api/flow/active`)가 로그인 없이 전처럼 돈다.
- 잘못된 비밀번호가 한 이름에 5분 안에 5번이면 그 이름의 로그인을 5분 동안 받지 않는다(429).
- 손님 포트(8119)와 문서 라이브러리(8121)에는 이 문이 없다(따로 선 앱 · 서버).

### 3. 계정마다 따로 — 작업 폴더의 뿌리

- **계정마다 작업 폴더의 뿌리가 따로다**: 관리자 = 지금의 뿌리(`works.root()` — 있던 작업은 모두 관리자의 것) · 그 밖의 계정 = `<뿌리>/_accounts/<이름>/`.
  요청의 계정은 맥락 변수 `works.ACCOUNT`(문이 건다 — 관리자 · 문 꺼짐 · 맥락 없는 뒤 스레드는 None).
- 그 뿌리에 든 것이 모두 계정마다 따로다 — **작업**(문서 · 기록 · 확정 · 실행 기록) · **프로젝트**(`projects.json` — 구성 · 버전: 계정이 다르면 같은 이름의 프로젝트도 따로) · **워크플로우 옵션**(`task_options`).
  작업 목록 · 같은 파일 찾기 · 묶음(프로젝트 · 워크플로우 · 라운드) 찾기가 그 뿌리만 본다 — 끝점마다 따로 거르지 않는다.
- **남의 작업 id 는 「없는 작업」 이다**(404): `works.folder(wid)` 는 계정 맥락에서 제 뿌리만 본다 · 문이 주소의 작업 id(`/api/docs/<id>` · `/api/works/<id>`)를 먼저 보고 · `server._sess()` 가 메모리에 열린 문서도 제 것인지 본다(본문으로 받은 id 까지).
- 맥락이 없는 뒤 스레드(작업 저장 · 검증)는 id 로 어느 뿌리의 작업이든 찾는다(`folder` — 맥락이 None 일 때만). LLM 호출 · 워크플로우 실행의 스레드는 전처럼 맥락을 들고 간다(`agent_notes.carry` · `copy_context` — 계정도 같이).
- 관리자는 다른 계정의 작업을 목록에서 보지 않는다(id 를 알면 열 수는 있다 — 관리자의 맥락은 None).
- `GET /api/flow/active`(도는 실행 모두)는 관리자만.
- **같이 쓰는 것(계정마다 따로가 아닌 것)**: 이 PC 의 설정 — 에이전트 설정 · 도구에 적어 두는 내용 · 도구 이름 · 조립한 워크플로우 · 서식 보관함 · 저장한 양식 · 표 매핑 규칙 · 양식의 표 판정 · 저장한 구성 · 헤딩 규칙 · 지침 · 스킬 글 —
  과 LLM(구독) · 문서 라이브러리 · 렌더 캐시 · LLM 호출 기록 · 서버 로그. 누가 고치든 모든 계정에 닿는다.

### 4. 화면

- `/login`(로그인 | 가입 신청) · `/account`(내 계정 — 비밀번호 바꾸기 · 로그아웃 / 관리자 — 승인 대기 · 계정 목록). 따로 선 페이지(`app/static/account/` — `app.js` 를 읽지 않는다 · 색 · 단추는 `style.css` 의 것).
- 상단 바 오른쪽 끝에 **계정 단추**(이름 — 누르면 `/account` · 관리자에게 승인 대기가 있으면 수를 붙임): `account/chip.js` 를 세 페이지(`/` · `/workflow` · `/agents`)가 읽는다 — 문이 꺼져 있으면 아무것도 안 그린다.
  그 스크립트가 401 을 받은 화면을 `/login` 으로 보낸다(로그인이 풀린 채 열려 있던 화면).

## ④ 미결 · 후속

- **바깥 문이 둘이다**: 바깥 주소는 Caddy 기본 인증(계정 하나) 뒤에 앱 로그인이 선다 — 가입할 사람도 Caddy 의 비밀번호를 먼저 알아야 한다. Caddy 의 기본 인증을 걷을지는 사용자 결정
  (걷으면 로그인 화면이 공개 주소에 바로 선다 — 그 전에 관리자 비밀번호 `sscb` 를 바꿔야 한다).
- 관리자 비밀번호 `sscb` 는 사용자가 정한 처음 값이다 — 짧다. 계정 화면에서 바꿀 수 있다.
- 같이 쓰는 설정(② §3 끝)을 계정마다 나누거나 관리자만 고치게 할지 — 지금은 누구나 고친다.
- 관리자가 다른 계정의 작업을 보는 화면 · 계정 사이에 작업을 넘기는 기능은 없다.
- 계정을 지울 때 그 작업 폴더를 지우는 기능은 없다(디스크에 남는다).
- 작업 저장을 끈 서버(`NFM_WORKS=off`)에서는 관리자 아닌 계정이 문서를 열 수 없다(제 작업인지 볼 폴더가 없다 — 404).
- 도는 워크플로우 실행의 바쁨 막이는 프로젝트 **이름**으로 본다 — 두 계정이 같은 이름의 프로젝트를 쓰면 한쪽의 실행 동안 다른 쪽의 그 프로젝트 초기화 · 이름 바꾸기가 409 로 기다린다(자료는 안 섞인다).
- 서버 로그 · LLM 호출 기록(어느 에이전트 · 모델 · 시간 — 글은 없음)은 모든 계정의 작업 진행 에이전트가 읽는다(`work_logs` 의 `llm` · `server`).
- 포인터의 방은 전처럼 문서 id 하나다 — 남의 문서는 열 수 없으니 방도 계정 안에 머문다(관리자가 id 로 연 경우만 섞인다).
