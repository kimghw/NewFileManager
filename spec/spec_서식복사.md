  `style_copy: {name: "문서 서식 복사", act: "서식 복사", doc: "any", file: "", up: "문서", kind: "general", entry: "Style", accept: ["hwp", "hwpx", "docx", "pdf"], desc, hint}`.
  - `accept` = 그 TASK 의 카드가 받는 확장자(없으면 hwp·hwpx — 다른 TASK 는 전과 같다).
  - `entry: "Style"` = 처음 여는 것이 패널 도구가 아니라 **서식 관리자의 「서식 복사」 보기**(2열). 화면은 `showTab(taskEntryOf(job))` 를 부르던 곳(app.js · home_files.js · project_workspace.js)을 `taskEnter(job)` 하나로 바꾼다:
    entry 가 `"Style"` 이면 패널 = hwpx 면 에이전트 보기(`Agent`) · docx 면 검증(`Verify`), 그리고 2열에 「서식 복사」 보기(`styleSaveOpen()`). 그 밖의 entry 는 전처럼 `showTab(entry)`.
  - desc 「문서에서 템플릿·문서 서식·테이블 서식을 뽑아 서식 관리자에 저장하고 PDF 로 검증합니다.」
- **시작**(카드를 누르거나 카드에 파일을 놓음):
  - hwp·hwpx·docx — 전과 같은 길: `POST /api/docs?job=style_copy` → `PUT /api/works/{id}/task {kind: "general", job: "style_copy", file: 양식 판정이 정한 종류(없으면 "")}` → 새 작업이면 첫 분석(hwpx: 헤딩 2·3단계 스크립트 — 글 후보가 쓴다 · 어느 TASK 든 같은 기본 분석이고 일반 문서라 구분 기준 항목은 없다: [spec_작업.md](spec_작업.md) ② §20) → `taskEnter`.
  - pdf — **작업을 만들지 않는다**: `POST /api/styles/extract-file` → 서식 관리자 「서식 복사」 보기(파일 후보). 시작 화면(문서 없음)에서도 2열이 시작 화면 본문 옆에 열린다(모달 아님 — 닫으면 시작 화면 그대로).
  - 카드에 여럿을 놓으면 전처럼 시작 화면 문서 목록에 더한다. pdf 는 목록에 넣지 않는다(알림 「PDF 는 「문서 서식 복사」 카드에 하나씩 놓으세요」). 목록으로 시작할 때 목적 문서 = 서식을 뽑을 문서 — **이 TASK 는 docx 도 된다**, 나머지 문서는 안 올린다(양식 맞추기와 같다).
  - 이 TASK 의 작업을 다시 열면(`load` — 둘째 면 PEEK 아님) 2열에 「서식 복사」 보기를 연다.
- **단계**(「서식 복사」 보기의 단계 줄 — §2): ① 후보 찾기(스크립트) → ② 에이전트 추출(LLM — 이름 · 저장할 만한가 · 띠 수) → ③ 저장(hwpx·docx 두 형식) → ④ PDF 검증(한글 · Word). 「한 번에 진행」 = ②③④ 를 차례로.
- 로고 `taskIcon-style_copy`(쪽 + 서식 붓) · 바탕 `data-doc="any"`(옅은 회색). 카드 일곱 장 — 한 줄 7 → 4 → 2 → 1(가로 넘침 없음: [design.md](../design.md) §12).

### 2. 서식 관리자 — 화면(`app/static/style_lib.js·css`)

2열(`headsDlg`) kind 둘 — `styleLib`(보관한 서식) · `styleSave`(서식 복사 — 후보). 팝업 아님([design.md](../design.md) §2·§13).

- **보관한 서식**(`styleLib` — 제목 「서식 관리자」):
  - **종류 고르기**(세그먼트 셋 — `[data-sl-tab]`): 「템플릿 n」(`text`) · 「문서 서식 n」(`page`) · 「테이블 서식 n」(`table`). 처음 = 템플릿. 고른 종류는 문서를 바꿔도 남는다.
  - 위 단추: 「이 문서에서 복사」(`[data-sl-act="fromDoc"]` — hwpx·docx 문서를 열었을 때) · 「파일에서 복사」(`fromFile` — hwp·hwpx·docx·pdf).
  - 서식 줄(`section.sl-item[data-style]`): 이름 · 충실도 꼬리표 · **검증 꼬리표 둘**(`.sl-verify[data-format="hwpx"|"docx"]` — 「hwpx 검증됨」 · 「docx 확인 필요」 · 「docx 없음」 …) · 요약 줄 · 견본 그림(형식 전환 — hwpx | docx) · 뺀 것·검증 내역(접힘 — 형식마다).
    문서 서식의 요약 줄 = 「A4 세로 · 여백 왼 30 · 오 30 · 위 20 · 아래 15mm · 본문 함초롬바탕 11pt」.
  - 동작: 테이블 서식 = 「빈 표 넣기」(구조 있음) · 「고른 표에 입히기」 / 템플릿 = 항목마다 「고른 문단에 입히기」 / 문서 서식 = 「이 문서에 입히기」(`[data-sl-act="page"]`) /
    공통 = 「hwpx 받기」 · 「docx 받기」(`[data-sl-act="getHwpx"|"getDocx"]`) · 이름 바꾸기 · 다시 검증 · 지우기.
    docx 문서에서 켜지는 것은 「빈 표 넣기」 · 「고른 문단에 입히기」 와 받기·관리뿐 — 나머지는 꺼 두고 도움말에 까닭(§9).
- **서식 복사**(`styleSave` — 제목 「서식 복사 — <문서·파일 이름>」):
  - **단계 줄**(`.sl-steps` — ①~④ 이름 + 끝난 것 ✓ · 지금 하는 것 동그라미: design.md §7·§11) + **「한 번에 진행」**(`[data-sl-act="auto"]` — 강조 단추).
  - 후보 구역 셋: 「문서 서식 후보」(0~1) · 「템플릿 후보」 · 「테이블 서식 후보」. 줄마다 체크 · 이름 · (표) 띠 수 · 「추천」(LLM 이 저장할 만하다고 본 것) · 자리로.
  - 「에이전트 추출」(`[data-sl-act="name"]` — 전의 「이름 붙이기(LLM)」: 문서·파일 모두) · 「고른 n개 저장」(`save`).
  - 저장 뒤 **검증 진행 줄**: 「PDF 검증 중 — 3/5 끝남」 → 끝나면 요약(검증됨 n · 확인 필요 n · 실패 n · 없음 n — 형식마다) + 「서식 관리자에서 보기」.
  - 「한 번에 진행」: ② LLM 한 번 → 추천(keep)된 후보 + 문서 서식 후보(+ 사람이 이미 고른 것)를 저장 → ④ 검증을 기다림(서식마다 2초 간격 · 180초 한도 — 넘으면 「검증이 아직 돕니다 — 서식 관리자에서 확인」).
    LLM 을 쓸 수 없으면 ② 에서 멈춘다(「에이전트(LLM)를 쓸 수 없습니다 — 후보를 직접 골라 저장하세요」). 사람이 고친 이름·띠 수는 덮지 않는다. 문서가 바뀌면 후보를 다시 찾는다(전과 같다).
- **여는 곳**: 도구 줄 「서식」 묶음(§3) · 에이전트 보기 상태 줄 「서식 관리자」 · 표 메뉴 「서식 관리자에 저장…」 · TASK 시작·다시 열기(§1) · 시작 화면의 PDF(§1)(문서 이름 줄의 아이콘은 2026-11-16 에 뺌 — 그 아이콘은 여백의 서식 라벨 켜기/끄기가 됐다: [spec_작업.md](spec_작업.md) ② §17 「이름 줄 표시 아이콘」).
- 구현하며 정한 것(2026-11-14): 저장이 끝나도 목록으로 넘어가지 않고 「서식 복사」 열에 남는다(검증 진행 줄을 보이려고 — 「서식 관리자에서 보기」 `[data-sl-act="toLib"]` 로 간다) · 끝난 단계는 「✓①」 ·
  문서 서식 후보의 「추천」 은 회색(LLM 판단이 아니라 규칙 — 보라는 LLM 제안에만) · 강조 단추는 고른 것이 없으면 「한 번에 진행」, 있으면 「고른 n개 저장」 · 표 메뉴 「서식 관리자에 저장…」 은 hwpx 문서만(전과 같다) ·

### 4. 두 형식 — docx 운반 문서(`app/style_docx.py`)

- 보관함의 서식 하나 = `carrier.hwpx`(기존 — 뜻의 원본) + **`carrier.docx`**. meta 에 `docx: {sha256, losses: [글…]} | null`.
- docx 운반 문서는 **형식 중립 명세에서 짓는다**(원본이 docx 여도 같다 — 원본 XML 을 옮기지 않는다): 테이블 서식 = hwpx 운반 문서의 표 명세(`style_carrier.view(carrier, meta)["spec"]` — 라벨·견본 글 포함) ·
  템플릿 = `meta.items`(서식 요약 `format` · `marker` · `sample`) · 문서 서식 = `meta.page`·`meta.body`. 바탕 = A4 · 여백 20mm(문서 서식은 그 값).
  - 옮기는 것: 표 = 격자(합친 칸) · 열 폭 · 칸 음영 · 세로 정렬 · 칸 여백 · 괘선(종류 · 굵기 · 색 — Word 가 받는 가장 가까운 값) · 칸 글의 글꼴 · 크기 · 굵게 · 기울임 · 밑줄 · 색 · 정렬 · 줄 간격 /
    글 = 같은 글 모양 + 왼쪽 여백 · 첫 줄 · 문단 위아래 간격 + 레터(글자 그대로).
  - 못 옮기는 것은 `docx.losses` 에: 자동 번호 · 서식 요약에 없는 값 · Word 에 없는 선 종류(장평·자간은 서식 요약에 있어 옮긴다 — 아래 「구현하며 정한 것」).
- 짓는 때: 저장(`create`)과 운반 문서가 바뀌는 `revise` 때 함께. 옛 서식(carrier.docx 없음)은 내려받기·검증·docx 문서에 적용할 때 그 자리에서 지어 그 revision 에 붙인다. 못 지으면 저장은 그대로 되고 `docx: null`.
- docx 문서를 열 수 있는 것으로 짓는다 — 최소 패키지(`[Content_Types].xml` · `_rels/.rels` · `word/document.xml` · `word/styles.xml` · `word/_rels/document.xml.rels`). 이 앱의 `DocxDoc` 으로 다시 열려야 한다(적용 §9 의 `src`).
- 구현하며 정한 것(2026-11-14): 패키지에 `word/settings.xml`(호환 모드 15 — 표 왼끝이 여백 자리에 오게)을 더함 · 모양은 모두 **직접 서식**(스타일을 가리키지 않는다 — 다른 docx 로 복사해도 받는 문서의 스타일에 물들지 않게) ·
  zip 시각을 고정해 **같은 명세는 같은 바이트** · 장평·자간도 옮긴다(서식 요약에 있는 값) · 내어쓰기는 Word 의 left 에 그 폭을 더해 첫 줄이 한글과 같은 자리에 오게.
- **같은 서식은 한 번만**(2026-11-14 — 실물 확인에서: 같은 문서를 다시 「한 번에 진행」 하면 서식 수십 개가 겹쳐 쌓인다): 저장할 때 **종류 · docx 운반 문서의 해시 · 띠 수 · 구조가 있나** 가 같은 서식이 보관함에 이미 있으면
  새로 만들지 않고 있던 것을 돌려준다(응답 201 그대로 + `existing: true` · 이름은 있던 것 · 검증을 다시 걸지 않는다). 다른 문서에서 뽑은 같은 서식도 하나가 된다. docx 를 못 지은 서식은 견주지 않는다(늘 새로).
  화면은 그 줄에 「이미 보관함에 있는 서식입니다 — 다시 저장하지 않았습니다」.

### 5. 문서 서식 — 종류 `page`(`app/style_page.py`)

- 뜻: **쪽 설정 + 본문 바탕 글 모양**. `meta.page = {widthMm, heightMm, landscape: bool, marginsMm: {l, r, t, b, header, footer, gutter}}`(`widthMm`·`heightMm` = 보이는 방향의 값 — 가로면 width > height) ·
  `meta.body = {format: 서식 요약 사전, count: 그 서식의 문단 수} | null`.
- 추출:
  - hwpx = 첫 구역의 쪽 설정(`pagePr` — `landscape="NARROWLY"` 는 세로로 적힌 값: `HwpxDoc._body_width_mm` 의 규칙). 구역마다 다르면 losses 「구역마다 쪽 설정이 다릅니다 — 첫 구역 것」.
    바탕 글 = 본문 최상위 문단 가운데 서식 요약이 같은 것끼리 묶어 **글자 수가 가장 많은** 서식.
  - docx = `sectPr` 의 `pgSz`·`pgMar`, 바탕 글은 같은 규칙.
  - pdf = 쪽 크기(가장 많은 크기) · 여백(쪽마다 글이 놓인 상자의 가장자리 → 중앙값. header·footer·gutter 는 0) · 바탕 글 = 가장 많이 쓰인 글 조각의 글꼴·크기. `fidelity: "approx"` · losses 「여백은 글이 놓인 자리로 어림했습니다 · 머리말·꼬리말 여백은 재지 못함」.
- 후보: 문서마다 0~1개 — `{key: "page", page, body, sample: 요약 한 줄}`.
- 운반 문서: hwpx = 빈 바탕(`style_carrier.open_base`)의 쪽 설정을 그 값으로 + 바탕 글 모양의 견본 문단 3줄 · docx = 같은 것(§4).
- 하지 않는 것(v1): 머리말·꼬리말 내용 · 쪽 번호 · 단 · 구역마다 다른 설정 · 바탕 글 모양을 문서 전체에 입히기.
- 구현하며 정한 것(2026-11-14 — 실측은 [references/HWPX_렌더링_검증.md](../references/HWPX_렌더링_검증.md) · [references/DOCX_포맷.md](../references/DOCX_포맷.md)):
  - **여백의 뜻을 하나로**: `t`·`b` = 종이 끝에서 **본문**까지, `header`·`footer` = 그 안에서 머리말·꼬리말이 차지하는 몫. 한글은 본문이 「위쪽 + 머리말」 에서 시작하므로 읽을 때 `t = top + header`, 쓸 때 `top = t − header` ·
    Word 는 `top = t`, 머리말 거리 = `t − header`. 속성 값을 그대로 옮기면 같은 문서 서식이 두 형식에서 다른 쪽을 그린다. `clean` 은 머리말 > 위 여백을 거절하고, `landscape` 는 폭 > 높이로 정한다.
  - 바탕 글이 없는 문서(본문 글이 모두 표 안 — 기술수요조사서)는 `body: null` — 쪽 설정만의 문서 서식이다.
  - hwpx 운반 문서의 **견본 첫 줄은 첫 문단**(구역 설정을 품은 문단)에 쓴다 — 비워 두면 견본이 둘째 줄로 밀려 본문 위끝을 잴 수 없다. 견본 문단 id = `style_page.sample_ids`.
  - `set_page` 는 본문 상자가 바뀐 구역의 **최상위 문단 줄 배치 캐시**를 지운다(한글이 옛 폭의 줄 나눔으로 그리지 않게 · 칸 안 문단은 그대로).
  - PDF: 글 상자의 아래·오른쪽 가장자리가 쪽 크기의 35% 를 넘으면(글이 쪽을 다 채우지 않음 — 표 하나뿐인 쪽) 여백으로 읽지 않고 맞은편 여백과 같게 두며 losses 에 알린다.
  - `fidelity`: hwpx 문서·파일 = `native` · docx = `summary` · pdf = `approx`.

### 6. 추출 — 문서 · 파일 · 에이전트

- **문서에서**(`POST /api/docs/{id}/styles/candidates` · `POST /api/docs/{id}/styles`): hwpx **· docx**.
  - docx 문서 = 파일 추출과 같은 규칙(표 = 명세로 다시 지음 · 글 = 서식이 같은 문단 묶음(레벨 없음) · `fidelity: "summary"`). 저장은 `{kind: "table", table}` · `{kind: "text", paras}` · `{kind: "page"}`(`template` 은 hwpx 만).
  - hwpx 문서에 2단계 그래프가 아직 없으면 그 자리에서 스크립트 그래프(`style_extract.script_graph` — 저장 안 함)로 글 후보를 낸다(`stage2: "script"`). 그 후보의 저장(`{kind: "text", template}`)도 같은 스크립트 그래프로 한다
    (실물 확인에서: 후보는 나오는데 저장이 400 「2단계 결과가 없습니다」 이던 것).
- **파일에서**(`POST /api/styles/extract-file` → `POST /api/styles/from-file`): 전과 같다 + 문서 서식 후보(`pages`) + 이름 붙이기 `POST /api/styles/name-file`.
- **에이전트 추출 ① — 서식 관리자의 「에이전트 추출」·「한 번에 진행」**: `style_extract.name`(LLM 한 번 — 후보마다 이름 · 저장할 만한가 `keep` · 띠 수 보정). 문서 서식 후보는 LLM 에 묻지 않는다(문서에 하나 — 늘 추천 · 기본 이름 「<문서 이름> 문서 서식」).
  프롬프트 = 계약(코드) + **할 일 프롬프트 `jobs/style_copy.md`**(계약 바로 뒤 「## 할 일 — 문서 서식 복사」 절 — 그 작업의 TASK 가 무엇이든 늘: 이 호출이 하는 일이 「문서 서식 복사」 다) + 자료. 무엇이 다시 쓸 만한 서식인가 · 이름 기준의 **원본은 그 글**이고,
  같은 기준이 계약 글(`style_extract.CONTRACT`)과 에이전트 지침(`agent.md` 「서식 복사」 절)에도 풀어 적혀 있다 — 기준을 바꾸면 세 곳을 함께 본다(2026-11-14 문서 검토에서: 처음에는 ① 이 그 글을 안 읽었다).
- **에이전트 추출 ② — 에이전트 보기의 행동 `styleCopy`**(hwpx 문서 — spec_일반편집 ② §8 의 다섯째 type):
  - `{type: "styleCopy", picks: [{kind: "table", table: 표 id, name, blueprint: bool} | {kind: "text", template: 템플릿 id, name} | {kind: "text", paras: [문단 id…], name} | {kind: "page", name}]}` — 1~8개.
  - 프롬프트 자료에 더한다: `templates`(2단계 그래프의 개요템플릿·서브 템플릿 — id · no · name · chain · 레벨 수, 20개까지 · 그래프가 없으면 빈 목록). `tables`·`selection` 은 이미 있다.
  - 계약: 사람이 서식을 **복사·추출·저장**해 달라고 할 때만 낸다 · 대상은 사람이 고른 표·문단이 먼저, 「이 문서의 서식」 처럼 넓게 말하면 다시 쓸 만한 표(같은 꼴이 여럿 · 머리행이 있는 자료 표)와 주 템플릿 + 문서 서식 ·
    이름은 구조와 겉모습으로(문서의 고유명사·수치·연도를 넣지 않는다) · 문서는 바뀌지 않는다. 판단 기준의 글은 지침 `app/merge_guides_default/agent.md` 에.
  - 스크립트 검사: 대상 id 가 이 턴에 보낸 것인가(표 · 템플릿 · 문단) · kind 꼴 · 이름 1~60자 · 같은 대상 중복 제거 → 통과한 picks 로 **제안 하나**(type `styleCopy` · 제목 「서식 복사 — 테이블 서식 2 · 템플릿 1 · 문서 서식 1」 · view = picks 목록).
    문서를 바꾸지 않으므로 경고가 없으면 처음부터 고른다. 대상 지문 = 고른 표·문단의 글·서식(바뀌면 `stale`).
  - 반영(`POST /api/docs/{id}/agent/apply` — 같은 끝점): **문서를 바꾸지 않는다**(`server._edit` 아님 — 실행 취소 없음 · 문서 차례 그대로). 쓰기 정책에 걸리지 않는다(**원본 문서에서도 된다**).
    picks 마다 `style_api.save_doc_style(s, body)`(= `POST …/styles` 의 몸통) → 응답 `{replayed: false, applied: {turn, proposal, type: "styleCopy", state, styles: [{id, name, kind, revision, pick}], failed: [{name, why, kind, pick}], note?}, rev}`
    (`pick` = `view.picks` 안의 차례 · 문서 조각 `tops`·`texts`·`undo` 는 없다). 하나라도 저장되면 제안은 「반영됨」(`state: "applied"`), 모두 실패면 열어 둔다(200 + `state: "open"` — 다시 반영하려면 새 `requestId`). 기록 `agentApply`.
    구현하며 정한 것: 제안의 `view = {picks: [{kind, kindName, name | null(기본 이름), summary, warn: [글], + 표 table·rows·cols·blueprint | 템플릿 template·no·chain | 문단 paras·texts}]}` · `target = {block, blocks, looks, hash}`(표 = 서식 지문 · 문단 = 글 + 서식 — 템플릿·문서 서식 pick 은 지문에 안 든다) ·
    60자를 넘는 이름 · `template` 과 `paras` 를 함께 적은 pick 은 버린다(`dropped` 에 `pick` 차례) · 지문 검사와 저장 사이에 세션 잠금이 풀린다(`save_doc_style` 이 안에서 잡는다).
  - 화면 카드: 꼬리표 「서식 복사」 · 저장 뒤 서식마다 검증 꼬리표(2초마다 다시 읽음) · 「서식 관리자에서 보기」.

### 7. PDF 검증 — 두 형식(`app/style_verify.py`)

- `start(sid)` 가 **hwpx(한글) → docx(Word)** 를 차례로 출력해 잰다. 기록 둘: `meta.verify`(기존 — hwpx) · **`meta.verifyDocx`**(같은 꼴 + `format: "docx"` · `renderer: {name: "Word"}`). 그림 `proof.png` · `proof_docx.png`.
  Word 출력이 없으면(`pdf_render.available("docx")` 가 거짓) `verifyDocx.status = "none"`. docx 운반 문서가 없으면 `verifyDocx = null`.
- docx 의 기대값은 **명세에서** 읽는다(표: 칸 글 · 글자 크기 · 굵게 · 색 · 글꼴 · 음영 · 괘선 있음 · 표 폭 / 글: 크기 · 굵게 · 색 · 글꼴 · 들여쓰기). 한글에 맞춘 보정(칸 폭 쌓기 · 선 굵기 맞춤)은 hwpx 쪽에만 —
  Word 가 달리 그려 견줄 수 없는 것은 `unknown`·`unsupported` 로 둔다(못 잰 것을 통과로 덮지 않는다).
- 문서 서식(profile `page-v1` — 검사 항목은 두 형식이 같다): `render` · `pageSize`(한글 ±1.0mm · Word ±0.5mm) · `marginLeft`·`marginTop`(견본 첫 줄의 자리 — ±1.5mm) · `fontSize` · `fontFace`. `unsupported`: 아래·오른쪽 여백 · 머리말·꼬리말 여백.
- 전체 판정·`subjectHash`·작업으로 도는 것(동기 응답이 아님)은 기존과 같다. 도는 동안 그 형식의 status 는 `running`.
- 구현하며 맞춘 것(2026-11-14 — 실제 한글·Word 출력으로):
  - **Word 의 그림 버릇을 걷어 낸 뒤 견준다**(`word_page`): 칸 음영 위에 글 줄마다 덧칠한 같은 색 사각형 · 선이 만나는 자리의 작은 조각(4pt 미만) · 괘선 옆 음영 색 띠 — 그대로 두면 그 변이 행 경계로 더 세어져
    칸 자리를 못 잡는다(실측: 6행 표가 「가로 경계 12개」 → 검사 268개가 「모름」. 걷어 낸 뒤 313개 통과).
  - docx 표의 칸 x = 잰 열 경계(세로선·채움) → 못 세면 명세의 열 폭(표 폭이 맞을 때) → 그것도 아니면 자리 검사 전체 unknown. `lineWidth` 는 Word 쪽에서 `unsupported`.
  - 쪽 크기 오차: 한글 ±1.0mm(한글 PDF 가 조금 작게 나온다 — Letter 279.4 → 278.7) · Word ±0.5mm.
  - `marginTop`: 문단 위 간격만큼(두 형식), docx 는 거기에 줄 간격이 100% 를 넘는 만큼 더 첫 줄이 내려와도 통과(Word 는 늘어난 줄 높이를 글 위에 둔다).
  - 바탕 글이 없는 문서 서식: `fontSize`·`fontFace` 는 「재지 못함」(unsupported — 모름으로 세지 않는다), 왼끝은 평범한 문단(왼쪽 정렬)으로 잰다.

| 끝점 | 바뀌는 것 |
|---|---|

| `GET /api/styles/{sid}/carrier?format=hwpx\|docx` | 기본 hwpx. docx 가 없으면 그 자리에서 지어 붙인 뒤 돌려준다(못 지으면 422) |
| `GET /api/styles/{sid}/proof.png?format=hwpx\|docx` | 형식마다의 견본 그림 |
| `POST /api/styles/{sid}/verify` | 두 형식 모두 다시(`{force?, formats?: ["hwpx", "docx"]}`) → 202 |

| `POST /api/styles/extract-file` | 응답에 `pages` |
| `POST /api/styles/name-file` `{token}` | → `{tables, texts, pages, note, call}`(후보에 이름·keep·띠 수를 합친 것 — candidates 의 `llm: true` 와 같은 꼴). 토큰 만료 410 · LLM 없음 503 · LLM 이 이름을 하나도 못 붙임 502 |

### 9. 적용(`app/style_apply.py`)

- hwpx 문서: 기존 네 모드 + **`{mode: "page"}`** — 모든 구역의 쪽 설정을 그 문서 서식의 값으로(`style_page.set_page`). 구조 편집 한 번(실행 취소 1개 · OWPML 검사 · 기록 `styleApply`) · 응답에 `paged: {sections: n}` — 화면은 문서를 통째로 다시 읽는다(`reloadDoc`: 쪽 크기가 바뀐다).
- docx 문서: **`tableBlank`**(docx 운반 문서의 표를 `after` 뒤에 — `DocxDoc.insert_after([{kind: "copy", srcId}], src=운반 문서)`, 구조(blueprint)의 `input`·`computed` 칸(없으면 머리 띠 밖 칸)의 글을 비운다) ·
  **`format`**(템플릿 항목의 서식 요약을 `DocxDoc.derive_format`·`apply_format` 으로 — 글·레터는 그대로). 그 밖의 모드는 400 「docx 문서에는 빈 표 넣기 · 문단에 입히기만 됩니다」. 쓰기 정책(그 TASK 의 원본 문서 403)은 같다.

### 12. 종류 넷 — 표지 서식 · 내용 서식 · 테이블 서식 · 문단 서식 (2026-11-14 사용자 답 「넷 + 쪽 설정은 내용에」 — §0 의 「종류 셋」 을 바꾼다)

사용자: "보통 표지 서식이 있고, 내용서식이 있고 테이블 서식이 있고, 문단 서식이 있잖아". 저장 꼴(`kind`)은 거의 그대로 두고 **화면의 갈래**를 넷으로 한다.

| 화면 갈래(`data-sl-tab`) | 저장하는 것 | 뜻 |
|---|---|---|
| **표지 서식**(`cover`) | `kind: "cover"`(새) | 문서 첫 쪽의 블록 묶음(제목·기관·날짜 자리 · 표지 표) — 배치 그대로, 글은 역할 견본으로(§14) |
| **내용 서식**(`content`) | 레벨이 있는 `kind: "text"`(개요템플릿·서브 템플릿의 글 서식) + `kind: "page"`(**쪽 설정** — 이 갈래 안의 한 구역) | 본문의 개요 체계와 그 본문이 놓이는 쪽 |
| **테이블 서식**(`table`) | `kind: "table"` | 표 서식 |
| **문단 서식**(`para`) | 레벨이 없는 `kind: "text"` + `role` | 본문 · 캡션 · 주석 · 상자 글 같은 낱 문단의 서식 |

- 갈래의 차례 = 표지 → 내용 → 테이블 → 문단. 처음 = 내용 서식. 「템플릿」·「문서 서식」 이라는 갈래 이름은 없어진다(「문서 서식」 = 내용 서식 갈래 안의 **「쪽 설정」**).
- `text` 가 어느 갈래인가: items 가운데 `level` 이 하나라도 있으면 내용 서식, 모두 없으면 문단 서식.
- 문단 서식의 `role`(meta — 고칠 수 있다: `PUT /api/styles/{sid}` `{role}`): `body` 본문 · `caption` 캡션 · `note` 주석 · `box` 상자 글 · `toc` 목차 · `other` 기타 · `null` 모름. 스크립트가 먼저 붙이고(§15), LLM 은 애매한 것만.
- **문단 서식의 자동 후보**(hwpx 에도): 헤딩 그래프의 노드에 들지 않은 본문 최상위 문단 + 1칸 표(글상자) 안 문단을, 서식 요약이 같은 것끼리 묶는다(쓰인 수 많은 차례 12개까지 · 빈 문단 제외) — 후보 `paras: [{key, role, count, items: [{para, level: null, sample, format, marker}], where: {caption, note, box}}]`.
  저장 = `{kind: "text", paras: [그 묶음의 대표 문단 id], role}`. docx·2단계가 없는 문서의 「서식이 같은 문단 묶음」 도 이 꼴이다(전에는 `texts` 에 섞여 있었다).
- **쪽 설정**(`page`)의 바탕 글은 문단 서식(본문)과 같은 것을 가리킨다 — 쪽 설정 후보는 `bodies`(바탕 글 후보 상위 3: `{key, format, count, chars, sample}`)를 싣고 그 가운데 하나를 `body` 로 고른다(스크립트 1위 → LLM 이 `bodyKey` 로 바꿀 수 있다 — §15).

### 13. 서식 그림 — Word 갤러리식 견본 (2026-11-14 사용자 답 「Word 갤러리식」 · astra 협의 반영 — ①)

사용자: "서식을 그림/이미지로 보여줘야지 … 그림으로 보고 사람이 템플릿 서식을 이해할 수 있게" · "mdword(= MS Word)에 보면 개요레벨 이미지로 보여주잖아. 그런거". 줄마다 **그림이 먼저** 보이고 이름·수치 글은 그 설명으로 내려간다.

- **무엇을 그리나 = 「서식 견본」**: 후보는 **저장될 견본**(저장과 같은 생성 함수로 지은 운반 문서의 보기 — 원문이 아니다: 글은 라벨·견본으로 바뀌고 캡션·칸 안 표·그림이 빠지고 폭이 맞춰진 그 모습), 보관한 서식은 **저장된 견본**. 원문은 전처럼 「자리로」 로 본다.
  그림은 「이 서식이 이렇게 생겼다」 이지 「적용하면 문서가 이렇게 된다」 가 아니다 — 동작 이름에 적용 범위를 적는다(「글자·문단 모양 입히기」 · 「표 모양 입히기」 · 「쪽 설정 입히기」 · 「빈 표 넣기」 · 「표지 넣기」).
- **그리는 방식**: 브라우저가 **형식 중립 값**(§10 의 표 명세 · `items` 의 서식 요약 · `page` · 표지 `parts`)만으로 그린다 — 새 파일 `app/static/style_pic.js`. **편집 화면의 그리기 함수(`renderTable`·`renderPara`)를 다시 쓰지 않는다**
  (astra: 그 함수들은 지금 문서의 `state`(글꼴 별칭·형식·편집 표시)를 읽고, 같은 id 의 요소가 저장 길(`paraEl`)에 잡힌다). 그림 안에는 편집 id·`contenteditable`·`.para`·`table.tbl`·`.sheet` 클래스를 쓰지 않는다(제 클래스 `sp-*`).
  글꼴은 서식 요약의 글꼴 이름 그대로(PC 에 있으면 그 글꼴 · 없으면 웹 기본) — 문서의 글꼴 별칭 표를 건드리지 않는다.
- **종류마다의 그림**(Word 의 갤러리처럼 작게 — 한 장의 높이 96~200px · 열 폭에 맞춤):
  - 내용 서식(개요 레벨) = **레벨마다 두 줄**(아래 「내용 서식의 견본」 — 2026-11-16: 처음의 「레벨마다 한 줄」 을 바꿈): 왼쪽 바깥에 「L1」·「L2」 표지 · 첫 줄 = 레터(글자 그대로 — 레터 글자의 굵기·크기·색) · 견본 글 · 글 막대(회색) /
    둘째 줄 = 「2번째 줄」 자리에서 시작하는 글 막대 · 자리는 실제 값을 **모든 레벨에 같은 배율**로. 레터뿐인 레벨도 글 막대가 붙는다.
  - **내용 서식의 견본**(2026-11-16 사용자 "견본은 2줄씩 있어야 하고 그래야 2번째줄 위치를 알지" — `style_pic.js` `levelLine`·`placeOf`): 한 줄만 그리면 내어쓰기(줄이 넘어가면 시작하는 자리)가 안 보인다 — 레벨마다 둘째 줄 막대를 그린다.
    - **자리 넷**(mm — 문단 상자 왼끝에서: [spec_hwpx_웹편집.md](spec_hwpx_웹편집.md) ② §8-1 과 같은 뜻): **앞 여백**(첫 줄 시작 = 왼쪽 여백 + max(첫 줄, 0)) · **레터 위치**(= 앞 여백 + 앞 공백 폭) ·
      **글 시작**(첫 내용 글자 = 앞 여백 + **레터 자리 폭** — 레터 자리 = 앞 공백 + 레터 + 레터 뒤 공백) · **2번째 줄**(= 왼쪽 여백 + max(−첫 줄, 0)).
    - 그리기: 첫 줄의 안쪽 여백 = 앞 여백 · 그 뒤 앞 공백 칸 · 레터 칸(최소 폭 = 레터 + 레터 뒤 공백 → 견본 글이 「글 시작」 에서 시작) · 견본 글 · 글 막대 / 둘째 줄의 안쪽 여백 = 2번째 줄.
      mm → px 배율은 **글자 크기와 같은 배율**(pt → px 배율 ÷ 0.3528 — 레터 자리·들여쓰기가 글자와 같은 비율로 보인다)이고 가장 깊은 자리가 상자 폭의 60% 를 넘으면 그만큼 줄인다.
    - **레터 자리 폭은 서버가 견본 문단에서 잰다**(`style_carrier.place` — `outline_pos.Measure`: 한글의 글자 폭) → `GET /api/styles/{sid}` 의 `view.pos = {항목 key: {line1Mm, letterMm, textMm, line2Mm, leadMm, prefixMm, letter} | null}`
      (`letter` = 레터 글자의 모양 — 본문 런과 다를 수 있다 · null = 못 잼: 자동 번호 · 레터 자리에 탭 · 여백 단위가 mm 가 아님). `view.items` 는 meta 것 그대로다.
      `view.pos` 가 없으면(옛 서버 · 후보의 견본) 화면이 한글의 글자 폭 규칙으로 어림한다(빈칸 0.5em · 전각·기호 1em · 그 밖 0.5em). 자동 번호는 글 시작을 모른다(회색 「1.」 뒤에 바로 견본 글).
    - 자리 높이 = 16 + 레벨 수 × 38px(64~260 — 15pt 레벨 하나가 약 37px) — 넘치면 아래를 흐리게 + 「전체 n레벨」.
    - 값을 고치는 레벨(§19-6 「고치는 동안의 견본」)은 표지가 파랗고 「글 시작」 자리에 세로 점선이 선다.
  - 문단 서식 = 「가나다 AaBb 123」 견본 두 줄을 그 서식(글꼴·크기·굵게·색·정렬·줄 간격·들여쓰기)으로 + 역할 꼬리표.
  - 테이블 서식 = 표 명세로 그린 작은 표(음영·괘선·합친 칸·칸 글 — **표 전체를 그리고 높이만 제한**: 넘치면 아래를 흐리게 + 「전체 n행」. 행을 잘라 내지 않는다) + **띠 표시**(표 바깥의 괄호선과 글 「머리행 1–2」·「머리열 1」·「합계행 18」 — 음영을 덮지 않는다).
  - 쪽 설정 = 쪽 도식(용지 비율 · 본문 상자 점선 · 여백 수치 mm · 본문 견본 줄 — 바탕 글이 없으면 글 막대).
  - 표지 서식 = 쪽 도식 위에 표지의 부분들(제목·기관명 … 을 그 크기·정렬로 · 표는 작은 표로).
- **원천은 둘 — 고르는 것은 사람**: 「웹 견본」(바로 — 기본) · 「한글 출력」·「Word 출력」(PDF 검증 그림 — 검증이 끝난 형식만 켜진다). 출력이 끝나도 저절로 바꾸지 않는다. 그림 옆에 원천 이름을 글로 적는다. 검증 꼬리표는 전처럼 따로 — **「검증됨」 = 저장한 서식이 제 값대로 출력된다**는 뜻이지 원본과 같다는 뜻이 아니다(도움말에 그렇게).
  출력 그림을 못 읽으면 숨기지 않고 웹 견본 + 「출력 그림을 읽지 못했습니다 — 다시」.
  쪽 설정·표지의 출력 그림은 내용 둘레를 자르지 않은 **첫 쪽 전체**(`proof.png` — 이미 저장된 `proof.pdf` 가 있으면 거기서 다시 만든다).
- **견본을 받는 길**(늦게 — 보이는 줄만):
  - 보관한 서식: `GET /api/styles/{sid}` 의 `view`(이미 있다 — 표 `spec` · 글 `items` · 쪽 `page`·`body` · 표지 `parts`).
  - 문서의 후보: `POST /api/docs/{id}/styles/preview` — 몸은 저장(`POST …/styles`)과 **같은 꼴**(`{kind, table | template | paras | cover …, bands?, keepText?, role?}`) → `{rev, kind, view, losses, fidelity}`. 저장·검증을 하지 않는다. 띠 수·「글도 그대로」 를 바꾸면 견본도 다시 받는다.
  - 파일 후보: `POST /api/styles/preview-file` `{token, pick: {kind, key, bands?}}` → 같은 꼴. 토큰이 없어졌으면 410 「올린 파일을 서버가 놓았습니다 — 다시 올려야 저장할 수 있습니다」(이미 그린 그림과 입력은 그대로 둔다).
- **목록의 살림**: 보이는 줄만 견본을 받는다(IntersectionObserver · root = `#headsDlgBody` · 요청은 넷까지 함께 · 같은 요청은 한 번 · 문서를 바꾼 뒤 늦게 온 답은 버림) · 그림 자리는 먼저 잡아 둔다(목록이 밀리지 않게) ·
  **검증 상태가 바뀌어 목록을 다시 그릴 때 그림을 버리지 않는다**(견본은 열쇠 = 서식 id + revision / 후보 key + 옵션으로 기억) · 축소는 `zoom`(1 이하 · 폭 맞춤).
  그림을 누르면 그 자리에서 크게(그 상자 안에서만 가로로 넘길 수 있다 — 열 전체는 안 넘친다). 그림 = `role="img"` + `aria-label`(요약 글), 크게 보기 단추는 그림 밖(`aria-expanded`).
- 폭 320px: 그림이 열의 전체 폭 · 관리 단추(받기 · 이름 바꾸기 · 다시 검증 · 지우기)는 「⋯ 더보기」 한 단추 아래로.
- 「비슷한 서식 n개」(전의 「같은 서식 n개」 — 서식 지문에는 행·열 수·합친 칸·열 폭이 들지 않는다: 그림은 **대표 표** 하나의 것이다).
- 에이전트 보기의 「서식 복사」 제안 카드: 「서식 그림 보기」 → 2열에 그 제안의 후보 견본(같은 견본 길). 에이전트 입력의 서식 고르기 목록(이름만)은 그대로(④).

### 14. 표지 서식 — 종류 `cover`(`app/style_cover.py`) (2026-11-14 사용자 답 「첫 쪽 통째로」)

- 뜻: 문서 **첫 쪽의 블록 묶음**을 배치 그대로 저장하고, 글은 **역할 견본**(「제목」·「기관명」·「날짜」 …)으로 바꾼다. 다른 문서의 맨 앞에 「표지 넣기」 로 다시 쓴다.
- 범위(스크립트 — hwpx·docx): 본문 최상위 블록을 처음부터 **다음 쪽이 시작하는 블록 앞까지**(블록의 `pageStart` · 둘째 구역의 `page`) — 그런 표시가 없으면 첫 개요 헤딩(그래프의 주 사슬 1레벨)이나 「목차」 문단 앞까지. 블록 40개 · 표 4개를 넘거나 경계를 못 찾으면 표지 후보를 내지 않는다.
  신호(`signals`): 그 범위의 가장 큰 글자 크기가 문서 본문보다 큰가 · 가운데 정렬 문단이 있는가 · 범위가 구역 하나를 다 차지하는가 · 첫 블록이 표 하나뿐인가(양식의 표지 표).
- 후보: `covers: [{key: "cover", blocks: [id…], end: 끝 블록 id, signals, parts: [요약], sample: 한 줄}]`(0~1개). PDF 는 내지 않는다(④).
- 부분의 역할(`ROLES`): `title` 제목 · `subtitle` 부제 · `org` 기관명 · `date` 날짜 · `person` 작성자 · `label` 라벨 · `other` 기타 — 스크립트가 어림(가장 큰 글 = 제목 · 날짜 꼴 · 「기관」 낱말)하고 LLM 이 고친다(§15).
- 운반 문서(hwpx): 그 블록들을 빈 바탕에 옮긴다(`insert_after(copy, src=)`). 문단의 글 = 그 역할의 견본(역할 이름 글 — `keep_text` 면 원문 60자) · 표 = 표 서식과 같은 규칙(라벨 칸만 남기고 견본으로) · 그림(로고)은 뺀다(losses 「그림은 옮기지 않았습니다」) · 쪽 설정은 그 구역의 것.
  meta: `kind: "cover"` · `page`(그 구역의 쪽 설정) · `parts: [{key, type: "text" | "table", role, sample, format | rows·cols}]`.
- docx 운반 문서 = 같은 부분들을 명세로(`style_docx.from_cover(parts, page)` — 문단은 그 서식의 견본 문단, 표는 표 명세).
- 보기(`view`): `{page, parts: [{type: "text", role, sample, format, gapBeforeMm} | {type: "table", spec}]}`.
- 검증(profile `cover-v1`): `render` · `pageSize` · 글 부분마다 `fontSize`·`bold`·`fontFace`(글 서식과 같은 견줌) · 표 부분은 `unsupported`(「표지 안 표는 견주지 않음」).
- 적용: `POST /api/docs/{id}/styles/{sid}/apply` `{mode: "cover"}` — hwpx 문서의 **맨 앞**에 표지의 블록들을 넣고, 원래 첫 블록은 다음 쪽에서 시작하게 한다(구역 설정을 품은 첫 문단의 자리는 지킨다). 구조 편집 한 번(실행 취소 1개) · 응답 `covered: {blocks: n}` + 화면은 문서를 다시 읽는다. docx 문서는 400(v1).
- 전의 기준 「표지에 한 번 나오는 표는 저장할 만하지 않다」(이름 붙이기 계약 · `jobs/style_copy.md`)는 「표지의 것은 표지 서식으로」 로 바꾼다.

### 15. LLM 검토 — 검증 · 보완 · 이름 (2026-11-14 사용자 답 「검증·보완까지」 · Fable 검토 반영 — ①)

사용자: "헤딩이나 이런건 스크립트로 하고 검증 + 보완을 LLM 이 해야지". ② 단계의 이름은 **「LLM 검토」**(전의 「에이전트 추출」 — LLM 은 추출하지 않는다: 값은 모두 스크립트가 문서에서 읽는다).

- **차례**: 스크립트 후보 → 스크립트 자기 점검 → LLM 판정 → 스크립트 재검사 → 화면.
- **먼저 고치는 스크립트 규칙**(LLM 과 무관 — Fable 검토의 지적):
  - 바탕 글: 헤딩 노드의 문단을 빼고 센다 · 상위 3개를 낸다(`bodies`) — 양식 문서에서 굵은 제목 줄이 바탕 글로 나오던 것.
  - 쪽 설정: 첫 구역이 아니라 **본문 글이 가장 많은 구역**의 것(표지 구역을 피한다 — 구역마다 다르면 전처럼 losses).
  - 띠 수 판단 자료: 첫 행만이 아니라 **앞 3행 + 끝 2행**의 격자 스케치(칸마다 가린 글 · 음영 · 굵게).
  - `of_pdf` 의 글꼴 이름은 표 추출과 같은 글꼴 색인으로 · 모듈 머리 설명의 옛 글.
- **스크립트 자기 점검**(후보에 `doubts` 로 — LLM 없이도 보인다): 템플릿 = `repAtypical`(슬롯의 대표 문단이 그 슬롯의 다수 서식이 아님) · `mixedSlot`(한 레벨에 서식이 여럿) · `levelGap`(레벨이 건너뜀) / 쪽 설정 = `bodyClose`(바탕 글 1·2위의 차이가 작음) · `sectionsDiffer`.
- **LLM 에 보내는 것**(글만 — 그림 입력은 쓰지 않는다): 후보의 요약 + 위 스케치·묶음 요약. **머리 띠 밖 칸 글과 문단 글은 꼴로 가려 보낸다**(「한글 3자」·「숫자」·「날짜」 — 성명·기관·금액이 LLM 으로 나가지 않게. 머리 띠 안 글과 레터는 그대로).
  호출은 셋으로 나눠 함께(`llm.ask_all`): 표 · 내용+문단 · 쪽 설정+표지. 프롬프트 = 계약 + 할 일 프롬프트(`jobs/style_copy.md`) + 자료.
- **LLM 의 답은 고르기뿐이다** — 서식 값(글꼴·크기·색·mm·괘선)은 답에 없다. 후보마다:
  `name`(이름) · `keep`(저장할 만한가) · `role`(정해진 코드 — 표: `data` 자료 표 · `form` 양식 · `layout` 배치 · `sign` 서명 · `cover` 표지 · `guide` 안내 / 문단: §12 의 역할) · `doubts: [코드…]`(정해진 코드 — 위 자기 점검의 코드 + `guideText` 안내문을 헤딩으로 읽음 · `levelOrder` 사슬 순서) ·
  `sameAs`(같은 서식으로 보이는 다른 후보의 key) · 표의 띠 수 정수(확신할 때 — 표 크기 안) · 템플릿의 `rep`(대표 문단을 **보낸 문단 id 가운데** 다른 것으로) · 쪽 설정의 `bodyKey`(보낸 `bodies` 가운데 하나 | `none`) · 표지의 `isCover`·`end`(보낸 블록 id)·`roles`(블록 id → 역할 코드).
- **스크립트 재검사**: 모르는 key·id·코드는 버린다 · **띠를 넓히는 보정은 받지 않고 `bandsWider` 로**(사람이 눌러야 — 머리 띠 안 글은 라벨로 보관함에 남는다) · `sameAs` 는 두 후보의 서식을 스크립트가 견줘 가까울 때만 · `rep` 는 같은 슬롯의 문단일 때만 · `end` 는 표지 범위 안의 블록일 때만(범위를 **줄이는** 쪽만) ·
  이름에 4자리 연도·6자리 넘는 수가 있으면 그 이름을 버린다(스크립트 이름으로).
- **후보마다의 검토 상태**(`review` — 화면이 글로 보인다): `by: "script"`(LLM 이 안 봄) | `"llm"` · `seen: [본 것 — "이름"·"띠 수"·"역할"·"레벨"·"바탕 글"·"범위"]` · `fixed: [{what, from, to}]`(LLM 이 바꾼 것 — 되돌릴 수 있다) · `doubts: [{code, text, by: "script" | "llm"}]`.
  「LLM 검토함」 은 「맞음」 이 아니다 — 체크 표시가 아니라 **본 것을 글로**(「LLM 이 봄 — 이름 · 띠 수 · 역할」), LLM 이 고친 것은 보라색 「LLM 고침 — 대표 문단」 + 「되돌리기」, 의심은 주황 「확인 — 한 레벨에 서식이 둘」.
- **「한 번에 진행」**: LLM 검토 뒤 **추천(keep)이면서 의심(`doubts`)도 LLM 고침(`fixed`)도 `bandsWider` 도 없는 후보만** 저장한다(+ 사람이 이미 고른 것). 나머지는 고르지 않은 채 남기고 요약에 「확인이 필요한 후보 n개 — 보고 골라 저장하세요」. 표지·쪽 설정도 같은 규칙.
- 하지 않는 것: LLM 이 후보에 없는 서식을 지어 더하기(「놓친 것」 은 스크립트가 낸 `paras`·`covers` 후보 가운데 고르는 것으로 한다) · 그림 입력 · 원본 문서와 뽑은 서식을 견주는 검증(④).

### 17. 원본 문서 기록 — 어느 문서에서 뽑은 서식인가 (2026-11-14 사용자 "어떤 문서에서 추출한 건지 정보를 넣어줘 … 에이전트가 사용할때 참조할 수 있도록")

서식마다 **뽑은 문서**를 남기고, 서식을 쓰는 쪽(사람 — 서식 관리자 · 에이전트 — 에이전트 보기)이 그것을 본다.

- **`meta.source`**(처음 뽑은 문서 — `style_lib.SOURCE_KEYS`): `name`(문서 이름 — 올린 이름) · `format`(hwpx·docx·pdf) · `work`(작업 id — **파일에서 바로 뽑았으면 null**) · `sha256`(올린 원본의 해시) ·
  `project` · `job`(TASK 키) · `round`(그 작업의 프로젝트·TASK·라운드 — 프로젝트가 없으면 `project`·`round` null, 프로젝트에 묶였는데 라운드가 안 적힌 옛 작업은 1) ·
  `block`(그 문서의 블록 id) · `page`(파일 후보의 쪽) · **`where`**(문서 안 자리 — 표 = 「표 3번째」(본문 최상위 표 차례) | 「칸 안의 표」 · 개요템플릿 = 「개요템플릿 1」 · 문단 = 「문단 3개」 · 표지 = 「첫 쪽」 · 파일의 표 = 「2쪽」 · 쪽 설정 = null) ·
  `at`(뽑은 때 — 초). 짓는 곳 = `style_api._src(s, fmt)`(문서) · `_file_build`(파일 — `at`·`where`).
  **문서의 글은 넣지 않는다**(앞뒤 문단·제목·캡션 — 보관함은 서버 전체가 같이 쓴다: ② §15 의 띠 보정과 같은 까닭). 자리는 차례·쪽으로만 적는다.
- **`meta.seenIn`**(같은 서식이 나온 **다른 문서**들 — `SEEN_KEYS` = source 에서 `block`·`page` 를 뺀 것, `SEEN_MAX` 20개: 넘으면 옛 것부터 버림): 같은 서식은 한 번만 저장하므로(② §4) 둘째 문서에서 뽑으면
  새로 저장하지 않고 **그 문서를 여기 적는다**(`style_lib.add_seen(sid, source)` — `style_api._create` 가 부른다). 같은 문서(해시가 같음 — 같은 파일을 다른 작업으로 연 것 포함 · 해시가 없으면 이름·형식)와 이미 적힌 문서는 다시 안 적는다.
  **revision·고친 때·검증 기록은 그대로**(서식의 모양이 바뀐 것이 아니다 — `put_docx` 와 같은 붙이기). 이름을 바꿔 revision 이 올라가도 `source`·`seenIn` 은 물려받는다.
- **끝점**: `GET /api/styles`(요약)·`GET /api/styles/{sid}`·저장 응답에 `source`·`seenIn` 이 그대로 실린다. 클라이언트가 원본 기록을 보내는 길은 없다(서버가 세션·잡아 둔 파일에서 짓는다).
- **서식 관리자**: 서식 줄의 「원본 <문서 이름> · 프로젝트 <이름> · <자리> 외 N개 문서」(`slSrcText`) · 그 줄의 풍선 = 「이 서식을 뽑은 문서 — 이름 · 프로젝트 · TASK · 라운드 · 자리 · 뽑은 때」 + 「같은 서식이 나온 다른 문서:」 목록(`slSrcTitle`).
- **에이전트**(`doc_agent.styles_data(metas, picked, here)` — `here` = 지금 문서 `{name, sha256, project}`): 프롬프트의 서식마다 **`from`** = `{doc, project?, where?, also?[같은 서식이 나온 다른 문서 이름 — 3개까지], more?, same?}`(`style_from`) —
  `same: "doc"` = 지금 이 문서에서 뽑은 서식(`seenIn` 포함) · `"project"` = 같은 프로젝트의 문서에서 뽑은 서식. `here` 를 주면 **이 문서의 것 → 같은 프로젝트의 것 → 그 밖** 차례로 싣는다(종류마다 40개에 잘릴 때 가까운 문서의 서식이 남게 — 같은 묶음 안은 보관함 차례).
  계약 글(`CONTRACT`)은 `from` 의 꼴만 말하고, **어떻게 쓰는지**(문서 이름으로 가리킨 서식 고르기 · 그 문서의 서식이 없으면 다른 문서의 것으로 대신하지 않기 · 가리키지 않았으면 가까운 문서 먼저 · 답에 어느 문서의 서식인지 적기 · 문서·프로젝트 이름은 서식을 고르는 데만)는
  지침 [agent.md](../app/merge_guides_default/agent.md) 「서식의 원본 문서(from)」 에 둔다(판단 기준은 지침 파일 — CLAUDE.md). 보관함 서식을 쓰는 제안의 보기에는 `styleFrom`(한 줄 — `from_text`: 「문서 · 프로젝트 · 자리 외 N개 문서」)이 붙고, 카드의 「서식 — <이름> (원본 …)」 으로 보인다.
- 옛 서식(이 절 전에 저장한 것): 새 키는 null · `seenIn` 은 빈 목록으로 읽힌다(고쳐 쓰지 않는다 — 다음 revision 때 채워진 꼴로 저장).

### 18. 「서식 복사」 열의 탭 — 후보를 갈래마다 따로 (2026-11-14 사용자 "표지/내용서식/테이블/쪽 을 여기 탭에서 따로 따로 볼 수 있게")

전에는 후보 구역(표지 → 내용(+ 쪽 설정) → 테이블 → 문단)이 한 목록으로 이어져, 큰 양식(후보 69개)에서는 다른 갈래를 찾으려면 길게 내려야 했다. 이제 **탭 하나에 한 갈래**.

- **탭 다섯, 이 차례**: 「표지 서식」(`cover`) · 「내용 서식」(`content` — 레벨 있는 글 서식만) · 「테이블 서식」(`table`) · **「쪽 설정」**(`page` — 이 열에서는 내용 서식과 따로) · 「문단 서식」(`para` — 레벨 없는 문단 묶음).
  자리 = 열 머리의 도구 줄 아래가 아니라 **본문 맨 위, 단계 줄 바로 아래**(단계 줄 → 탭 → 옵션·알림 → 그 탭의 후보). 서식 관리자의 갈래 단추와 같은 모양(세그먼트 단추 · `aria-pressed`) · 속성은 `data-sl-ctab="<키>"`(서식 관리자의 `data-sl-tab` 과 다른 이름 — 두 화면의 검사가 서로를 잡지 않게).
- **탭 글** = 「<이름> <후보 수>」, 그 탭에서 **고른 것이 있으면** 「 · <n>개 고름」 을 붙인다(다른 탭에 고른 것이 있다는 것이 보여야 한다 — 저장 단추 「고른 N개 저장」 은 모든 탭을 합친 수 그대로). 도움말(title)에 그 갈래의 뜻 + 「후보 N · 고름 n · 확인이 필요한 것 n」(LLM 검토 뒤 — 의심·고침이 있는 후보 수).
  후보가 0개인 탭도 **감추지 않고 보인다**(0) — 누르면 그 갈래가 왜 없는지 한 줄(내용 서식 = 지금의 「헤딩 2단계 결과가 없어 …」 · 그 밖 = 「이 문서에서 ○○ 후보를 찾지 못했습니다」).
- **처음 탭** = 내용 서식에 후보가 있으면 내용 서식(서식 관리자와 같은 처음), 없으면 표지 → 테이블 → 쪽 설정 → 문단 차례로 처음 후보가 있는 탭. 고른 탭은 그 후보 묶음(`STYLE.save` 의 `S.tab`)에 남는다 — 서식 관리자로 갔다 돌아와도, 다시 그려도 그대로. 문서를 다시 찾으면(후보 묶음이 새것) 처음 규칙.
  **고른 채로 연 후보**(`S.focus` — 표 메뉴 「서식 관리자에 저장…」 · 에이전트 카드의 「서식 그림 보기」)가 있으면 그 후보의 탭으로 바꾸고 그 줄로 간다.
- **보이는 탭의 후보만 그린다**(DOM 에도 그 탭의 줄만) — 서식 견본(그림)은 그 탭의 보이는 줄만 받는다(§13 의 「보이는 줄만」 그대로: 탭을 바꾸면 새 줄을 지켜본다). 고름·이름·띠 수·역할 같은 줄의 상태는 후보 자료(`S.rows`)에 있어 탭을 바꿔도 남는다.
  탭을 바꾸면 본문을 맨 위로(탭마다 스크롤 자리를 기억하지 않는다 — 에이전트 판단).
- 탭 아래 첫 줄은 갈래 이름과 설명 노트 도움말, 「글도 그대로 저장」 옵션이다. 이 줄이 `[data-sl-sec="<키>"]` 를 가진다(그 탭의 것 하나만). 설명은 도움말에 온전히 남긴다(design.md §13-3).
- **바뀌지 않는 것**: 「LLM 검토」·「한 번에 진행」·저장·검증은 **모든 탭의 후보**에 걸친다(보이는 탭만이 아니다) · 저장 단추·수 · 단계 줄 · 「글도 그대로 저장」 · 검증 진행·요약 줄(탭 아래 옵션·알림 자리 — 모든 탭에 걸친 것이라 어느 탭에서나 보인다) · 후보 줄의 모양(그림 · 검토 상태 · 「자리로」).
  서식 관리자(보관함 목록)의 갈래는 그대로 넷이고 쪽 설정은 「내용 서식」 안이다(§12).
- 320px 열: 탭이 다음 줄로 접힌다(가로 넘침 없음 — design.md §13-1).

### 19. 서식 지도 · 서식 이름 · 서식 값 고치기 · 복사본 · 모양 복사 · 서식으로 본문 고치기 (2026-11-14 사용자 — ① 의 세 말 · 물어서 받은 답 ㉮㉯㉰)

**사용자가 정한 것** = ① 의 원문과 답 ㉮(복사 = 복사본 + 모양 복사) · ㉯(서식 단위로 고치고 「본문에 적용」 · 보관함 서식도 같은 칸) · ㉰(이름 앞 = 문서 종류 낱말) · 접기(§19-0). 그 밖의 배치·키·끝점은 에이전트 판단(④ ⓝ).

#### 19-0. 「서식 복사」 열 후보 줄 — 그림 아래는 기본으로 접는다 (구현 끝 — ③)

- 후보 줄 = 체크·이름 줄 → 그림 → **「▸ 자세히」(`details.sl-cfold` — 기본 닫힘)** → 상태 줄. 접힌 안(`.sl-cfold-body`) = 그림 아래 한 줄(저장될 견본 · 원천 · 「크게」) · 서식 정보(`.sl-cmeta` — 띠 수·역할·구조까지 저장 같은 고르기 포함) · 검토 상태(`.sl-review`).
- 접어도 요약 줄(`summary.sl-cfold-sum`)에 **추천** · **확인 n**(주황 — 의심 수) · **LLM 고침 n** · **LLM 제안**(보라)을 남긴다 — 경고가 숨지 않게(design.md §1-6). 편 줄은 다시 그려도 편 채로(`STYLE.cfold` — 「갈래|후보 키」).
  그림 안의 글(「전체 3레벨」)과 그림을 못 받았을 때의 「다시」 는 그림 쪽이라 접지 않는다. 서식 관리자(보관함 목록)의 줄은 그대로(전부터 「뺀 것 · 검증 내역」 만 접힘).

#### 19-1. 서식 자리 · 기대 서식 · 다름 — `app/format_map.py`

- **서식 자리**(slot) = 문서 안에서 같은 서식을 써야 하는 문단 묶음. 셋:
  - **템플릿 레벨** — 2단계 그래프의 개요템플릿·서브 템플릿 레벨(화면의 「T1 L2」). 줄 = 개요 편집 오버레이 `s.outline.lines`(편집을 따라 고쳐진다 — `server._outline_ov(s)`)에서 그 (템플릿, 레벨)인 문단 · 오버레이가 없으면 그래프 노드(2단계가 없으면 `style_api._doc_graph` 의 스크립트 그래프).
    자리 키 `tpl:<no>:<L>`(no = 화면의 T 번호). 표 칸 안 템플릿(「cell:…」)도 자리지만 여백 표시는 본문 줄만(지금 「TN Lk」 와 같다).
  - **문단 서식 묶음** — 서식 복사 열 「문단 서식」 탭의 후보와 **같은 묶음·같은 차례**(`style_extract.candidates(doc, graph)["paras"]` — 서식이 정확히 같은 문단끼리, 헤딩 줄은 빼고, `TEXT_GROUPS` 12묶음까지). 자리 키 `para:<대표 문단 id>` · 줄 = 그 묶음 서식과 같은 본문 문단 모두.
    12묶음 밖의 문단은 자리가 없다(표시 없음).
  - **표 묶음** — 「테이블 서식」 탭의 후보와 같은 묶음·차례(`candidates()["tables"]` — `same` 의 표들). 자리 키 `table:<대표 표 id>`. **v1 은 이름·표 수·자리로만**(다름을 재지 않고 값 고치기·적용도 없다).
- **비교 값**(`COMPARE` — 서식 요약에서, 글자는 **본문 런**(레터 런이 아님 — `style_carrier.body_char`)):
  글자 `font` · `sizePt` · `bold` · `italic` · `underline` · `color` · `ratioPct` · `spacingPct` / 문단 `align` · **`line1Mm`**(첫 줄 시작 = 왼쪽 여백 + max(첫 줄, 0) — 화면 「앞 여백」) · **`line2Mm`**(둘째 줄 시작 = 왼쪽 여백 + max(−첫 줄, 0) — 화면 「2번째 줄」) ·
  `indentRightMm` · `lineSpacing`(글 — `160%` · `고정 20pt` 따위: `heading_extract.para_shape`) · `lineSpacingPct`(% 일 때 수 · 아니면 null) · `spaceBeforePt` · `spaceAfterPt`. 견줄 때 mm·pt 는 0.1 · % 는 1 단위로 반올림한다(앞 공백 수·레터는 견주지 않는다 — 글이다).
- **기대 서식**(`expected`): 템플릿 레벨 = 그 레벨 줄들의 **가장 많은 비교 값 묶음**(같은 수면 그래프 대표 문단 `rep` 을 품은 쪽 → 문서 순 앞 줄의 것) · 문단 서식 묶음 = 그 묶음의 서식(같은 서식끼리 묶었으므로 줄은 늘 같다 — 사용자 "본문같은 경우는 … 동일해").
  **사람이 고쳐 둔 값(`pending` — §19-3)이 있으면 그 위에 덮는다** → 그때부터 그 자리의 줄은 「다름」 이 되고 「본문에 적용」 으로 맞춘다.
- **다름**(`diff`): 줄마다 비교 값에서 기대와 다른 것 `[[키, 기대, 지금], …]`(키 차례 = `COMPARE`). 자리의 `diff` = 다른 줄 수.
- **내용 서식 후보와 견줌**(템플릿 레벨만 — ① 「현재 템플릿이랑 내용 서식이랑 동일한지」): `content` = 서식 복사 「내용 서식」 후보가 그 레벨로 저장할 문단(그래프 `slot.rep`)의 비교 값 · `contentDiff` = 기대와 다른 키들.
  「스크립트 확인 — 대표 문단이 그 레벨의 다수 서식이 아님」 이 붙은 레벨은 여기서 무엇이 다른지 보인다(후보의 대표 문단을 바꾸지는 않는다 — 서식 복사 열의 LLM 검토·사람이 정한다).
- 계산은 요청마다(같은 rev·같은 저장 version 이면 세션에 기억). docx 문서는 **v1 에서 끈다**(`off` — 「hwpx 문서에서만 됩니다」: 헤딩 그래프가 hwpx 만).

#### 19-2. 서식 이름 — 「<문서 이름>: <갈래><번호>」 — `app/format_names.py`

- **문서 이름** = 파일 이름에서 찾은 **문서 종류 낱말**(`DOC_KINDS` — 긴 것 먼저: 연구개발계획서 · 사업계획서 · 연차보고서 · 기술수요조사서 · 회의록 · 보고서 · 계획서 …, 띄어 쓴 것도) → 못 찾으면 파일 이름(확장자·앞 번호 「1. 」 뺌).
  사람이 문서마다 고칠 수 있다(서식 지도 머리 — 비우면 다시 자동). 프레임 문서 「사업계획서_<프로젝트>_프레임」 → 「사업계획서」.
- **갈래 표기**: 내용 서식(템플릿) `T<no>`(그 레벨 `T<no> L<k>`) · 문단 서식 = 역할 `body`·`caption`·`note`·`box`·`toc`(그 밖·모름 = `body`) + 그 역할 안 번호 · 테이블 `table<n>` · 표지 `cover` · 쪽 설정 `page`.
  번호 = 서식 복사 열 탭의 후보 차례(서식 지도와 같은 차례 — `format_names.keys_for(cands)` **하나로** 짓는다). 예: 「사업계획서: T1」 · 「사업계획서: T1 L2」 · 「사업계획서: body1」 · 「사업계획서: table2」 · 「사업계획서: cover」 · 「사업계획서: page」. 60자를 넘으면 문서 이름 쪽을 줄인다.
- **이름 키**(문서를 다시 분석해도 같은 자리): 템플릿 `tpl:<앵커>` · 그 레벨 `tpl:<앵커>#<L>` · 문단 묶음 `para:<대표 문단 id>` · 표 묶음 `table:<대표 표 id>` · `page` · `cover`. 서식 지도에서 사람이 고친 이름은 이 키로 저장(§19-3)된다.
- **쓰이는 곳**: ⓐ 서식 지도의 자리 이름 ⓑ **서식 복사 열 후보의 기본 이름** — `POST …/styles/candidates` 응답의 후보마다 `defaultName`(서식 지도에서 고친 이름이 있으면 그것) — 화면은 사람이 안 고친 이름 칸에 이것을 넣는다.
  파일에서 뽑는 후보(`/api/styles/candidates-file` 따위)는 파일 이름으로 같은 꼴(저장된 고친 이름은 없다) ⓒ 화면이 이름을 안 보낸 저장의 서버 기본 이름 ⓓ 에이전트 행동 `styleCopy` 로 저장할 때(사용자가 요청에 이름을 말했으면 그것).
  서식 관리자의 「이름 바꾸기」 는 그대로 자유 이름(1~60자).
- **LLM 이 붙이는 이름**(§15 — 구조와 겉모습: 「예산 총괄표 — 머리 2행·합계행」)은 **이름을 덮지 않고 설명(`note`)** 으로 간다 — 후보 줄 이름 칸 아래 한 줄 · 저장하면 `meta.note`. LLM 계약의 키 이름(`name`)은 그대로 두고 뜻만 「설명」 으로(계약 글 · 전제 글 · 지침을 같이 고친다).
  전제 글 `jobs/style_copy.md` 「이름 · 자료값」 을 이 꼴로 고친다(문서 이름은 종류 낱말만 — 문서의 다른 고유명사·수치·연도는 이름에도 설명에도 넣지 않는다 · 사람이 고친 이름은 그대로).

#### 19-3. 서식 지도 — 2열(`headsDlg` kind `fmtMap`, 화면 이름 「서식 지도」) — `app/static/format_map.js·css`

- 여는 곳: 도구 줄 다섯째 묶음 「서식」 의 새 아이콘 「서식 지도」(`#tbFmtMap`) · 문서 여백의 「≠」 표지와 문단 서식 표지(§19-4) · 서식 관리자 열의 도구 줄에서 「서식 지도」(같은 열을 바꿔 연다). hwpx 문서만(docx 는 단추를 끄고 까닭을 도움말에 — design.md §13-1).
- **머리**: 문서 이름 줄 「문서 이름 사업계획서 (자동) ✎」 — 누르면 줄 안 입력(Enter 저장 · Esc 취소 · 비우면 자동) · 「여백 표시」 켜고 끄기(localStorage `nfm.fmMarks` — 끄면 §19-4 의 문단 서식 표지·「≠」 를 안 그린다) · 갈래 세그먼트 「내용 서식 n · 문단 서식 n · 테이블 n」(`data-fm-tab`) · 「다른 것만」 거르기.
- **자리 줄**(그리드 — 머리 한 번): [태그 「T1 L2」·「body1」·「table1」] [이름(누르면 줄 안 이름 바꾸기 — 비우면 기본 이름)] [「문단 38 · 다름 5」(다름은 주황)] [▸]. 내용 서식 갈래는 템플릿마다 머리 줄(「T1 □ › ㅇ › -」 + 템플릿 이름 — 바꿀 수 있음) 아래 레벨 줄.
  줄에 올리면 문서의 그 자리 문단(표)을 파랗게(`slHit` 와 같은 표시 — 다른 줄은 주황 테두리) · 누르면 펼침(한 번에 하나).
- **펼친 자리**(템플릿 레벨 · 문단 서식):
  - **값 다섯 칸**(답 ㉯ — 사용자가 든 다섯): 앞 여백 [mm] · 2번째 줄 [mm] · 폰트 [글 — 문서 글꼴 목록 datalist] · 크기 [pt] · 줄간격 [%] — 기대 서식으로 채움, 고쳐 둔 값은 강조. 「값 저장」(문서는 안 바뀜 — 대기 값 `pending`) · 「되돌리기」(대기 값 지움).
    그 밖의 값 한 줄(굵게 · 정렬 · 오른쪽 여백 · 위/아래 간격 — 읽기만).
  - 템플릿 레벨: **「내용 서식 후보와 — 같음」** 또는 「다름 — 2번째 줄 10.4 ↔ 10.9mm …」(§19-1 `contentDiff`).
  - **다른 문단 목록**(30개까지 — 넘으면 「외 n개」): 「ㅇ 전기추진, 극지운항 … — 2번째 줄 10.9 → 10.4mm」 · 누르면 그 문단으로(열은 그대로).
  - 동작: **「본문에 적용 (n)」**(강조 단추 — 그 자리의 다른 문단 모두를 기대 서식으로 · 다른 문단이 없고 대기 값도 없으면 꺼짐 + 까닭) — 문서에서 고른 문단(끌어 고르기)이 그 자리 안에 있으면 「고른 문단에 적용 (k)」 ·
    **「모양 복사」**(그 자리의 기대 서식을 집는다 — §19-5 의 붙이기로).
- **펼친 자리**(테이블): 표 수 · 표 목록(누르면 그 표로) · 이름 바꾸기만.
- 문서가 바뀌면(rev) 지도를 다시 읽는다(편집 응답 뒤 0.5초 모아서 — 열이 닫혀 있어도 여백 표시 때문에 읽는다). 대기 값·이름·문서 이름은 문서 편집이 아니라 **실행 취소에 들지 않는다**.

#### 19-4. 문서 여백 표시 — 어느 단락이 어느 서식인가 · 다른가

- **「TN Lk」 를 문서를 열 때 그린다**(전에는 헤딩 추출 탭을 열어야): 2단계 결과가 있으면 `load()` 가 그래프를 읽어 `heads.marks` 를 채운다 — TASK 와 무관(서식 복사 · 일반 편집 · 이관 · 취합 모두).
  **구현은 다른 길로 됐다**(2026-11-14 — [spec_hwpx_웹편집.md](spec_hwpx_웹편집.md) ② §8-2): 그래프가 아니라 문서를 열 때 이미 읽는 개요 오버레이(`GET …/outline`)의 줄로 그린다(그래프는 표를 누를 때 읽음).
  `paginate`·`flowSettle` 가 `heads.marks` 없이 `heads.outline` 만 있을 때도 손잡이를 다시 그린다(전에는 다시 나눌 때 손잡이가 사라졌다).
- **문단 서식 표지**(새 — `.tpl-mark.fm`): 「TN Lk」 가 없는 본문 문단 가운데 문단 서식 자리에 든 것에 그 갈래 표기(「body1」) — 같은 자리(쪽 안 왼쪽 여백 · 오른끝 맞춤 · 화면 크기 고정). 누르면 서식 지도의 그 자리.
- **「≠」 표지**(새 — `.fm-diff`, 주황): 기대 서식과 다른 줄 — 「TN Lk」·문단 서식 표지 바로 뒤. 풍선 = 다른 값들(「2번째 줄 10.9 → 10.4mm · 크기 14 → 15pt」) · 누르면 서식 지도의 그 자리를 펴고 그 줄을 목록에서 강조.
  「TN Lk」 를 누르면 지금처럼 「템플릿 관계」(바꾸지 않음).
- **표 표지**(`.tbl-mark`)에 표 묶음 표기(「table2」) — 누르면 서식 지도의 그 자리.
- 범례(design.md §4): 「≠」 의 뜻은 `#fileInfo` 범례 줄에 한 칩(「≠ 서식 다름」 + 「감추기」 = 여백 표시 끄기).

#### 19-5. 모양 복사 — 문서에서 한 문단의 서식을 다른 문단에 (답 ㉮)

- 도구 줄 「서식」 묶음에 아이콘 둘: **「모양 복사」**(`#tbFmtCopy` — 커서 문단의 서식(문단 모양 + 본문 글자 모양)을 집는다 · 집은 동안 눌림 · 다시 누르거나 Esc 로 놓음) · **「모양 붙이기」**(`#tbFmtPaste` — 집은 것이 있을 때만 켜짐: 고른 문단들(끌어 고르기) · 없으면 커서 문단에 붙인다).
  서식 지도의 「모양 복사」 는 자리의 기대 서식을 집는다(같은 붙이기). 집은 것은 화면 메모리(문서를 바꿔도 남음 — 다른 문서에 붙여도 된다: 값으로 보낸다).
- 붙이기 = **비교 값 전부**(§19-1)를 그 문단들에: 문단 키는 문단 모양에 · 글자 키는 **본문 런에만**(레터 런·개요 번호·글은 그대로) — 서식 지도의 「본문에 적용」 과 같은 쓰기 함수. 한 번 = 실행 취소 1.

#### 19-6. 서식 관리자 — 값 고치기 · 복사본 만들기 (답 ㉮ · ㉯)

- **값 고치기**: 글 서식(내용 서식 레벨 · 문단 서식)의 item 줄마다 「값 고치기」 — 그 줄 안에서 §19-3 의 다섯 칸에 **「글 시작」** 을 더한 여섯 칸(앞 여백 · 글 시작 · 2번째 줄 · 폰트 · 크기 · 줄간격) + 「저장」·「취소」.
  - **글 시작**(2026-11-16 사용자 "앞 여백 맞고, 그리고 첫번째 글자의 맨 앞으로의 부터 거리. 이게 있어야 제어를 하지 … 어떤 레터가 오던 숫자가 오던 첫번째 내용의 절대위치"): 레터 뒤 **첫 내용 글자가 시작하는 자리**(본문 왼끝에서 mm) = 앞 여백 + 레터 자리 폭(§13 「내용 서식의 견본」).
    - 레터 자리(앞 공백 + 레터 + 레터 뒤 공백)는 **글**이라 폭이 정해져 있다 — 그래서 앞 여백과 글 시작은 **한 값의 두 이름**이다: 한쪽을 고치면 다른 쪽이 따라 바뀐다(글 시작을 고치면 글이 그 자리에 오게 줄이 움직인다 — 앞 여백 = 글 시작 − 레터 자리 폭).
      화면은 사람이 **마지막에 친 쪽만** 보낸다(`textMm` | `line1Mm`) — 글 시작이면 서버가 레터 자리 폭을 다시 재어 첫 줄을 옮긴다(화면의 어림값에 기대지 않는다). 레터 자리 폭보다 작은 글 시작은 저장하지 않고 까닭을 보인다.
    - 칸의 도움말에 그 항목의 레터 자리 폭을 적는다(「앞 여백 + 레터 자리 폭 10.6mm」 — 서버가 잰 값이 없으면 「어림값」 이라고).
    - 글자 레터가 없는 항목(문단 서식 — 글 시작 = 앞 여백)은 칸을 보이지 않고, 자동 번호 항목(번호 폭은 대상 문서의 번호 설정이 정한다)·레터 자리에 탭이 있는 항목은 칸을 끈다(까닭은 도움말).
    - **「글 시작에 맞춤」**(2번째 줄 칸 옆 단추): 2번째 줄을 글 시작과 같은 자리로 — 줄이 넘어가면 첫 내용 글자 바로 아래에서 시작한다. 이미 같으면 눌린 채 꺼져 있다.
    - 폰트·크기는 본문 글자에만 — 레터 글자는 그대로라 레터 자리 폭(글 시작 − 앞 여백)이 안 바뀐다.
  - **고치는 동안의 견본**(2026-11-16 사용자 "밑에 수정하면 견본도 바뀌어야지"): 칸의 값이 바뀔 때마다 그 서식의 **웹 견본을 그 값으로 바로 다시 그린다**(서버에 묻지 않는 저장 전 미리보기 — 목록은 다시 그리지 않아 입력 초점이 그대로다).
    고치는 레벨은 표지가 파랗고 「글 시작」 자리에 세로 점선(둘째 줄 막대가 글 아래에서 시작하는지 견줘 본다) · 그림 아래 글은 「고치는 값 미리 보기」 · 원천은 웹 견본으로 고정(출력 그림은 저장된 값의 것이라 그동안 꺼 둔다) ·
    그 서식의 견본은 **열 위에 붙어 있다**(sticky — 레벨이 많아 칸이 아래에 있어도 보인다 · 높이는 그대로라 목록이 안 밀린다). 틀리거나 비운 칸은 처음 값으로 그린다. 닫거나 저장하면 표시가 사라진다.
  - **레벨별 배치**(2026-11-16 · 같은 날 고침 — 사용자 「2줄이면 될거 같은데」): 레벨 한 줄은 **2줄** — 왼쪽에 레벨 표지와 이름(윗줄)·견본 글(아랫줄), 오른쪽에 「글자·문단 모양 입히기」·「값 고치기」(두 줄 높이 가운데).
    서식 열 안쪽이 430px 보다 좁으면(버튼 둘 ≈ 260px 를 옆에 두면 이름 칸이 너무 좁다) 이름·견본을 한 줄에, 버튼을 아랫줄에 — 어느 폭이든 2줄. 편집 중인 레벨의 값 입력은 그 행 안 아래에만(행 전체 폭) 열린다. 긴 이름·견본과 320px 폭에서도 다음 레벨의 조작과 섞이거나 가로로 넘치지 않는다. 적용 범위·저장 방식은 그대로다.
  저장 = 운반 문서(hwpx)의 그 견본 문단 서식을 고쳐(글자 키는 본문 런만) **새 revision** — `items[].format` 다시 · docx 운반 문서 다시 지음 · **PDF 검증 다시**(전 검증 기록은 그 revision 에 남는다). 표·쪽 설정·표지는 v1 에 없다.
- **복사본 만들기**: 「⋯ 더보기」 → 「복사본 만들기」 → 같은 운반 문서·같은 값으로 **새 서식**(이름 「<이름> 복사」 — 60자 안 · `copyOf` = 원래 서식 id · `source`·`seenIn` 물려받음 · 검증은 새로) — 「같은 서식은 한 번만」(§4)을 지나지 않는다(사람이 일부러 만든 것).
  만든 뒤 그 줄로 가서 이름 칸을 연다(바로 이름을 바꾸게).
- **서식으로 본문 고치기**(보관함 쪽) = 전부터 있는 「글자·문단 모양 입히기」(고른 문단·커서 문단) 그대로. 문서 안의 자리 단위 적용은 서식 지도의 「본문에 적용」.

#### 19-7. 끝점

서식 지도 — `app/format_map_api.py`(server.py 가 include):
- `GET /api/docs/{id}/formats/map` → `{off: null | 까닭, rev, prefix, prefixAuto, graph: "stage2"|"script"|null, slots: [자리], paras: {문단 id: {slot, diff: [[키, 기대, 지금]…]}}, tables: {표 id: 자리 키}}`.
  자리 = `{key, kind: "tpl"|"para"|"table", tag("T1 L2"|"body1"|"table1"), name, nameKey, named(사람이 고친 이름), tpl: {no, level, letter, anchor, chain, name(템플릿 이름), nameKey} | null, role, paras: [줄 id — 문서 순], tables: [표 id], count, diff(다른 줄 수),
  expected: {비교 값}, pending: {고친 값} | null, content: {비교 값} | null, contentDiff: [[키, 기대, 후보]…] | null}`. 차례 = 내용 서식(템플릿 번호 · 레벨) → 문단 서식 → 테이블.
- `PUT /api/docs/{id}/formats/map` `{prefix?: 글 | null(자동), names?: {이름 키: 글 | null(기본)}}` → 지도. 이름 1~60자(400). 문서를 안 바꾼다.
- `PUT /api/docs/{id}/formats/slots/{key}` `{changes: {line1Mm?, line2Mm?, font?, sizePt?, lineSpacingPct?} | null(지움)}` → 지도. 값 검사(mm 0~300 · sizePt 1~200 · lineSpacingPct 50~500 · font 1~40자) 400 · 표 자리 400 · 없는 자리 404. 문서를 안 바꾼다(대기 값).
- `POST /api/docs/{id}/formats/slots/{key}/apply` `{paras?: [문단 id]}` → **구조 편집 트랜잭션 하나**(`server._edit` — 실행 취소 1 · 기록 `formatMapApply` · 문서 표준 검사) — 그 자리의 다른 줄(paras 를 주면 그 가운데 자리에 든 것만)을 기대 서식(대기 값 포함)으로.
  쓰기: 문단 키 → `derive_format`(line1·line2 → 왼쪽 여백 = min, 첫 줄 = line1 − line2 · `lineSpacingPct` 는 기대가 % 일 때만 — 아니면 그 키는 `skipped`) · 글자 키 → 본문 런만(접두 뒤 글 범위 — `format_chars` 와 같은 런 쪼개기).
  템플릿 레벨의 대기 값에 앞 여백·2번째 줄이 있으면 오버레이 슬롯 규칙도 `{line2: "mm", mm: 2번째 줄, set: true}` 로(뒤의 새 줄·글 고침이 그 값을 따른다 — spec_hwpx_웹편집 ② §8-1). 자리의 줄이 모두 같아지면 대기 값을 지운다.
  정책 = 보관함 적용과 같은 `doc_agent.policy`(403). 응답 = 다른 구조 편집과 같은 꼴(`structOp` 가 그대로 받는다) + `changed: [id]` · `skipped` · `map`.
- `POST /api/docs/{id}/formats/paint` `{from?: 문단 id | look?: {비교 값} | slot?: 자리 키, to: [문단 id](1~2000)}` → 같은 트랜잭션(기록 `formatPaint`) · 같은 쓰기 · 같은 응답.

서식 관리자 — `app/style_api.py`:
- `PUT /api/styles/{sid}/items/{key}/format` `{expectedRevision, changes: {line1Mm? | textMm?, line2Mm?, font?, sizePt?, lineSpacingPct?}}` → 새 revision 의 meta(§19-6). 글 서식만(400) · revision 다름 409 · 없는 item 404.
  `textMm` = 글 시작(§19-6 — 서버가 레터 자리 폭을 재어 앞 여백 = textMm − 폭 으로 넣는다) · `line1Mm` 과 함께는 400 · 못 재는 항목(자동 번호·탭)·레터 자리 폭보다 작은 값 400 · 모르는 키·범위 밖(mm 0~300 · pt 1~200 · % 50~500 · font 1~40자)·빈 changes 400.
  쓰기(`style_carrier.retune`): 그 항목의 견본 문단만 — 왼쪽 여백 = min(앞 여백, 2번째 줄) · 첫 줄 = 앞 여백 − 2번째 줄 · 폰트·크기는 본문 런만(레터 자리 뒤 — 런을 쪼갠다) → `items[].format` 다시 읽음 · docx 운반 문서 다시 지음 · 두 형식 검증을 다시 건다.
- `POST /api/styles/{sid}/copy` `{name?}` → 201 새 서식의 meta(§19-6 — 이름을 안 주면 「<이름> 복사」(60자 안) · 이름 1~60자 아니면 400 · 없는 서식 404).
- `GET /api/styles/{sid}` 의 글 서식 `view` 에 `pos`(§13 「내용 서식의 견본」 — 항목마다 잰 자리).
- `POST /api/docs/{id}/styles/candidates` 응답의 후보마다 `defaultName`(§19-2) · 글(템플릿) 후보의 `template.anchor`.
