### 0. 용어

- **문단 레코드**: hp:p 하나(본문·표 칸·글상자·캡션·머리말·꼬리말·각주·미주, 빈 문단·개체만 품은 문단 포함)의 추출 결과. 그 안의 **구간**(span) = 첫머리(레터) · 이어지는

- **규칙식**: 앞 공백을 뗀 글 첫머리(또는 첫 줄 전체)에 거는 정규식 + 종류(kind) + 계열(family). **내장 규칙**(코드) · **배운 규칙**(LLM 이 제안해 검증을 통과한 것·사용자가 넣은 것 —

  placeholder(자리표시 「○○명」「0,000」「20××」) · plain(보통 글) · empty(빈 문단) · object(표·그림만 품은 문단).

- **이종 형제**: 같은 의미 부모 아래, 변형군·오차를 뺀 뒤에도 레터 계열이 다른 형제(예: 「□」 아래 「o」 와 「※」 가 아닌 「-」). 같은 변형군(o/ㅇ/○/◦, -/–, ·/⋅/•, □/■, △/▲)은 같은 레터.
  **2026-11-09**: 이종 형제 = 가지 템플릿이 뿌리를 내리는 자리(아래 「템플릿 가지 규칙」 ①) — 허용·표시만 하던 것에서 바뀜.
- **개요템플릿**(사용자 정의 2026-11-09): 문서 전체 개요의 주 사슬 — 레벨마다 레터 계열 + 대표 서식 라벨 + 허용 이종 형제. 예: 그림 2 「1. › 1-1. › □ › o › - › ⋅」 6레벨
  (번호형 → 기호형 전환은 끊는 곳이 **아님**).
- **서브 템플릿**(사용자 정의): 주 사슬 노드 아래 붙는 다른 사슬(「1, 1.1, 1.1.1, [1], □, △」 의 「[1], □, △ 이하」) — 정의(뿌리 유형 + 레벨별 유형·대표 서식) + 인스턴스
  (실제 부분 트리 뿌리 + 구분 기준 값) + 편차. 서브 템플릿 레벨은 뿌리부터 1.
- **템플릿 가지 규칙**(2026-11-09 사용자 확정 · astra 협의 반영): 템플릿은 **한 줄 사슬** 그대로 두고, **가지 자리**(한 부모 아래 레터 계열이 둘 이상 나오는 자리 —
  예: 1-1. 아래 (N)·o·□·라벨)마다 **새 템플릿이 뿌리**(L1)를 내린다.
  ① 같은 부모 아래 열린 템플릿의 그 레벨 레터와 **다른 레터**가 오면 그 노드부터 다른 템플릿 — 이것이 이종 형제. ② **구분 라벨은 그 라벨부터 새 템플릿**(라벨 = L1,
  아래 내용 = L2…; division 간선은 그대로) — 라벨 아래 「o」 의 개요레벨은 (라벨 템플릿, 2). ③ 템플릿의 정체 = **사슬 꼴** `key = scope:사슬`(scope = body | cell — 1칸 상자
  투명을 반영한 흐름 종류; 사슬 = 정규 레터 키 열 — 변형군 합침(o/ㅇ/○/◦ → o …), 라벨은 `[basis]`). 같은 key 면 어디에 매달려도 **같은 템플릿 하나로 관리**(정의 1개 —
  레벨별 레터·대표 서식 — 사용자 "동일한 가지 템플릿을 관리한다"), 매달린 자리마다 인스턴스. **id**(정수 — #1 주 사슬, 가지는 문서 순 첫 등장, 라벨·칸 템플릿은 그 뒤 —
  사용자 "id 를 붙여서 관리")는 실행 안 번호. **앵커 = key**(사용자 "각 템플릿의 최상위에 앵커 — 중복 없고 독립적으로 그 개요를 대표": 정의마다 하나, 인스턴스 뿌리가
  참조. 문서·실행이 달라도 같은 사슬이면 같은 앵커 → 자동 변환·병합의 열쇠. main/branch 구실(kind)은 정체성이 아니라 이 문서에서의 쓰임이라 앵커에 안 넣음 — astra). 사람이
  붙이는 이름은 `displayName`(④). ④ **인스턴스** = 템플릿 L1 이 나타나는 모든 자리(가지 뿌리·라벨·주 사슬 1.·2.·… 각각) `{no, template(id), root, parent(노드 id — 권위 있는
  부착 참조), path(표시용 글), basis 값, members(직접 소속 — 안쪽 인스턴스 경계까지), childInstances}` — 1.·2.·…·7. 은 모두 #1 의 인스턴스, 2. 안의 가지와 6. 안의 가지가

### 2. 규칙식 (`app/heading_rules.py`)

- 판정 순서(처음 맞는 것): 빈 문단 → 목차·캡션 → **앞선 배운 규칙**(`first` — 충돌 묶음을 바로잡는 것만, §3 검증 엄격) → 글 전체 규칙(내장 → 배운) → 첫머리 규칙(내장 → 배운) → plain.
  첫머리 규칙은 앞 공백 뒤 첫 줄(최대 400자)에 `match`(앞에 고정 — 배운 규칙은 맞은 자리가 0 이어야 함, `\K`·`(?r)` 로 뒤에서 맞춘 것은 안 맞음), 빈 글에 맞는 패턴 금지.
- 내장 규칙(코드 `BUILTIN`): 자리표시·값(글 전체 — 번호 쓸 자리 「1.」「(9)」 는 값이 아님) · 제N장·절·조 · N.N(.N…) · N-N(.) · N. · N) · (N) · 가. · 가) · (가) · ①~㊿ · ❶⑴⒈⒜ⓐ㉠㉮ ·
  Ⅰ./I. · ⅰ./i. · A. · a. · (a) · [N] · [가] · [ … ] 라벨(40자까지, 줄 전체가 아니어도) · 【 … 】 · □■ · ○◦● · o · ㅇ · △▲ · -–— · ·․•ㆍ⋅∙⦁‧ · ▫▪ · ◇◆ · ▶►▷➢➤ · ※ · *~****.
  기호 뒤가 글자로 붙는 「o리」·「-10」 은 아님. 레터 뒤 공백 = 레터 다음 공백, 제목 = 그 뒤 글, 제목 없음 = `blank`(양식의 쓸 자리 — 헤딩 후보로 남김).
- 구간(spans): 0 = 첫머리 판정, 라벨·기호 뒤가 「※」/「*」 면 안내·각주 구간, 강제 줄 바꿈 뒤 줄마다 그 줄의 첫머리 판정(plain·빈 줄 빼고).
- 배운 규칙 `{id(l1…), name, kind, family, pattern, scope(prefix|whole), first(앞선 규칙), status(candidate|global), docs[문서 sha256…], enabled, source(llm|user), note, examples,
  provenance{model, guide, run, doc}, created}` — 정규식은 `regex` 패키지로 호출당 50 ms·실행당 5 s 예산, 길이 200자·되풀이 곱 100,000·역참조 금지(FileMergeManager 변환 규칙과 같은 막이),
  시간 초과는 「안 맞음」 과 구분해 경고로 남김. 후보 규칙은 그 규칙을 검증한 문서(docs)에만 걸린다. 다른 문서 추출 때 후보 규칙을 시험해(§3 과 같은 검증) 통과하면 그 문서를 docs 에
  더하고, 서로 다른 문서 **2개** 에서 통과하면 전역(global)으로 올린다. 사용자는 화면에서 켜고 끄기·전역 올리기·지우기(내장은 끄기만).
- 저장: `%LOCALAPPDATA%\NewFileManager\headings\rules.json`(env `NFM_HEADINGS`; `off`·`0` = 메모리만) — 내장 규칙은 켜고 끄기만 저장(코드 개선이 계속 반영), 바뀔 때마다 `version` +1 과
  `history.jsonl` 한 줄({t, kind: rules, action, ids, reason, source}). 조건부 저장(기대 version 이 다르면 409, 정수가 아니면 400). 읽기·쓰기 모두 잠금 안(Windows 교체 충돌은
  짧게 다시 시도). **깨진 rules.json 은 덮어쓰지 않는다** — 읽기는 빈 저장소 + `broken`, 쓰기는 `StoreBroken` 으로 거절, 파일은 `rules.json.broken-<시각>` 으로 한 번 복사(2026-11-09).

### 3. 규칙 보강 — LLM (1단계 안, `heading_extract.propose_rules`)

- 보강 대상(`review`): ① **못 맞춤** = plain 인데 앞머리에 기호·짧은 토큰이 있는 문단(`headings.skeleton` core) — 꼴별 묶음, 2회 이상 또는 제목이 붙은 기호 1회(1회짜리는 20묶음까지) ·
  ② **충돌** = 첫머리에 종류가 다른 규칙이 둘 이상 맞는 문단(먼저 온 규칙이 이김 — 앞선 배운 규칙(`first`)이 이긴 문단은 이미 바로잡은 것이라 충돌 아님) — 규칙 쌍별 묶음. 묶음마다 예문 ≤ 6(글 앞 80자·자리·서식 라벨·앞뒤 문단 kind/레터).
- LLM(Opus 5.5, effort low, 지침 `rules.md`) → 묶음마다 `{group, decision: rule|keep|unsure, rule{name, kind, family, pattern, scope, first}, positives[예문 id], negatives[맞으면 안 되는
  글], globalHint(다른 문서에도 나올 꼴인가), reason}`.
- 검증(스크립트, 모두 통과해야 저장): 컴파일·안전 막이 → positives 가 모두 맞음(그 kind 로 바뀜) → negatives 가 하나도 안 맞음 → **빼앗음 검사**: 대상 묶음 밖 문단의 판정이 바뀌면
  안 됨(`first` 규칙은 0개, 보통 규칙(kind plain 포함)은 대상 밖 plain 을 가져가는 수 ≤ max(3, plain 의 1%) — 가져간 수·예문을 결과에 남김). 통과 = 후보 규칙(docs = 이 문서)으로 저장 + 다시 판정.
  통과 못 한 제안은 까닭과 함께 결과에만(저장 안 함). 한 실행에 LLM 호출은 묶음 30개씩, 병렬 ≤ 4(서버 전체 자리 `NFM_LLM_SLOTS`).

### 4. 서식 라벨 (`heading_extract`, 1단계)

- F 지문 = [정렬, 왼·오른 여백, 첫 줄, 위·아래 간격, 줄 간격 종류·값, 문단 테두리 id, 글 런 글자(글꼴·크기·굵게·기울임·밑줄·색·장평·자간·첨자), 레터 런 글자(다르면), 앞 공백 꼴,
  레터 뒤 공백 꼴] — 원본 값 그대로. 문서 첫 등장 순 F1…
- S 라벨 = F 를 **제목 있는 F 먼저**, 많이 쓰인 순으로 돌며 기존 S 대표와 **범주 값이 같고**(정렬·굵게·기울임·밑줄·글꼴 별칭군·색 군·첫 줄 부호·줄 간격 종류) **수치 차이가 오차 안**(§5)이면
  그 S, 아니면 새 S(대표 = 그 F). 쓸 자리(blank)뿐인 F 는 레터 뒤 공백을 견주지 않고 같은 서식의 제목 있는 S 에 붙는다(대표는 되지 않음). 줄 간격은 % 면 `lineSpacingPct`,
  고정·최소·여백(pt)이면 `lineSpacingPt` 로 견줌. 빈 문단·개체 문단은 글자 크기·줄 간격만으로 따로 묶음(간격 장치). S 마다 이름(「Dotum 13pt 굵게 · 양쪽 · 왼0 · 위0 아래0 · 160% · 앞_2 뒤_1」 — 레터 글자 없음)·
  문단 수·kind 분포·변형(F 목록과 수)·대표 문단.

### 5. 지침 · 판단 기준 (`app/heading_guides.py`, 기본본 `app/heading_guides_default/*.md`)

- 지침 5개(마크다운): `rules`(규칙식 제안) · `graph`(헤딩 그래프·개요레벨) · `templates`(개요템플릿·서브 템플릿·조정) · `tolerance`(오차 판단 기준 — 맨 앞 ```json 블록이 스크립트가 읽는
  숫자 문턱의 **단일 원본**: leadSpaces·leadMm·indentMm·firstLineMm·sizePt·spacePt·gapPt·lineSpacingPct·lineSpacingPt(고정·최소·여백 줄 간격)·ratioPct·spacingPct·fontAliases·colors) ·
  `tables`(표 구조 — 칸 역할·서브 테이블 나누기·판단 기준, 3단계 §8, 2026-11-09).
- 프롬프트 = **코드 고정 출력 계약**(역할·입력 꼴·출력 스키마 설명) + 지침 본문 + 자료(JSON). 사용자 글은 지침 칸에만 들어간다(고정 계약을 대체하지 않음).
- 사용자 사본: `%LOCALAPPDATA%\NewFileManager\headings\guides\<이름>.md` + 메타 `{base: 고칠 때의 기본본 sha1, updated, version}`. 기본본이 그 뒤 바뀌면 `defaultChanged` 로 알리고
  화면이 기본본·사본을 나란히 보인다. 저장마다 이전 글을 `guides\history\<이름>\<시각>.md` 로 남기고 `history.jsonl` 에 한 줄({kind: guide, name, version, sha1, reason}).
  「기본본으로 되돌리기」 = 사본 지움(이력은 남음) + 메타 `{version+1, updated, base}` 는 남김 — version 이 0 으로 돌아가지 않아 되돌리기 전 판을 든 저장은 409(ABA 막음).
  tolerance 숫자 블록은 NaN·무한·음수·참거짓을 거절.
- 실행마다 쓴 지침의 이름·sha1·글 전체, 규칙 저장소 version, 모델·effort, 프롬프트·응답 원문, 시간·비용을 실행 폴더에 남긴다(§7).

### 6. 2단계 — 헤딩 그래프 · 템플릿 (`app/heading_graph.py`)

- 후보 노드: kind ∈ marker·label 구간 + 개요·번호 문단 + plain 중 제목 같은 것(짧고 굵거나 둘레보다 큰 글 — 유형 표에 넣어 LLM 이 role 결정). note·footnote 구간은 그래프의 잎(부모만 정함).
- **유형 표**(스크립트): 헤딩 유형(§0)마다 수 · 예문 3 · 대표 S·앞 공백 분포 · 앞/뒤에 자주 오는 유형 · 자리(본문/칸) 분포.
- **A 호출(전역 1회, 지침 graph + templates + tolerance)**: 유형마다 `{type, role(heading|label|note|not_heading|title), template, level, variantOf, basis(구분 기준 — 단계·차년도·기관…)}`,
  템플릿 `{name, kind: main|sub, root, levels[유형…]}`, 오차 판정 `same[{a, b, same, reason}]`(S 라벨 쌍).
- **초안 그래프(스크립트)**: A 의 유형 → (템플릿, 레벨) 로 문서 순 스택을 쌓는다 — 본문은 하나의 스택, 표 칸은 칸마다 새 스택(칸 그릇 아래, 칸 안 레벨 1부터; 표 그릇의 의미 부모 = 표
  자리의 열린 본문 노드), 1칸 상자는 투명(바깥 그릇의 흐름 — 본문 안이면 본문, 여러 칸 표 칸 안이면 그 칸), 글상자·각주·머리말 같은 다른 그릇은 그릇(key)마다 따로 스택. 구분 라벨은 투명 — 의미 부모는 그 자리의 열린 노드, 다음 같은 유형 라벨이나 더 얕은 노드 전까지가 division.
  서브 템플릿 뿌리 유형이 나오면 그 뿌리 아래는 서브 템플릿 레벨(뿌리 = 1), 같은 서브 템플릿 인스턴스가 열려 있으면 새 뿌리는 열린 뿌리의 형제(「① 개발 목표」 → 「② 개발 내용」).
  A 가 레벨을 안 준 제목(title)은 잎. LLM 이 없으면 대체 판정 = 레터 스택(같은 레터 = 형제, 새 레터 = 자식) + 한국어 개요 계열 서열(N. < N-N. < 가. < (N) < ① < □ < o < - < ·)로 깊은 것 닫기.
- **템플릿 가지**(2026-11-09 사용자 확정 — §0 「템플릿 가지 규칙」; astra 협의로 순서·역할 확정. 구현 ③ 2026-11-09): **부모 확정과 슬롯 배정을 분리**한다(astra 최우선 —
  레터만으로 스택을 쌓으면 이종 형제의 부모를 알 수 없음; 시제품으로도 확인). 순서 `A → 부모 초안 → B(일괄 검증, 부모 변경 보존) → 최종 부모·역할 → 사슬 학습·슬롯·인스턴스 →
  id 동결 → C → D → finish`.
  - **A 호출** = 유형마다 role·basis·variantOf·**parents**(그 레터가 보통 매달리는 부모 레터 키들 — 라벨 키·"root" 포함)·reason + **mainChain**(스크립트가 빈도로 제안한
    본문 주 사슬을 확인·수정) + 서식 같음(same) + summary. 유형 → (템플릿, 레벨) 매기기는 없앰.
  - **부모 초안(스크립트)**: 흐름마다 열린 노드 스택을 문서 순으로. 노드(정규 레터 키 k)마다 스택 위에서부터 — 같은 키 → **형제**(그 항목의 부모로); 항목이 k 의 부모로
    받아들여지면 → **자식**; 아니면 그 항목을 닫고 아래로. 받아들임 = 항목 키 ∈ parents(k) 또는 주 사슬에서 항목 키의 바로 다음 레터 = k 또는 parents 가 없을 때의 어림(항목
    앞 공백 < 노드 앞 공백, 같으면 한국어 개요 서열이 더 얕음 — 어림으로 둔 부모는 `heuristic` 표지, 확정 사실로 안 봄). 라벨 = 같은 묶음(basis / 꼴+앞 공백) 라벨이 열려 있으면
    그 닻까지 닫고 형제, 아니면 자식; 스택 위 라벨이 k 를 내용으로 받아들이지 않으면 라벨 범위 끝. 헤딩 아님·안내는 스택에 안 올림. 정규 레터 키는 초안·학습·배정 모두 같은 것.
  - **B 호출**(구간별, 입력·검증은 지금 꼴) = 초안과 다른 노드만 `{id, parent, role, division, template, level, reason}` — template·level 은 **슬롯 예외**(「(N) 을 건너뛴 주 사슬
    L4」 처럼 부모만으로 구별 안 되는 경우만; ""·0 = 스크립트가 정함). 모든 구간의 답을 같은 초안에 대해 모아 검증한 뒤 적용(부모 변경은 보존 제약). 실패 구간 `undecided` 유지.
  - **사슬 학습·슬롯 배정(스크립트, 확정 트리 위에서)**: 템플릿 key 마다 레벨별 자식 레터 빈도 → 사슬(§0 ⑥); 노드의 (템플릿, 레벨) = 부모의 (템플릿, 레벨)과 노드 키로 위에서
    아래로 — 부모 사슬의 다음 레터와 같으면 잇고(L+1), 라벨이면 라벨 템플릿 L1, 그 밖은 가지 템플릿 L1(인스턴스 시작; B 슬롯 예외가 있으면 그대로). 사슬 ↔ 배정은 고정점까지
    되풀이(트리는 안 바뀜). 그 뒤 **id 동결**(§0 ③ 순서), 노드에 `template`(앵커)·`tplNo`(id)·`level`·`instance`.
  - **C·D**: 슬롯 키 = (템플릿 id, 레벨, a, b) — 슬롯별 답만 쓰고 다른 슬롯·전역 쌍 답을 재사용하지 않음(없으면 미판정 — astra; d0 세션의 「다른 슬롯 답 재사용」 시험은 바뀜).
    라벨 L1 도 슬롯·조정에 포함. 템플릿 간 교차 조정(같은 레터 다른 템플릿)은 자동 전파하지 않음(④).
  - **결과 v2**: `templates[{id, anchor(=key), kind(main|branch|label|cell — 이 문서에서의 구실), scope, chain[], name(=anchor, 화면 호환), no(=id), displayName(""),
    slots[{level, letter, count, types, format(S), formats, rep(대표 문단 id)}], instances(수), where[]}]`, `instances[§0 ④]`, 노드 `template`·`tplNo`·`level`·`instance`.
    화면은 id 로 찾도록 함께 고침(인스턴스 참조가 정수), 문서 표시는 label 포함. v1 결과는 옛 규칙 결과로 읽기만.
  - **자동 변환·병합 대비**(사용자 목적, 구현은 ④): 슬롯마다 대표 문단 id + S/F 참조 + stage1Run 을 남겨 실제 서식 속성을 해석할 수 있게 함; 같은 앵커 = 「사슬이 같은 병합
    후보」 까지만(자식 템플릿의 부착 슬롯·구분 기준·순서·누락 정책은 따로 견줌 — astra).
  - LLM 없을 때(fallback) = 같은 절차, role 은 스크립트(label 꼴 → label, 그 밖 heading), parents 없음 → 어림(heuristic 표지).
  - 시험(astra 목록): 라벨 안/밖 같은 o · 다음 라벨·(N)·□ 복귀 · (N)→가. · □→① · L2→L4 생략(B 슬롯 예외) · B 수정 보존 · 라벨 L1 조정 · 슬롯별 상반된 C/D 판정 ·
    중첩 인스턴스 · v1 읽기 · 양식 기대값((1) 최종목표 = #1 L3, 그 아래 □ 부모 (1)·□ 가지 L1, [기관] = 라벨 템플릿 L1, 그 o 부모 = 라벨·L2, 2절·6절 같은 가지 = 같은 id 다른 인스턴스).
- **B 호출(본문 구간별, 병렬 ≤ 4)**: 구간 = 최상위(템플릿 레벨 1) 노드 단위 — 작은 이웃 구간은 노드 120개까지 합치고(2026-11-09, 최상위가 많은 문서의 호출 수 폭증 방지),
  한 구간이 120개 넘으면 레벨 2 에서 더 자름(표·라벨 인스턴스 안에서는 안 자름). 입력 = A 요약 + 구간 앞 조상 사슬 +
  구간 노드 `[id, 유형, 글 앞 60자, 초안 부모, 초안 레벨]` + 다음 구간 첫 5노드 미리보기 → 출력 = **초안과 다른 노드만** `{id, parent, template, level, role, division, reason}`.
  칸 안 노드는 B 에 안 보낸다(부모 = 칸 그릇 — 유형 수준 결정은 A 가 함).
- **검증·조립(스크립트)**: parent ∈ 구간 ∪ 조상, 문서 순 앞, 순환 없음, 템플릿 이름·레벨 범위 안 — 어기면 그 변경은 버리고 기록.
  B 변경의 parent `""`·template `""`·level 0 은 「초안 값 그대로」(스키마가 모든 칸을 요구하므로 — 2026-11-09, 계약에도 「안 바꾸는 칸은 초안 값을 적는다」).
  부모가 라벨이면 투명(의미 부모 = 라벨의 부모, 라벨은 division — B 가 역할만 라벨로 바꾼 노드의 자식도), 헤딩 아님·안내 부모는 버림, division 은 B 가 본 라벨(구간·조상·초안 구분)이고
  문서 순 앞이어야 함(아니면 초안 구분 유지). B 가 실패한 구간은 초안 + 「미판정」 표지
  (템플릿 통일의 근거로 쓰지 않음). 구간 변경률이 30% 를 넘으면 그 구간을 한 번 더 묻는다.
- **템플릿·인스턴스**: 개요템플릿 = main 템플릿 레벨별 (레터 계열, 대표 S, 이종 형제 목록, 문단 수). 서브 템플릿 인스턴스 = 같은 부모 아래 **같은 꼴 부분 트리**(상대 레벨·계열 열 해시)의
  되풀이 + A 의 sub 템플릿 — 인스턴스마다 뿌리·구분 값·멤버·편차(레벨 빠짐·다른 S). 뿌리는 헤딩·제목·**라벨**(「[기관] › o」 — 멤버는 division 으로), 헤딩 아님으로 내려간 뿌리는
  인스턴스 아님. 헤딩 아님 노드는 투명(그 아래 헤딩은 위 노드의 자식으로 셈 — 그래프 부모는 그대로).
- **조정**: 슬롯마다 대표 S 와 다른 S 의 문단 → `{id, para, template, level, from, to, decision: adjust|keep|undecided, reason}`. S 라벨은 이미 오차 안을 묶었으므로
  다른 S 는 오차 밖 — **C 호출**(그래프 뒤, 지침 templates + tolerance, 쌍 60개씩 effort low)이 슬롯의 (대표 a, 다른 b) 쌍마다 같은 구실이면 조정(same true), 아니면 「다름 유지」.
  A 가 유형 안 쌍으로 이미 판정한 쌍은 다시 안 묻는다. C 의 답은 **슬롯마다**(같은 쌍이 여러 슬롯에 나오면 슬롯마다 따로 판정).
- **재검토(D 호출)**(2026-11-09 ①): 조정 판정은 두 번 — 1차(A·C) 뒤 **새 호출**(세션 없음·1차 맥락 모름, 지침 templates + tolerance, 쌍 60개씩, effort medium)이
  모든 슬롯 서식 쌍에 1차 판정 `first{same, reason}` 을 붙여 받아 **스스로 판정한 뒤 반박 검증** → `{slot, a, b, verdict, same, reason}`. verdict 는 스크립트가 재검토 same 과
  1차 same 을 견줘 정한다(응답 verdict 칸은 모델이 스스로 견주게 하는 장치). agree = 1차 판정 그대로(✓), **disagree = 그 문단의 조정은 `undecided`** 로 두고 `first`(1차 결론)·
  `review{verdict, same, reason}` 을 남김(사람이 정함), 답이 없는 쌍·호출 실패 = `failed`(1차 그대로 + 「재검토 못 함」). 1차 판정이 없는 쌍(C 실패)은 재검토 안 함(어차피 미판정).
  재검토의 「확신 없음」 = same false 로 답하라 함 → 1차가 조정이면 불일치(미판정), 1차가 다름 유지면 동의(C 의 「확신 없으면 다름 유지」와 같은 쪽). 답은 **슬롯 그대로**만
  쓴다 — slot 이 비거나 다른 쌍의 답은 그 쌍에 안 맞춰 줌(failed, 2026-11-09 템플릿 가지 규칙 때 bc 세션이 C 의 전역 (a, b) 재사용과 함께 없앰 — 슬롯마다 구실이 다르므로).
  `llm.reviewPairs/reviewFailed/reviewDisagree` 는 LLM 길에서만 있다(스크립트 대체 판정이면 키 없음 — 화면은 `!= null`).
  자료 구실은 `heading_graph.review_pairs`·`apply_review`, 계약은 `heading_llm.REVIEW_CONTRACT/SCHEMA`, 지침 기본본 templates.md 「재검토」 절.
- **템플릿 번호**(2026-11-09 ①): `templates[].no` = 1부터 — 개요템플릿(main) → 서브(sub) → 표 칸(cell) 차례, 같은 종류는 문서에 먼저 나온 노드 순. 노드·조정에 `tplNo`,
  서브 템플릿 인스턴스에 템플릿 안 번호 `no`(문서 순). 화면·문서 표시 꼴 「TN Lk」 = 템플릿 TN 의 k번째 줄(= 템플릿 안 레벨). 2026-11-09 ① 「#N Lk」 에서 바꿈 — 유형 번호(T28)와는
  L 이 뒤따르는 것으로 구별하고, 화면에서 유형은 늘 「유형 T28」 로 쓴다(자료의 유형 id `T28` 은 그대로).
- 결과 `graph.json`: `{nodes[{id, span, kind, type, role, template, tplNo, level, sourceOutlineLevel, area, text}], edges[{t: contains|parent|division|instance, from, to}],
  templates[{…, no, slots}], instances[{…, no}], adjustments[{…, tplNo, decision, first?, review?}], heterogeneous[{parent, letters}], issues,
  counts{…, reviewed, disagreed}, llm{calls, failed, seconds, costUsd, reviewPairs, reviewFailed, reviewDisagree}, stage1Run}`.
  단위: `counts.reviewed/disagreed` = 재검토가 닿은 **조정 문단** 수(못 함 failed 는 빼고)·그 중 불일치 문단 수(실행 메시지 「재검토 N(불일치 M)」·2단계 카드 「재검토 불일치」 도 문단 수),
  `llm.reviewPairs/reviewFailed/reviewDisagree` = **쌍**(슬롯·a·b) 수.

### 7. 실행 · 저장 · API · 화면

- **실행** = 단계 하나(1: 스크립트 + 선택 LLM 규칙 보강, 2: 그래프, 3: 표 구조 — §8)의 불변 결과. 시작 때 세션 `rev`·원본 sha256·규칙 version·지침 sha1 을 고정하고 문서는 그때의 블록·XML 로 읽는다
  (잠금 안에서 레코드를 뽑고 LLM 은 잠금 밖). 지침은 시작 때 한 번 찍어(snapshot) 프롬프트·오차 기준·기록에 모두 그것을 쓴다 — 실행 중 지침을 고쳐도 그 실행엔 안 걸림.
  규칙 version = 마지막 추출에 쓴 저장소의 version. 끝난 뒤 문서 `rev` 가 바뀌었으면 결과에 「오래됨」. 세션마다 헤딩 작업 하나(검증 `s.jobs` 와 따로) — 돌고 있으면 새 시작은 409.
  실행 번호는 작업 잠금 안에서 디스크의 번호 폴더 + 메모리 중 큰 것 + 1(겹치지 않음), 지운 작업·밀려난(evicted) 세션의 실행은 쓰지 않음, 깨진 gz·run.json 은 하나씩 건너뜀.
- 저장: 작업 폴더 `works/<id>/headings/<n>/`(`run.json` 메타·`stage1.json` 또는 `graph.json` 또는 `tables.json`·`llm/<호출>.json` 프롬프트·응답·`guides/` 쓴 지침) +
  `works/<id>/headings/current.json` {stage1, stage2, stage3}. 저장 끔이면 메모리만. 표 지침·사용자 수식은 `works/<id>/tables/`(§ 10). 기록 탭에 `works.log(wid, "headings", stage, n, status, …)`.
- API: `GET /api/docs/{id}/headings`(작업 상태 + 지금 결과 요약 + 오래됨 — stage3 는 표 목록 요약까지) · `POST /api/docs/{id}/headings` `{stage: 1|2|3, llm: bool}`(시작, 202) ·
  `GET /api/docs/{id}/headings/paras?kind=&fmt=&rule=&area=&q=&offset=&limit=`(문단 목록 쪽 나눔) · `GET /api/docs/{id}/headings/labels` · `GET /api/docs/{id}/headings/graph` ·
  `GET /api/docs/{id}/headings/tables`(3단계 결과 전체 — 표마다 칸·서브 테이블·경로, 없으면 404) ·
  `GET /api/docs/{id}/headings/tables/{tid}/xlsx`(표 하나를 엑셀로 — § 9; 3단계 결과·그 표가 없으면 404, openpyxl 이 없으면 503) · `GET …/headings/tables/agents` · `GET|PUT …/headings/tables/{tid}/agent`(표 지침·사용자 수식 — § 10, `app/tables_api.py`) ·
  `GET /api/headings/rules` · `PATCH /api/headings/rules/{rid}` `{enabled?, status?, version}` · `DELETE /api/headings/rules/{rid}?version=` · `GET /api/headings/guides` ·
  `GET|PUT|DELETE /api/headings/guides/{name}` · `GET /api/headings/history` · `GET /api/headings/llm`(연결 상태).
  입력 검사: stage 는 정수 1|2|3, llm 은 참거짓(아니면 400) · PATCH 는 쓰기 전에 모두 검사(거절이면 아무것도 안 바뀜) · version 이 정수 아니면 400 · 파일 쓰기 실패(OSError)는 503.
- 화면: 작업 영역 상단 **「헤딩 추출」**(검증과 따로 — 통과/실패 판정이 아니라 분석). 결과 보기·추출 설정 분리와 문서 비교 UI는 [spec_hwpx_웹편집.md](spec_hwpx_웹편집.md) ② §9. 탭을 열면 1단계 스크립트를 자동으로 돌림(LLM 없이, 1~2 s). 추출·설정의 1단계 카드(문단 수 = XML 수 확인 ·
  kind 분포 · 못 맞춤·충돌 수 · 서식 라벨 수) + 「LLM 규칙 보강」 · 2단계 카드 「헤딩 그래프 만들기(LLM)」 + 접이식 트리(이종 형제·투명 라벨·서브 템플릿 표지) + 템플릿 목록 + 조정 수.
  큰 표(문단 목록·서식 라벨·규칙·지침 편집)는 **2열**(2026-11-09 ①, 팝업 아님): 문서(1열)와 패널(3열) 사이 컬럼 하나를 여러 보기(문단 목록·서식 라벨·규칙·지침 편집·표 보기·템플릿 관계·표 지침·엑셀식 보기 — § 10)가 바꿔 쓰고, ✕ 로 닫는다(저장 안 한 지침 글은 묻는다).
  목록의 문단을 누르면 열은 그대로 두고 문서만 그 문단으로 — 찾아간 줄은 표시. 열 폭은 패널처럼 왼쪽 가장자리로 조절·기억(`nfm.headsColWidth`), 문서 보기 몫 360px 은
  두 열(헤딩 열·패널)의 폭을 합쳐 지킨다(창이 좁아지면 패널 → 헤딩 열 차례로 줄어듦). 좁은 창(≤820px)에선 패널처럼 아래로 쌓인다.
- 화면 — 템플릿·조정·**문서 표시**(2026-11-09 ①; 표기 「TN」·왼쪽 여백·라벨 식별자는 같은 날 ① 「왼쪽 여백에 좀 배치」): 템플릿 목록은 번호 「TN」(단추 — 누르면 아래 「템플릿 관계」
  에서 그 템플릿을 펼침) + 줄(레벨)마다 한 항목(L1 「N.」 ×9 …), 트리 배지 「TN Lk」(라벨 노드는 「TN L1 [기관]」, 단추). 조정 표는 판단 칸에 재검토 결과(✓ 동의 · 「미판정 · 재검토
  불일치(1차 조정)」 · 「(재검토 못 함)」), 까닭 칸에 불일치면 「1차: … / 재검토: …」, 2단계 카드에 「재검토 불일치」 수. **문서 표시** = 그래프를 읽으면 문서 쪽(`.sheet`) **왼쪽 여백**에
  문단마다 「TN Lk」 표(`.tpl-mark`, 문단 요소 밖 절대 위치 — contentEditable 글에 안 섞임): 끌기 손잡이(⋮⋮, 쪽 바로 옆) 바깥쪽에 **오른끝 맞춤** 한 열로, 쪽 배율과 무관하게 **화면 크기
  고정**(표·손잡이에 zoom 1/z, 자리는 화면 px), 같은 높이·표 한 줄 높이(17px) 안에 붙은 줄들(표 한 행의 칸들)은 한 표로 「T4 L1 · T4 L2」(4개 넘으면 「+n」), **구분 라벨 문단**은 라벨
  식별자(정규 라벨 키 = A 호출 basis 「[기관]」 — 값 「[한국선급]」 이 아님)를 붙여 「T5 L1 [기관]」(청록), 미판정 노드는 노랑, 마우스를 올리면 템플릿 이름·줄·라벨 값·인스턴스 번호·노드 id,
  **누르면** 「템플릿 관계」(2열)에서 그 템플릿을 펼침. 표는 헤딩·제목·**라벨** 노드(role heading|title|label, 웹 블록 있는 문단)만 — 안내·헤딩 아님은 없음. 표·손잡이가 있으면 스크롤
  상자에 여백(`.scroller.gutter` 왼쪽 172px, 2쪽 보기는 오른쪽도)을 두고 폭 맞춤은 좌우 padding 을 뺀 폭으로 다시 잰다; 2쪽 보기의 오른쪽 쪽은 표를 오른쪽 여백에(왼쪽 쪽과 안 겹침).
  쪽 보기 끔(hide-pages)·문서 보기 숨김이면 표·여백 모두 없음. 쪽을 다시 나누거나(paginate) 창 크기·2쪽 보기가 바뀌면 다시 그림. 「문서에 표시/끄기」 단추(이 브라우저에 기억
  `nfm.headsMarks`, 기본 켬).
- 화면 — **템플릿 관계**(2026-11-09 ①, 2열 kind "templates" — 2단계 템플릿 목록의 「템플릿 관계」 단추·T번호·트리 배지·문서 표시를 누르면): 템플릿을 **매달린 자리**로 이은 트리 —
  인스턴스의 부모 노드가 (TN, Lk) 이면 그 템플릿은 TN 의 k번째 줄 아래 가지(그래프에 따로 저장하지 않고 화면이 `instances[].parent` → 그 노드의 `tplNo`·`level` 로 만든다; 부모가
  없거나 root 면 「문서 최상위」, 칸 그릇이면 「표 칸」, 템플릿 없는 노드면 「템플릿 밖 노드」). 절 = 본문(문서 최상위에 매달린 템플릿 — 주 사슬 먼저) · 표 칸 템플릿 · 그 밖(매달린 자리를
  모름). 줄마다 [▸] [TN] 사슬 · 구실(주 사슬·가지·라벨·표 칸) · 인스턴스 수(그 자리에 매달린 수) — **TN 을 누르면** 펼침: 매달린 자리(「T1 L3 ×20 · T1 L2 ×4」) · 레벨(줄)마다

### 8. 3단계 — 표 구조 (`app/heading_tables.py`, 지침 `tables.md`, 2026-11-09)

- **입력** = 1단계 결과만(2단계처럼 불변 — 문서를 다시 안 읽음): 레코드의 그릇 사슬 `path` 로 표(`tbl{id, rows, cols, cells, host}`)·칸(`cell{id, row, col, rs, cs, fill}`)을 모은다.
  여러 칸 표만(1칸 표는 투명 — 그 글은 바깥 칸의 글), 중첩 표는 따로 한 표 + 바깥 칸에 `nested`·표에 `parentCell`·`depth`. 칸마다 글(문단 글을 이은 것, 80자)·문단 kind 분포·모든 글 런
  굵게·음영(`fill` ≠ 흰색)·문단 id 목록·대표 서식 라벨. 표의 「앞 문단」(`before`) = 표 밖에서 바로 앞의 글 있는 문단(표 제목 맥락 — 「<연구개발성과 성능 목표>」).
- **칸 성격**(`nature`, 초안 근거): header(음영 칸 — 빈 칸도) · headish(굵은 짧은 글 ≤ 24자·괄호 라벨 하나) · text(중립 — 짧은 보통 글·순번 「1.」「①」 홀로) · field(값·자리표시만,
  「( )」「[ ]」 체크·빈 칸 꼴, 글머리 글 내용, 40자 넘거나 문장 끝·문단 3개 이상) · note(※·각주 kind, 또는 안내 낱말 `_NOTE_WORDS` = 「작성 가이드라인/요령/방법/예시 · ※ · ☞ · 유의 사항」 — § 10 작성요령도 같은 목록) · empty(글 없음, 음영 없음).
- **스크립트 초안**: ⓐ 행 띠 나누기 — 전체 너비 한 칸 행은 자기 띠(title·note·spacer), 필드 행 뒤에 시작 칸이 모두 header·headish 인 행이 다시 오면 새 띠, 열헤더 띠 안에서
  음영 키 + 바로 오른쪽 필드의 열 범위가 헤더 행 칸들의 열 범위와 하나도 안 맞는 키-값 행부터 새 띠(규칙 ⓒ — 표지의 「공동연구개발기관」 매트릭스 뒤 「실무책임자」 키-값). 병합 칸을 가르는
  경계는 안 자른다. 한 열 표는 list 띠 하나. ⓑ 띠마다 **헤더 행 수** = 위부터 시작 칸이 모두 header·headish(위에서 내려온 칸뿐인 행은 이어짐, 최대 4, 필드 행이 하나는 남아야) ·
  **헤더 열 수**(격자 열 단위) = 왼쪽부터 필드 행의 시작 칸이 모두 헤더·중립 글(첫 열은 순번 값도)이고 오른쪽에 칸이 더 있는 열(최대 4) — 중립 글뿐이면 오른쪽 절반 이상이 채울 칸이어야,
  열 위 열헤더 글이 번호·순번·구분·항목·내용·명·기관·지표·단계·연도·목표·성명·대상 이면 빈 칸이 섞여도 헤더 열(「개발 내용」 아래 빈 양식 줄). ⓒ **역할** — 헤더 행 칸 → colhead(헤더 열과
  겹치면 corner), 헤더 열 칸 → rowhead, 그 밖 header·headish 칸은 **이웃 규칙**(오른쪽이 채울 칸(empty·field·text)이고 아래는 아니면 rowhead, 아래가 채울 칸이면 colhead, 둘 다면 가로
  병합 1행은 colhead 아니면 rowhead, 둘 다 헤더면 세로 병합 + 오른쪽 헤더 = rowhead(「단계 › 1단계 › 1년차」 부모), 가로 병합 + 아래 헤더 = colhead), note → note, 나머지 → field.
  띠 종류 = matrix(헤더 행 ≥ 1) · form(헤더 열만) · plain. 연구개발계획서 양식 135표 5,797칸 0.2 s.
- **T 호출**(LLM, 지침 tables + tolerance, effort medium, 병렬 ≤ 4): 4칸 이상이고 2행·2열 이상인 표만(1~3칸·한 행·한 열은 초안 그대로, `skipped`), 문서 순으로 **칸 500·표 10 까지
  한 묶음**(큰 표는 혼자 — 691칸 일정표). 입력 = 표마다 `{table, rows, cols, before, draft[띠…], grid[행마다 칸 토큰]}`, 토큰 「칸id|행수x열수|표지(F 음영 B 굵게 + 문단 종류 글자)|글 30자|
  초안 역할」, 덮인 자리 「^」(위) 「<」(왼쪽), 빈 1×1 필드는 칸 id 만. 출력 = 표마다 `subtables[{sub, rows:[r0,r1), cols:[c0,c1), kind, headerRows, headerCols(−1 = 스크립트 값), note}]`
  (겹치지 않게 **빠짐없이**, 병합 칸을 가르지 않게) + `cells[{cell, role, reason}]`(헤더 수로 정해지는 역할과 **다른 칸만**) + summary. 계약은 「음영·굵게는 힌트 — 칸의 값을 보고 판단」.
- **검증·적용**: 영역이 정수 쌍·표 안·서로 안 겹침·모든 칸을 하나의 영역이 통째로 품어야 함 — 어기면 그 표의 영역 답은 버리고(`rejected`) 초안 띠 유지, 칸 역할 덮어쓰기는 그래도
  적용(없는 칸 id·모르는 역할은 거절). 영역이 서면 띠마다 헤더 행·열 수(LLM 값, −1 이면 스크립트)로 역할을 다시 매기고 덮어쓰기를 얹는다. 초안과 다른 칸 = `changed`(+ 까닭).
  답에 표가 빠졌거나 묶음 호출이 실패한 표 = `undecided`(초안 그대로). 모든 호출이 실패하면 `llm.fallback`.
- **조립**: 띠(서브 테이블)마다 **헤더 트리** — colhead 의 부모 = 바로 위에서 끝나며 열 범위를 품는 colhead(없으면 위쪽 가장 가까운 것), rowhead 의 부모 = 왼쪽에서 끝나며 행 범위를
  품는 rowhead(키-값 양식의 「주관연구개발기관 › 기관명」); 필드마다 `colPath`(위쪽에서 열 범위가 겹치는 가장 가까운 colhead 와 그 조상, 위 → 아래)·`rowPath`(왼쪽에서 행 범위가 겹치는
  가장 가까운 rowhead 와 그 조상). 띠 **서명**(종류·헤더 수·헤더 글(숫자 → N)) 이 같은 띠가 둘 이상이면 **되풀이**(`repeats` — 2단계 「되풀이」의 표 판). **문제**(`issues`): 거느린
  필드·헤더가 없는 헤더, 헤더 없는 필드.
- 결과 `tables.json`: `{version, tables[{id, n, host, before, depth, parentCell, rows, cols, cells[{id, row, col, rs, cs, fill, shaded, bold, kinds, text, paras, n, nested, nature,
  draft, role, sub, parent, rowPath, colPath, changed, reason}], subtables[{id, rows, cols, kind, headerRows, headerCols, source(script|llm), note, counts, cells, signature, issues}],
  counts, issues, llm{sent, changed, rejected, error, undecided, summary}}], repeats[{signature, count, where[{table, sub}]}], counts{tables, cells, subtables, split, roles, repeats,
  changed, issues, nested}, llm{requested, fallback, error, calls, failed, sent, skipped, applied, rejected, undecided, summary, costUsd, seconds}, guides, meta}`.

### 9. 표 의미 — 구분 헤더 · 계산식 표 · 엑셀 수식 검증 · 소속 (`app/heading_calc.py`, 2026-11-09)

- **자리**: 3단계 `build` 가 띠(서브 테이블)·헤더 트리·필드 경로를 만든 뒤(§8 조립) 표마다 `heading_calc.annotate` 를 부른다 — 입력은 3단계 칸(역할·rowPath·colPath)·띠와
  **2단계 결과**(있고 같은 1단계 실행(`meta.stage1Run`)의 것일 때만). 문서를 다시 읽지 않고 LLM 도 부르지 않는다(스크립트만 — 정규식·헤더 트리). 3단계 결과 `version` 2.
- **구분 헤더**(칸 `basis[]`·`basisKind`·`code`·`expr`): 열헤더·행헤더·귀퉁이 칸의 글(각주 번호 「15)」·단위 괄호·코드를 뗀 **핵심 글**)을 정규식으로 — 값: 「N단계」(N·n·로마자·둘레 번호) ·
  「N차년도·N년차·N연차·N차(열헤더 이름이 차년도일 때만)」 · 「2024(년)·YYYY·20XX」 · 기관 역할 「주관/공동/위탁/참여연구개발기관(N)」·「[…기관명 기입]」 라벨·기관 열 아래 자리표시(「XXXXX」);
  이름: 「단계」·「차년도·연차·년차·연도·년도」·「기관(명)·연구개발기관·소속 기관」. total: 「계·합계·소계·총계·총액·총합·누계·Total」(소계는 `subtotal`), ratio: 「비율·구성비·비중·점유율」.
  코드: 「(A)」 → `code`, 「(A/E)」「(B+C)」 → `expr`. 순번 값 행헤더는 같은 열 위 열헤더 이름의 basis 를 받는다(「단계 | 연차」 아래 「1 | 1」). 칸 안 kind=label 문단은 표의
  `labels[{cell, text, basis}]`(「[주관연구개발기관(기관명 기입)]」 → org).
- **구분 축·구분 값**: 띠마다 `axes.col/row = [{level, basis, kind, values[], count}]`(헤더 트리 레벨 = 경로 길이, basis = 그 레벨 헤더의 최빈 basis — 이름 헤더가 있으면 그 이름), 띠·표의
  `basis[]` = basis 합집합(total·ratio 제외), 필드마다 `div{stage, year, org, period}` = 행헤더·열헤더 경로의 값 헤더 글(먼저 만난 것, 30자).
- **숫자**(칸 `num`·`pct`·`dash`): 필드 글에서 뒤 코드 「(A/E)」·단위(%·원·천원·백만원·명·건·개·회·년·개월·시간…)를 떼고 부호·괄호 음수·쉼표·소수 꼴 전체가 수일 때만 값. 「-·－·—」 홀로 = 0(`dash`).
  1단계 kind placeholder(「0,000,000」「00%」)·「0,000」 꼴·빈 칸 = None. `pct` = 글 끝 %.
- **적용 헤더**(effective path): 경로 끝 헤더가 ratio(또는 나누기 식)인데 칸 값이 % 가 아니면 그 헤더를 뗀 경로를 쓴다 — 한 행헤더 아래 금액 줄과 비율 줄이 겹치는 양식(「800,000」 과
  「80% (A/E)」). 필드가 헤더 h 에 **속한다** = 적용 경로의 마지막이 h.
- **계산식 표**(띠 `calc{is, why, numeric}`): matrix·form·plain 띠 중 ① total·ratio 헤더나 코드 식이 있거나 ② 숫자 필드가 2행×2열 이상인 것. 표 `unit` = 「(단위: 천원)」(제목·안내·귀퉁이·앞 문단).
- **수식**(표 `formulas[{id, cell, ref, axis, kind(expr|sum|ratio), formula, operands[], expected, actual, status, diff, excel}]`), 칸마다 축별로 하나, 우선순위 코드 식 > 합계 > 비율:
  ① **코드 식** — 식의 변수마다 같은 띠에서 그 `code` 를 가진 헤더(같은 축 먼저)를 찾아, 그 헤더에 속하고 다른 축 적용 경로가 같은 필드(같은 행/열 먼저)를 피연산자로. 나누기는 실제값이 % 면 ×100.
  ② **합계** — 적용 경로의 total 헤더 h(깊은 것부터) 마다: h 와 **같은 부모의 형제** 헤더 중 total 아닌 것(소계가 있으면 소계들 + 어느 소계에도 안 든 항목, 소계는 앞 합계 뒤의 항목만)을 골라
  경로의 h 자리를 그 형제로 바꾸고 꼬리는 핵심 글이 같은 헤더인 필드(「합계 › 현금」 = 「정부지원 › 현금(A)」 + 「기관부담 › 현금(B)」, 같은 행/열 먼저)를 피연산자로; 처음 피연산자가 나온 h 가 그 축의 수식.
  양 축이 모두 합계인 칸은 **두 수식**(axis row·col)을 다 검증하고 엑셀 수식은 행 축(세로 합) 하나(`excel: true`).
  ③ **비율** — ratio 헤더에 속한 필드 = (바로 왼쪽/위 형제 수량 헤더의 같은 줄 값) ÷ (그 수량 헤더의 합계 줄 값) × 100 — 합계 줄이 없으면 수식 없음.
  이어진 한 줄 피연산자는 `=SUM(E5:E7)`, 아니면 `=E5+E9`; 식은 `=E5/K5*100`. 주소 = 격자 (행, 열) → 엑셀 A1(병합 칸은 왼쪽 위).
- **검증**: expected = 피연산자 num 으로 계산(dash 0; 모두 None 이면 blank, 일부 None 이면 incomplete — 둘 다 「미검증」), actual = 그 칸 num. ok = |expected − actual| ≤ 0.5 × 10^(−actual 소수 자릿수)
  (비율은 + 0.05) · mismatch(`diff` = actual − expected) · missing(피연산자는 있는데 칸이 비어 있음) · nonnumeric(칸 글이 수가 아님). 표 `calc{is, formulas, ok, mismatch, missing, incomplete, blank,
  nonnumeric}`, 전체 `counts.calc{tables, formulas, ok, mismatch, missing, incomplete, blank, nonnumeric}` · `counts.basis{stage, year, org, period}`(그 basis 헤더가 있는 표 수) ·
  `counts.basisTables` · `counts.owners{stage2, stage1, none}`.

  path[조상 글…], division{id, para, text, basis}, source: "stage2"}`; 뿌리(root·area)면 `{source: "stage2", root: true}`. 2단계가 없으면 1단계 어림 — 표 앞(n 작은) 본문 흐름(area body)의 마지막
  marker·label 문단(쓸 자리 제외)과 마지막 label 문단(`source: "stage1"`, template 없음). 어느 쪽도 없으면 None.

  수식은 안 들어감, ④).

## ④ 미결/후속

- **문서 서식 실제 맞추기**(조정 결과를 문서에 반영): 조정 목록은 `apply_format` 입력 꼴로 남기지만 적용 화면·번호/혼합 런 보존 적용·출력파일 검증 연결은 아직(astra P2 — 단순 apply 로 끝나지 않음).
- 가져오기 검증에 「구조 추출」 단계(fable 제안)는 안 넣음 — 탭이 스크립트 단계를 자동으로 돌린다. 필요하면 검증 흐름 담당 세션과 협의.
- 개요 번호(OUTLINE) 글자 계산·번호 재시작(newNum) — hwpx_doc 이 안 함. 자동 글머리(BULLET)는 기술수요조사서 「◦」 5문단으로 시험함, 자동 번호(NUMBER)·OUTLINE 표본은 아직 없음.
- 런 색 경계로 문단을 「가상 줄」 로 가르기(fable 제안 — 이번엔 「※」 안내·강제 줄 바꿈만 구간으로).
- docx 는 아직(요청 「우선 hwpx」).
- 밀려난(evicted) 세션에서 끝난 헤딩 실행은 이제 저장하지 않음(번호 겹침 막음) — 돌던 유료 LLM 실행이 사라질 수 있다. `server._admit` 이 헤딩 작업이 도는 세션은 안 밀어내거나
  다시 연 세션이 그 작업을 이어받게(공용 코드 — 담당 세션과 협의 후).
- 한 LLM 묶음에서 함께 저장된 규칙끼리 가리는 것(먼저 저장된 넓은 규칙이 이김) — 넓이 1% 제한으로 묶였지만 따로 막지는 않음.

- 화면: 탭을 열어 둔 채 문서를 고치면 결과 요약에 「이전 분석」을 바로 표시한다. 탭을 다시 열 때 자동 재추출 정책은 그대로다. 본문 트리에 표 그릇(tbl:)은 아직 안 보임. 화면에서 실물 LLM 실행은 아직 안 해 봄.

  「별첨N·붙임N·부록」 을 1단계 label 계열 규칙으로 넣을지 검토 — 역할은 A 호출이 정함. 본문 트리도 칸 흐름 노드를 보일지 함께.
