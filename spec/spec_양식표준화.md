## ② 확정 사양

### 0. 이름 · 키

- TASK 이름 **「사업계획서 양식 표준화」** · 줄인 이름(act) 「양식 표준화」 · 키 `plan_fit`(그대로) · 받는 형식 hwp · hwpx · 목적 문서 하나(전과 같다).
  한 줄 설명: 「프로젝트 구성을 읽어 양식의 절·표에 적용하고, 헤딩·표를 뽑아 서식을 맞춥니다.」
- 화면 · 지침 · 등록부의 글에서 이 TASK 를 「양식 맞추기」 라 부르지 않는다(「연차보고서 양식 맞추기」 는 그대로 — 둘을 같이 가리킬 때 「양식 표준화 · 양식 맞추기」).
- 프레임 이름(`works.FRAME_FILE` — 반영한 뒤 「사업계획서_<프로젝트>_프레임」)은 그대로.

### 1. 단계 — 등록부(`app/workflow.py` `_std`)

묶음 셋(묶음 id · 번호 · 이름). 단계 key 는 화면(대시보드 · 에이전트)이 상태를 붙이는 계약이다 — 바꾸면 `dashboard.js` · `doc_agent_work.js` 의 그 TASK 가지도 바꾼다.

**1단계 「프로젝트 구성」**(`config`) — 단계 · 차년도 · 기관 값을 읽거나 불러와 확정하고, 양식의 절 · 표 행 · 표 열에 적용한다(문서는 「적용」 에서만 바뀐다).

| key | 이름 | 누가 | 문서 | 비고 |
|---|---|---|---|---|
| `open` | 문서 올리기 · 첫 분석 | 사람 · 스크립트 | 저장만 | 저절로 — 올리면 기본 분석(헤딩 · 표 — 스크립트) |
| `read` | 구성 읽기 | 스크립트 | 저장만 | 안 해도 됨 — 문서(빈 사업계획서 포함)에 적힌 단계 · 차년도 · 기관을 읽어 입력 값으로(확정은 따로). 못 읽으면 직접 입력 |
| `load` | 구성 불러오기 | 사람 | 저장만 | 안 해도 됨 — 이 프로젝트 확정본 · 같은 프로젝트의 문서 · 파일 · 다른 프로젝트 · 저장한 프로젝트 구성(「작업 내용」 의 「프로젝트 구성 불러오기」 와 같은 목록 · 같은 함수) |
| `values` | 프로젝트 구성 확정 | 사람 | 저장만 | 입력 · 확인 → 프로젝트에 저장(확정) |
| `review` | 구분 기준 자리 확인 | 스크립트 · LLM | 저장만 | 안 해도 됨 — 전과 같다(LLM 검토 실행 — spec_작업에이전트 ② §9) |
| `plan` | 변경 계획 보기 | 스크립트 | 안 바뀜 | 「적용」 의 앞 — 바뀔 자리 목록 |
| `apply` | 적용(문서에 반영) | 사람 · 스크립트 | **문서 바뀜** | 절 · 표 행 · 표 열을 값에 맞춤(구조만) |

**2단계 「헤딩 추출」**(`heads`) — 문서의 개요(헤딩) · 템플릿 · 서식을 뽑아 LLM 으로 검증 · 보완하고, 같은 템플릿의 줄을 대표 서식에 맞춘다.

| key | 이름 | 누가 | 문서 | 비고 |
|---|---|---|---|---|
| `heads` | 헤딩 · 템플릿 추출 | 스크립트 | 저장만 | 저절로(첫 분석) — 문단 · 라벨 → 헤딩 그래프 · 템플릿 |
| `headsLlm` | 헤딩 LLM 판정 · 서식 계획 | 사람 · LLM | 저장만 | 유료 — 규칙 보강(스크립트가 판정 못 한 첫머리) → 헤딩 판정 → 서식 정리 계획 |
| `adjust` | 조정 — 템플릿 조정 · 서식 조정 | 사람 · 스크립트 | **문서 바뀜** | 받은 계획 「모두 반영」 + 자리 맞춤(스크립트) · 실행 취소 1 |
| `tree` | 템플릿 관계 — 손으로 맞추기 | 사람 | 문서 바뀜 | 안 해도 됨 — 남긴 줄 · 애매한 것을 「템플릿 관계」 에서 |

**3단계 「표」**(`tables`) — 표마다 칸의 역할(열헤더 · 행헤더 · 필드 · 서브 테이블)을 라벨로 붙이고 LLM 으로 검증한다.

| key | 이름 | 누가 | 문서 | 비고 |
|---|---|---|---|---|
| `tables` | 표 구조 — 칸 역할 라벨 | 스크립트 | 저장만 | 저절로(첫 분석) |
| `tablesLlm` | 표 판정(LLM) — 라벨 검증 · 보완 | 사람 · LLM | 저장만 | 유료 — 2단계 「한 번에 진행」(전체 실행)이 같이 돌렸으면 끝남 |
| `tableTools` | 표 점검 · 서식 맞추기 | 사람 · 스크립트 | 문서 바뀜 | 안 해도 됨 — 「테이블」 탭(수식 판정 · 표 서식 점검 · 빈 필드) |

- 차례: 1 → 2 → 3. 2 · 3단계는 1단계와 따로 돌 수 있다(헤딩 · 표 분석은 프로젝트 구성에 기대지 않는다) — 1단계가 남았어도 「할 수 있음」 이고, 「지금」 은 앞 묶음이 끝난 뒤에 넘어온다.
  1단계를 먼저 하는 까닭: 적용으로 늘어난 절 · 표까지 헤딩 · 표 판정이 함께 본다(LLM 단계는 지금 문서로 스크립트 초안을 다시 뽑는다).
- 시작 점검(`entry`)은 전의 양식 맞추기 것에 더해, 2 · 3단계의 LLM 이 저절로 돌지 않는다는 것(「저절로 돌지 않는 것」 — 헤딩 · 표 LLM 판정 · 조정)을 이 TASK 의 단계로 적는다.

### 2. 상태 — 어디서 세나(새 상태를 만들지 않는다)

- 1단계: 에이전트의 상태(`agwFitStatus` — `dv`): `values` · `plan` · `apply` 는 전과 같고, `read` = 이 문서에서 읽어 봤으면(`agw().readTried`) 「끝남」 + 읽은 값 한 줄 · 확정했으면 상태 없이 · 그 밖은 「할 수 있음」,
  `load` = 상태 없음(안 해도 됨 — 불러온 곳 `dv.preset.from` 이 있으면 그 글).
- 2 · 3단계: **분석 상태**(`dsState.main` — `GET /api/docs/{id}/analysis`, 이름 줄 · 진행표와 같은 값)의 항목 `heads` · `templates` · `formats` · `tables` 와 그 `llm`:
  `heads`·`tables` = 항목 `state`(done · running · wait · failed · 없음) · `headsLlm` = `heads.llm.state` · `tablesLlm` = `tables.llm.state` ·
  `adjust` = 서식 항목: 헤딩 판정(LLM) 전이면 「남음」(「헤딩 LLM 판정 뒤에 합니다」) · 판정 뒤 **반영할 것이 남지 않았으면 끝남**(받은 계획의 바꿀 줄 · 자리 맞춤 · 확실한 종속 · 받을 계획이 없음 — 「모두 반영」 이 할 것이 없음:
  등록부의 「끝난 것으로 보는 때」). 에이전트가 「그대로」 로 둔 줄 · 답이 없던 줄 · 대표가 없는 레벨이 남았으면 끝남이어도 그 수와 보정할 곳(「템플릿 관계」)을 글로 보인다(§7 ⓐ — 남긴 것을 숨기지 않는다).
  계산은 한 곳 — `doc_agent_work.js` `agwStdSteps`(에이전트와 대시보드가 같이 쓴다).
  도는 중은 헤딩 작업(`heads.view.job`) · 전체 실행(`headsAllRunning`) · 단계별 실행(`headsPickRunning`) · LLM 검증·보완(`dsRunning`)으로 본다.
- 셈: 안 해도 되는 단계(`read` · `load` · `review` · `tree` · `tableTools`)는 끝난 수에 넣지 않는다(대시보드의 규칙 그대로).

### 3. 실행 — 기존 함수만(spec_작업에이전트 ② §7 ⓒ)

| 단계 | 단추 | 부르는 것 |
|---|---|---|
| `read` | 구성 읽기 | 에이전트 행동 `config_read`(`divRead`) |
| `load` | 고르기 목록 + 「불러오기」 | `divSourceFill` · `divSourceLoad`(「작업 내용」 의 그 줄과 같은 목록 · 함수 — 입력 칸만 바뀜) |
| `values` | 프로젝트 구성 입력 · 확정… | 에이전트 질문 카드의 폼 `agwConfigForm` → `config_set` |
| `review` | LLM 검토 실행 · 검토 결과 보기 | `dashReview`(→ `divReview`) · `divReviewList` |
| `plan` | 변경 계획 보기 · 목록 | `plan` · `open:plan` |
| `apply` | 문서에 반영 | `divApply`(제 확인 창) |
| `heads` | 헤딩 추출(스크립트) — 결과가 없거나 실패했을 때 | `headsPickRun(["s1","s2"])`(무료 — 확인 없음) |
| `headsLlm` | LLM 판정 | `headsPickRun(["l2"])`(제 확인 창 — 규칙 보강을 먼저 한다) |
| `adjust` | 모두 반영 · 계획 보기 | `tpbApply({plans})`(**묻지 않는다** — 2026-11-18 사용자 「모두 반영할때... 팝업 알림 확인 받지마」 [spec_hwpx_웹편집.md](spec_hwpx_웹편집.md) ② §8-4 · 받아 둔 계획의 표시를 실어 그 사이 바뀐 계획은 서버가 막음) · `tplPlanGo()` |
| `tree` | 템플릿 관계 열기 | `tplRelOpen()` |
| `tables` | 표 구조(스크립트) — 없거나 실패 | `headsPickRun(["s3"])` |
| `tablesLlm` | 표 판정(LLM) | `headsPickRun(["l3"])`(제 확인 창) |
| `tableTools` | 테이블 탭 열기 | `showTab(dsTo("Tables"))` |

- 묶음의 「한 번에 진행」: 1단계 = `divRunAll()`(계획 → 반영 · 제 확인 창 · 멈추는 검사 `divAutoStops`) · 2단계 = `headsRunAll()`(전체 실행 — LLM 판정 → 조정 · 제 확인 창) · 3단계 = `headsPickRun(남은 표 단계)`(제 확인 창).
- 같은 문서에 두 실행을 겹치지 않는다(`agwRunning` 이 있으면 단추는 「지금 진행 중인 작업이 끝난 뒤에」).

### 4. TASK 전체 — 「이어서 한 번에 1→3단계」

- 대시보드 머리 아래(이관의 「이어서 한 번에」 와 같은 자리 · 같은 꼴). 남은 묶음이 둘 이상일 때 보이고, 이름은 남은 첫 묶음 → 끝 묶음(「이어서 한 번에 2→3단계」).
- 누르면 **확인 창 한 번**(돌 묶음마다 무엇을 하나 · 유료 LLM · 문서가 바뀜 · 묶음마다 실행 취소) → 차례로 `divRunAll({asked: true})` → `headsRunAll({asked: true})` → (표 판정이 남았으면) `headsPickRun(["l3"], {asked: true})`.
  `asked` = 부른 쪽이 이미 확인받았다 — 그 함수의 확인 창만 건너뛰고 멈추는 검사 · LLM 연결 확인은 그대로다(2026-11-18 이 사양으로 세 함수에 더함).
- 앞 묶음이 끝나지 않으면(멈춤 · 실패 · 계획 오류 · 미해결 — 1단계가 「적용」 까지 안 감) 뒤 묶음을 시작하지 않고, 머리 아래 끝 글에 한 것 · 멈춘 까닭 · 남은 것을 적는다(§7 ⓐ — 실패로도 「끝남」 으로도 뭉개지 않는다).
- 1단계 값이 확정되지 않았으면 단추는 꺼져 있고 까닭(「프로젝트 구성 값을 먼저 확정하세요」)을 보인다 — 값을 지어내지 않는다.

### 5. 에이전트(작업 진행 — `agwFitStatus` · `agwExec`)

- `plan_fit` 의 상태(steps)에 2 · 3단계 단계(`heads` · `headsLlm` · `adjust` · `tables` · `tablesLlm` — 위 §2 의 셈)를 더한다. `report_fit` 은 전과 같다.
- 행동(1단계가 「적용」 까지 끝난 뒤에 — 그 전에는 1단계 행동만): `heads_llm`(헤딩 LLM 판정 · 서식 계획 — 유료 · 저장만 → `headsPickRun(["l2"], {asked: true})`) ·
  `heads_apply`(조정 모두 반영 — 문서 바뀜 → `tpbApply()` · key = 서식 항목의 계획 표시) · `tables_llm`(표 판정 — 유료 · 저장만 → `headsPickRun(["l3"], {asked: true})`). 실행 카드의 「진행」 이 그 확인이다.
  `primary` = 남은 것 가운데 첫째(헤딩 판정 → 조정 → 표 판정).
- 양식이 프로젝트 구성 자동 반영을 지원하지 않으면 1단계는 적용할 수 없으므로 2 · 3단계 행동을 그대로 낸다(「이어서 한 번에」 도 1단계를 빼고 센다) — 헤딩 · 표는 구성에 기대지 않는다.
- LLM 이 꺼져 있으면(`AGENT.enabled` 거짓) 유료 행동(`heads_llm` · `tables_llm`)은 내지 않고 「지금 차례는 「헤딩 LLM 판정 …」」 으로 알린다(스크립트 답).
- 상태 · 행동의 셈은 `agwStdSteps` · `agwStdStatus`(에이전트 턴마다 분석 상태를 다시 읽음 — `agwStatus({fresh: true})`). 1단계의 `read` · `load` 는 대시보드에만 있다(에이전트는 `config_read` · `config_set` 행동으로 같은 일을 한다).
