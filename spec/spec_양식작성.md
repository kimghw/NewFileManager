## ② 확정 사양

### 0. 용어 · 범위

- **양식 작성** = 워크플로우(키 `form_write` · 작업 종류 일반 문서 `general`). 목적 문서 = 채울 **양식**(hwp · hwpx — 양식 제한 없음) 하나.
- **자료 문서** = 내용이 나오는 문서(hwp · hwpx · docx · pdf) — 문서 라이브러리가 보관한다(8114 의 작업이 아니다 · 바뀌지 않는다). **자료** = 그 문서에서 뽑은 MD(이 문서의 에이전트 자료로 가져온 것) · 파일 · 붙여 넣은 글.
- **문서 라이브러리** = 자료 문서를 보관하고 자료 추출을 하는 따로 선 서버(와 그 화면)의 이름. **자료 추출** = 문서에서 **뽑을 범위**(특정 기관 · 특정 연구)의 내용만 MD 로 만드는 일.
- **작성 지침** = 그 자리(헤딩 · 표)에 무엇을 어떻게 쓰는지 — 양식이 적어 둔 것(작성 요령 · ※ 안내 · 각주 항목) + 사람이 적은 것. 고르기는 `place_guides` 하나([spec_병합.md](spec_병합.md) ② §5-11).
- 하지 않는 것(v1): 제안을 사람 확인 없이 문서에 넣기 · docx 양식 채우기 · 그림 · 수식을 양식에 넣기(자료의 캡션만 글로) · 스캔 PDF 의 OCR · 서버가 도는 「한 번에 진행」(④).

### 1. 워크플로우 「양식 작성」

- 묶음 셋 — **준비**(양식 올리기) → **자료 준비**(자료 문서 올리기 → 자료 추출(MD) → 자료 가져오기) → **지침 작성**(작성 지침 확인 · 적기 → 제안 받기 → 스크립트 검사 → 고른 제안 반영). 차례는 등록부 `app/workflow.py` 의 `form_write`.
- 전제 = [jobs/form_write.md](../jobs/form_write.md): 자료에 있는 내용만 넣는다 · 자료에 없으면 넣지 않고 그렇게 답한다 · 지침의 예시는 내용이 아니다 · 넣을 것은 먼저 제안으로.
- 문서를 바꾸는 것은 **에이전트 보기의 제안 카드에서 「문서에 반영」 을 누른 것뿐**이다(문서 일반 편집과 같은 길 — [spec_일반편집.md](spec_일반편집.md) ② §9). 자료 추출 · 자료 가져오기 · 제안 받기는 문서를 바꾸지 않는다.
- 유료 LLM 은 사람이 누를 때만: 문서 라이브러리의 「추출 시작」(확인 창) · 「지침 작성」 열의 「제안 받기」(확인 창 — 자리 수).

### 2. 문서 라이브러리 서버 — `doclib/`

- **따로 선 프로세스**: `python -m uvicorn doclib.server:app --host 127.0.0.1 --port 8121`(띄우개 `tools/start_doclib.ps1` — 구독 로그인의 Claude CLI · 키를 넣지 않는다). 포트 대장에 8121 로 등록. 8114 가 꺼져 있어도 돈다.
- **의존**: `doclib/` 는 `app.server` · `app.*_api` · `app.works` · `app.llm` 을 가져오지 않는다. `app/` 에서 빌려 쓰는 것은 한글 · Word 의 PDF 출력 `app.pdf_render`(순수 모듈) 하나다. 8114 쪽은 이 서버의 파일 · 함수를 가져오지 않고 HTTP 로만 읽는다(§4).
- **저장소** = `%LOCALAPPDATA%\NewFileManager\doclib`(env `NFM_DOCLIB`): `docs/<문서 id>/{meta.json, source.<ext>, source.pdf, extracts/<추출 id>/{meta.json, doc.md, images/*.png, chunks/<n>.json}}` · `prompts/<이름>.md`(사람이 고친 스킬 글).
  문서 id = 「d」 + sha256 앞 12자(같은 파일은 같은 문서) · 받는 형식 hwp · hwpx · docx · pdf · 80 MB 까지. 문서마다 사람이 적는 것 = 기관 · 연구 · 메모(뽑을 범위의 처음 값이 된다).
- **끝점**(`doclib/server.py` 머리말이 원본): 문서 목록 · 올리기 · 고치기 · 지우기 · 올린 파일 · 읽을 PDF / 추출 시작 · 상태 · 멈춤 · 지우기 · MD · 그림 · zip / 스킬 글 읽기 · 고치기 / 관리 화면 `GET /`.
  127.0.0.1 만 듣는다. 다른 출처의 페이지가 보내는 바꾸는 요청(Origin 이 이 서버가 아님)은 403.
- **화면**(`doclib/static/` — 8114 의 스크립트 · 스타일을 읽지 않는다): 왼쪽 문서 목록(올리기 · 끌어 놓기) · 오른쪽 고른 문서(기관 · 연구 · 메모 / 자료 추출: 뽑을 범위 · 쪽 범위 · 「추출 시작」 / 추출 결과: 상태 · 진행 · 그림 · 수식 · 확인 필요 수 · 「MD 보기」 · 「내려받기(zip)」 / MD 글과 그림 모음).
  상단 바의 「스킬 글」 = 추출 · 그림 확인 · 수식의 판단 기준을 보고 고친다(기본본 `doclib/prompts/*.md` · 고치면 저장소에 내 사본 · 「기본본으로」). 주소의 `#d=<문서>&x=<추출>` 로 그 문서 · 그 추출을 연다.
- 서버를 다시 켜면 돌던 추출은 「끊김」 이 되고 저절로 잇지 않는다.

### 3. 자료 추출(MD) — `doclib/extract.py` · `pdfkit.py` · `agent.py`

- **읽을 PDF**: pdf 는 올린 것, hwp · hwpx · docx 는 한글 · Word 로 찍는다(`app.pdf_render` — 없으면 「PDF 로 저장해 올려 주세요」).
- **쪽 묶음**: 20쪽까지 한 묶음(`pdfkit.SIZE` — LLM 의 Read 도구가 PDF 를 한 번에 읽는 한도). 쪽 범위를 주면 그 범위만. 묶음은 같이 돈다(자리 수 env `NFM_DOCLIB_SLOTS` 기본 10 — 2026-11-24 사용자 「20페이지씩 · 병렬 10개씩」: 전에는 3).
- **스크립트가 하는 것**(LLM 을 부르기 전 — `pdfkit`):
  - 그림 후보 = PDF 의 그림 상자 + 선 · 면으로 그린 그림(벡터 묶음 — 곧은 선뿐이고 글 줄이 든 묶음은 표라 뺀다 · 그림 여럿을 품은 큰 묶음은 틀이라 뺀다). **쪼개져서 붙은 그림**은 맞닿은 조각을 합친다:
    작은 조각(변 40pt 미만) · 선 그림끼리는 모서리가 3pt 안으로 맞닿으면 합치고, 큰 그림 둘이 맞닿았으면 **이음매의 화소가 이어질 때만** 한 그림으로 본다(양쪽이 종이 흰색이면 따로 선 그림 — 옅은 바탕색은 그림으로 본다).
    그림과 선 그림은 겹칠 때만 합친다(맞닿기만 한 선 묶음이 따로 선 그림 둘을 잇는 다리가 되지 않게). 여러 쪽에 되풀이되는 꾸밈 그림(로고)과 쪽을 덮는 바탕은 후보가 아니다.
  - **모서리 확인**(`settle`): 자를 상자의 네 변을 **가로지르는 잉크**(변 안쪽 줄과 바깥 줄의 같은 자리가 둘 다 잉크이고 빛깔이 닮음)가 있으면 없어질 때까지 그 변을 민다(한 변 60pt 까지). 한도까지 밀어도 남으면 `open`(사람이 볼 것).
    변 밖에 따로 선 글 · 옆 그림 · 표의 괘선은 가로지르지 않으므로 밀지 않는다.
  - 수식 후보 = 따로 선 수식 줄(수식 글꼴 · 기호 밀도 · 수식 번호로 판정 — 위 「앞선 구현 참조」 · 그림 후보 · 표 안의 것은 뺀다) + 납작한 작은 그림(수식 그림).
  - 그림 · 수식의 key 는 문서 전체에서 겹치지 않는다: 후보 「p<쪽>_F<n>」 · 「p<쪽>_E<n>」 · LLM 이 상자로 가리킨 그림 「p<쪽>_N<n>」 · 수식 「p<쪽>_Q<n>」 — 그대로 `images/` 의 파일 이름이 된다.
  - 후보마다 PNG 로 잘라 그 묶음의 임시 폴더에 둔다(LLM 이 Read 로 열어 본다).
- **앞선 구현 참조**(2026-11-24 — `E:\dev\SSCB_guidelines\makemd` 의 `pdf_assets.py` · `prompts.py` · `pipeline.py`): 아래는 그 구현의 규칙을 옮긴 것이다 —
  문서 훑기 `pdfkit.survey`(추출을 시작할 때 한 번: 머리말 · 꼬리말 = 위 · 아래 8% 띠에 세 쪽 이상 · 쪽의 30% 이상 되풀이되는 글(숫자는 같게 본다) · 꾸밈 그림 = 세 쪽 이상 · 쪽의 절반 이상에 되풀이되는 같은 그림 · 헤딩 참고 = PDF 책갈피, 없으면 글꼴 크기 단계와 힌트 · 글 층이 없는 쪽) ·
  표 영역(`find_tables`)의 괘선은 그림이 아니다 · 선 · 면 묶음의 영역을 경로 좌표로 다시 셈 · 곧은 선 · 네모뿐인 묶음은 조각 여덟 이상 + 글이 덮은 몫 12% 아래일 때만 그림 · 둘레 40pt 안의 캡션 줄을 후보의 `caption` 힌트로 ·
  수식 줄 = 수식 글꼴의 몫 **+ 기호 밀도 · 수식 번호**(글꼴만 보면 놓친다)로 판정하고 분자 · 분모 · 첨자 조각과 오른쪽의 수식 번호를 묶음 · 문단 한가운데 끼인 줄은 글 속 수식 · 납작한 작은 그림 = 수식 그림 후보 ·
  추출 호출의 실패는 한 번 더 · 시간 초과는 묶음을 반으로 나눠 다시 · 수식 목록 `equations.md`(캡처와 LaTeX 를 나란히) · 스킬 글의 옮겨 쓰기 규칙(줄 잇기 · 여러 단 · 합친 칸은 HTML 표 · 각주 · 같은 번호 깊이는 같은 제목 깊이).
  **이 서버에만 있는 것**(그 구현과 다르게 둔 것): 뽑을 범위로 거르기 · 구조화된 답(JSON — 그림 · 수식을 key 나 상자로) · 큰 그림 둘이 맞닿았을 때 이음매의 화소를 보는 것(그 구현은 맞닿으면 합친다 — 나란히 놓인 따로 선 그림이 한 그림이 된다) ·
  모서리 확인(`settle`)과 LLM 의 그림 확인 호출 · 수식을 **따로 캡처한 그림으로** LaTeX 로 바꾸는 호출(그 구현은 추출 호출이 쪽을 보고 바로 쓴다 — 사용자 "수식은 별도로 캡쳐해서 ltex로 변환") · 묶음을 같이 돌림(그 구현의 기본은 차례로 — 앞 묶음의 끝 글을 다음에 준다: 여기는 헤딩 참고만 준다).
- **추출 호출**(묶음마다 한 번 — Claude CLI 헤드리스 · 모델 `claude-opus-5-5`(env `NFM_DOCLIB_MODEL`) · **도구는 Read 하나** · 구조화 출력 · 설정 안 읽음 · 임시 폴더):
  자료 = 문서 이름 · 뽑을 범위 · 쪽 · 그림 후보 · 수식 후보(key · 쪽 · 상자 · PNG 파일 · 캡션 힌트) · 머리말 · 꼬리말(옮기지 않을 글) · 글 층이 없는 쪽 · 헤딩 참고(책갈피 | 글꼴 크기 단계 + 힌트). 답 = `{relevant, markdown, figures[{key, caption, page, box, join}], formulas[{key, page, box, near}], skipped, note}`.
  그림 자리 `{{fig:KEY}}` · 따로 선 수식 자리 `{{eq:KEY}}`. 그림 = 후보 key 그대로 · `join`(조각 여럿을 한 그림으로) · 후보가 잘렸거나 없으면 쪽 + 상자(쪽 폭 · 높이를 1000 으로 본 값).
  판단 기준은 스킬 글 `extract.md`(범위에 해당하는 내용만 · 글을 그대로 · 표는 MD 표 · 쪽 표시 `<!-- p.N -->` · 그림 후보는 PNG 를 열어 모서리를 확인 · 따로 선 수식은 자리표시만).
- **그림 확인 호출**(LLM 의 상자로 자른 그림이 있을 때만 — 묶음마다 한 번 · Read): 잘라 낸 PNG 를 원본 쪽과 견줘 `ok` · `cut`(새 상자 → 다시 자름) · `drop`(그림 아님). 다시 자른 그림과 확인을 못 받은 그림은 MD 에 「확인 필요」 로 남긴다(세 번째 확인은 없다).
- **수식 호출**(수식 캡처를 6개씩 그림 입력으로 · 도구 없음): 캡처 → LaTeX(`{key, latex, ok, note}`). ok 면 `$$ … $$` + 캡처 파일을 가리키는 주석, 아니면 캡처 그림을 그대로 넣고 「확인 필요」.
- **조립**: `equations.md`(수식 목록 — 캡처와 LaTeX 를 나란히: zip 에 `<이름>.equations.md`) · `doc.md`(머리 = 범위 · 쪽 · 때 · 모델 · 그림 · 수식 · 확인 필요 수 / 본문 / 「추출하며 뺀 것」 / 「추출 메모」) + `images/`. 묶음마다의 프롬프트 · 답 · 호출 기록은 `chunks/<n>.json`.
- **스크립트가 판정하지 못한 것**(LLM 이 함께 본다): 후보에 없는 그림 · 수식 글꼴이 아닌 수식(그림으로 든 식) · 조각인지 따로 선 그림인지 · 그 내용이 범위에 드는지.
- 복구: 추출 호출이 실패하면 한 번 더 부르고(꺼짐 · 멈춤 제외), 시간 초과면 그 묶음을 반으로 나눠 다시 한다(한 쪽짜리는 나누지 않는다).
- 실패: 한 묶음(반쪽)의 실패는 그 자리에 「추출하지 못함」 주석으로 남기고 나머지는 계속 · 모든 묶음이 실패면 추출 실패 · 사람이 「멈춤」 을 누르면 도는 CLI 를 끊는다.

### 4. 8114 쪽 연결 — `app/doclib_client.py` · `app/guide_write_api.py`

- 주소 = env `NFM_DOCLIB_URL` | `http://127.0.0.1:<NFM_DOCLIB_PORT | 8121>`. **읽기만** 한다(건강 · 문서 목록 · 추출 기록 · MD) — 추출을 시작 · 지우는 것은 그 서버의 화면에서.
- `GET /api/doclib` → 문서 · 끝난 추출 목록(그 서버가 꺼져 있으면 `alive: false` + 까닭 — 8114 는 그대로 돈다).
- `POST /api/docs/{id}/agent/material/library {extract}` → 그 추출의 MD 를 이 문서의 **자료**로(에이전트 보기의 자료와 같은 저장소 · 같은 한도 — 같은 글이면 있는 것). 자료의 메모에 추출 id 와 그림 · 수식 · 확인 필요 수를 적는다.
- 그림 파일은 가져오지 않는다(자료는 글이다 — 그림은 문서 라이브러리에서 보고 내려받는다).

### 5. 지침 작성 — `app/guide_write.py` · `app/guide_write_api.py`

- **새 LLM 호출 · 새 반영 길을 만들지 않는다**: 자리마다 **문서 에이전트의 한 턴**(작업 번호 16 `doc_agent` — [spec_일반편집.md](spec_일반편집.md) ② §8)을 돌리고, 제안은 에이전트 보기의 턴 · 제안 카드로 남아 그 카드의 「문서에 반영」 으로만 들어간다.
  그래서 검사(보낸 id 만 대상 · 수 검사 · 엑셀 검증 · 지은 글은 처음부터 안 고름 · 낡은 제안 409)와 정책(원본 문서는 반영 금지)은 문서 에이전트의 것 그대로다.
- **자리**(`guide_write.places`) = 본문 헤딩 줄 전부(헤딩 추출 2단계의 그래프) + 지침이 붙은 표. 자리마다 작성 지침(`place_guides_api.index_of` — 양식의 것 · 사람의 것) · 이미 글이 있나 · 그 헤딩 아래의 표.
- **요청 글**(`guide_write.request`) = 그 자리(헤딩 글 · id) + 그 자리의 작성 지침(사람의 것이 앞 · 2,400자까지) + 이번 작성의 지침(사람이 실행할 때 적는 글 · 1,000자까지) + 무엇을 답할지
  (자료에서 그 자리의 내용을 찾아 헤딩 아래 글로 · 옮길 수 있으면 옮긴 글 · 지침이 정리를 요구하면 자료의 내용만으로 지은 글 · 표는 자료에 값이 있을 때만 표 채우기 · 자료에 없으면 행동 없이 그렇게 답).
  턴의 selection = 헤딩 자리는 그 줄에 커서 · 표 자리는 그 표.
- **실행**(`POST …/guide-write/run {places, materials, note}`): 배경 스레드에서 자리마다 한 턴(같이 2개 · 한 번에 40곳까지) — 자료를 하나 이상 골라야 하고 LLM 을 쓸 수 있어야 한다. 한 자리의 실패가 다른 자리를 멈추지 않는다.
  상태 = 자리마다 기다림 · 받는 중 · 제안 n · 자료에 없음 · 실패. 「멈춤」 = 남은 자리를 돌리지 않는다(도는 턴은 끝까지). 끝나면 작업 기록 `guideWrite` 한 줄. 실행 상태는 메모리에만(끝난 턴은 에이전트 대화에 남는다).
- 스크립트가 판정하지 못한 것 = 그 자리에 무엇을 써야 하는지(지침과 자료를 읽어야 안다) — 문서 에이전트가 판정한다.

- 견본 문서의 벡터 구성도 하나는 스크립트 후보가 아래 일부를 놓친다(선 묶음이 둘로 갈림) — LLM 이 PNG 를 보고 상자를 다시 줘 바로잡는다(① 의 실측).
- 「자료 가져오기」 · 「지침 작성」 열을 다른 워크플로우(문서 일반 편집 · 이관의 빈 자리)에서 여는 입구 · 첫 화면 카드 여덟 장의 한 줄 배치(지금은 일곱 열이라 여덟째가 넘어간다 — design.md §12).
- 지침 작성의 실행 상태는 서버 메모리에만 있다(다시 켜면 「마지막 실행」 이 사라진다 — 턴은 남는다).
