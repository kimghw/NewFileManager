# 사양서 — 그림 도구 (그림 → 표 · 캡션 넣기 · 선명하게 · 가운데 · 한 줄에)

문서의 그림(그림 블록)을 골라 하는 일. 그림을 누르면 그림 위에 「그림 도구」 띠가 서고, 오른쪽 단추 메뉴에도 같은 항목이 있다.
LLM 이 그림을 읽는 일(표로 바꾸기 · 캡션 짓기)은 옆 열에서 미리 보고 사람이 「넣기」 를 눌러야 문서가 바뀐다. 화면 꼴은 [design.md](../design.md) §25.

## ① 질의·요청 히스토리

- 2026-11-23 사용자(웹 문서에서 표를 캡처한 그림 — 그림 안에 「1.4 Data Channel ID 의 예시」 · 설명 한 줄 · 표 둘이 든 것을 보이며)
  **"추가하고 싶은 기능이 현재 그림이 테이블로 되어 있는데 이걸 .. 진테 테이블로 변경하고 싶거든그림에 있는 글자는 캡션으로 넣어주면 될거 같고 ... 이건 그림 선택했을때. 옵션으로 선택할 수 있게 하고, ,  LLM 으로 처리하면될거 같아. 그리고, 이미지 선명도 개선 기능도 넣어줘,"**
  → ② §2 「그림 → 표」 · §4 「선명하게」 · §1 「고르기 · 띠」.
- 같은 날(이어서) **"이미지 캡션이 없으면 캡션넣고도.. 이 그림이 속해 있는 헤딩을 읽고 참조해서 캡션을 넣는거야. 이미지도 같이 일겅서,"** → ② §3 「캡션 넣기」(그림 + 소속 헤딩 + 앞뒤 글을 LLM 이 읽음).
- 같은 날(이어서) **"가운데 정렬 기능이나 이미지2개를 선택해서 한 줄에 넣기 기능도 추가."** → ② §5 「가운데」 · §6 「한 줄에 나란히」.
- 겹침 협의(착수 전 알림 → 답): 7c(design.md — 끝남 · §17 「카드 머리」 줄 그대로) · d1(겹침 없음 · 전체 시험 도는 중) · 79(workflow.py 다른 자리 · caption_tpl 은 고치는 중 — 이 도구는 읽기만) · 65(겹침 없음).

## ② 확정 사양

### 0. 말 · 대상

- **그림 도구** = 그림 블록(웹 블록 `type: image` — hwpx `hp:pic`) 하나 또는 둘에 하는 일 다섯: **표로 바꾸기**(LLM) · **캡션 넣기**(LLM) · **선명하게**(스크립트) · **가운데**(스크립트) · **한 줄에**(스크립트 — 두 그림).
- 대상 밖: 글 속 그림(글머리 아이콘 — 블록의 `inlineOf`) · 묶음 개체 안의 그림 · docx 문서(④). LLM · 선명하게는 **래스터 그림**(png · jpg · gif · bmp · webp)만 — wmf · emf 같은 벡터 그림은 가운데 · 한 줄에만.
- LLM 의 답은 미리보기일 뿐이다 — 문서는 사람이 옆 열에서 「넣기」 를 누를 때만 바뀐다(실행 취소 한 번). 가운데 · 한 줄에 · 선명하게의 「바꾸기」 는 누르면 바로 바뀐다(실행 취소 한 번).

### 1. 고르기 · 띠 · 메뉴

- 그림을 누르면 그 그림을 **고른다**(파란 테두리) · Ctrl/Shift+누름 = 둘째 그림을 더한다(둘까지 — 셋째를 누르면 첫째가 빠진다) · Esc · 문서의 다른 곳 누름 = 풀기.
- 고른 그림 바로 위에 **떠 있는 띠**(모달 아님 — 문서를 가리지 않게 그림의 위 가장자리에 붙음): 하나면 「표로 바꾸기 · 캡션 넣기 · 선명하게 · 가운데」, 둘이면 「한 줄에 · 가운데」. 쓸 수 없는 항목은 흐리게 + 까닭(풍선).
- 오른쪽 단추 메뉴: 그림 위에서 누르면 같은 항목(그림이 안 골라져 있었으면 그 그림을 고른 뒤).
- 「캡션 넣기」 는 캡션이 없는 그림에서만 선다(개체 캡션도 · 바로 아래 글 캡션도 없음 — 있으면 「캡션 있음」 으로 흐림). 캡션을 다시 짓는 것은 ④.

### 2. 그림 → 표 (LLM — 에이전트 「그림 → 표」 `pic_table`)

- **입력**(`pic_tools.table_prompt`): 그림(바이트 — 긴 변 2000px 넘으면 줄여 PNG 로) + 소속 헤딩 경로 + 앞뒤 글(앞 3 · 뒤 2 문단) + 그림의 지금 캡션(있으면) + 이 문서의 표 캡션 예(최대 8) + 표 양식(서식을 따올 표 — 표 만들기와 같은 `table_llm.template_data`).
- **답**: `tables`(격자 — 표 만들기의 격자 꼴: 행 › 칸 {text, rowSpan, colSpan} + headerRows · headerCols · footRows, 그림에 표가 여럿이면 위에서 아래로 여럿) · `caption`(줄 목록 — 그림 안에서 표 밖에 있는 글: 첫 줄 = 제목, 나머지 = 설명 줄) · `note`.
  계약: 그림에 보이는 글을 **그대로** 옮긴다(요약 · 번역 · 맞춤법 고침 · 보탬 금지) · 못 읽는 글자는 짐작하지 않고 note 에 적는다 · 표가 아닌 그림이면 `tables` 를 비우고 note 에 까닭.
  답의 격자는 `table_make.normalize` 로 검사해 못 쓰는 표는 빼고 note 에 적는다.
- **미리보기**(옆 열): 그림 · 표마다 격자 · 캡션 글(고칠 수 있음) · 표 양식 고르기(문서의 표 — 기본 = 그림 앞의 가장 가까운 여러 칸 표, 없으면 뒤의 것) · 넣는 방법 「그림을 표로 바꾸기」(기본) | 「그림은 두고 뒤에 넣기」.
- **넣기**(`POST …/pics/{pid}/table`): 그림의 문단 바로 뒤에 표들을 차례로(서식 = 표 양식 — 표 만들기의 hwpx 어댑터 `table_make`) · 캡션 글은 **첫 표의 개체 캡션(위)** 으로(§3 「캡션의 모양」) · 「바꾸기」 면 그림을 지운다(그림만 든 문단이면 문단째 — `delete_blocks`). 문서의 표가 하나도 없으면 표 양식을 못 골라 넣지 못한다(④).

### 3. 캡션 넣기 (LLM — 에이전트 「그림 캡션」 `pic_caption`)

- **입력**(`pic_tools.caption_prompt`): 그림 + **소속 헤딩 경로**(스크립트 — `headings.levels` 의 부모 사슬: 그림 바로 앞의 본문 헤딩부터 뿌리까지) + 앞뒤 글 + **이 문서의 그림 캡션 예**(최대 8 — 개체 캡션 · 그림 바로 아래의 글 캡션).
- **답**: `caption`(한 줄 — 이 문서의 그림 캡션 꼴대로: 예가 「< 제목 >」 이면 그 꼴) · `note`. 계약: 그림과 헤딩 · 앞뒤 글에 있는 것만으로 짓는다(없는 사실 · 수를 짓지 않는다) · 번호(「그림 3」)는 예에 번호가 있을 때만 붙이되 수는 정하지 않고 사람이 고친다(④).
- **미리보기**(옆 열): 그림 · 소속 헤딩 · 지은 캡션(고칠 수 있음) → 「넣기」.
- **넣기**(`POST …/pics/{pid}/caption`): 그림의 **개체 캡션(아래)** 으로 붙인다.
- **캡션의 모양**(§2 와 같음 — `HwpxDoc.pic_caption_set`): 이 문서의 같은 대상(표 | 그림) 개체 캡션 가운데 가장 많이 쓴 (문단 모양 · 글자 모양 · 캡션 속성)을 따른다 → 없으면 같은 대상의 글 캡션 문단의 모양 → 없으면 그 개체를 품은 문단의 모양. 캡션 템플릿 「CN」(spec_hwpx_웹편집 ② §8-10)의 대표에 맞추는 것은 그 화면의 「대표에 맞추기」 가 한다.

### 4. 선명하게 (스크립트 — Pillow · LLM 없음)

- 그림의 바이트를 **키우고(작을 때) · 또렷하게** 만든다(`pic_tools.enhance`): 표시 폭(mm)에서 목표 화소 = 폭 × dpi/25.4(「보통」 220dpi · 「강하게」 300dpi) — 지금 화소가 그보다 작으면 LANCZOS 로 키움(최대 4배 · 2천5백만 화소까지) → 언샤프 마스크(보통 반지름 1.2 · 110% / 강하게 2.0 · 170%) → 강하게는 자동 대비(양끝 0.5%) 도.
- 결과는 새 그림 파일(BinData)로 넣고 그 그림이 그것을 가리킨다(`HwpxDoc.pic_replace`) — **표시 크기(mm)는 그대로**, 원본 크기 · 자르기 · 배율 값은 새 화소로. 같은 그림 파일을 다른 그림이 같이 쓰면 그 그림은 그대로다(옛 파일은 지우지 않는다).
- 형식: jpg 는 jpg(품질 95) · 나머지는 png.
- 옆 열에서 바꾸기 전 · 뒤를 나란히 보이고(`GET …/pics/{pid}/sharpen.png?level=`) 「바꾸기」 로 넣는다.

### 5. 가운데

- 고른 그림(들)의 문단을 가운데 정렬한다(`format_para` 의 `align: center` — 글자처럼 취급 그림) · 떠 있는 그림은 가로 자리를 「단 가운데」 로(`hp:pos horzRelTo=COLUMN horzAlign=CENTER horzOffset=0`).
- 이미 가운데면 「이미 가운데」 로 알리고 문서를 안 바꾼다.

### 6. 한 줄에 나란히 (두 그림)

- 고른 두 그림(같은 그릇 — 둘 다 본문이거나 같은 칸)을 **문서 차례가 앞선 그림의 문단에 한 줄로** 놓는다(`HwpxDoc.pic_row`): 뒤 그림을 앞 그림 바로 뒤(같은 문단 · 같은 런 뒤)로 옮기고 둘 다 글자처럼 취급으로 · 두 폭 + 사이 3mm 가 글 폭보다 넓으면 **같은 비율로** 줄인다 · 그 문단은 가운데 정렬.
- 뒤 그림이 홀로 있던 문단(글 없음)은 지운다 — 글이 있던 문단이면 그림만 빼고 남긴다. 그림의 개체 캡션은 그림을 따라간다(한글은 그림마다 아래에 그린다) · 뒤 그림 아래에 따로 친 글 캡션 문단은 그 자리에 남는다(④).
- 다른 그릇이거나 그림이 아닌 것이 섞이면 400.

### 7. LLM 에 그림 보내기 — `llm.call(…, images=[…])`

- `llm.call` 에 `images`(목록 — {data: bytes, media: "image/png" | "image/jpeg" …})를 주면 프롬프트 글 앞에 그림을 싣는다. 길마다: sdk = 사용자 메시지 하나의 스트림(content = 그림 블록 + 글) · **cli = `--input-format stream-json --output-format stream-json --verbose`**(stdin 에 사용자 메시지 한 줄 · 끝의 `type: result` 줄의 `structured_output`) · api = content 목록.
  외부 지식: [references/Claude_CLI_헤드리스.md](../references/Claude_CLI_헤드리스.md) 「그림 입력」.
- 그림이 없는 호출은 전과 같은 길(바뀌지 않음).

### 8. 모듈 · 끝점

- `app/pic_tools.py`(순수 — 그림 줄이기 · 선명하게 · 소속 헤딩 · 앞뒤 글 · 캡션 예 · LLM 계약 둘) · `app/hwpx_pic.py`(HwpxDoc 믹스인 — `pic_replace` · `pic_caption_set` · `pic_center` · `pic_row` · `pic_info`) · `app/pic_tools_api.py`(끝점) · `app/static/pic_tools.js` · `pic_tools.css`.

  문서를 바꾸는 끝점은 모두 `server._edit`(실행 취소 · OWPML 지역 검사 · 바뀐 블록만 응답) 위에서 돈다.

## ④ 미결/후속

- docx 문서의 그림 도구(어댑터 없음 — 띠가 「hwpx 만」 으로 흐림).
- **웹은 개체 캡션을 위 · 아래 가리지 않고 늘 개체 뒤에 그린다**(기존 동작 — `hwpx_doc._para_blocks` 가 캡션 블록을 개체 뒤에 · `app.js renderList`). 그림 → 표가 붙인 표의 위 캡션(`side="TOP"`)은
  한글 · 저장본에서는 표 위에 서지만 웹 화면에서는 표 아래에 보인다 — 캡션의 `side` 를 블록에 싣고 화면이 위 캡션을 개체 앞에 그리게 하는 것은 따로(app.js 를 다른 세션이 고치는 중이라 이번에 안 함).
- 표 양식의 기본이 「가장 가까운 여러 칸 표」 라 작성요령(TEMP) 표가 뽑힐 수 있다(시험 견본에서 t996 = 작성 요령 표) — TEMP · 작성요령 표를 빼고 고르는 것.
- 캡션 다시 짓기(캡션이 있는 그림) · 그림 번호(「그림 3」)의 수를 문서 차례로 매기기.
- 「한 줄에」 뒤 그림 아래의 글 캡션 문단을 그 그림의 개체 캡션으로 옮기기.
- 문서에 표가 없을 때의 표 양식(서식 보관함의 표 서식을 쓰는 길).
- 선명하게의 초해상(모델 기반) — 지금은 Pillow 의 키우기 + 언샤프뿐(글자 캡처에는 충분하나 사진의 흐림은 못 되살림).
- 에이전트 판단(사용자 확인 전): 「그림 도구」 를 떠 있는 띠 + 오른쪽 단추로 둔 것 · 둘째 그림을 Ctrl/Shift 로 더하는 것 · LLM 두 기능을 옆 열의 미리보기 → 「넣기」 로 둔 것 · 그림 → 표의 캡션을 첫 표의 위 개체 캡션으로 둔 것 ·
  표 양식의 기본(가장 가까운 여러 칸 표) · 선명하게의 dpi · 언샤프 값 · 「한 줄에」 의 사이 3mm 와 가운데 정렬 · 캡션의 모양을 문서에서 가장 많이 쓴 캡션에서 따오는 것.
