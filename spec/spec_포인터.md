# 포인터 — 같은 문서를 보는 다른 화면에 내 마우스 자리와 「클릭」

## ① 질의 · 요청 히스토리

- 2026-11-23 사용자: "포인터 기능을 추가 하고 싶은데... 지금은 같은 계정으로 로그인되어 있는경우 한 사람이 포인터로 움직이면 다른 사람도 볼 수 있게 해줘, 포인터 상태에서 클릭 하면 클릭이라고  표시되게 해줘,"
  → ② 전부. 사용자가 말한 것은 이 한 문장이다 — **「같은 계정」 을 지금 접속한 모든 화면으로 읽은 것**(앱에 계정이 없고 바깥 주소의 로그인 계정이 하나다 — [spec_배포.md](spec_배포.md) ② §1)과
  켜고 끄는 단추 · 이름 · 색 · 자리를 보내는 법 · 서버의 꼴은 **에이전트 판단이다(사용자 확인 전)** — 아래에서 그렇게 표시한다.

## ② 확정 사양

### 0. 말

- **포인터** = 내 마우스가 문서 위에서 가리키는 자리를 다른 화면에 보이는 것. **「포인터 상태」** = 상단 바 「포인터」 단추를 켠 상태(사용자의 말 — 켠 사람의 마우스가 보인다).
- **같이 보는 화면** = 같은 문서를 연 다른 브라우저 창 · 탭(다른 사람의 것이든 내 다른 창이든 — 앱은 사람을 가리지 못한다: 계정이 없다).
- **「클릭」** = 포인터를 켠 채로 문서를 눌렀다는 표시(퍼지는 원 + 글 「클릭」).
- **자리** = 화면 좌표가 아니라 문서 안의 자리(어느 블록 · 표 칸 · 표 · 쪽 안의 어느 비율 — §2).

### 1. 켜고 끄기 · 보내는 쪽 (에이전트 판단 — 사용자 확인 전)

- **단추**: 문서 화면 상단 바의 「포인터」(「공유」 · 「저장」 앞 · 문서를 열었을 때만 · 글 없이 아이콘). 눌림 = 켬. 이 브라우저에 기억한다(`nfm.pointer` — **기본 끔**).
  문서를 연 541~880px 폭에서는 꺼져 있을 때 단추를 감춘다(상단 바가 넘친다 — 켜져 있으면 끌 수 있게 보인다 · 남의 포인터는 단추가 없어도 보인다).
- **켜면** 문서 창(스크롤 상자) 위에서 움직이는 내 마우스의 자리를 서버로 보낸다 — 초당 16번 안(60ms 에 한 번 · 같은 자리는 다시 안 보낸다). 스크롤만 해도 마우스 아래의 자리가 달라지면 보낸다.
- **끄거나 · 마우스가 문서 창 밖으로 나가거나 · 다른 창으로 가면** 다른 화면에서 내 포인터가 사라진다(「감춤」 을 한 번 보낸다). 쪽과 쪽 사이(쪽 상자 밖)를 지나는 동안은 마지막 자리 그대로 둔다(깜빡이지 않게).
- **클릭**: 켠 채로 문서(쪽 안)를 왼쪽 단추로 누르면 그 자리의 「클릭」 을 보낸다. **누른 것은 원래대로 작동한다** — 포인터 상태는 편집 · 단추 · 고르기를 막지 않는다(화면 코드가 듣기만 한다).
  내 화면에도 같은 표시를 짧게(0.7초) 보인다(눌렀다는 확인).
- **이름 · 색**: 앱에 계정이 없어 브라우저마다 이름을 지닌다 — 단추를 **오른쪽 단추로 누르면**(자판: 메뉴 키 · Shift+F10) 떠 있는 작은 창(모달 아님 — ✕ · Esc · 바깥 누름)에서 「내 이름」(16자 안)을 정한다. 이 브라우저에 기억(`nfm.pointerName`).
  이름을 안 정했으면 서버가 그 방에서 안 쓰는 가장 작은 수로 **「사용자 N」** 을 준다. 색은 서버가 방 안에서 안 겹치게 여덟 색 가운데서 준다(지난번 받은 색 `nfm.pointerColor` 를 먼저 바란다 — 아홉째 화면부터는 겹친다).
  그 창은 「같이 보는 화면」(이름 · 색)과 「포인터 켜기/끄기」 도 보인다.
- 문서를 닫거나 다른 문서를 열면 연결을 끊고 새 문서의 방으로 간다. 연결이 끊기면 3초 뒤 다시 잇는다(한 번도 못 붙었으면 두 배씩 — 30초까지 · 방이 찼으면 1분 뒤).

### 2. 보는 쪽 · 「클릭」 표시 (에이전트 판단 — 사용자 확인 전)

- **같은 문서를 연 화면은 단추를 켜지 않아도 다른 화면의 포인터를 본다**(색 화살표 + 이름표). 내 포인터는 내 화면에 그리지 않는다.
- **자리는 문서 안의 자리로 오간다**(창 크기 · 확대 · 스크롤이 화면마다 다르다): 보내는 쪽 = 마우스 아래의 **가장 안쪽** 블록(`#doc` 안의 `[data-id]` — 문단 · `td[data-cell]` 표 칸 · `table.tbl[data-tbl]` 표:
  「누른 자리 따라 보기」 `peer_follow.js` 가 쓰는 표식과 같다) 안의 비율(x/너비 · y/높이)과, 쪽에 걸쳐 나뉜 블록이면 몇째 조각인지. 블록이 없는 곳(쪽의 여백)이면 그 쪽(`#doc > .sheet` 의 몇째) 안의 비율.
  받는 쪽 = 같은 요소(같은 id · 같은 조각)를 찾아 그 비율 자리에 그린다. **못 찾으면 그리지 않는다**(짐작한 자리에 그리지 않는다).
- 그 자리가 문서 창의 위 · 아래로 벗어나 있으면 문서 창의 그 가장자리에 이름표만 보인다(「↑ 이름」 · 「↓ 이름」). 옆으로 벗어나면 안 보인다.
- 문서를 스크롤하거나 창 크기가 바뀌면 그 자리에 다시 그린다(미끄러지지 않고 바로). 글을 고쳐 줄이 밀린 것은 0.5초마다 다시 맞춘다.
- **「클릭」**: 남이 누른 자리에 퍼지는 원 + 글 「클릭」 이 1.3초 보이고 사라진다(그 사람의 색). 누른 자리가 문서 창 밖이면 표시하지 않는다(포인터의 가장자리 이름표만).
- 표시는 누를 수 없는 층에 그린다 — 문서의 누르기 · 고르기를 가리지 않는다. 화면 낭독에는 읽히지 않는다(눈으로 보는 표시).
- 늦게 들어온 화면도 그때 보이던 포인터를 바로 본다(서버가 첫 답에 지금 자리를 싣는다).

### 3. 서버 — 방 · 메시지 (에이전트 판단 — 사용자 확인 전)

- 끝점 하나: **WebSocket `/api/docs/{문서 id}/pointer`**(8114 — `app/pointer_api.py`). 화면은 `location` 에서 `wss:`(https) · `ws:` 를 골라 같은 호스트로 붙는다.
- **방 = 문서 id 하나**. 지금은 접속한 화면이 모두 같은 계정이라 계정으로 나누지 않는다(④). 방은 서버 메모리에만 있다 — **저장하지 않는다**(서버를 다시 켜면 화면이 다시 붙는다).
- 서버는 받은 것을 같은 방의 다른 연결에 나눠 줄 뿐이다 — **문서를 읽지 않고 · 잠그지 않고 · 바꾸지 않는다**(편집 차례 `_bump` 를 지나지 않는다 · 작업 기록에 남지 않는다). 문서 id 가 실제 작업인지도 보지 않는다(방에 문서의 글이 없다).
- 메시지(JSON 글):

  | 방향 | `t` | 내용 |
  |---|---|---|
  | 화면 → 서버 | `hello` | 첫 메시지(10초 안) — `name`(빈 글 = 기본 이름) · `color`(바라는 색) |
  | 화면 → 서버 | `move` · `click` | 자리 `k`(p 블록 · c 표 칸 · t 표 · s 쪽) · `a`(그 id — 쪽이면 0부터의 차례) · `n`(몇째 조각) · `x` · `y`(0~1) |
  | 화면 → 서버 | `off` | 내 포인터를 걷는다 |
  | 화면 → 서버 | `name` | 이름 바꾸기 |
  | 서버 → 화면 | `hi` | 첫 답 — 나의 `id` · `name` · `color` + `peers`(지금 있는 화면들 — 보이는 포인터의 자리 `at` 까지) |
  | 서버 → 화면 | `join` · `leave` | 다른 화면이 들어옴(`id` · `name` · `color`) · 나감(`id`) |
  | 서버 → 화면 | `move` · `click` · `off` | 다른 화면의 것(`id` + 자리) — 보낸 화면에는 돌아가지 않는다 |
  | 서버 → 화면 | `name` | 이름이 바뀜(`id` · `name`) — 바꾼 화면에도 간다(서버가 다듬은 이름) |
  | 서버 → 화면 | `full` | 방이 찼다 — 곧 닫는다 |

- 느린 연결이 다른 연결을 붙잡지 않는다: 연결마다 보낼 줄(64개)을 따로 두고, 차면 가장 오래된 것을 버린다(움직임은 새것이 옛것을 대신한다).

### 4. 안전

- **같은 출처만**: 손잡이의 `Origin` 이 있으면 요청의 `Host` 와 같은 호스트 · 포트일 때만 받는다(아니면 403 으로 끝난다). 브라우저는 다른 사이트가 연 WebSocket 에도 기본 인증을 붙일 수 있고,
  Caddy 의 「다른 출처의 변경 요청 403」 규칙([deploy/Caddyfile](../deploy/Caddyfile))은 GET 인 업그레이드를 막지 않는다 — 그래서 앱이 본다. `Origin` 이 없는 연결(브라우저가 아닌 것)은 받는다(8114 는 이 PC 안에서만 닿는다).
- 메시지 하나 1,024자까지(넘으면 그 연결을 닫는다) · 글이 아닌 것(바이트)도 닫는다 · 연결마다 초당 40개까지(넘는 것은 버린다) · 방마다 연결 16개까지(넘으면 `full`) · 이름 16자 · 블록 id 80자 · 문서 id 는 영문 · 숫자 · `_` · `-` 64자 안.
- **받은 JSON 은 정해진 키만 골라 다시 지어 보낸다** — 받은 것을 그대로 중계하지 않는다(모르는 키 · 모르는 `t` · 꼴이 다른 값은 버린다 · 비율은 0~1 로 자른다 · 보낸 화면의 `id` 는 서버가 붙인다).
  화면은 받은 이름을 글로만 넣고(HTML 로 안 넣는다) 색은 `#rrggbb` 꼴일 때만 쓴다.
- 오가는 것은 자리(블록 id · 비율)와 이름 · 색뿐이다 — 문서의 글은 방을 지나지 않는다.

### 5. 구성 — 다른 코드와의 접점

| 파일 | 일 | 기대는 것 |
|---|---|---|
| `app/pointer_api.py` | WebSocket 끝점 · 방 · 받은 것 다듬기 | 표준 라이브러리 · FastAPI — **`app.server` 를 포함해 앱의 다른 코드를 import 하지 않는다**(`tests/test_pointer.py` 가 본다) |
| `app/static/pointer.js` · `pointer.css` | 단추 · 내 포인터 보내기 · 남의 포인터 · 「클릭」 그리기 · 작은 창 | `app.js` 의 이름 — **목록의 원본은 `pointer.js` 머리의 주석**(`state.id` · `$` · `el` · `toast` · `PEEK` · 문서의 꼴 `#scroller` · `#doc > .sheet` · `data-id` · `data-cell` · `data-tbl`) · `share.js` 의 `#shareBtn`(있으면 그 앞에 단추) |

- `app/server.py` 의 접점은 `app.include_router(pointer_api.router)` 한 줄 · `index.html` 은 `pointer.css` · `pointer.js` 두 줄(`app.js` · `peer_follow.js` · `share.js` 다음).
- `app.js` 에 끼어들지 않는다 — 문서가 바뀐 것은 0.5초마다 `state.id` 를 보고 안다(`share.js` 와 같은 방식).
- **문서의 꼴(위 표식 · 쪽 상자)을 바꾸면 `pointer.js` 의 자리 찾기(`ptrAt` · `ptrHost`)도 본다.**
- 둘째 면 화면(`PEEK` — 같은 `index.html` 을 iframe 으로 띄운 것)에서는 단추를 세우지 않고 연결도 하지 않는다(④).
- 워크플로우 등록부(`app/workflow.py` `COMMON` 의 `pointer`)에 도구로 적는다 — `/workflow` 에 보인다.

## ④ 미결 · 후속

- **계정별 방**: 앱 로그인이 생기면 방 열쇠에 계정을 더한다(지금은 같은 문서를 연 모든 화면이 한 방 — 「같은 계정」 을 그렇게 읽었다: 사용자 확인 전).
- **바깥 주소에서의 확인**: `https://files.rndsscb.com`(Caddy 기본 인증 뒤)에서 브라우저가 WebSocket 손잡이에 인증을 붙여 연결되는지는 **확인하지 못했다**(브라우저마다 다를 수 있다). 안 붙으면 401 로 끊기고 화면은 30초 간격까지 늘려 가며 다시 잇는다 —
  그때는 Caddy 에서 그 경로의 인증을 달리 하거나(쿠키 · 토큰) 앱 로그인이 필요하다. 확인한 사실은 references 에 적는다.
- **공유의 손님**: 손님 포트(8119 — [spec_공유.md](spec_공유.md))의 손님 화면에는 포인터가 없다(8114 의 끝점을 손님에게 내주지 않는다 — 넣으려면 손님 앱에 그 일만 하는 끝점을 따로).
- **둘째 면**: 둘째 면(iframe) 위의 마우스는 보내지 않고, 둘째 면에 뜬 문서에는 남의 포인터를 그리지 않는다.
- **쪽 나눔이 다른 화면**: 쪽에 걸쳐 나뉜 블록의 조각 수 · 쪽 차례가 화면마다 다르면(글꼴 · PDF 매핑 전후) 그 블록 · 쪽 여백의 포인터가 안 보이거나 다른 조각에 보일 수 있다(문단 대부분은 조각이 하나라 그대로 맞는다).
- **좁은 폭**: 문서를 연 541~880px 에서는 꺼진 단추를 감춘다 — 그 폭에서는 새로 켤 수 없다(보는 것은 된다). 상단 바에 자리를 낼지 · 다른 곳(도구 줄)에 둘지.
- **색 고르기**: 색은 서버가 준다 — 사람이 고르는 칸은 없다. **이름표의 겹침**: 문서 창 오른쪽 끝의 이름표는 옆 열 위로 조금 나갈 수 있다.
- **화면 검사**: 두 화면을 띄워 포인터 · 「클릭」 을 보는 화면 검사(`tools/smoke_*_ui.py`)가 아직 없다.
- 터치 화면(떠 있는 마우스가 없다)은 따로 다루지 않았고 확인하지도 않았다.
