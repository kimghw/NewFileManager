# `<input list>` + `<datalist>` — 지금 적힌 값으로 걸러 보인다

- 확인: 2026-11-13, 사용자 화면(Chromium 계열 브라우저) 그림 둘. 프로젝트 이름이 여섯 개 든 `datalist` 에 「데이터」 를 적자 「데이터」·「데이터플랫폼」 둘만 떴고, 「KIMGHW」 가 적혀 있을 때는 다른 프로젝트가 안 보였다.
- 브라우저 기본 목록은 **입력 칸에 지금 적힌 글자와 맞는 선택지만** 띄운다. 값이 미리 채워진 칸(지금 프로젝트 이름 등)에서는 ▼ 를 눌러도 다른 선택지가 안 나온다 — 칸을 지워야 전체가 보인다.
  「있는 것 가운데 고르기」 가 목적이면 사용자는 목록이 비었다고 읽는다.
- 걸러 내는 방식(앞부분 일치 · 가운데 일치)과 목록의 모양·위치는 브라우저마다 다르고 CSS·스크립트로 바꿀 수 없다. 선택지에 표지(상태·개수)를 붙일 수도 없다(`label` 표시는 브라우저마다 다름).
- 목록은 DOM 밖(브라우저 UI)에 그려져 Playwright 로 보이는 항목을 검사할 수 없다 — `datalist option` 을 세는 검사는 「목록에 들어 있다」 만 확인하고 「사용자에게 보인다」 는 확인하지 못한다.
- 그래서: 값이 미리 채워지는 칸 · 전체를 보여야 하는 칸 · 선택지에 표지가 필요한 칸은 자체 목록(`role=combobox` + `listbox`)으로 만든다. 빈 칸에서 시작하는 자유 입력 + 제안 정도면 `datalist` 로 충분하다.

프로젝트 적용(프로젝트 고르기 목록)과 검사 상태는 [작업 사양서](../spec/spec_작업.md) ② §19 에 기록한다.
