# 두 번 누르기(dblclick)와 배치 밀림 (Chrome)

첫 `click` 을 처리하는 동안 화면 배치가 바뀌면 두 번 누르기가 엉뚱한 요소에 떨어진다. 2026-11-10 Playwright Chromium(헤드리스)에서 겪음 —
엑셀식 보기 격자 위의 「참조」 줄이 칸을 고를 때마다 한 줄 ↔ 두 줄로 접혔다.

- 브라우저는 두 번 누르기를 `mousedown · mouseup · click`(1) → `mousedown · mouseup · click`(2) → `dblclick` 순으로 보낸다. 각 사건의 대상은 **그 순간 그 좌표에 있는 요소**다.
- 첫 `click` 핸들러가 위쪽 요소의 높이를 바꾸면(글이 접히는 줄·나타났다 사라지는 안내 줄) 아래 내용이 밀려, 같은 좌표의 둘째 `click`·`dblclick` 은 **이웃 요소**가 받는다.
  증상: 「칸을 두 번 눌러 고치기」 가 바로 위·아래 칸을 고친다(값이 옆 칸에 들어가거나 옆 칸의 수식이 지워진다). 마우스로도 똑같이 난다 — 자동화 도구만의 문제가 아니다.
- 막는 법: 누를 때마다 내용이 바뀌는 줄은 **높이를 고정**한다(`height` 고정 + `white-space: nowrap` + `overflow-x: auto`, 넘치면 가로로 굴림). `min-height` 만으로는 줄이 접힐 때 밀린다.
  줄이 꼭 늘어나야 하면 눌리는 영역 **아래**에 둔다(아래가 늘어나면 위 좌표는 안 변한다).
- 확인: 내용이 가장 많을 때와 없을 때 눌리는 영역의 `getBoundingClientRect().top` 이 같은지 잰다(`tools/smoke_table_refs_ui.py` 「참조 줄 높이 고정」).
- 가로 스크롤 줄에 스크롤 막대를 감추면(`scrollbar-width: none` · `::-webkit-scrollbar { display: none }`) 휠로는 안 굴러간다 — `wheel` 사건에서 `scrollLeft += deltaY` 를 직접 하고
  `preventDefault()`(리스너는 `{ passive: false }` 로 달아야 한다).
