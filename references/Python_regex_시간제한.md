# Python `regex` 패키지 — LLM 이 만든 정규식을 시간 제한으로 돌리기

사용처: `app/heading_rules.py`(헤딩 추출 배운 규칙, spec_헤딩_추출 ② §2). 판: `regex==2026.9.29`.

- 표준 `re` 에는 시간 제한이 없다. `regex` 는 `pattern.match(s, timeout=초)` 를 받아 넘으면 `TimeoutError` — 규칙 하나를 건너뛰고 경고로 남기는 데 쓴다.
- `regex` 는 고전적인 파국 꼴 일부를 스스로 빨리 끝낸다: `(a+)+$` 를 `'a'*30 + 'b'` 에 대면 ~0 ms 에 「안 맞음」(2026-11-09 실측) — 시간 제한 시험에 쓰면 안 걸린다.
  `(a|aa)+$` 는 여전히 지수적이라 제한에 걸린다(시험용).
- 역참조(`\1`)·조회 길이 같은 막이는 패턴 글을 보고 따로 한다(`regex` 에도 정적 검사는 없음).
- 이름·키 검사에 `^…$` + `match` 를 쓰면 **끝에 줄바꿈이 붙은 글도 통과**한다 — `$` 는 글 끝의 줄바꿈 바로 앞에서도 맞는다(`re`·`regex` 같음: `re.match(r"^[a-z]+$", "abc\n")` 은 맞음).
  파일 이름·식별자처럼 글 전체가 꼴에 맞아야 하는 검사는 `fullmatch`(또는 `\Z`)로 한다(2026-11-10 — `app/heading_forms.py` 양식 키 검사, spec_헤딩_추출 ② §12).
- **`timeout` 은 벽시계라 GC 멈춤도 센다**(2026-11-10 실측): CPython 의 세대 2 GC 는 힙이 크면 수십~백 ms 멈춘다(객체 28만 개 = 85 ms, 딕셔너리 40만 개 = 110 ms). 그 멈춤이 `match(…, timeout=0.05)` 호출 안에 떨어지면
  패턴 `.` · 글 3자도 `TimeoutError` 가 난다(걸린 시간 101 ms — `concurrent=True` 든 아니든 같다). 재현: 딕셔너리 40만 개를 쥔 채 `regex.compile(".").match("기관명", timeout=0.05)` 를 6초 돌리면 2~3번.
  GC 가 어느 호출에 떨어지는지는 그때까지의 할당 수로 정해지므로 같은 입력에서는 **늘 같은 자리**에서 난다 — 코드 한 줄(모듈 import 하나)이 늘어도 자리가 옮겨 가, 무관한 변경 뒤에 「시간 초과」 시험이 갑자기 늘 실패하는 꼴로 보인다
  (`tests/test_headings.py::test_propose_rules_fake_llm` — 큰 문서 1단계 결과를 쥔 채 13,000 문단에 시험 규칙을 댐). 막이: `TimeoutError` 면 **그 자리에서 한 번 더** 부른다 — GC 는 방금 돌았으니 다시 안 걸리고,
  정말 느린 식은 다시 넘는다(`heading_rules._Run.match`). `gc.disable()`·`gc.freeze()` 로 막는 길은 호출마다 켜고 끄는 값이 더 든다.
