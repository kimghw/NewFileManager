# Python difflib.SequenceMatcher — 같은 줄이 많으면 제곱 시간

대상: 표준 라이브러리 `difflib.SequenceMatcher` 로 문서의 줄(문단·표) 차례를 맞출 때의 시간과 `autojunk`. (프로젝트에서 쓰는 곳 = 취합의 기준본 ↔ 기관 문서 맞춤 — [spec/spec_취합.md](../spec/spec_취합.md) ② §4-1.)

## 알아낸 것 (2026-11-12 — 취합 엔진을 만들며 잰 값, Python 3 · 이 PC)

- `SequenceMatcher` 는 두 번째 열(b)의 원소마다 나오는 자리 목록을 만들어 두고, 첫 열(a)의 원소마다 그 목록을 훑는다. **같은 글의 줄이 많으면**(양식의 빈 줄 · 「o」 만 있는 자리표시 줄 · 같은 뼈대의 소제목) 훑는 양이 줄 수의 곱에 가까워진다.
  - 2000 × 2000 줄에 같은 줄이 많은 입력: 약 3.8 초, 가장 나쁜 꼴은 약 28 초.
  - 줄이 대부분 서로 다르면 거의 줄 수에 비례한다(47 MB 실제 계획서 2,785 블록 · 25,008 칸: 맞춤 전체 0.62 초 — 아래 줄이기를 한 뒤의 값).
- `autojunk=True`(기본값)는 b 가 200 원소 이상일 때 **1% 넘게 나오는 원소를 통째로 무시**한다 — 빨라지지만 되풀이되는 양식 줄이 전부 「없는 것」 이 되어 맞춤이 달라진다. 양식 문서 맞춤에는 `autojunk=False` 로 두고 입력을 줄이는 쪽이 안전하다.
- `get_matching_blocks()`·`get_opcodes()` 는 같은 계산을 쓴다(한 번 계산해 둔 것을 다시 씀 — 객체 하나에서 둘 다 불러도 두 번 계산하지 않는다).

## 쓰는 법

- 먼저 **하나뿐인 줄(닻)**로 구간을 나눈다(patience diff 방식) — 긴 열 하나를 맞추지 않고 닻 사이의 짧은 구간들만 맞춘다.
- 구간 안에서도 **앞·뒤의 같은 줄을 먼저 떼고**(자리대로 견줌 — 선형) 가운데만 `SequenceMatcher` 에 넘긴다.
- 가운데가 그래도 크면(줄 수의 곱이 상한을 넘으면 — 취합은 400,000) 맞추지 않고 「자리를 정하지 못함」 으로 둔다. 느리게 틀린 맞춤을 내는 것보다 낫다.
- 같은 글의 줄이 이어진 구간의 맞춤은 **하나로 정해지지 않는다**(`[해당 없음 ×3]` ↔ `[검토 완료, 해당 없음]`) — 결과가 나와도 그 자리를 믿으면 안 된다(경계가 그 구간에 하나뿐인 줄인지 따로 확인).
