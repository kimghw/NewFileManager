# Windows — 「임시 파일 → 바꿔 넣기」(os.replace) 가 거절되는 경우

원자적 쓰기(임시 파일에 쓰고 `os.replace(tmp, path)`)를 여러 스레드·프로세스가 같은 파일에 쓸 때의 Windows 동작. 2026-11-10 이 PC(Windows 11, Python 3.12, NTFS E:)에서 잼.

## 사실

- **대상 파일을 다른 손잡이가 열어 두고 있으면 `os.replace` 가 거절된다** — `PermissionError(13)`, `winerror 5`(Access is denied).
  읽으려고 연 것(`open(path, "rb")`)만으로도 그렇다. 닫으면 바로 된다.
  (알려진 까닭: Python `open()` 은 `FILE_SHARE_DELETE` 없이 연다 — 지우기·바꿔 넣기는 그 공유 권한이 있어야 한다. POSIX 는 열린 파일 위로도 rename 이 된다.)
- **바꿔 넣는 순간에는 읽기도 거절된다** — 읽는 쪽이 `PermissionError` 를 받는다(파일이 없는 것이 아님).
- 빈도: 한 스레드가 `read_text` 를 쉬지 않고 돌리고 다른 스레드가 `os.replace` 를 3,000번 → 바꿔 넣기 2,856번 거절, 읽기 824번 중 262번 거절.
  (쉬지 않고 맞붙인 최악의 경우 — 실제 서버에서는 드물지만 0 은 아니다. 백신·색인기가 막 쓴 파일을 잠깐 여는 것도 같은 결과를 낸다.)
- 임시 파일 이름에 pid·스레드 id 를 넣어도 소용없다 — 막히는 것은 임시 파일이 아니라 **대상 파일**.

## 대응

- 쓰는 쪽: `PermissionError` 면 짧게 쉬고 몇 번 다시(20 ms·40 ms … 6번, 모두 0.3 s 안). 끝까지 안 되면 임시 파일을 지우고 예외를 올린다.
- 읽는 쪽: `PermissionError` 는 「없음」으로 치지 말고 몇 번 다시(10 ms …). `FileNotFoundError`·깨진 JSON 과 구분한다 — 구분하지 않으면
  「작업이 없습니다(404)」·목록에서 잠깐 사라짐 같은 가짜 결과가 난다.
- 같은 프로세스 안의 쓰기끼리는 잠금으로 줄 세우되, 잠금 없이 읽는 길이 하나라도 있으면 위 두 가지가 필요하다.
- 적용: `app/works.py` `_write`·`_read_json`.
