# 사업계획서 → 연차보고서 이관 — `plan_to_report`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(워크플로우 상세 문서 — 화면 `/workflow` 의 이 워크플로우 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [워크플로우 전체 지도](../workflow.md) 가 모든 워크플로우의 차례를 보인다면 이 글은 이 워크플로우 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

사업계획서에서 필요한 내용을 뽑아 연차보고서로 옮깁니다.

- 받는 문서: 사업계획서(내용이 든 연구개발계획서, 원본 문서) + 연차보고서 양식(빈 파일, 목적 문서)
- 산출물: 계획서의 내용이 들어간 연차보고서 초안
- 문서마다 단위문서 TASK — 원본 문서(사업계획서): 1단계 문서 검토(「헤딩 · 표 분석」 › 「LLM 검증·보완」) / 목적 문서(연차보고서): 1단계 문서 검토(「헤딩 · 표 분석」) › 2단계 구성 맞추기(「프로젝트 구성 반영」 › 「다시 문서 검토」 › 「다시 문서 검토(LLM)」) › 3단계 내용 넣기(← 원본 문서: 「자리 연결」 › 「자리 연결 LLM 검토」 › 「표 안 연결 · 넣기 계획」 › 「빈 자리 검토(LLM)」 › 「표 대응(LLM)」 › 「내용 반영」 › 「합계 계산 → 결과 확인」) › 4단계 문서 정리(「작성요령 삭제」)
- 워크플로우 전체(문서마다가 아니라 한 번): 1단계 문서 검토(「준비」) › 2단계 구성 맞추기(「구성 불러오기」 › 「프로젝트 구성 추출」) — 구성의 기준: 원본 문서(사업계획서)
- 알아 둘 것: 프로젝트 구성과 내용의 기준은 모두 사업계획서입니다. 결과물은 연차보고서 초안입니다. 모든 자리를 채우는 것이 목표가 아니므로, 같은 자리인지 불분명하면 비워 둡니다. 빈 자리는 이후 각 기관이 이어서 작성합니다. 사업계획서(원본)는 바뀌지 않습니다.
- 한 번에 진행: 에이전트가 단계 묶음마다 「한 번에 진행」 을 제안하고 실행 카드에서 확인받습니다. 1단계 문서 검토에서는 두 문서의 헤딩 · 표 분석과 사업계획서의 LLM 검증·보완(유료)을 합니다. 사업계획서는 헤딩 줄의 레터와 서식만 맞추고 내용은 그대로입니다. 2단계 구성 맞추기에서는 프로젝트 구성 추출, 구조 반영, 연차보고서의 다시 문서 검토(재분석과 LLM 검증·보완)를 합니다. 3단계 내용 넣기에서는 자리 연결과 내용 넣기(유료 LLM)를 하고, 4단계 문서 정리에서는 양식 안내를 지웁니다. LLM 을 쓸 수 없으면 LLM 단계는 건너뛰고 스크립트 분석만으로 진행합니다. 패널 「작업 개요」 의 「이어서 한 번에」 를 누르면 확인 창 없이 남은 묶음을 바로 이어서 실행합니다. 끝나면 바뀐 문서의 고친 문단을 한 번 확정하며, 이전 상태는 「고친 문단」 탭의 확정 기록에서 복원할 수 있습니다.
- 에이전트가 묻는 것: 사업계획서와 연차보고서가 둘 다 있어야 시작합니다. 프로젝트 이름은 비우면 임시 이름으로 두 문서를 묶습니다. 사업계획서에서 프로젝트 구성을 읽지 못하면 직접 입력받습니다.
- 멈추거나 남기는 곳 · 보정: 2단계에서는 계획 오류나 미해결 자리가 있거나 기관 순서가 다르면 구조를 반영하지 않고 멈춥니다. 3단계에서는 같은 자리인지 불분명하면 연결하지 않고 비워 둡니다. 이는 실패가 아니라 초안 작성 방식이며, 연결 목록의 「확인 필요」 와 넣기 계획에서 보정할 수 있습니다. 4단계는 3단계가 끝난 문서에서만 실행하며, 안내를 지우기 전에 작성 지침을 헤딩과 표별로 저장합니다.
- 단계별(세부 작업): 패널 「작업 개요」 의 단계 묶음마다 세부 목록을 씁니다. 「분석」 이나 「다시 분석」 으로 분석만 먼저 하거나, 「건너뛰기」 로 LLM 검증·보완을 넘길 때, 파일이나 저장된 곳에서 「구성 불러오기」 를 할 때 씁니다. 자리 연결을 직접 고치거나 LLM 검토, 표 대응, 넣기 계획을 따로 확인할 때도 사용합니다. 프로젝트 구성 추출과 구조 반영은 원본의 LLM 검증·보완이 도는 동안에도 함께 진행할 수 있습니다.
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/plan_to_report.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 도구 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### 워크플로우를 시작할 때

시작 화면의 워크플로우 카드, 문서 목록, 대화창에서 문서를 올리기 전에 확인합니다. 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 워크플로우가 받는 형식(hwp · hwpx)인지 확인합니다.
  - 안 맞으면: 시작하지 않고 알립니다. docx 파일은 「워크플로우 없이 열기」로 열거나 「문서 서식 복사」 워크플로우에서 시작합니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 선택했는지 확인합니다. 파일이 하나면 그 파일을 목적 문서로 씁니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다. 시스템이 임의로 정하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **사업계획서 · 프로젝트 이름** — 스크립트. 목적 문서는 연차보고서입니다. 문서 목록의 나머지 문서가 사업계획서 하나까지인지, hwp · hwpx 인지 봅니다. 두 문서는 같은 프로젝트로 묶습니다 — 프로젝트 이름을 비우면 임시 이름(임시 프로젝트 N)으로.
  - 안 맞으면: 나머지가 둘 이상이면 남길 둘만 두라고 알리고 시작하지 않습니다. 목적 문서가 프로젝트에 묶이지 않으면(작업 저장이 꺼짐 등) 사업계획서는 목록에 남기고 알립니다.
  → 사양: spec_작업.md ② §15-1·§17

### 문서를 올릴 때

문서를 올리면 자동으로 실행됩니다. 사람이 누를 필요가 없으며 유료 LLM을 쓰지 않습니다.

- **작업 만들기 · 같은 파일 고르기** — 스크립트. 올린 파일마다 작업 공간을 만들고, hwp 파일은 한글로 hwpx로 변환합니다. 같은 파일의 기존 작업이 있으면 열기 전에 선택 창을 띄웁니다. 같은 워크플로우 작업, 미지정 작업 순으로 「이어서」와 「초기화하고 열기」를 보이고, 아래에 프로젝트 칸과 「새 작업으로 시작」을 둡니다.
  - 안 맞으면: 다른 워크플로우, 프로젝트, 역할의 작업은 「그대로 열기」만 됩니다. 고르면 그 작업의 설정을 바꾸지 않고 열며, 현재 워크플로우 시작은 멈춥니다. 창을 닫으면 열지 않고, 올리지 못하면 원인을 알리고 시작하지 않습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§3-1·§15
- **양식 판정 · 문서 종류** — 스크립트. 문서 목록으로 시작하면 목적 문서를 연차보고서로 적습니다. 카드에 파일 하나만 올리면 양식 판정이 정한 종류(사업계획서 · 연차보고서)로 적습니다.
  - 안 맞으면: 양식 판정이 종류를 못 정하면 비워 둡니다 — 패널 「작업 개요」 의 첨부 파일 칸에서 고릅니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **워크플로우 · 프로젝트 · 라운드** — 스크립트. 작업에 현재 워크플로우를 지정합니다. 프로젝트 이름을 적었으면 해당 프로젝트의 다음 라운드로 시작합니다. 비우면 임시 이름(임시 프로젝트 N)으로 함께 올린 문서를 묶습니다.
  - 안 맞으면: 임시 이름은 문서를 연 뒤 「작업 개요」의 프로젝트 칸이나 작업 리스트의 「이름 정하기」에서 바꿀 수 있습니다. 이미 있는 프로젝트 이름을 적으면 문서가 모두 그 프로젝트로 옮겨집니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **사업계획서 올리기** — 스크립트. 함께 시작한 사업계획서는 늘 새 작업으로 올려 같은 프로젝트 · 워크플로우 · 라운드의 사업계획서로 적고(첨부 파일 칸이 저절로 잇습니다) 기본 분석을 겁니다 — 화면에 열지 않습니다.
  - 안 맞으면: 못 올리면 알립니다 — 패널 「작업 개요」 의 사업계획서 칸에서 다시 올립니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §9·§11
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 화면에서 제대로 읽었는지 기본 분석과 함께 검사합니다. 한글이나 Word가 있으면 PDF로 변환해 비교하며, 결과는 패널 상단 「검증」에 표시됩니다. 주의나 실패가 나오면 「LLM 검토」가 자동으로 한 번 실행되어 실제 오류인지 PDF 변환 차이인지 구분합니다.
  - 안 맞으면: LLM을 쓸 수 없거나 호출에 실패하면 스크립트 판정 결과를 유지하고 「LLM 검토」 단계에 원인을 기록합니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 hwpx 문서의 헤딩 그래프와 표 구조를 스크립트로 한 번 분석합니다. 이미 결과가 있는 단계는 건너뛰며, 이어서 연 작업에서는 실행되지 않습니다.
  - 안 맞으면: 시작하지 못하면 문서 이름 줄에 「헤딩 없음 · 표 없음」이 표시되고, 도중 실패하면 해당 단계가 「실패」로 뜹니다. 이름 줄의 「분석」 단추로 다시 실행합니다.
  → 도구: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 분석 항목(헤딩, 템플릿, 서식, 표)과 LLM 검증·보완, 구분 기준 검토 상태가 표시됩니다. 어느 워크플로우나 같으며 누르면 진행표가 열립니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **편집 구역의 기준 적기** — 스크립트. 시작 화면 문서 목록의 「편집 구역」에서 기준(기관, 단계, 차년도)을 선택했으면, 워크플로우 설정 시 해당 묶음의 옵션으로 함께 저장합니다.
  - 안 맞으면: 따로 선택하지 않으면 기본값(취합은 기관 켜짐, 나머지는 꺼짐)으로 시작합니다. 문서를 연 뒤 「편집 구역」 줄에서 바꿀 수 있습니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1

### 워크플로우 화면을 열 때

패널 「작업 개요」와 에이전트 시작 안내가 현재 상태를 확인합니다. 부족한 항목이 사전 준비 대상입니다.

- **에이전트의 시작 턴** — 스크립트 → LLM. LLM을 쓸 수 있으면 상단 바의 에이전트 창(또는 패널 탭)이 열리며 시작 안내가 한 번 실행됩니다. 사전 준비, 현재 진행 상태, 다음 단계를 설명하고 다음 작업을 제안합니다. 같은 작업과 워크플로우에 이미 진행 기록이 있으면 다시 실행되지 않습니다.
  - 안 맞으면: LLM이 꺼져 있으면 패널 「작업 개요」가 열립니다. 이때도 에이전트 보기의 「작업 설명 듣기」로 스크립트 안내를 볼 수 있습니다.
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §1
- **두 문서가 있는가** — 스크립트. 같은 프로젝트 · 워크플로우 · 라운드에 사업계획서와 연차보고서가 둘 다 있는지 봅니다.
  - 안 맞으면: 모자라면 패널 「작업 개요」 의 첨부 파일 칸에서 고르거나 올리게 합니다 — 프로젝트 이름이 없으면 다른 문서를 고를 수 없습니다.
  → 사양: spec_작업.md ② §11·§17
- **지금 문서가 목적 문서인가** — 스크립트. 연 문서가 연차보고서(목적 문서)인지 사업계획서(원본)인지 봅니다.
  - 안 맞으면: 원본을 열었으면 실행 행동을 내지 않고 「연차보고서 열기」 를 카드로 묻습니다(원본은 바뀌지 않습니다).
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7
- **헤딩 · 표 분석** — 스크립트. 두 문서에 헤딩 그래프 · 표 구조가 있는지 봅니다 — 문서를 고친 뒤에도 있던 분석을 씁니다. 분석이 도는 중이면 5초마다 다시 읽습니다.
  - 안 맞으면: 없으면 1단계 「문서 검토」 가 지금 차례입니다(「한 번에 진행」 이 없는 문서만 스크립트로 분석).
  → 도구: 헤딩 추출 | 사양: spec_작업.md ② §21
- **LLM 을 쓸 수 있나 · 건너뛴 문서** — 스크립트. 서버의 LLM 을 쓸 수 있는지(한 번)와, 사람이 LLM 검증·보완을 건너뛴 문서인지(이 브라우저의 기억)를 봅니다.
  - 안 맞으면: LLM 을 쓸 수 없거나 건너뛴 문서면 그 문서의 LLM 단계(「LLM 검증·보완」 · 「다시 문서 검토(LLM)」)는 「건너뜀」 으로 끝난 것으로 봅니다 — 스크립트 분석만으로 진행합니다.
  → 도구: 헤딩 추출 | 사양: spec_작업.md ② §21
- **작성 지침 저장** — 스크립트. 연차보고서에 분석은 있는데 저장한 작성 지침이 없으면 한 번 모아 저장합니다 — 작성 요령 표 · 「<참고 N>」 자료 · ※ 안내를 어느 헤딩 · 어느 표의 것인지와 함께(스크립트 · 문서 안 바뀜).
  - 안 맞으면: 모으지 못하면 그대로 넘어갑니다 — 4단계 「작성요령 삭제」 가 지우기 바로 전에 다시 남깁니다.
  → 사양: spec_작업.md ② §21
- **프로젝트 구성 확정** — 스크립트. 사업계획서 기준의 프로젝트 구성을 프로젝트에 확정했는지 봅니다 — 저장된 값이 없으면 사업계획서에서 읽어 보입니다.
  - 안 맞으면: 확정 전이면 2단계 「구성 맞추기」 의 첫 단계가 지금 차례입니다 — 확정해야 프로젝트 구성 반영으로 갑니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §18
- **연차보고서의 구조** — 스크립트. 연차보고서의 값이 사업계획서와 같은지, 그 값이 연차보고서에 반영됐는지 봅니다(당해 차년도는 견주지 않고, 다르면 글로 보입니다).
  - 안 맞으면: 값이 다르면 「사업계획서 기준으로 맞추기」, 반영 전이면 「변경 계획 보기」 가 다음 차례입니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §11·§14
- **구조 반영 뒤의 분석** — 스크립트. 연차보고서의 헤딩 · 표 분석이 마지막 구조 반영 뒤의 것인지 봅니다 — 구조 반영 밖의 편집은 따지지 않습니다.
  - 안 맞으면: 구조 반영 전의 분석이면 2단계의 「다시 문서 검토」 가 남습니다(「한 번에 진행」 이 스크립트로 다시 분석 → LLM 검증·보완). LLM 판정을 거친 분석이어도 다시 분석합니다 — LLM 을 쓸 수 없을 때만 그대로 두었다고 알립니다.
  → 도구: 헤딩 추출 | 사양: spec_작업.md ② §21
- **이관 조건** — 스크립트. 3단계(내용 넣기)는 두 문서가 1 · 2단계를 마친 뒤에만 진행합니다 — 원본 문서(사업계획서): 헤딩 · 표 분석 › LLM 검증·보완 / 목적 문서(연차보고서): 헤딩 · 표 분석 › 구조 반영 › 다시 문서 검토 / 워크플로우 전체(문서마다가 아니라 한 번): 프로젝트 구성 추출 — 구성의 기준: 원본 문서(사업계획서). 1 · 2단계의 문서마다 하는 단계는 두 문서에서 같이 진행할 수 있습니다(원본의 LLM 검증·보완이 도는 동안 목적 문서의 구성을 맞춤).
  - 안 맞으면: 덜 끝난 조건이 있으면 3단계의 「한 번에 진행」 이 꺼지고 묶음 머리에 「N단계 … 완료 후 진행」 이 보입니다 — ② 자리 연결 줄은 서버가 본 까닭(분석 없음 · 값 없음 · 반영 전 · 값이 다름)을 문서별로 보입니다.
  → 사양: spec_작업.md ② §21
- **연결 목록** — 스크립트. 분석이 있으면 두 문서의 자리를 이은 연결 목록을 읽습니다(연결됨 · 확인 필요 · 후보 없음 · 같은 이름 자리) — 같은 서식 쌍에 저장해 둔 짝이 있으면 먼저 씁니다.
  - 안 맞으면: 서버가 목록을 낼 수 없으면 까닭을 그대로 보입니다(헤딩·표 분석 없음 · 프로젝트 구성 값 없음 · 반영 전 · 값이 사업계획서와 다름 · hwpx 가 아님).
  → 사양: spec_병합.md ② §0-1·§4
- **지난 반영 기록** — 스크립트. 이 연차보고서에 앞서 넣은 자리의 기록이 남아 있는지 봅니다.
  - 안 맞으면: 있으면 넣기 계획 · 내용 반영을 끝난 것으로 보고, 더 넣을 것은 「넣기 계획 다시」 가 셉니다.
  → 사양: spec_병합.md ② §6
- **지울 양식 안내** — 스크립트. 연차보고서에서 지우는 패턴(작성 요령 표 · 「<참고 N>」 자료 · 안내 색 ※ 글 · 1칸 상자의 색 글 안내 · 위첨자 각주 번호)에 걸린 자리를 셉니다.
  - 안 맞으면: 세지 못하면 까닭을 보이고 「다시 읽기」 를 냅니다.
  → 사양: spec_작업.md ② §14
- **편집 구역 — 보일 기준과 구역 읽기** — 스크립트. 이 묶음(프로젝트 · 워크플로우 · 라운드)의 편집 구역에서 보일 기준(기관, 단계, 차년도)을 확인합니다. 켠 기준이 있으면 문단과 표, 표 칸이 어디에 속하는지 스크립트로 읽어 색 띠와 이름표로 표시합니다.
  - 안 맞으면: 켠 기준이 없으면 구역을 읽지 않으며, 패널 「작업 개요」의 「편집 구역」 줄에서 켤 수 있습니다. 프로젝트 구성 값이 없으면 계산할 수 없다고 알립니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1·§6
- **지금 도는 실행** — 스크립트. 이 문서에서 「한 번에 진행」(간단 모드, 묶음, 실행 카드)이 실행 중인지 확인합니다.
  - 안 맞으면: 실행 중에는 에이전트가 새 실행이나 저장을 제안하지 않고 진행 카드만 표시합니다. 끝나면 이어서 안내합니다.
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7

### 저절로 돌지 않는 것

자동으로 실행되지 않고 사람이 단추를 눌러 실행하는 항목입니다. 유료 LLM을 씁니다.

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 문서를 올릴 때는 실행되지 않으며, 사람이 직접 실행합니다. 「헤딩 추출」과 「테이블」 탭의 「단계별 실행 ▾」에서 단계를 골라 「고른 n개 실행」하거나, 「추출·설정」 하위 탭의 단계 카드를 씁니다. 「헤딩 추출」 탭의 「전체 실행」(조정까지 실행), 「조정」 끝의 「LLM 판정」(판정 전 문서), 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」로도 실행합니다. 헤딩 판정 시 스크립트가 못 맞췄거나 충돌한 첫머리 묶음도 함께 봅니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **구분 기준 LLM 검토** — 사람 → LLM. 선택 기능입니다. 문서 이름 줄의 「구분 기준」 표시나 프로젝트 구성의 「LLM 검토」를 연 뒤, 「LLM 검토 실행」을 눌러 실행합니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §20
- **편집 구역 LLM 검토** — 사람 → LLM. 선택 기능이며 유료입니다. 「편집 구역」 줄의 「LLM 검토」를 눌러 실행합니다. 스크립트가 기관이나 차년도를 못 정한 자리를 LLM이 판별해 「LLM」 지정으로 표시합니다. 문서는 바뀌지 않습니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §8
- **이 워크플로우의 LLM 검토** — 사람 → LLM. 자리 연결 LLM 검토 · 표 대응 · 빈 자리 검토(유료): 단계의 단추나, 확인을 받은 3단계 「한 번에 진행」 안에서 돕니다. 문서를 올리거나 여는 것만으로는 실행되지 않습니다.
  → 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 자동/필수/선택/준비 중 · 하는 문서. 하는 일`(하는 문서 = 문서 여럿인 워크플로우의 단계만 — 원본 문서 · 목적 문서 · 두 문서 · 원본 → 목적 · 워크플로우 전체), 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 도구 | 코드(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 1단계 문서 검토 — 두 문서의 헤딩과 표를 스크립트로 분석하고 원본 문서를 LLM 으로 검증 · 보완함. 양식의 작성 지침을 헤딩과 표별로 저장. 원본 문서는 헤딩 줄의 레터와 서식만 맞춤(내용은 그대로)

조립한 단계: 문서 검토(`stage_review`)

- **준비** — 사람 · 문서 안 바뀜 · 필수 · 워크플로우 전체. 같은 프로젝트 · 워크플로우 · 라운드의 사업계획서와 연차보고서를 첨부 파일 칸에서 고르거나 새로 올립니다. LLM을 쓸 수 있으면 상단 바의 에이전트 창이 열려 사전 준비와 다음 단계를 안내합니다.
  - 하려면: 프로젝트 이름. 없으면 문서는 올릴 수 있지만 같은 프로젝트의 다른 문서는 못 고릅니다.
  - 끝난 것으로 보는 때: 사업계획서 칸과 연차보고서 칸이 모두 찼을 때.
  → 도구: 문서 올리기 · 첫 분석 · 에이전트 보기 | 사양: spec_작업.md ② §10·§17
- **헤딩 · 표 분석** — 스크립트 · 저장만 · 필수 · 두 문서. 사업계획서, 연차보고서에 헤딩 그래프와 표 구조가 있는지 확인합니다. 분석이 없는 문서만 스크립트로 기본 분석을 돌립니다(LLM 없이 올릴 때와 같은 분석). 끝나면 양식의 작성 지침(작성 요령 표, 「<참고 N>」 자료, ※ 안내, 각주 작성 요령)을 해당 헤딩과 표에 연결해 저장합니다.
  - 하려면: 사업계획서 · 연차보고서(hwpx).
  - 끝난 것으로 보는 때: 문서마다 헤딩 그래프와 표 구조가 있을 때. 문서를 고친 뒤에도 기존 분석을 그대로 씁니다.
  - 멈추는 때: 분석이 실패하면 까닭을 알리고 멈춥니다. 「헤딩 추출」 탭에서 확인할 수 있습니다.
  - 남기는 것 · 보정: 작성 지침은 작업에 저장돼 「문서 정리」 뒤에도 남습니다. 이 줄의 「작성 지침」 으로 헤딩별 · 표별 목록을 봅니다.
  → 문서마다의 헤딩 그래프 · 표 구조 · 헤딩/표별 작성 지침 | 도구: 헤딩 추출 | 코드: `heading_runs` · `form_guides` | 사양: spec_작업.md ② §21
- **LLM 검증·보완** — 사람 → LLM · 문서 바뀜 · 필수 · 원본 문서. LLM 이 사업계획서의 헤딩과 템플릿, 표, 서식 정리 계획을 차례로 검증하고 보완합니다. 유료이며 몇 분 걸립니다. 이어서 사업계획서에는 받은 서식 정리 계획(템플릿 조정과 서식 조정)을 반영합니다. 내용은 그대로 두고 헤딩 줄의 레터와 서식만 맞춥니다. 연차보고서의 LLM 검증·보완은 구조를 맞춘 뒤 「다시 문서 검토(LLM)」 에서 합니다. 구조 반영 전 판정은 반영 뒤에 못 쓰게 됩니다.
  - 하려면: 사업계획서의 헤딩 · 표 분석과 LLM 연결(유료). 줄의 「LLM 검증·보완」 이나 묶음의 「한 번에 진행」 으로 실행합니다.
  - 끝난 것으로 보는 때: 사업계획서의 헤딩과 표가 LLM 검증·보완을 거쳤을 때. LLM 을 쓸 수 없거나 「건너뛰기」 를 누르면 스크립트 분석만으로 진행하며 「건너뜀」 으로 끝납니다.
  - 멈추는 때: LLM 이 답을 못 하면 멈춥니다. 다시 실행하거나 「건너뛰기」 를 눌러 스크립트 분석만으로 진행합니다. 서식 정리 계획을 반영하다가 표준 검사에 걸리면 되돌리고 멈춥니다.
  - 남기는 것 · 보정: 건너뛴 문서는 스크립트 분석만으로 진행하며, 「건너뛰기 취소」 로 되돌릴 수 있습니다. 사업계획서의 헤딩 판정에 미판정이 있거나 반영하지 못한 줄과 계획이 남으면 「남김」 으로 알립니다. 「헤딩 추출」 탭의 「조정」 에서 확인합니다.

- **② 자리 연결** — 스크립트 · 저장만 · 필수 · 원본 → 목적. 구분 기준 값과 이름으로 두 문서의 문단 묶음과 표를 잇습니다. 연결됨, 확인 필요, 후보 없음으로 나누며, 같은 서식 쌍에 저장한 짝이 있으면 먼저 씁니다.

- **④ 내용 반영** — 사람 → 스크립트 · 문서 바뀜 · 필수 · 원본 → 목적. 「계획 보기」 에서 확인하고 「반영」 을 누르면 사업계획서의 글과 표 · 그림이 목적 자리에 들어갑니다. 서식은 연차보고서의 틀에 맞추며, 개요가 자리보다 깊어 받을 레벨이 없는 줄은 사업계획서에서 정리된 서식 그대로 종속 템플릿에 넣습니다(템플릿 표시 「T2L4a」). 양식의 예시 값은 실제 내용으로 바꾸거나 비웁니다.

  - 끝난 것으로 보는 때: 내용을 반영했거나 지난 반영 기록이 있을 때, 또는 넣을 것이 없을 때(계획의 넣을 것이 0건이거나 넣을 자리가 0곳 — ③ 과 같은 셈).
  - 남기는 것 · 보정: 짝이 분명하지 않은 자리는 비워 둡니다. 초안 상태이며 실패가 아닙니다.

- **⑤ 합계 계산 → 결과 확인** — 스크립트 · 문서 안 바뀜 · 준비 중 · 원본 → 목적. 아직 없는 단계입니다. 넣은 값으로 합계, 소계, 비율을 다시 계산하고 검사할 예정입니다. 지금은 원본과 줄이 같은 합계 칸만 옮기고 나머지 계산 칸은 비워 둡니다.

조립한 단계: 문서 정리(`stage_clean`)

## 쓰는 도구

단계가 「도구」 로 가리키는 과정 — 그 과정의 단계는 [워크플로우 전체 지도](../workflow.md) 의 「도구」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 워크플로우든 문서를 올리면 먼저 거치는 과정입니다. 문서마다 작업 공간이 생기고, 새 문서이면 스크립트로 헤딩과 표 기본 분석이 저절로 돕니다. 진행 상태는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 대화하는 창이며, 어느 워크플로우의 문서에서나 엽니다. 워크플로우를 시작하면 사전 준비와 진행 상황을 안내하고 다음 단계를 제안·실행합니다. 글로 요청하면 글 작성, 새 표, 표 채우기 · 서식 입히기, 서식 복사 같은 제안을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 비어 있을 때는 「지금 할 수 있는 일」 에서 현재 작업 진행 현황 보고(스크립트), 남은 헤딩·표 LLM 검토(유료), 서식 반영을 바로 고를 수 있습니다.
- **헤딩 추출**(`headings`) — 문서의 개요(헤딩)와 표 구조를 뽑아 뼈대를 만듭니다. 자리 연결, 넣기, 서식 후보, 템플릿 관계가 이 뼈대를 쓰며 문서는 바꾸지 않습니다. 진행 상태는 탭 위 진행 줄에 스크립트(문단, 헤딩 그래프, 표 구조), LLM(규칙 보강, 헤딩 판정, 표 판정), 조정 세 층으로 보입니다. LLM 이 구간과 표를 판정할 때는 양식의 작성 지침(작성 요령 표, 참고 자료, 안내, 각주 작성 요령)도 함께 읽습니다. 「작성요령 삭제」 뒤에는 저장해 둔 지침을 씁니다. LLM 칸(✓)을 누르면 문서 옆 열 「LLM 이 바꾼 것」 에서 스크립트와 달라진 판정 결과를 볼 수 있습니다. LLM 판정만으로는 문서가 바뀌지 않습니다. 진행 줄 「조정」 에는 템플릿 조정(레터가 다른 줄을 서식 종속 템플릿으로 분리), 서식 조정(같은 템플릿 줄을 대표 서식에 맞추기와 자리 맞춤), 「모두 반영」 이 있습니다. 두 칸을 누르면 받아 둔 계획을 보고, 「모두 반영」 을 눌러야 문서 서식이 바뀝니다. 헤딩 판정(LLM)을 아직 안 했으면 줄 끝에 「계획 받기」 대신 「LLM 판정」 단추가 뜹니다(헤딩과 템플릿, 표, 서식 정리 계획을 차례로 받음 · 유료 · 문서는 안 바뀜). 「계획 받기」 는 판정을 마친 뒤에 뜹니다. 「모두 반영」 은 계획을 적용한 뒤 레터 뒤 빈칸을 묶음 빈칸으로 맞추고 둘째 줄을 글 시작에 정렬합니다. 계획이 없어도 자리가 안 맞은 줄이 있으면 뜹니다. 대표만 바꾸는 계획도 반영합니다. 반영 뒤 에이전트가 답하지 못한 줄이 남으면 「서식 조정」 칸에 「답 없음 n줄」 로 남습니다. 이런 줄은 계획을 다시 받거나 「템플릿 관계」 에서 손으로 맞춥니다. 형광펜이나 필드 표지가 든 줄은 글을 못 바꾸면 모양만 맞추고 남깁니다(「서식 조정 · 표지 n줄」). 한글의 자동 글머리표나 문단 번호가 붙은 헤딩 줄도 맞추면 대표의 레터가 글로 들어갑니다. 탭 머리에는 실행 단추가 둘 있습니다. 「단계별 실행 ▾」 은 고른 단계만 차례로 돌리며, 실패하거나 LLM 이 답하지 못하면 뒤 단계를 멈춥니다. 「전체 실행」 은 남은 단계를 조정까지 한 번에 돌립니다(유료 LLM · 문서가 바뀜 · 반영마다 실행 취소 1번). 대시보드의 2단계 「한 번에 진행」 은 끝나면 고친 문단을 확정합니다. 「전체 실행」 은 계획을 따로 묻지 않고 바로 반영하며, 멈추거나 실패하면 한 일과 남은 일을 알립니다. LLM 구간 검증 실패로 미판정이 있으면 반영하지 않고 남깁니다. 표 칸에 혼자 있는 레터(빈 값 「-」 나 번호 칸)는 헤딩 후보에서 뺍니다. 끝나면 「LLM 이 바꾼 것」 의 「반영 결과」 가 열려 바뀐 내용과 남긴 까닭을 보여 줍니다. 한 자리에만 매달린 가지 템플릿은 확실한 경우 종속 템플릿으로 자동 편입하고, 되돌린 뒤에도 줄이 그대로면 받아 둔 서식 계획을 다시 씁니다.
- **템플릿 관계 · 서식 정리**(`outline`) — 헤딩 그래프에서 개요 템플릿의 레벨별 서식을 보고 대표 서식에 맞춥니다. 같은 템플릿의 줄은 서식을 통일하고, 레터가 다른 줄은 서식 종속 템플릿(예: T1L3a)으로 분리합니다. 「o」·「ㅇ」·「○」 나 「·」·「⋅」·「•」 같은 닮은 레터 글자는 같은 레터로 보아 대표 글자로 맞춥니다. 마지막 레벨 아래나 표 제목(L1)으로 새 레벨을 더할 수도 있습니다. 표 칸에 혼자 있는 「-」 나 번호 칸은 서식 목록에서 빼고, 장평과 자간은 비교하거나 바꾸지 않고 원래 값을 유지합니다. 표 안의 줄은 머리글이 같은 표끼리 서식을 공유하며, 대표 서식이 없는 표의 줄은 「대표에 맞추기」 가 건드리지 않고 정리 계획이 표마다 서식 종속 템플릿으로 뗍니다. 여백의 서식 라벨은 대표와 같아지면 번호를 따로 표시하지 않습니다. 문서 왼쪽 여백의 라벨(「T1 L4」)을 오른쪽 단추로 누르면 그 줄의 레벨부터 새 템플릿(「T1L4a」)으로 나눌 수 있습니다 — 「여기서만」(그 줄과 그 아래) 또는 그 레벨 줄 「모두」 를 고르고, 문서는 바뀌지 않으며 「합치기」 로 되돌립니다. 대표와 맞출 대상을 사람이나 LLM 이 고르면, 실제 변경은 「확정 서식으로 바꾸기」 스크립트가 처리하며 조정의 「모두 반영」 과 이관·취합에서도 함께 씁니다.
- **프로젝트 구성(구분 기준)**(`division`) — 단계, 기관, 차년도 값에 맞춰 문서의 절과 표 행·열을 늘리고 줄입니다. 프로젝트 구성 값은 프로젝트당 하나이며 같은 프로젝트의 워크플로우가 함께 씁니다.
