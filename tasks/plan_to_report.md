# 사업계획서 → 연차보고서 이관 — `plan_to_report`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(워크플로우 상세 문서 — 화면 `/workflow` 의 이 워크플로우 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [워크플로우 전체 지도](../workflow.md) 가 모든 워크플로우의 차례를 보인다면 이 글은 이 워크플로우 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

사업계획서에서 필요한 내용을 뽑아 연차보고서로 옮깁니다.

- 받는 문서: 사업계획서(내용이 든 연구개발계획서 — 원본 문서) + 연차보고서 서식(빈 파일 — 목적 문서)
- 산출물: 계획서의 내용이 들어간 연차보고서 초안
- 문서마다 단위문서 TASK — 원본 문서(사업계획서): 1단계 문서 검토(「헤딩 · 표 분석」 › 「LLM 검증·보완」) / 목적 문서(연차보고서): 1단계 문서 검토(「헤딩 · 표 분석」) › 2단계 구성 맞추기(「프로젝트 구성 반영」 › 「다시 문서 검토」 › 「다시 문서 검토(LLM)」) › 3단계 내용 넣기(← 원본 문서: 「자리 연결」 › 「자리 연결 LLM 검토」 › 「표 안 연결 · 넣기 계획」 › 「빈 자리 검토(LLM)」 › 「표 대응(LLM)」 › 「내용 반영」 › 「합계 계산 → 결과 확인」) › 4단계 문서 정리(「작성요령 삭제」)
- 워크플로우 전체(문서마다가 아니라 한 번): 1단계 문서 검토(「준비」) › 2단계 구성 맞추기(「구성 불러오기」 › 「프로젝트 구성 추출」) — 구성의 기준: 원본 문서(사업계획서)
- 알아 둘 것: 값도 내용도 기준은 사업계획서입니다. 결과는 초안입니다 — 모든 자리를 채우는 것이 목표가 아니고, 같은 자리인지 분명하지 않으면 잇지 않고 비워 둡니다(그 뒤 각 기관이 이어서 작성). 사업계획서(원본)는 바뀌지 않습니다.
- 한 번에 진행: 에이전트가 묶음마다 「한 번에 진행」 을 제안하고 실행 카드에서 확인받습니다 — 1단계 문서 검토(두 문서의 헤딩 · 표 분석 → 사업계획서의 LLM 검증·보완: 유료 · 문서 안 바뀜) · 2단계 구성 맞추기(프로젝트 구성 추출 → 구조 반영 → 다시 문서 검토: 연차보고서의 다시 분석 → LLM 검증·보완) · 3단계 내용 넣기(자리 연결 → 넣기 — 유료 LLM) · 4단계 문서 정리(양식 안내 지우기). LLM 을 쓸 수 없으면 LLM 단계는 건너뛰고 스크립트 분석만으로 갑니다. 패널 「작업 개요」 의 「이어서 한 번에」 는 남은 묶음을 누르면 바로 잇습니다(확인 창 없음 · 끝나면 바뀐 문서의 고친 문단을 한 번 확정 — 앞 상태는 「고친 문단」 탭 확정 기록의 복원).
- 에이전트가 묻는 것: 사업계획서와 연차보고서(둘 다 있어야 시작합니다) · 프로젝트 이름(비우면 임시 이름으로 두 문서를 묶음) · 프로젝트 구성(사업계획서에서 읽지 못하면).
- 멈추거나 남기는 곳 · 보정: 2단계는 계획 오류 · 미해결 자리가 있거나 기관의 차례가 다르면 구조를 반영하지 않고 멈춥니다. 3단계는 같은 자리인지 분명하지 않으면 잇지 않고 비워 둡니다(초안 — 실패가 아닙니다): 연결 목록의 「확인 필요」 와 넣기 계획의 못 넣는 까닭에서 보정합니다. 4단계(지우기)는 3단계가 끝난 문서에서만 합니다 — 지우기 전에 작성 지침을 헤딩/표별로 남깁니다.
- 단계별(세부 작업): 패널 「작업 개요」 의 묶음마다 세부 목록 — 분석만 먼저 하거나(「분석」 · 「다시 분석」 은 그 단계만), LLM 검증·보완을 건너뛰거나(「건너뛰기」), 구성을 불러오거나(「구성 불러오기」 — 파일 · 저장된 곳), 자리 연결을 고치거나 LLM 검토 · 표 대응 · 넣기 계획을 따로 볼 때. 프로젝트 구성 추출과 구조 반영은 원본의 LLM 검증·보완이 도는 동안에도 누를 수 있습니다(1 · 2단계는 두 문서에서 같이).
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/plan_to_report.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 도구 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### 워크플로우를 시작할 때

시작 화면의 워크플로우 카드 · 문서 목록 · 첫 화면 대화창에서, 문서를 올리기 전에 봅니다 — 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 워크플로우가 받는 형식(hwp · hwpx)인지 봅니다.
  - 안 맞으면: 시작하지 않고 알립니다 — docx 는 「워크플로우 없이 열기」 로 열거나 워크플로우 「문서 서식 복사」 로 시작합니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 골랐는지 봅니다 — 하나면 그 파일이 목적 문서입니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다 — 어느 파일인지 짐작하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **사업계획서 · 프로젝트 이름** — 스크립트. 목적 문서는 연차보고서입니다. 문서 목록의 나머지 문서가 사업계획서 하나까지인지, hwp · hwpx 인지 봅니다. 두 문서는 같은 프로젝트로 묶습니다 — 프로젝트 이름을 비우면 임시 이름(임시 프로젝트 N)으로.
  - 안 맞으면: 나머지가 둘 이상이면 남길 둘만 두라고 알리고 시작하지 않습니다. 목적 문서가 프로젝트에 묶이지 않으면(작업 저장이 꺼짐 등) 사업계획서는 목록에 남기고 알립니다.
  → 사양: spec_작업.md ② §15-1·§17

### 문서를 올릴 때

올리면 저절로 도는 것입니다 — 사람이 누르지 않고, 유료 LLM 호출이 없습니다.

- **작업 만들기 · 같은 파일 고르기** — 스크립트. 올린 파일로 작업(문서마다의 저장 공간)을 만듭니다. 같은 파일로 하던 작업이 있으면 열기 전에 묻습니다 — 이 워크플로우의 작업 → 워크플로우가 빈 작업 차례로 줄마다 「이어서」 · 「초기화하고 열기」, 맨 아래 「새 작업으로 시작」(프로젝트 칸). hwp 는 한글이 hwpx 로 바꿔 받습니다.
  - 안 맞으면: 다른 워크플로우 · 프로젝트 · 역할을 하던 작업은 「그대로 열기」 만이고 고르면 그 작업을 열고 이 워크플로우 시작은 멈춥니다(그 작업의 워크플로우는 안 바꿈). 창을 닫으면 아무것도 열지 않습니다. 올리지 못하면 까닭을 알리고 시작하지 않습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§3-1·§15
- **양식 판정 · 문서 종류** — 스크립트. 문서 목록으로 시작하면 목적 문서를 연차보고서로 적습니다. 카드에 파일 하나만 올리면 양식 판정이 정한 종류(사업계획서 · 연차보고서)로 적습니다.
  - 안 맞으면: 양식 판정이 종류를 못 정하면 비워 둡니다 — 패널 「작업 개요」 의 첨부 파일 칸에서 고릅니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **워크플로우 · 프로젝트 · 라운드** — 스크립트. 작업에 이 워크플로우를 적습니다. 문서 목록에 프로젝트 이름을 적었으면 그 프로젝트의 이 워크플로우 다음 라운드로 시작합니다. 비우면 임시 이름(임시 프로젝트 N)으로 함께 올린 문서를 묶습니다.
  - 안 맞으면: 임시 이름은 연 뒤 「작업 개요」 의 프로젝트 칸이나 작업 리스트의 「이름 정하기」 에 이름을 적으면 바뀝니다 — 이미 있는 프로젝트 이름이면 그 프로젝트로 문서를 모두 옮깁니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **사업계획서 올리기** — 스크립트. 함께 시작한 사업계획서는 늘 새 작업으로 올려 같은 프로젝트 · 워크플로우 · 라운드의 사업계획서로 적고(첨부 파일 칸이 저절로 잇습니다) 기본 분석을 겁니다 — 화면에 열지 않습니다.
  - 안 맞으면: 못 올리면 알립니다 — 패널 「작업 개요」 의 사업계획서 칸에서 다시 올립니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §9·§11
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 웹 화면이 제대로 읽었는지 검사합니다(한글 · Word 가 있으면 PDF 로 찍어 견줌) — 기본 분석과 함께 돌고, 결과는 패널 머리 「검증」 에 보입니다. 주의 · 실패가 나면 마지막 「LLM 검토」(LLM 호출 한 번)가 저절로 돌아 그 단계가 실제 문제인지 기준 PDF 쪽 사정인지 가립니다.
  - 안 맞으면: LLM 을 쓸 수 없거나 호출이 실패하면 스크립트 판정 그대로 두고 「LLM 검토」 단계에 까닭을 적습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 한 번, 헤딩 그래프 → 표 구조를 스크립트만으로 분석합니다(hwpx). 이미 결과가 있는 단계는 건너뛰고, 이어 연 작업에서는 돌지 않습니다.
  - 안 맞으면: 시작하지 못했으면 문서 이름 줄이 「헤딩 없음 · 표 없음」, 돌다 실패했으면 멈춘 단계가 「실패」 입니다 — 이름 줄의 「분석」 단추로 다시 돌립니다.
  → 도구: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 헤딩 · 템플릿 · 서식 · 표 · LLM 검증·보완 · 구분 기준 검토가 어디까지 됐는지 보입니다 — 어느 워크플로우에서나 같은 꼴입니다(누르면 진행표).
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **편집 구역의 기준 적기** — 스크립트. 시작 화면 문서 목록의 묶음 「편집 구역」 에서 기준(기관 · 단계 · 차년도)을 골랐으면, 워크플로우를 적은 뒤 그 워크플로우 묶음의 옵션으로 적습니다.
  - 안 맞으면: 손대지 않았으면 적지 않습니다 — 그 워크플로우의 기본값(취합 = 기관 · 그 밖은 꺼짐)으로 시작하고, 연 뒤 「편집 구역」 줄에서 바꿉니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1

### 워크플로우 화면을 열 때

패널 「작업 개요」 와 에이전트의 시작 턴이 지금 상태를 셈합니다 — 여기서 모자란 것이 사전 준비입니다.

- **에이전트의 시작 턴** — 스크립트 → LLM. LLM 을 쓸 수 있으면 에이전트 창(상단 바의 에이전트 아이콘 — 패널 탭에 넣었으면 그 탭)이 열려 시작 턴이 돕니다(LLM 호출 한 번) — 이 워크플로우의 사전 준비 · 지금까지 된 것 · 다음 단계를 설명하고 다음 행동을 제안합니다. 같은 작업 · 같은 워크플로우에 진행 턴이 이미 있으면 다시 돌지 않습니다.
  - 안 맞으면: LLM 이 꺼져 있으면 옮기지 않고 패널 「작업 개요」 를 엽니다 — 에이전트 보기의 「작업 설명 듣기」 로 스크립트 설명을 볼 수 있습니다.
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §1
- **두 문서가 있는가** — 스크립트. 같은 프로젝트 · 워크플로우 · 라운드에 사업계획서와 연차보고서가 둘 다 있는지 봅니다.
  - 안 맞으면: 모자라면 패널 「작업 개요」 의 첨부 파일 칸에서 고르거나 올리게 합니다 — 프로젝트 이름이 없으면 다른 문서를 고를 수 없습니다.
  → 사양: spec_작업.md ② §11·§17
- **지금 문서가 목적 문서인가** — 스크립트. 연 문서가 연차보고서(목적 문서)인지 사업계획서(원본)인지 봅니다.
  - 안 맞으면: 원본을 열었으면 실행 행동을 내지 않고 「연차보고서 열기」 를 카드로 묻습니다(원본은 바뀌지 않습니다).
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7
- **헤딩 · 표 분석** — 스크립트. 두 문서에 헤딩 그래프 · 표 구조가 있는지 봅니다 — 문서를 고친 뒤에도 있던 분석을 씁니다. 분석이 도는 중이면 5초마다 다시 읽습니다.
  - 안 맞으면: 없으면 1단계 「문서 검토」 가 지금 차례입니다(「한 번에 진행」 이 없는 문서만 스크립트로 분석).

  - 안 맞으면: 값이 다르면 「사업계획서 기준으로 맞추기」, 반영 전이면 「변경 계획 보기」 가 다음 차례입니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §11·§14
- **구조 반영 뒤의 분석** — 스크립트. 연차보고서의 헤딩 · 표 분석이 마지막 구조 반영 뒤의 것인지 봅니다 — 구조 반영 밖의 편집은 따지지 않습니다.
  - 안 맞으면: 구조 반영 전의 분석이면 2단계의 「다시 문서 검토」 가 남습니다(「한 번에 진행」 이 스크립트로 다시 분석 → LLM 검증·보완). LLM 판정을 거친 분석이어도 다시 분석합니다 — LLM 을 쓸 수 없을 때만 그대로 두었다고 알립니다.
  → 도구: 헤딩 추출 | 사양: spec_작업.md ② §21
- **이관 조건** — 스크립트. 3단계(내용 넣기)는 두 문서가 1 · 2단계를 마친 뒤에만 진행합니다 — 원본 문서(사업계획서): 헤딩 · 표 분석 › LLM 검증·보완 / 목적 문서(연차보고서): 헤딩 · 표 분석 › 구조 반영 › 다시 문서 검토 / 워크플로우 전체(문서마다가 아니라 한 번): 프로젝트 구성 추출 — 구성의 기준: 원본 문서(사업계획서). 1 · 2단계의 문서마다 하는 단계는 두 문서에서 같이 진행할 수 있습니다(원본의 LLM 검증·보완이 도는 동안 목적 문서의 구성을 맞춤).
  - 안 맞으면: 덜 끝난 조건이 있으면 3단계의 「한 번에 진행」 이 꺼지고 묶음 머리에 「N단계 … 완료 후 진행」 이 보입니다 — ② 자리 연결 줄은 서버가 본 까닭(분석 없음 · 값 없음 · 반영 전 · 값이 다름)을 문서별로 보입니다.
  → 사양: spec_작업.md ② §21
- **연결 목록** — 스크립트. 분석이 있으면 두 문서의 자리를 이은 연결 목록을 읽습니다(연결됨 · 확인 필요 · 후보 없음 · 같은 이름 자리) — 같은 서식 쌍에 저장해 둔 짝이 있으면 먼저 씁니다.
  - 안 맞으면: 서버가 목록을 낼 수 없으면 까닭을 그대로 보입니다(헤딩·표 분석 없음 · 프로젝트 구성 값 없음 · 반영 전 · 값이 사업계획서와 다름 · hwpx 가 아님).
  → 사양: spec_병합.md ② §0-1·§4
- **지난 반영 기록** — 스크립트. 이 연차보고서에 앞서 넣은 자리의 기록이 남아 있는지 봅니다.
  - 안 맞으면: 있으면 넣기 계획 · 내용 반영을 끝난 것으로 보고, 더 넣을 것은 「넣기 계획 다시」 가 셉니다.
  → 사양: spec_병합.md ② §6
- **지울 양식 안내** — 스크립트. 연차보고서에서 지우는 패턴(작성 요령 표 · 「<참고 N>」 자료 · 안내 색 ※ 글 · 위첨자 각주 번호)에 걸린 자리를 셉니다.
  - 안 맞으면: 세지 못하면 까닭을 보이고 「다시 읽기」 를 냅니다.
  → 사양: spec_작업.md ② §14
- **편집 구역 — 보일 기준과 구역 읽기** — 스크립트. 이 워크플로우 묶음(프로젝트 · 워크플로우 · 라운드)의 옵션 — 편집 구역에서 보일 기준(기관 · 단계 · 차년도) — 을 읽고, 켠 기준이 있으면 문서의 문단 · 표 · 표 칸이 어느 기관 · 단계 · 차년도의 것인지 스크립트로 읽어 색 띠와 이름표로 보입니다.
  - 안 맞으면: 켠 기준이 없으면 구역을 읽지 않습니다 — 패널 「작업 개요」 의 「편집 구역」 줄에서 켭니다. 프로젝트 구성 값이 없으면 셀 수 없다고 알립니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1·§6
- **지금 도는 실행** — 스크립트. 이 문서에 「한 번에 진행」(간단 모드 · 묶음 · 실행 카드)이 도는 중인지 봅니다.
  - 안 맞으면: 도는 동안 에이전트는 실행 · 저장하는 행동을 내지 않고 진행 카드만 보입니다 — 끝나면 이어서 안내합니다.

### 저절로 돌지 않는 것

시작할 때 돌 것 같지만 사람이 단추로 돌려야 하는 것입니다(유료 LLM).

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 기본 분석과 따로이고 올릴 때 돌지 않습니다 — 「헤딩 추출」 · 「테이블」 탭 머리의 「단계별 실행 ▾」 메뉴(돌릴 단계를 여러 개 골라 「고른 n개 실행」 — 고른 것만 차례로 · 또는 하위 탭 「추출·설정」 의 단계 카드 · 헤딩 추출 탭의 「전체 실행」 은 조정까지 한 번에) · 헤딩 추출 탭 진행 줄 「조정」 끝의 「LLM 판정」(판정을 아직 안 한 문서) · 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」(실행 카드)로 돌립니다. 헤딩의 LLM 판정은 스크립트가 판정하지 못한 첫머리 묶음(못 맞춤 · 충돌)도 함께 봅니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **구분 기준 LLM 검토** — 사람 → LLM. 옵션입니다 — 문서 이름 줄의 「구분 기준」 표시나 프로젝트 구성의 「LLM 검토」 로 열어 「LLM 검토 실행」 을 눌러 돌립니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §20
- **편집 구역 LLM 검토** — 사람 → LLM. 옵션입니다 — 「편집 구역」 줄의 「LLM 검토」 를 눌러야 돕니다(유료). 스크립트가 기관 · 차년도를 못 정한 표 · 자리를 LLM 이 보고, 정한 것은 「LLM」 지정으로 따로 보입니다 — 문서는 바뀌지 않습니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §8
- **이 워크플로우의 LLM 검토** — 사람 → LLM. 자리 연결 LLM 검토 · 표 대응 · 빈 자리 검토 — 단계의 단추나, 확인을 받은 3단계 「한 번에 진행」 안에서 돕니다(유료). 올리거나 여는 것만으로는 돌지 않습니다.
  → 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 자동/필수/선택/준비 중 · 하는 문서. 하는 일`(하는 문서 = 문서 여럿인 워크플로우의 단계만 — 원본 문서 · 목적 문서 · 두 문서 · 원본 → 목적 · 워크플로우 전체), 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 도구 | 코드(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 1단계 문서 검토 — 두 문서의 헤딩 · 표를 분석하고(스크립트) 원본 문서를 LLM 으로 검증 · 보완 — 양식의 작성 지침을 헤딩/표별로 저장 · 문서는 안 바뀜

조립한 단계: 문서 검토(`stage_review`)

- **준비** — 사람 · 문서 안 바뀜 · 필수 · 워크플로우 전체. 같은 프로젝트 · 워크플로우 · 라운드의 사업계획서와 연차보고서를 첨부 파일 칸에서 고릅니다(없으면 올립니다). LLM 을 쓸 수 있으면 에이전트 창(상단 바의 에이전트 아이콘)이 열려 사전 준비와 다음 단계 묶음을 설명하고 진행합니다.
  - 하려면: 프로젝트 이름 — 없으면 같은 프로젝트의 다른 문서를 고를 수 없습니다(올리는 것은 됩니다).
  - 끝난 것으로 보는 때: 사업계획서 칸과 연차보고서 칸이 모두 찼을 때.
  → 도구: 문서 올리기 · 첫 분석 · 에이전트 보기 | 사양: spec_작업.md ② §10·§17
- **헤딩 · 표 분석** — 스크립트 · 저장만 · 필수 · 두 문서. 문서(사업계획서 · 연차보고서)에 헤딩 그래프 · 표 구조가 있는지 보고, 없는 문서만 스크립트로 분석합니다(LLM 호출 없음 — 올릴 때 저절로 돈 기본 분석). 끝나면 양식의 작성 지침(작성 요령 표 · 「<참고 N>」 자료 · ※ 안내 · 각주 번호가 가리키는 작성 요령 항목)을 어느 헤딩 · 어느 표의 것인지와 함께 저장합니다.
  - 하려면: 사업계획서 · 연차보고서(hwpx).
  - 끝난 것으로 보는 때: 문서마다 헤딩 그래프 · 표 구조가 있을 때 — 문서를 고친 뒤에도 있던 분석을 씁니다(다시 하라고 하지 않습니다).
  - 멈추는 때: 분석이 실패하면 까닭을 알리고 멈춥니다 — 「헤딩 추출」 탭에서 확인합니다.
  - 남기는 것 · 보정: 작성 지침은 작업에 저장돼 「문서 정리」 가 문서에서 지운 뒤에도 남습니다 — 줄의 「작성 지침」 으로 헤딩별 · 표별 목록을 봅니다.
  → 문서마다의 헤딩 그래프 · 표 구조 · 헤딩/표별 작성 지침 | 도구: 헤딩 추출 | 코드: `heading_runs` · `form_guides` | 사양: spec_작업.md ② §21
- **LLM 검증·보완** — 사람 → LLM · 문서 바뀜 · 필수 · 원본 문서. 사업계획서의 헤딩 · 템플릿 → 표 → 서식 정리 계획을 LLM 이 차례로 검증 · 보완합니다(유료 · 몇 분). 이어서 사업계획서에는 받은 서식 정리 계획(템플릿 조정 · 서식 조정)을 반영합니다 — 내용은 그대로이고 헤딩 줄의 레터 · 서식만 맞춥니다. 연차보고서의 LLM 검증·보완은 구조를 맞춘 뒤 「다시 문서 검토(LLM)」 에서 합니다 — 구조 반영 전에 받은 판정은 반영 뒤 옛것이 됩니다.
  - 하려면: 사업계획서의 헤딩 · 표 분석 · LLM 연결(유료 — 줄의 「LLM 검증·보완」 · 묶음의 「한 번에 진행」).
  - 끝난 것으로 보는 때: 사업계획서의 헤딩 · 표가 LLM 검증·보완을 거쳤을 때 — LLM 을 쓸 수 없거나 사람이 「건너뛰기」 를 누르면 「건너뜀」 으로 끝난 것으로 봅니다(스크립트 분석만으로 진행).
  - 멈추는 때: LLM 이 답을 못 하면 멈춥니다 — 다시 누르거나 그 줄의 「건너뛰기」 로 스크립트 분석만으로 진행합니다. 서식 정리 계획의 반영이 표준 검사에 걸리면 되돌리고 멈춥니다.
  - 남기는 것 · 보정: 건너뛴 문서는 스크립트 분석만으로 갑니다 — 그 줄의 「건너뛰기 취소」 로 되돌립니다. 사업계획서의 헤딩 판정에 미판정이 있거나 반영하고 남은 줄 · 못 받은 계획이 있으면 「남김」 으로 알립니다 — 「헤딩 추출」 탭의 「조정」 에서 봅니다.

### 2단계 구성 맞추기 — 프로젝트 구성을 확정하고(불러오기는 선택) 연차보고서의 구조를 값에 맞춘 뒤 다시 문서 검토 — 내용은 넣지 않음

### 3단계 내용 넣기 — 두 문서의 자리를 잇고, 계획서의 내용을 그 자리에 넣음(서식 맞춤)

- **② 자리 연결** — 스크립트 · 저장만 · 필수 · 원본 → 목적. 두 문서의 자리(문단 묶음 · 표)를 구분 기준 값과 이름으로 잇습니다 — 연결됨 · 확인 필요 · 후보 없음. 같은 서식 쌍에 저장해 둔 짝이 있으면 그것을 먼저 씁니다.

- **④ 내용 반영** — 사람 → 스크립트 · 문서 바뀜 · 필수 · 원본 → 목적. 「계획 보기」 에서 확인하고 「반영」 을 누르면 사업계획서의 글 · 표 · 그림이 그 자리에 들어갑니다 — 서식은 연차보고서의 틀에 맞추고, 넣는 내용의 개요가 자리보다 깊으면 넘친 개요 레벨로 처리합니다(받을 레벨이 없는 줄은 사업계획서에서 정리된 서식 그대로 그 자리의 종속 템플릿에 넣습니다 — 템플릿 표시 「T2L4a」). 양식이 보기로 적어 둔 예시 값은 실제 내용으로 바꾸거나 비웁니다.
  - 하려면: 넣기 계획 — 「계획 보기」 에서 확인하고 「반영」.
  - 끝난 것으로 보는 때: 반영했거나 · 넣을 것이 없거나(계획의 넣을 것이 0 · 넣을 자리가 0곳 — ③ 과 같은 셈) · 지난 반영 기록이 남아 있을 때.
  - 남기는 것 · 보정: 같은 자리인지 분명하지 않은 자리는 비워 둡니다(초안 — 실패가 아닙니다).
  → 내용이 들어간 연차보고서 | 코드: `merge_fill` · `merge_tables` · `merge_table_map` · `merge_gaps` · `merge_schedule` · `merge_copy` · `merge_convert` · `merge_over` · `merge_register` · `merge_origins` · `outline_conform` | 사양: spec_병합.md ② §5-2·§5-5·§5-12·§6
- **⑤ 합계 계산 → 결과 확인** — 스크립트 · 문서 안 바뀜 · 준비 중 · 원본 → 목적. 아직 없는 단계입니다 — 넣은 값으로 합계 · 소계 · 비율 칸을 다시 세고 결과를 검사할 자리. 지금은 원본과 줄이 같은 합계 칸만 옮기고 나머지 계산 칸은 비워 둡니다.

### 4단계 문서 정리 — 연차보고서 서식이 글쓴이에게 주는 안내를 지움 — 지우기 전에 작성 지침을 저장

조립한 단계: 문서 정리(`stage_clean`)

- **⑥ 작성요령 삭제** — 스크립트 → 사람 · 문서 바뀜 · 필수 · 목적 문서. 지우는 패턴 목록에 걸린 양식 안내(작성 요령 표 · 「<참고 N>」 자료 · 안내 색 ※ 글 · 위첨자 각주 번호)를 한 번에 지웁니다(확인 창 없이 · 실행 취소 한 번). 내용과 쓸 자리는 남깁니다. 지우기 바로 전에 작성 지침을 헤딩/표별로 한 번 더 저장합니다.
  - 하려면: ④ 내용 반영이 끝난 연차보고서.
  - 끝난 것으로 보는 때: ④ 가 끝났고 지울 안내가 남지 않았을 때.
  - 멈추는 때: 한 번에 지웁니다 — 멈춤을 요청했거나 그 사이 다른 문서를 열었으면 지우지 않고 멈춤으로 보고합니다.
  - 남기는 것 · 보정: 지우는 패턴 목록에 없는 안내와 내용 · 쓸 자리는 남깁니다. 지운 작성 지침은 작업에 저장돼 있습니다(「헤딩 · 표 분석」 줄의 「작성 지침」).

## 쓰는 도구

단계가 「도구」 로 가리키는 과정 — 그 과정의 단계는 [워크플로우 전체 지도](../workflow.md) 의 「도구」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 워크플로우든 문서를 올리면 먼저 거치는 과정입니다 — 작업(문서마다의 저장 공간)이 생기고, 새 작업이면 기본 분석(헤딩 · 표 — 스크립트)이 저절로 돕니다. 어디까지 됐는지는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 주고받는 대화창입니다 — 워크플로우를 시작하면 에이전트가 사전 준비와 진행 상황을 설명하고 다음 단계를 제안·실행하며(작업 진행), 글로 요청하면 제안(글 · 새 표 · 표 채우기 · 서식 입히기 · 서식 복사)을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 빈 동안은 「지금 할 수 있는 일」 — 현재 작업 진행 현황 보고(스크립트 · 무료) · 남은 헤딩·표 LLM 검토(실행 카드 · 유료) · 서식 반영 — 을 고릅니다. 어느 워크플로우의 문서에서나 엽니다.
- **헤딩 추출**(`headings`) — 문서의 개요(헤딩)와 표의 구조를 뽑아 뼈대로 둡니다 — 자리 연결 · 넣기 · 서식 후보 · 템플릿 관계가 이 뼈대를 씁니다. 문서는 바꾸지 않습니다. 어디까지 했는지는 탭 위 진행 줄에 두 층으로 보입니다 — 스크립트(문단·라벨 · 헤딩 그래프 · 표 구조)와 LLM(규칙 보강 · 헤딩 판정 · 표 판정). LLM 의 구간 판정 · 표 판정은 그 자리에 양식이 적어 둔 작성 지침(작성 요령 표 · <참고 N> 자료 · ※ 안내 · 각주 번호가 가리키는 작성 요령 항목)도 함께 받습니다 — 「작성요령 삭제」 뒤에는 저장해 둔 지침으로. LLM 칸(✓)을 누르면 문서 옆 열 「LLM 이 바꾼 것」 에 LLM 이 스크립트와 다르게 정한 것(규칙 · 노드 · 서식 쌍 판정 · 표 칸 역할 · 받아 둔 서식 계획)이 보입니다 — LLM 판정은 문서를 바꾸지 않습니다. 진행 줄의 셋째 층 「조정」 에는 템플릿 조정(레터가 다른 줄을 서식 종속 템플릿으로 — 뗄 줄 수) · 서식 조정(같은 템플릿의 줄을 대표 서식에 — 맞출 줄 수 + 자리 맞춤 줄 수)과 「모두 반영」 이 있습니다 — 두 칸을 누르면 받아 둔 계획이 보이고, 문서 서식은 「모두 반영」 을 눌러야 바뀝니다. 조정은 LLM 판정 뒤의 일입니다 — 헤딩 판정(LLM)을 아직 안 한 문서에서는 그 줄 끝의 단추가 「계획 받기」 가 아니라 「LLM 판정」 입니다(헤딩 · 템플릿 → 표 · 서식 정리 계획을 차례로 — 누르면 바로 · 유료 · 문서는 안 바뀜). 서식 정리 계획만 받는 「계획 받기」 는 판정을 거친 뒤에 뜹니다. 「모두 반영」 은 계획을 반영한 뒤 스크립트로 자리를 맞춥니다(레터 뒤 빈칸을 묶음 빈칸으로 · 둘째 줄을 글 시작에 — 받아 둔 계획이 없어도 자리가 안 맞은 줄이 있으면 뜹니다). 대표만 바꾸는 계획도 반영합니다(「서식 조정 · 대표 n」). 반영한 뒤에 에이전트가 답하지 않아 안 바꾼 줄이 남아 있으면 「서식 조정」 칸은 ✓ 가 아니라 「답 없음 n줄」 로 남습니다 — 그 줄은 계획을 다시 받거나 「템플릿 관계」 에서 손으로 맞춥니다. 형광펜·필드 표지가 든 줄은 글을 못 바꾸면 모양만 맞추고 남깁니다(그 줄 때문에 전체를 되돌리지 않음 — 「서식 조정 · 표지 n줄」, 누르면 그 줄로). 한글의 자동 글머리표·문단 번호로 레터를 매긴 헤딩 줄도 그 레벨의 서식으로 들어(다른 값 「자동 글머리」) 맞추면 대표의 레터가 글로 들어간 친 레터 줄이 됩니다(번호는 맞추기 전에 보이던 번호). 실행은 탭 머리의 단추 둘입니다 — 「단계별 실행 ▾」 은 돌릴 단계를 골라(여러 개를 눌러 표시한 뒤 「고른 n개 실행」) 고른 것만 차례로 돌리고(누르면 바로 · 한 단계가 실패하거나 LLM 이 답을 못 하면 뒤는 돌리지 않고 남김 · 도는 동안 같은 메뉴에 차례와 「멈추기」), 「전체 실행」 은 남은 단계를 조정까지 차례로 돌립니다(LLM 판정: 헤딩 · 템플릿 → 표 · 서식 정리 계획 → 조정: 받은 계획 모두 반영 — 이미 거친 단계는 건너뜀 · 누르면 바로 · 유료 LLM · 문서가 바뀜 · 반영마다 실행 취소 1 — 대시보드의 2단계 「한 번에 진행」 은 끝나면 고친 문단을 확정). 「전체 실행」 은 계획을 보이지 않고 에이전트가 고른 그대로 반영합니다 — 멈추거나 실패하면 거기서 서고, 한 것과 남은 것(보정할 자리)을 알립니다. 헤딩 판정에 미판정(LLM 구간 검증 실패)이 있으면 반영하지 않고 남깁니다. 표 칸에 혼자 있는 레터(빈 값 「-」 · 번호 칸)는 헤딩 후보가 아닙니다. 끝나면 문서 옆 열 「LLM 이 바꾼 것」 의 「반영 결과」 가 열려 서식마다 무엇이 어떻게 바뀌었는지(전 → 후 값) · 뗀 것 · 남긴 것과 까닭을 보입니다. 한 자리에만 매달린 가지 템플릿은 그 자리의 템플릿 아래 종속 템플릿으로 저절로 넣고(확실한 것만 — 번호가 윗줄을 넘어 이어지는 것은 제안으로), 받은 서식 계획은 그 템플릿의 줄이 그대로면 되돌린 뒤에도 다시 받지 않고 씁니다.
- **템플릿 관계 · 서식 정리**(`outline`) — 헤딩 그래프 위에서 개요 템플릿의 레벨마다 쓰인 서식을 보고 대표 서식에 맞춥니다 — 같은 템플릿의 줄은 서식이 같아야 하고, 레터가 다른 줄은 서식 종속 템플릿(T1L3a)으로 뗍니다. 닮은 레터 글자(「o」·「ㅇ」·「○」 · 「·」·「⋅」·「•」)는 같은 레터라 떼지 않고 대표 글자로 맞춥니다. 템플릿에 레벨을 더할 수도 있습니다(마지막 레벨 아래 · 표 제목을 L1 으로). 맞추지 않는 것: 표 칸에 혼자 있는 레터(빈 값 「-」 · 번호 칸 — 값 칸)는 서식 목록에 넣지 않고, 장평·자간(한 줄에 넣으려고 줄인 값)은 견주지 않으며 맞추는 줄도 제 값을 지킵니다. 표 안의 줄은 표마다 서식이 따로입니다 — 머리글이 같은 표끼리 서식을 같이 쓰고, 대표 서식의 줄이 없는 표의 줄(표의 서식)은 「대표에 맞추기」 가 건드리지 않으며 정리 계획이 표마다 서식 종속 템플릿으로 뗍니다. 여백의 서식 라벨(S41)은 맞춘 줄이면 대표의 라벨이 되고, 대표와 같은 줄에는 번호를 따로 그리지 않습니다. 무엇을 대표로 삼고 어느 서식을 맞출지는 사람·LLM 이 고르고, 줄을 그 서식으로 바꾸는 것은 스크립트 하나(「확정 서식으로 바꾸기」)가 합니다 — 대표에 맞추기 · 템플릿 맞추기 · 조정의 「모두 반영」 · 이관·취합의 넣은 줄이 같이 씁니다.
- **프로젝트 구성(구분 기준)**(`division`) — 단계 · 차년도 · 기관 값(프로젝트 구성)에 맞춰 문서의 절 · 표 행 · 표 열을 늘리고 줄입니다. 값은 프로젝트에 하나이고 그 프로젝트의 워크플로우들이 같이 씁니다.
