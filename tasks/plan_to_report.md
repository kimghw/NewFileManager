# 사업계획서 → 연차보고서 이관 — `plan_to_report`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(TASK 문서 — 화면 `/workflow` 의 이 TASK 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [workflow.md](../workflow.md) 가 모든 TASK 의 차례를 보이는 **전체 지도**라면 이 글은 이 TASK 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

사업계획서에서 필요한 내용을 뽑아 연차보고서로 옮깁니다.

- 받는 문서: 사업계획서(내용이 든 연구개발계획서 — 원본 문서) + 연차보고서 서식(빈 파일 — 목적 문서)
- 산출물: 계획서의 내용이 들어간 연차보고서 초안
- 알아 둘 것: 값도 내용도 기준은 사업계획서입니다. 결과는 초안입니다 — 모든 자리를 채우는 것이 목표가 아니고, 같은 자리인지 분명하지 않으면 잇지 않고 비워 둡니다(그 뒤 각 기관이 이어서 작성). 사업계획서(원본)는 바뀌지 않습니다.
- 한 번에 진행: 에이전트가 묶음마다 「한 번에 진행」 을 제안합니다 — 1단계(프로젝트 구성 확정 · 문서 안 바뀜)는 바로 하고, 2단계(구조 반영) · 3단계(내용 매핑 — 유료 LLM) · 4단계(양식 안내 지우기)는 묶음마다 실행 카드에서 확인받습니다. 패널 「작업 내용」 의 「이어서 한 번에」 는 남은 묶음을 한 번 확인으로 잇습니다(실행 취소는 묶음마다 따로).
- 에이전트가 묻는 것: 사업계획서와 연차보고서(둘 다 있어야 시작합니다) · 프로젝트 이름(두 문서를 묶음) · 프로젝트 구성(사업계획서에서 읽지 못하면).
- 멈추거나 남기는 곳 · 보정: 2단계는 계획 오류 · 미해결 자리가 있거나 기관의 차례가 다르면 멈춥니다. 3단계는 같은 자리인지 분명하지 않으면 잇지 않고 비워 둡니다(초안 — 실패가 아닙니다): 연결 목록의 「확인 필요」 와 넣기 계획의 못 넣는 까닭에서 보정합니다. 4단계(지우기)는 3단계가 끝난 문서에서만 합니다.
- 단계별(세부 작업): 패널 「작업 내용」 의 묶음마다 세부 목록 — 자리 연결을 고치거나 LLM 검토 · 표 대응 · 넣기 계획을 따로 볼 때.
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/plan_to_report.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 공통 모듈 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### TASK 를 시작할 때

시작 화면의 TASK 카드 · 문서 목록 · 첫 화면 대화창에서, 문서를 올리기 전에 봅니다 — 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 TASK 가 받는 형식(hwp · hwpx)인지 봅니다.
  - 안 맞으면: 시작하지 않고 알립니다 — docx 는 「TASK 없이 열기」 로 열거나 TASK 「문서 서식 복사」 로 시작합니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 골랐는지 봅니다 — 하나면 그 파일이 목적 문서입니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다 — 어느 파일인지 짐작하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **사업계획서 · 프로젝트 이름** — 스크립트. 목적 문서는 연차보고서입니다. 문서 목록의 나머지 문서가 사업계획서 하나까지인지, hwp · hwpx 인지, 함께 시작하려면 프로젝트 이름을 적었는지 봅니다.
  - 안 맞으면: 나머지가 둘 이상이면 남길 둘만 두라고, 프로젝트 이름이 없으면 적으라고 알리고 시작하지 않습니다(두 문서를 같은 프로젝트로 묶습니다).
  → 사양: spec_작업.md ② §15-1

### 문서를 올릴 때

올리면 저절로 도는 것입니다 — 사람이 누르지 않고, 유료 LLM 호출이 없습니다.

- **작업 만들기 · 이어 열기** — 스크립트. 올린 파일로 작업(문서마다의 저장 공간)을 만듭니다. 같은 파일로 하던 작업이 있으면 이 TASK 의 작업(가장 최근) → TASK 가 빈 작업 차례로 이어 엽니다. hwp 는 한글이 hwpx 로 바꿔 받습니다.
  - 안 맞으면: 다른 TASK 를 하던 작업뿐이면 그 작업은 그대로 두고 새 작업으로 열고 알립니다. 올리지 못하면 까닭을 알리고 시작하지 않습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§15
- **양식 판정 · 문서 종류** — 스크립트. 문서 목록으로 시작하면 목적 문서를 연차보고서로 적습니다. 카드에 파일 하나만 올리면 양식 판정이 정한 종류(사업계획서 · 연차보고서)로 적습니다.
  - 안 맞으면: 양식 판정이 종류를 못 정하면 비워 둡니다 — 패널 「작업 내용」 의 첨부 파일 칸에서 고릅니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **TASK · 프로젝트 · 라운드** — 스크립트. 작업에 이 TASK 를 적습니다. 문서 목록에 프로젝트 이름을 적었으면 그 프로젝트의 이 TASK 다음 라운드로 시작합니다.
  - 안 맞으면: 프로젝트 이름을 비우면 프로젝트 없이 시작합니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **사업계획서 올리기** — 스크립트. 함께 시작한 사업계획서는 늘 새 작업으로 올려 같은 프로젝트 · TASK · 라운드의 사업계획서로 적고(첨부 파일 칸이 저절로 잇습니다) 기본 분석을 겁니다 — 화면에 열지 않습니다.
  - 안 맞으면: 못 올리면 알립니다 — 패널 「작업 내용」 의 사업계획서 칸에서 다시 올립니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §9·§11
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 웹 화면이 제대로 읽었는지 검사합니다(한글 · Word 가 있으면 PDF 로 찍어 견줌) — 기본 분석과 함께 돌고, 결과는 패널 머리 「검증」 에 보입니다. 주의 · 실패가 나면 마지막 「LLM 검토」(LLM 호출 한 번)가 저절로 돌아 그 단계가 실제 문제인지 기준 PDF 쪽 사정인지 가립니다.
  - 안 맞으면: LLM 을 쓸 수 없거나 호출이 실패하면 스크립트 판정 그대로 두고 「LLM 검토」 단계에 까닭을 적습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 한 번, 헤딩 그래프 → 표 구조를 스크립트만으로 분석합니다(hwpx). 이미 결과가 있는 단계는 건너뛰고, 이어 연 작업에서는 돌지 않습니다.
  - 안 맞으면: 시작하지 못했으면 문서 이름 줄이 「헤딩 없음 · 표 없음」, 돌다 실패했으면 멈춘 단계가 「실패」 입니다 — 이름 줄의 「분석」 단추로 다시 돌립니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 헤딩 · 템플릿 · 서식 · 표 · LLM 검증·보완 · 구분 기준 검토가 어디까지 됐는지 보입니다 — 어느 TASK 에서나 같은 꼴입니다(누르면 진행표).
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20

### TASK 화면을 열 때

패널 「작업 내용」 과 에이전트의 시작 턴이 지금 상태를 셈합니다 — 여기서 모자란 것이 사전 준비입니다.

- **에이전트의 시작 턴** — 스크립트 → LLM. LLM 을 쓸 수 있으면 패널 「에이전트」 로 옮겨 시작 턴이 돕니다(LLM 호출 한 번) — 이 TASK 의 사전 준비 · 지금까지 된 것 · 다음 단계를 설명하고 다음 행동을 제안합니다. 같은 작업 · 같은 TASK 에 진행 턴이 이미 있으면 다시 돌지 않습니다.
  - 안 맞으면: LLM 이 꺼져 있으면 옮기지 않고 패널 「작업 내용」 을 엽니다 — 에이전트 보기의 「작업 설명 듣기」 로 스크립트 설명을 볼 수 있습니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_작업에이전트.md ② §1
- **두 문서가 있는가** — 스크립트. 같은 프로젝트 · TASK · 라운드에 사업계획서와 연차보고서가 둘 다 있는지 봅니다.
  - 안 맞으면: 모자라면 패널 「작업 내용」 의 첨부 파일 칸에서 고르거나 올리게 합니다 — 프로젝트 이름이 없으면 다른 문서를 고를 수 없습니다.
  → 사양: spec_작업.md ② §11·§17
- **지금 문서가 목적 문서인가** — 스크립트. 연 문서가 연차보고서(목적 문서)인지 사업계획서(원본)인지 봅니다.
  - 안 맞으면: 원본을 열었으면 실행 행동을 내지 않고 「연차보고서 열기」 를 카드로 묻습니다(원본은 바뀌지 않습니다).
  → 공통 모듈: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7
- **프로젝트 구성 확정** — 스크립트. 사업계획서 기준의 프로젝트 구성을 프로젝트에 확정했는지 봅니다 — 저장된 값이 없으면 사업계획서에서 읽어 보입니다.
  - 안 맞으면: 확정 전이면 1단계가 지금 차례입니다 — 확정해야 2단계로 갑니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §18
- **연차보고서의 구조** — 스크립트. 연차보고서의 값이 사업계획서와 같은지, 그 값이 연차보고서에 반영됐는지 봅니다(당해 차년도는 견주지 않고, 다르면 글로 보입니다).
  - 안 맞으면: 값이 다르면 「사업계획서 기준으로 맞추기」, 반영 전이면 「변경 계획 보기」 가 다음 차례입니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §11·§14
- **헤딩 · 표 분석** — 스크립트. 두 문서에 헤딩 그래프 · 표 구조가 있는지 봅니다 — 문서를 고친 뒤에도 있던 분석을 씁니다.
  - 안 맞으면: 없으면 자리 연결 전에 분석합니다(「한 번에 진행」 은 스크립트로 저절로). 구조 반영으로 늘어난 절 · 표가 분석에 아직 없으면 알리기만 합니다.
  → 공통 모듈: 헤딩 추출 | 사양: spec_병합.md ② §3
- **연결 목록** — 스크립트. 분석이 있으면 두 문서의 자리를 이은 연결 목록을 읽습니다(연결됨 · 확인 필요 · 후보 없음 · 같은 이름 자리) — 같은 서식 쌍에 저장해 둔 짝이 있으면 먼저 씁니다.
  - 안 맞으면: 서버가 목록을 낼 수 없으면 까닭을 그대로 보입니다(헤딩·표 분석 없음 · 프로젝트 구성 값 없음 · 반영 전 · 값이 사업계획서와 다름 · hwpx 가 아님).
  → 사양: spec_병합.md ② §0-1·§4
- **지난 반영 기록** — 스크립트. 이 연차보고서에 앞서 넣은 자리의 기록이 남아 있는지 봅니다.
  - 안 맞으면: 있으면 넣기 계획 · 내용 반영을 끝난 것으로 보고, 더 넣을 것은 「넣기 계획 다시」 가 셉니다.
  → 사양: spec_병합.md ② §6
- **지울 양식 안내** — 스크립트. 연차보고서에서 지우는 패턴(작성 요령 표 · 「<참고 N>」 자료 · 안내 색 ※ 글 · 위첨자 각주 번호)에 걸린 자리를 셉니다.
  - 안 맞으면: 세지 못하면 까닭을 보이고 「다시 읽기」 를 냅니다.
  → 사양: spec_작업.md ② §14
- **지금 도는 실행** — 스크립트. 이 문서에 「한 번에 진행」(간단 모드 · 묶음 · 실행 카드)이 도는 중인지 봅니다.
  - 안 맞으면: 도는 동안 에이전트는 실행 · 저장하는 행동을 내지 않고 진행 카드만 보입니다 — 끝나면 이어서 안내합니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7

### 저절로 돌지 않는 것

시작할 때 돌 것 같지만 사람이 단추로 돌려야 하는 것입니다(유료 LLM).

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 기본 분석과 따로이고 올릴 때 돌지 않습니다 — 「헤딩 추출」 · 「표」 탭 머리의 「실행 ▾」 메뉴(또는 하위 탭 「추출·설정」 의 단계 카드) · 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」(실행 카드)로 돌립니다. 헤딩의 LLM 판정은 스크립트가 판정하지 못한 첫머리 묶음(못 맞춤 · 충돌)도 함께 봅니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **구분 기준 LLM 검토** — 사람 → LLM. 옵션입니다 — 문서 이름 줄의 「구분 기준」 표시나 프로젝트 구성의 「LLM 검토」 로 열어 「LLM 검토 실행」 을 눌러 돌립니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §20
- **이 TASK 의 LLM 검토** — 사람 → LLM. 자리 연결 LLM 검토 · 표 대응 · 빈 자리 검토 — 단계의 단추나, 확인을 받은 3단계 「한 번에 진행」 안에서 돕니다(유료). 올리거나 여는 것만으로는 돌지 않습니다.
  → 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 저절로/안 해도 됨/준비 중. 하는 일`, 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 공통 모듈 | 모듈(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 1단계 프로젝트 구성 — 단계 · 차년도 · 기관 구성만 정해 프로젝트에 확정 — 문서는 안 바뀜

- **준비** — 사람 · 문서 안 바뀜. 같은 프로젝트 · TASK · 라운드의 사업계획서와 연차보고서를 첨부 파일 칸에서 고릅니다(없으면 올립니다). LLM 을 쓸 수 있으면 패널 「에이전트」 가 열려 사전 준비와 다음 단계 묶음을 설명하고 진행합니다.
  - 하려면: 프로젝트 이름 — 없으면 같은 프로젝트의 다른 문서를 고를 수 없습니다(올리는 것은 됩니다).
  - 끝난 것으로 보는 때: 사업계획서 칸과 연차보고서 칸이 모두 찼을 때.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 에이전트 보기 | 사양: spec_작업.md ② §10·§17
- **프로젝트 구성 확정** — 스크립트 → 사람 · 저장만. 사업계획서에서 단계 · 차년도 · 기관 구성만 추출해 확인한 뒤 프로젝트에 저장(확정)합니다. 프로젝트에 이미 확정한 구성이 있으면 그것을 씁니다. 문서는 바뀌지 않습니다.
  - 하려면: 준비가 끝난 뒤.
  - 끝난 것으로 보는 때: 값을 프로젝트에 확정했고 확정한 뒤 값이 바뀌지 않았을 때 — 프로젝트에 이미 확정한 구성이 있으면 끝난 것으로 봅니다.
  - 멈추는 때: 사업계획서에 저장된 값이 없으면 문서에서 읽어 보이고 사람이 확인해 저장(확정)합니다 — 읽지 못하면 묻습니다. 확정한 뒤 값을 바꾸면 다시 확정해야 2단계로 갑니다.
  → 확정한 프로젝트 구성 | 공통 모듈: 프로젝트 구성(구분 기준) | 모듈: `division_model` · `projects` | 사양: spec_작업.md ② §18

### 2단계 문서 프레임 작성 — 연차보고서의 구조를 값에 맞춤 — 내용은 넣지 않음

- **① 프로젝트 구성 반영** — 스크립트 → 사람 · 문서 바뀜. 연차보고서의 값을 사업계획서 기준으로 맞추고 변경 계획(바뀔 자리)을 확인한 뒤 반영합니다 — 절 · 표 행 · 표 열만 늘리고 줄입니다. 계획서의 내용은 넣지 않습니다.
  - 하려면: 1단계 확정 · 사업계획서(기준)의 프로젝트 구성 값.
  - 끝난 것으로 보는 때: 연차보고서의 값이 사업계획서와 같고 그 값이 연차보고서에 반영됐을 때.
  - 멈추는 때: 계획을 못 세웠거나 · 계획 오류 · 미해결 자리가 있거나 · 기관의 차례가 마지막 반영과 다르면 「한 번에 진행」 이 반영하지 않고 멈춥니다.
  - 남기는 것 · 보정: 지원 안 되는 자리는 그대로 둡니다.
  → 구조를 맞춘 연차보고서 | 공통 모듈: 프로젝트 구성(구분 기준) | 모듈: `division_plan` · `division_model` | 사양: spec_작업.md ② §11·§14

### 3단계 내용 매핑 — 두 문서의 헤딩 · 표를 분석해 자리를 잇고, 계획서의 내용을 그 자리에 넣음(서식 맞춤)

- **헤딩 · 표 분석** — 스크립트 · 저장만. 두 문서에 헤딩 그래프 · 표 구조가 없으면 스크립트로 분석합니다(LLM 호출 없음). 구조 반영으로 늘어난 절 · 표는 「한 번에 진행」 이 다시 분석합니다.
  - 하려면: 사업계획서 · 연차보고서 두 문서(hwpx).
  - 끝난 것으로 보는 때: 두 문서에 헤딩 그래프 · 표 구조가 있을 때 — 문서를 고친 뒤에도 있던 분석을 씁니다(다시 하라고 하지 않습니다).
  - 남기는 것 · 보정: 구조 반영으로 늘어난 절 · 표가 분석에 아직 없으면 알리기만 하고, 3단계 「한 번에 진행」 이 다시 분석합니다.
  → 공통 모듈: 헤딩 추출 | 모듈: `heading_runs` · `heading_compare` | 사양: spec_병합.md ② §3
- **② 자리 연결** — 스크립트 · 저장만. 두 문서의 자리(문단 묶음 · 표)를 구분 기준 값과 이름으로 잇습니다 — 연결됨 · 확인 필요 · 후보 없음. 같은 서식 쌍에 저장해 둔 짝이 있으면 그것을 먼저 씁니다.
  - 하려면: 두 문서의 헤딩 · 표 분석 · 프로젝트 구성이 반영된 연차보고서 — 서버가 목록을 못 내는 까닭(분석 없음 · 값 없음 · 반영 전 · 값이 사업계획서와 다름)이 없을 때.
  - 끝난 것으로 보는 때: 연결 목록에 확인 필요가 없거나, LLM 검토를 한 번 했을 때.
  - 남기는 것 · 보정: LLM 검토 뒤에도 남은 확인 필요 자리는 넣지 않고 비워 둡니다(각 기관이 이어서 작성) — 「연결 목록」 에서 후보를 골라 보정합니다.
  → 연결 목록 | 모듈: `merge_pairs` · `merge_fixed` · `merge_saved` · `merge_api` | 사양: spec_병합.md ② §0-1·§4·§5-1
- **자리 연결 LLM 검토** — LLM · 저장만 · 안 해도 됨. 확인 필요로 남은 자리와 같은 표인지 못 정한 표를 LLM 이 쪽 묶음마다 판정합니다. 한 번 검토한 뒤에도 남은 자리는 넣지 않고 비워 둡니다.
  - 하려면: 연결 목록에 확인 필요 · 후보 없음 자리나 같은 표인지 못 정한 표가 있을 때 · LLM(유료 — 단추나 확인을 받은 3단계 「한 번에 진행」 안에서).
  - 끝난 것으로 보는 때: 한 번 검토했을 때 — 안 해도 넣기 계획은 세울 수 있습니다.
  - 남기는 것 · 보정: 한 번 검토한 뒤에도 남은 자리는 넣지 않고 비워 둡니다.
  → 에이전트: 09 자리 연결 검토 | 모듈: `merge_llm` · `merge_chunks` · `merge_guides` · `job_prompts` | 사양: spec_병합.md ② §4
- **③ 표 안 연결 · 넣기 계획** — 스크립트 · 문서 안 바뀜. 이어진 자리마다 넣을 본문 블록 · 표 칸 · 늘릴 행과 못 넣는 까닭을 셉니다. 문서는 바뀌지 않습니다.
  - 하려면: 이어진 자리(연결됨 · 같은 이름 자리)가 하나라도 있을 때 — ② 에 확인 필요가 남아 있어도 세울 수 있습니다.
  - 끝난 것으로 보는 때: 넣기 계획이 있거나 · 이미 반영했거나 · 이어진 자리가 없어 계획할 것이 없거나 · 지난 반영 기록이 남아 있을 때.
  - 남기는 것 · 보정: 못 넣는 자리는 까닭과 함께 셉니다.
  → 넣기 계획 | 모듈: `merge_fill` · `merge_tables` | 사양: spec_병합.md ② §5·§6
- **표 대응(LLM)** — LLM · 저장만 · 안 해도 됨. 같은 표로 이었지만 두 서식의 행 · 열 구성이 달라 칸을 못 맞춘 표를 표마다 LLM 이 대응시킵니다 — 글은 LLM 이 쓰지 않고 사업계획서 칸의 글을 옮깁니다.
  - 하려면: 같은 표로 이었지만 행 · 열 구성이 달라 칸을 못 맞춘 표가 있을 때 · LLM(유료).
  - 끝난 것으로 보는 때: 칸을 못 맞춘 표가 남지 않았을 때 — 안 해도 됩니다.
  - 남기는 것 · 보정: 글은 LLM 이 쓰지 않습니다 — 사업계획서 칸의 글을 옮깁니다.
  → 에이전트: 10 표 대응 연결 | 모듈: `merge_table_map` | 사양: spec_병합.md ② §5-3
- **빈 자리 검토(LLM)** — LLM · 저장만 · 안 해도 됨. 다른 길이 못 채운 빈 표 · 글머리만 있는 칸 · 라벨만 있는 줄을 모아 사업계획서의 어디에서 가져올지 LLM 이 찾습니다(없으면 없다고 답합니다).
  - 하려면: 넣기 계획이 있고 다른 길이 못 채운 빈 자리가 있을 때 · LLM(유료).
  - 끝난 것으로 보는 때: 아직 묻지 않은 빈 자리가 남지 않았을 때 — 안 해도 됩니다.
  - 남기는 것 · 보정: 가져올 곳이 없으면 없다고 답하고 비워 둡니다.
  → 에이전트: 11 빈 자리 검토 | 모듈: `merge_gaps` | 사양: spec_병합.md ② §5-4
- **④ 내용 반영** — 사람 → 스크립트 · 문서 바뀜. 「계획 보기」 에서 확인하고 「반영」 을 누르면 계획서의 글 · 표 · 그림이 그 자리에 들어갑니다 — 서식은 연차보고서의 틀에 맞추고, 넣는 내용의 개요가 자리보다 깊으면 넘친 개요 레벨로 처리합니다.
  - 하려면: 넣기 계획 — 「계획 보기」 에서 확인하고 「반영」.
  - 끝난 것으로 보는 때: 반영했거나 · 넣을 것이 없거나(이미 넣었거나 넣을 자리가 없음) · 지난 반영 기록이 남아 있을 때.
  - 남기는 것 · 보정: 같은 자리인지 분명하지 않은 자리는 비워 둡니다(초안 — 실패가 아닙니다).
  → 내용이 들어간 연차보고서 | 모듈: `merge_fill` · `merge_tables` · `merge_convert` · `merge_over` · `merge_origins` | 사양: spec_병합.md ② §5-2·§5-5·§6
- **⑤ 합계 계산 → 결과 확인** — 스크립트 · 문서 안 바뀜 · 준비 중. 아직 없는 단계입니다 — 넣은 값으로 합계 · 소계 · 비율 칸을 다시 세고 결과를 검사할 자리. 지금은 원본과 줄이 같은 합계 칸만 옮기고 나머지 계산 칸은 비워 둡니다.

### 4단계 문서 정리 — 연차보고서 서식이 글쓴이에게 주는 안내를 지움

- **⑥ 작성요령 삭제** — 스크립트 → 사람 · 문서 바뀜. 지우는 패턴 목록에 걸린 양식 안내(작성 요령 표 · 「<참고 N>」 자료 · 안내 색 ※ 글 · 위첨자 각주 번호)를 확인 창 뒤 한 번에 지웁니다. 내용과 쓸 자리는 남깁니다.
  - 하려면: ④ 내용 반영이 끝난 연차보고서.
  - 끝난 것으로 보는 때: ④ 가 끝났고 지울 안내가 남지 않았을 때.
  - 멈추는 때: 확인 창 뒤에 한 번에 지웁니다 — 멈춤을 요청했거나 그 사이 다른 문서를 열었으면 지우지 않고 멈춤으로 보고합니다.
  - 남기는 것 · 보정: 지우는 패턴 목록에 없는 안내와 내용 · 쓸 자리는 남깁니다.
  → 안내를 지운 연차보고서 | 모듈: `form_cleanup` | 사양: spec_작업.md ② §14

## 쓰는 공통 모듈

단계가 「공통 모듈」 로 가리키는 과정 — 그 과정의 단계는 [workflow.md](../workflow.md) 의 「공통 모듈」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 TASK 든 문서를 올리면 먼저 거치는 과정입니다 — 작업(문서마다의 저장 공간)이 생기고, 새 작업이면 기본 분석(헤딩 · 표 — 스크립트)이 저절로 돕니다. 어디까지 됐는지는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 주고받는 대화창입니다 — TASK 를 시작하면 에이전트가 사전 준비와 진행 상황을 설명하고 다음 단계를 제안·실행하며(작업 진행), 글로 요청하면 제안(글 · 새 표 · 표 채우기 · 서식 입히기 · 서식 복사)을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 빈 동안은 「지금 할 수 있는 일」 — 현재 작업 진행 현황 보고(스크립트 · 무료) · 남은 헤딩·표 LLM 검토(실행 카드 · 유료) · 서식 반영 — 을 고릅니다. 어느 TASK 의 문서에서나 엽니다.
- **프로젝트 구성(구분 기준)**(`division`) — 단계 · 차년도 · 기관 값(프로젝트 구성)에 맞춰 문서의 절 · 표 행 · 표 열을 늘리고 줄입니다. 값은 프로젝트에 하나이고 그 프로젝트의 TASK 들이 같이 씁니다.
- **헤딩 추출**(`headings`) — 문서의 개요(헤딩)와 표의 구조를 뽑아 뼈대로 둡니다 — 자리 연결 · 넣기 · 서식 후보 · 템플릿 관계가 이 뼈대를 씁니다. 문서는 바꾸지 않습니다. 어디까지 했는지는 탭 위 진행 줄에 두 층으로 보입니다 — 스크립트(문단·라벨 · 헤딩 그래프 · 표 구조)와 LLM(규칙 보강 · 헤딩 판정 · 표 판정). LLM 칸(✓)을 누르면 문서 옆 열 「LLM 이 바꾼 것」 에 LLM 이 스크립트와 다르게 정한 것(규칙 · 노드 · 서식 쌍 판정 · 표 칸 역할 · 받아 둔 서식 계획)이 보입니다 — LLM 판정은 문서를 바꾸지 않습니다.
