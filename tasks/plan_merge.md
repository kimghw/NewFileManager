# 사업계획서 취합 — `plan_merge`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(TASK 문서 — 화면 `/workflow` 의 이 TASK 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [workflow.md](../workflow.md) 가 모든 TASK 의 차례를 보이는 **전체 지도**라면 이 글은 이 TASK 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

기관이 나눠 쓴 문서의 내용을 사업계획서 하나로 모읍니다.

- 받는 문서: 사업계획서(취합본 — 목적 문서) + 기관이 채워 돌려준 문서들(기관 문서 — 원본 문서, 여럿)
- 산출물: 기관의 내용을 모은 취합본 하나 + 자리 · 반영 기록
- 알아 둘 것: 기관 문서는 2단계에서 만든 배포 기준본을 나눠 받아 각 기관이 자기 몫만 채워 돌려준 문서입니다. 취합본에 이미 글이 있는 자리는 덮지 않고 「겹침」 으로 알립니다 · 기관 문서(원본)는 바뀌지 않습니다. 간단 모드 — 시작 화면에서 문서를 한꺼번에 올리고 취합본만 고르면 1 → 3단계를 끝까지 자동으로 합니다(확인 창 없이).
- 한 번에 진행: 간단 모드 — 시작 화면의 문서 목록에서 취합본을 목적 문서로 고르고 「자동 진행」 을 켠 뒤 TASK 카드를 누르면(확인 창 없이) 기관 문서 올리기 → 1단계 → 2단계 → 3단계를 끝까지 합니다. 진행과 결과(기관 문서마다 넣은 것 · 남긴 것)는 에이전트 보기의 진행 카드와 보고로 봅니다. 연 뒤에는 에이전트가 남은 묶음의 「한 번에 진행」 을 묶음마다 실행 카드로 제안합니다.
- 에이전트가 묻는 것: 목적 문서(취합본) · 기관 문서마다 반영할 기관(파일 이름 → 추천으로 정하고, 못 정한 문서는 넣지 않고 남깁니다) · 프로젝트 구성(값이 없으면 취합본에서 읽습니다).
- 멈추거나 남기는 곳 · 보정: 구조를 맞추려면 지워야 하는 곳 · 계획 오류 · 미해결 자리가 있으면 2단계에서 멈춥니다. 겹침 · 확인 필요 · 표 구조가 다른 내용은 넣지 않고 남깁니다(실패가 아닙니다) — 기관 문서마다 「남긴 것 보기」 목록이나 끌어 넣기로 보정합니다. 못 올린 문서는 「이어서」 가 다시 올립니다.
- 단계별(세부 작업): 패널 「작업 개요」 의 묶음마다 세부 목록 — 반영할 기관 지정 · LLM 검토 · 넣기 계획 · 반영을 기관 문서마다 보고 고르며 할 때(세부 작업 모드).
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/plan_merge.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 공통 모듈 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### TASK 를 시작할 때

시작 화면의 TASK 카드 · 문서 목록 · 첫 화면 대화창에서, 문서를 올리기 전에 봅니다 — 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 TASK 가 받는 형식(hwp · hwpx)인지 봅니다.
  - 안 맞으면: 시작하지 않고 알립니다 — docx 는 「TASK 없이 열기」 로 열거나 TASK 「문서 서식 복사」 로 시작합니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 골랐는지 봅니다 — 하나면 그 파일이 목적 문서입니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다 — 어느 파일인지 짐작하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **기관 문서 · 자동 진행** — 스크립트 → 사람. 목적 문서(취합본)가 아닌 문서는 기관 문서로 봅니다 — hwp · hwpx 인지 보고, 「자동 진행」 을 켰으면 기관 문서가 하나 이상 있는지 봅니다(그 뒤 확인 창 없이 끝까지 — 2026-11-18).
  - 안 맞으면: docx 가 섞였거나 자동 진행인데 기관 문서가 없으면 시작하지 않고 알립니다. 「자동 진행」 을 끄면 올리고 등록만 합니다(세부 작업 모드).
  → 사양: spec_취합.md ② §8

### 문서를 올릴 때

올리면 저절로 도는 것입니다 — 사람이 누르지 않고, 유료 LLM 호출이 없습니다.

- **작업 만들기 · 같은 파일 고르기** — 스크립트. 올린 파일로 작업(문서마다의 저장 공간)을 만듭니다. 같은 파일로 하던 작업이 있으면 열기 전에 묻습니다 — 이 TASK 의 작업 → TASK 가 빈 작업 차례로 줄마다 「이어서」 · 「초기화하고 열기」, 맨 아래 「새 작업으로 시작」(프로젝트 칸). hwp 는 한글이 hwpx 로 바꿔 받습니다.
  - 안 맞으면: 다른 TASK · 프로젝트 · 역할을 하던 작업은 「그대로 열기」 만이고 고르면 그 작업을 열고 이 TASK 시작은 멈춥니다(그 작업의 TASK 는 안 바꿈). 창을 닫으면 아무것도 열지 않습니다. 올리지 못하면 까닭을 알리고 시작하지 않습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§3-1·§15
- **양식 판정 · 문서 종류** — 스크립트. 목적 문서는 취합본(사업계획서)으로 적습니다.
  - 안 맞으면: 카드에 파일 하나만 올렸고 양식 판정이 종류를 못 정하면 사업계획서로 둡니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **TASK · 프로젝트 · 라운드** — 스크립트. 작업에 이 TASK 를 적습니다. 문서 목록에 프로젝트 이름을 적었으면 그 프로젝트의 이 TASK 다음 라운드로 시작합니다. 비우면 임시 이름(임시 프로젝트 N)으로 함께 올린 문서를 묶습니다.
  - 안 맞으면: 임시 이름은 연 뒤 「작업 개요」 의 프로젝트 칸이나 작업 리스트의 「이름 정하기」 에 이름을 적으면 바뀝니다 — 이미 있는 프로젝트 이름이면 그 프로젝트로 문서를 모두 옮깁니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **기관 문서 올리기 · 등록 · 분석** — 스크립트. 함께 올린 기관 문서를 목록 차례로 올려 취합본에 등록하고, 문서마다 헤딩 · 표를 스크립트로 분석합니다(화면에 열지 않습니다). 자동 진행이면 이어서 1 → 3단계를 끝까지 하고, 반영할 기관은 파일 이름에 든 기관 이름 → 넣을 수 있는 내용이 가장 많은 기관 차례로 정합니다.
  - 안 맞으면: 못 올린 문서는 남기고 알립니다 — 「간단 모드 이어서」 가 다시 올립니다. 반영할 기관을 못 정한 문서는 넣지 않고 남깁니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_취합.md ② §8
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 웹 화면이 제대로 읽었는지 검사합니다(한글 · Word 가 있으면 PDF 로 찍어 견줌) — 기본 분석과 함께 돌고, 결과는 패널 머리 「검증」 에 보입니다. 주의 · 실패가 나면 마지막 「LLM 검토」(LLM 호출 한 번)가 저절로 돌아 그 단계가 실제 문제인지 기준 PDF 쪽 사정인지 가립니다.
  - 안 맞으면: LLM 을 쓸 수 없거나 호출이 실패하면 스크립트 판정 그대로 두고 「LLM 검토」 단계에 까닭을 적습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 한 번, 헤딩 그래프 → 표 구조를 스크립트만으로 분석합니다(hwpx). 이미 결과가 있는 단계는 건너뛰고, 이어 연 작업에서는 돌지 않습니다.
  - 안 맞으면: 시작하지 못했으면 문서 이름 줄이 「헤딩 없음 · 표 없음」, 돌다 실패했으면 멈춘 단계가 「실패」 입니다 — 이름 줄의 「분석」 단추로 다시 돌립니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 헤딩 · 템플릿 · 서식 · 표 · LLM 검증·보완 · 구분 기준 검토가 어디까지 됐는지 보입니다 — 어느 TASK 에서나 같은 꼴입니다(누르면 진행표).
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **편집 구역의 기준 적기** — 스크립트. 시작 화면 문서 목록의 묶음 「편집 구역」 에서 기준(기관 · 단계 · 차년도)을 골랐으면, TASK 를 적은 뒤 그 TASK 묶음의 옵션으로 적습니다.
  - 안 맞으면: 손대지 않았으면 적지 않습니다 — 그 TASK 의 기본값(취합 = 기관 · 그 밖은 꺼짐)으로 시작하고, 연 뒤 「편집 구역」 줄에서 바꿉니다.
  → 공통 모듈: 편집 구역 | 사양: spec_구역.md ② §1

### TASK 화면을 열 때

패널 「작업 개요」 와 에이전트의 시작 턴이 지금 상태를 셈합니다 — 여기서 모자란 것이 사전 준비입니다.

- **에이전트의 시작 턴** — 스크립트 → LLM. LLM 을 쓸 수 있으면 에이전트 창(상단 바의 에이전트 아이콘 — 패널 탭에 넣었으면 그 탭)이 열려 시작 턴이 돕니다(LLM 호출 한 번) — 이 TASK 의 사전 준비 · 지금까지 된 것 · 다음 단계를 설명하고 다음 행동을 제안합니다. 같은 작업 · 같은 TASK 에 진행 턴이 이미 있으면 다시 돌지 않습니다.
  - 안 맞으면: LLM 이 꺼져 있으면 옮기지 않고 패널 「작업 개요」 를 엽니다 — 에이전트 보기의 「작업 설명 듣기」 로 스크립트 설명을 볼 수 있습니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_작업에이전트.md ② §1
- **취합본이 있는가 · 지금 문서가 취합본인가** — 스크립트. 취합본(목적 문서)을 골랐는지, 연 문서가 취합본인지 기관 문서인지 봅니다.
  - 안 맞으면: 취합본이 없으면 패널 「작업 개요」 에서 고르게 하고, 기관 문서를 열었으면 실행 행동 대신 「취합본 열기」 를 카드로 묻습니다(기관 문서는 바뀌지 않습니다).
  → 공통 모듈: 에이전트 보기 | 사양: spec_취합.md ② §5
- **프로젝트 구성 확정** — 스크립트. 취합본의 프로젝트 구성을 프로젝트에 확정했는지 봅니다.
  - 안 맞으면: 값이 없으면 취합본에서 추출하거나 불러오게 합니다 — 확정해야 2단계로 갑니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §18
- **취합본의 구조** — 스크립트. 확정한 값이 취합본에 반영됐는지(구조가 이미 값에 맞으면 확인만), 자동 반영을 지원하는 양식인지 봅니다.
  - 안 맞으면: 반영 전이면 「변경 계획 보기」 가 다음 차례입니다. 지원하지 않는 양식이면 자동 반영을 하지 않습니다(연구개발계획서 양식만).
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_취합.md ② §3
- **배포 기준본** — 스크립트. 배포 기준본이 있는지, 만든 뒤 프로젝트 구성을 다시 반영해 낡았는지 봅니다.
  - 안 맞으면: 없거나 낡았으면 기관 문서 줄이 열리지 않습니다 — 새로 만듭니다(낡은 기준본으로 온 기관 문서는 저절로 넣지 않습니다).
  → 사양: spec_취합.md ② §3
- **기관 문서마다** — 스크립트. 반영할 기관을 정했는지 · 자리 연결을 막는 까닭(다른 판의 기준본 · 헤딩·표 분석 없음 …)이 있는지 · 넣을 것이 남았는지 · 넣지 않고 남긴 것(겹침 · 확인 필요 · 표 구조 다름)이 몇 곳인지 봅니다.
  - 안 맞으면: 기관 미지정인 문서는 넣지 않고 다른 문서는 그대로 진행합니다. 남긴 것이 있으면 에이전트가 그 문서의 「남긴 것 보기」 를 냅니다(문서 셋까지).
  → 공통 모듈: 에이전트 보기 | 사양: spec_취합.md ② §4-1·§5
- **간단 모드의 끝** — 스크립트. 첫 화면에서 돌린 간단 모드가 멈췄는지, 못 올린 문서가 남았는지 봅니다.
  - 안 맞으면: 남았으면 「간단 모드 이어서」 를 실행 카드로 냅니다(앞서 넣은 것은 다시 넣지 않습니다).
  → 공통 모듈: 에이전트 보기 | 사양: spec_취합.md ② §8
- **편집 구역 — 보일 기준과 구역 읽기** — 스크립트. 이 TASK 묶음(프로젝트 · TASK · 라운드)의 옵션 — 편집 구역에서 보일 기준(기관 · 단계 · 차년도) — 을 읽고, 켠 기준이 있으면 문서의 문단 · 표 · 표 칸이 어느 기관 · 단계 · 차년도의 것인지 스크립트로 읽어 색 띠와 이름표로 보입니다 — 취합은 기관이 기본으로 켜져 있어 기관 구역과 기관 문서에서 넣은 내용이 바로 보입니다.
  - 안 맞으면: 켠 기준이 없으면 구역을 읽지 않습니다 — 패널 「작업 개요」 의 「편집 구역」 줄에서 켭니다. 프로젝트 구성 값이 없으면 셀 수 없다고 알립니다.
  → 공통 모듈: 편집 구역 | 사양: spec_구역.md ② §1·§6
- **지금 도는 실행** — 스크립트. 이 문서에 「한 번에 진행」(간단 모드 · 묶음 · 실행 카드)이 도는 중인지 봅니다.
  - 안 맞으면: 도는 동안 에이전트는 실행 · 저장하는 행동을 내지 않고 진행 카드만 보입니다 — 끝나면 이어서 안내합니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7

### 저절로 돌지 않는 것

시작할 때 돌 것 같지만 사람이 단추로 돌려야 하는 것입니다(유료 LLM).

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 기본 분석과 따로이고 올릴 때 돌지 않습니다 — 「헤딩 추출」 · 「테이블」 탭 머리의 「단계별 실행 ▾」 메뉴(돌릴 단계를 여러 개 골라 「고른 n개 실행」 — 고른 것만 차례로 · 또는 하위 탭 「추출·설정」 의 단계 카드 · 헤딩 추출 탭의 「전체 실행」 은 조정까지 한 번에) · 헤딩 추출 탭 진행 줄 「조정」 끝의 「LLM 판정」(판정을 아직 안 한 문서) · 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」(실행 카드)로 돌립니다. 헤딩의 LLM 판정은 스크립트가 판정하지 못한 첫머리 묶음(못 맞춤 · 충돌)도 함께 봅니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **구분 기준 LLM 검토** — 사람 → LLM. 옵션입니다 — 문서 이름 줄의 「구분 기준」 표시나 프로젝트 구성의 「LLM 검토」 로 열어 「LLM 검토 실행」 을 눌러 돌립니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §20
- **편집 구역 LLM 검토** — 사람 → LLM. 옵션입니다 — 「편집 구역」 줄의 「LLM 검토」 를 눌러야 돕니다(유료). 스크립트가 기관 · 차년도를 못 정한 표 · 자리를 LLM 이 보고, 정한 것은 「LLM」 지정으로 따로 보입니다 — 문서는 바뀌지 않습니다.
  → 공통 모듈: 편집 구역 | 사양: spec_구역.md ② §8
- **이 TASK 의 LLM 검토** — 사람 → LLM. 기관 작성 내용의 LLM 검토 — 기관 문서 줄의 「LLM 검토」 단추나, 확인을 받은 「한 번에 진행」 · 간단 모드 안에서 돕니다(유료). 올리거나 여는 것만으로는 돌지 않습니다.
  → 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 자동/필수/선택/준비 중. 하는 일`, 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 공통 모듈 | 모듈(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 1단계 프로젝트 구성 — 단계 · 차년도 · 기관 구성만 정해 프로젝트에 확정 — 문서는 안 바뀜

- **준비** — 사람 · 문서 안 바뀜 · 필수. 사업계획서(취합본)를 올리거나 같은 프로젝트의 문서에서 고릅니다. LLM 을 쓸 수 있으면 에이전트 창(상단 바의 에이전트 아이콘)이 열려 사전 준비와 다음 단계 묶음을 설명하고 진행합니다.
  - 하려면: 프로젝트 이름 — 없으면 같은 프로젝트의 다른 문서를 고를 수 없습니다(올리는 것은 됩니다).
  - 끝난 것으로 보는 때: 취합본을 골랐을 때.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 에이전트 보기 | 사양: spec_작업.md ② §10·§17
- **프로젝트 구성 확정** — 스크립트 → 사람 · 저장만 · 필수. 취합본에서 단계 · 차년도 · 기관 구성만 추출해 확인한 뒤 프로젝트에 저장(확정)합니다. 프로젝트에 이미 확정한 구성이 있으면 그것을 씁니다. 문서는 바뀌지 않습니다.
  - 하려면: 준비가 끝난 뒤.
  - 끝난 것으로 보는 때: 값을 프로젝트에 확정했고 확정한 뒤 값이 바뀌지 않았을 때 — 프로젝트에 이미 확정한 구성이 있으면 끝난 것으로 봅니다.
  - 멈추는 때: 취합본에 저장된 값이 없으면 문서에서 읽어 보이고 사람이 확인해 저장(확정)합니다 — 읽지 못하면 묻습니다. 확정한 뒤 값을 바꾸면 다시 확정해야 2단계로 갑니다.
  → 확정한 프로젝트 구성 | 공통 모듈: 프로젝트 구성(구분 기준) | 모듈: `division_model` · `projects` | 사양: spec_작업.md ② §18

### 2단계 문서 프레임 작성 — 취합본의 구조를 값에 맞추고, 기관에 나눠 줄 기준본을 고정

- **① 프로젝트 구성 반영** — 스크립트 → 사람 · 문서 바뀜 · 필수. 확정한 값에 맞춰 취합본의 변경 계획(바뀔 자리)을 확인한 뒤 반영합니다 — 절 · 표 행 · 표 열만 늘리고 줄입니다.
  - 하려면: 1단계 확정 · 프로젝트 구성 자동 반영을 지원하는 양식(연구개발계획서 양식).
  - 끝난 것으로 보는 때: 확정한 값이 취합본에 반영됐거나, 구조가 이미 값에 맞아 확인만 했을 때.
  - 멈추는 때: 계획을 못 세웠거나 · 계획 오류 · 미해결 자리가 있거나 · 기관의 차례가 마지막 반영과 다르면 「한 번에 진행」 이 반영하지 않고 멈춥니다. 간단 모드는 구조를 맞추려면 글을 지워야 하는 곳이 있어도 멈춥니다.
  - 남기는 것 · 보정: 지원 안 되는 자리는 그대로 둡니다.
  → 구조를 맞춘 취합본 | 공통 모듈: 프로젝트 구성(구분 기준) | 모듈: `division_plan` · `division_model` | 사양: spec_취합.md ② §3
- **◆ 배포 기준본 만들기** — 스크립트 → 사람 · 저장만 · 필수. 구조를 맞춘 취합본 파일과 자리 정보(자리마다 기관 · 차년도 · 문단 헤딩 · 표 · 서식)를 고정합니다. 헤딩 · 표 분석이 지금 문서의 것이 아니면 먼저 다시 분석합니다. 프로젝트 구성을 다시 반영하면 기준본이 낡으므로 새로 만듭니다.
  - 하려면: ① 프로젝트 구성 반영이 끝난 취합본.
  - 끝난 것으로 보는 때: 배포 기준본이 있고 낡지 않았을 때 — 프로젝트 구성을 다시 반영하면 낡습니다(새로 만듭니다).
  - 남기는 것 · 보정: 낡은 기준본으로 온 기관 문서는 저절로 넣지 않습니다. 간단 모드에서 기준본이 없으면 취합본의 그때 모습을 기준본으로 봅니다.
  → 배포 기준본(hwpx) + 자리 정보 | 공통 모듈: 헤딩 추출 | 모듈: `merge_gather_frame` · `merge_gather_api` | 사양: spec_취합.md ② §3
- **기관에 배포 · 회수** — 사람 · 문서 안 바뀜 · 필수. 기준본을 내려받아 기관에 나눠 주고, 기관은 자기 몫만 채워 돌려줍니다(앱 밖의 일).
  - 하려면: 배포 기준본(「기준본 내려받기」).
  - 끝난 것으로 보는 때: 앱이 세지 않습니다 — 앱 밖의 일입니다(기관 문서가 들어오면 3단계).
  → 기관 문서들

### 3단계 내용 매핑 — 기관 문서가 들어올 때마다 그 내용을 취합본의 같은 자리에 넣음 — 기관 문서마다 되풀이

- **기관 문서 올리기 · 반영할 기관 지정** — 사람 · 저장만 · 필수. 기관 문서를 올리고 어느 기관의 문서인지 고릅니다 — 미지정이면 그 문서는 넣지 않습니다(다른 문서는 그대로 진행).
  - 하려면: 낡지 않은 배포 기준본 — 없으면 기관 문서 줄이 열리지 않습니다.
  - 끝난 것으로 보는 때: 그 문서의 반영할 기관을 정했을 때.
  - 남기는 것 · 보정: 기관 미지정인 문서는 넣지 않습니다 — 다른 문서는 그대로 진행합니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 모듈: `merge_gather_api` | 사양: spec_취합.md ② §2·§5
- **헤딩 · 표 분석** — 스크립트 · 저장만 · 자동. 기관 문서를 올릴 때 헤딩 그래프 · 표 구조를 스크립트로 분석합니다(LLM 호출 없음) — 넣을 때의 틀 맞춤 · LLM 검토의 서식 정보 · 끌어 넣기의 범위에 씁니다. 자리 연결 자체는 분석이 아니라 문서의 블록을 차례로 견줍니다.
  - 하려면: 올린 기관 문서(hwpx).
  - 끝난 것으로 보는 때: 그 기관 문서에 헤딩 · 표 분석이 있을 때.
  - 멈추는 때: 분석이 없으면 자리 연결을 할 수 없습니다 — 그 줄의 「헤딩·표 분석」 으로 다시 돌립니다(스크립트).
  → 공통 모듈: 헤딩 추출 | 모듈: `heading_runs` | 사양: spec_취합.md ② §4-1
- **② 자리 연결 · 기관 작성 내용 판정** — 스크립트 · 문서 안 바뀜 · 필수. 기준본 · 기관 문서 · 취합본을 견줘 기관이 더하거나 고친 것(기관 작성 내용)을 찾고 취합본의 같은 자리에 잇습니다. 프레임에 원래 있던 것(제목 줄 · 빈 틀 · 안내 글)과 서식만 바뀐 것은 넣지 않습니다.
  - 하려면: 배포 기준본 · 반영할 기관 · 기관 문서의 분석 — 막는 까닭(기준본 없음 · 낡음 · 다른 판의 기준본 · 분석 없음)이 없을 때.
  - 끝난 것으로 보는 때: 기준본과 견줘 기관 작성 내용의 수가 나왔을 때.
  - 남기는 것 · 보정: 기준본과 자리를 충분히 확인하지 못한 문서는 막지 않고, 「기관 작성 내용」 에서 사람이 넣음을 켠 것만 넣습니다. 기준본과 맞는 자리를 찾지 못한 문서는 끌어 넣기만 됩니다.
  → 기관 작성 내용 목록 | 모듈: `merge_gather` · `merge_gather_frame` | 사양: spec_취합.md ② §4-1·§4-2
- **LLM 검토** — LLM · 저장만 · 선택. 넣기로 한 기관 작성 내용이 실제로 기관이 쓴 내용인지, 양식의 안내 글 · 빈 틀인지를 취합본의 챕터별로 봅니다 — 넣을 것을 줄이기만 합니다(안 해도 넣기 계획은 세울 수 있음).
  - 하려면: 넣을 수 있는 기관 작성 내용이 있을 때 · LLM(유료 — 단추나 확인을 받은 「한 번에 진행」 안에서).
  - 끝난 것으로 보는 때: 한 번 검토했을 때 — 안 해도 넣기 계획은 세울 수 있습니다.
  - 남기는 것 · 보정: LLM 은 넣을 것을 줄이기만 합니다 — 보류는 확인 필요로 두고, 스크립트가 막은 것을 넣게 하지 못하며, 사람이 고른 것은 바꾸지 않습니다.
  → 에이전트: 12 취합 검토 | 모듈: `merge_gather_llm` · `merge_guides` · `job_prompts` | 사양: spec_취합.md ② §4-3
- **③ 넣기 계획** — 스크립트 · 문서 안 바뀜 · 필수. 넣을 문단 · 표 · 그림 · 칸 · 행을 셉니다. 겹치는 자리는 넣지 않고 「겹침」 으로 둡니다. 문서는 바뀌지 않습니다.
  - 하려면: 자리 연결이 끝난 기관 문서.
  - 끝난 것으로 보는 때: 그 문서의 넣기 계획이 있을 때 — 계획 뒤 문서나 설정이 바뀌면 다시 계획합니다.
  - 남기는 것 · 보정: 겹치는 자리는 넣지 않고 「겹침」 으로 둡니다.
  → 넣기 계획 | 모듈: `merge_gather` | 사양: spec_취합.md ② §4-4
- **④ 내용 반영 · 틀 맞춤** — 사람 → 스크립트 · 문서 바뀜 · 필수. 「계획 보기」 에서 확인하고 「반영」 을 누르면 취합본에 들어갑니다 — 서식은 취합본의 틀에 맞추고, 기관이 틀보다 깊게 쓴 개요는 넘친 개요 레벨로 처리합니다.
  - 하려면: 넣을 것이 있는 넣기 계획 — 「계획 보기」 에서 확인하고 「반영」.
  - 끝난 것으로 보는 때: 그 기관 문서에서 더 넣을 것이 없을 때(넣었거나 · 이미 들어 있음).
  - 남기는 것 · 보정: 겹침 · 확인 필요 · 표 구조가 다른 내용은 넣지 않고 남깁니다(실패가 아닙니다) — 기관 문서마다 「남긴 것 보기」 목록이나 끌어 넣기로 보정합니다.
  → 내용이 들어간 취합본 | 모듈: `merge_gather` · `merge_gather_fit` · `merge_over` | 사양: spec_취합.md ② §4-4
- **끌어 넣기** — 사람 · 문서 바뀜 · 선택. 프레임에서 나오지 않은 문서나 겹친 내용은, 옆에 띄운 기관 문서의 절(제목 줄 + 그 아래 내용)을 끌어 취합본의 원하는 자리에 놓습니다.
  - 하려면: 취합본 옆에 띄운 기관 문서.
  - 끝난 것으로 보는 때: 안 해도 됩니다 — 끝남을 따로 세지 않습니다.
  → 모듈: `merge_gather_drop` | 사양: spec_취합.md ② §4-6

## 쓰는 공통 모듈

단계가 「공통 모듈」 로 가리키는 과정 — 그 과정의 단계는 [workflow.md](../workflow.md) 의 「공통 모듈」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 TASK 든 문서를 올리면 먼저 거치는 과정입니다 — 작업(문서마다의 저장 공간)이 생기고, 새 작업이면 기본 분석(헤딩 · 표 — 스크립트)이 저절로 돕니다. 어디까지 됐는지는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 주고받는 대화창입니다 — TASK 를 시작하면 에이전트가 사전 준비와 진행 상황을 설명하고 다음 단계를 제안·실행하며(작업 진행), 글로 요청하면 제안(글 · 새 표 · 표 채우기 · 서식 입히기 · 서식 복사)을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 빈 동안은 「지금 할 수 있는 일」 — 현재 작업 진행 현황 보고(스크립트 · 무료) · 남은 헤딩·표 LLM 검토(실행 카드 · 유료) · 서식 반영 — 을 고릅니다. 어느 TASK 의 문서에서나 엽니다.
- **프로젝트 구성(구분 기준)**(`division`) — 단계 · 차년도 · 기관 값(프로젝트 구성)에 맞춰 문서의 절 · 표 행 · 표 열을 늘리고 줄입니다. 값은 프로젝트에 하나이고 그 프로젝트의 TASK 들이 같이 씁니다.
- **헤딩 추출**(`headings`) — 문서의 개요(헤딩)와 표의 구조를 뽑아 뼈대로 둡니다 — 자리 연결 · 넣기 · 서식 후보 · 템플릿 관계가 이 뼈대를 씁니다. 문서는 바꾸지 않습니다. 어디까지 했는지는 탭 위 진행 줄에 두 층으로 보입니다 — 스크립트(문단·라벨 · 헤딩 그래프 · 표 구조)와 LLM(규칙 보강 · 헤딩 판정 · 표 판정). LLM 칸(✓)을 누르면 문서 옆 열 「LLM 이 바꾼 것」 에 LLM 이 스크립트와 다르게 정한 것(규칙 · 노드 · 서식 쌍 판정 · 표 칸 역할 · 받아 둔 서식 계획)이 보입니다 — LLM 판정은 문서를 바꾸지 않습니다. 진행 줄의 셋째 층 「조정」 에는 템플릿 조정(레터가 다른 줄을 서식 종속 템플릿으로 — 뗄 줄 수) · 서식 조정(같은 템플릿의 줄을 대표 서식에 — 맞출 줄 수 + 자리 맞춤 줄 수)과 「모두 반영」 이 있습니다 — 두 칸을 누르면 받아 둔 계획이 보이고, 문서 서식은 「모두 반영」 을 눌러야 바뀝니다. 조정은 LLM 판정 뒤의 일입니다 — 헤딩 판정(LLM)을 아직 안 한 문서에서는 그 줄 끝의 단추가 「계획 받기」 가 아니라 「LLM 판정」 입니다(헤딩 · 템플릿 → 표 · 서식 정리 계획을 차례로 — 누르면 바로 · 유료 · 문서는 안 바뀜). 서식 정리 계획만 받는 「계획 받기」 는 판정을 거친 뒤에 뜹니다. 「모두 반영」 은 계획을 반영한 뒤 스크립트로 자리를 맞춥니다(레터 뒤 빈칸을 묶음 빈칸으로 · 둘째 줄을 글 시작에 — 받아 둔 계획이 없어도 자리가 안 맞은 줄이 있으면 뜹니다). 대표만 바꾸는 계획도 반영합니다(「서식 조정 · 대표 n」). 반영한 뒤에 에이전트가 답하지 않아 안 바꾼 줄이 남아 있으면 「서식 조정」 칸은 ✓ 가 아니라 「답 없음 n줄」 로 남습니다 — 그 줄은 계획을 다시 받거나 「템플릿 관계」 에서 손으로 맞춥니다. 형광펜·필드 표지가 든 줄은 글을 못 바꾸면 모양만 맞추고 남깁니다(그 줄 때문에 전체를 되돌리지 않음 — 「서식 조정 · 표지 n줄」, 누르면 그 줄로). 한글의 자동 글머리표·문단 번호로 레터를 매긴 헤딩 줄도 그 레벨의 서식으로 들어(다른 값 「자동 글머리」) 맞추면 대표의 레터가 글로 들어간 친 레터 줄이 됩니다(번호는 맞추기 전에 보이던 번호). 실행은 탭 머리의 단추 둘입니다 — 「단계별 실행 ▾」 은 돌릴 단계를 골라(여러 개를 눌러 표시한 뒤 「고른 n개 실행」) 고른 것만 차례로 돌리고(누르면 바로 · 한 단계가 실패하거나 LLM 이 답을 못 하면 뒤는 돌리지 않고 남김 · 도는 동안 같은 메뉴에 차례와 「멈추기」), 「전체 실행」 은 남은 단계를 조정까지 차례로 돌립니다(LLM 판정: 헤딩 · 템플릿 → 표 · 서식 정리 계획 → 조정: 받은 계획 모두 반영 — 이미 거친 단계는 건너뜀 · 누르면 바로 · 유료 LLM · 문서가 바뀜 · 반영마다 실행 취소 1). 「전체 실행」 은 계획을 보이지 않고 에이전트가 고른 그대로 반영합니다 — 멈추거나 실패하면 거기서 서고, 한 것과 남은 것(보정할 자리)을 알립니다. 헤딩 판정에 미판정(LLM 구간 검증 실패)이 있으면 반영하지 않고 남깁니다. 표 칸에 혼자 있는 레터(빈 값 「-」 · 번호 칸)는 헤딩 후보가 아닙니다. 끝나면 문서 옆 열 「LLM 이 바꾼 것」 의 「반영 결과」 가 열려 서식마다 무엇이 어떻게 바뀌었는지(전 → 후 값) · 뗀 것 · 남긴 것과 까닭을 보입니다. 한 자리에만 매달린 가지 템플릿은 그 자리의 템플릿 아래 종속 템플릿으로 저절로 넣고(확실한 것만 — 번호가 윗줄을 넘어 이어지는 것은 제안으로), 받은 서식 계획은 그 템플릿의 줄이 그대로면 되돌린 뒤에도 다시 받지 않고 씁니다.
