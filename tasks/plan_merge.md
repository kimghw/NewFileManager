# 사업계획서 취합 — `plan_merge`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(워크플로우 상세 문서 — 화면 `/workflow` 의 이 워크플로우 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [워크플로우 전체 지도](../workflow.md) 가 모든 워크플로우의 차례를 보인다면 이 글은 이 워크플로우 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

기관이 나눠 쓴 문서의 내용을 사업계획서 하나로 모읍니다.

- 받는 문서: 사업계획서(취합본, 목적 문서) + 기관이 채워 돌려준 기관 문서들(원본 문서, 여럿)
- 산출물: 기관의 내용을 모은 취합본 하나 + 자리와 반영 기록
- 문서마다 단위문서 TASK — 원본 문서(기관 문서 — 문서마다): 3단계 내용 매핑(「기관 문서 올리기 · 반영할 기관 지정」 › 「헤딩 · 표 분석」) / 목적 문서(취합본): 2단계 문서 프레임 작성(「프로젝트 구성 반영」 › 「배포 기준본 만들기」 › 「기관에 배포 · 회수」) › 3단계 내용 매핑(← 원본 문서마다: 「자리 연결 · 기관 작성 내용 판정」 › 「LLM 검토」 › 「넣기 계획」 › 「내용 반영 · 틀 맞춤」 › 「끌어 넣기」)
- 워크플로우 전체(문서마다가 아니라 한 번): 1단계 프로젝트 구성(「준비」 › 「프로젝트 구성 추출」) — 구성의 기준: 목적 문서(취합본)
- 알아 둘 것: 기관 문서는 2단계에서 만든 배포 기준본을 받아 각 기관이 자기 몫만 채워 돌려준 문서입니다. 취합본에 이미 글이 있는 자리는 덮지 않고 「겹침」 으로 알립니다. 기관 문서(원본)는 바뀌지 않습니다. 시작 화면에서 문서를 한꺼번에 올리고 취합본만 고르면 간단 모드로 1~3단계를 확인 창 없이 끝까지 자동으로 진행합니다.
- 한 번에 진행: 시작 화면의 문서 목록에서 취합본을 목적 문서로 고르고 「자동 진행」 을 켠 뒤 워크플로우 카드를 누르면 간단 모드로 진행합니다. 확인 창 없이 기관 문서 올리기부터 1~3단계까지 끝까지 진행합니다. 진행 상황과 기관 문서별 결과(넣은 것과 남긴 것)는 에이전트 보기의 진행 카드와 보고에서 확인합니다. 화면을 연 뒤에는 에이전트가 남은 단계 묶음의 「한 번에 진행」 을 실행 카드로 제안합니다.
- 에이전트가 묻는 것: 목적 문서(취합본), 기관 문서마다 반영할 기관, 프로젝트 구성을 확인합니다. 반영할 기관은 파일 이름과 추천으로 먼저 정하고, 못 정한 문서는 넣지 않고 남깁니다. 프로젝트 구성 값이 없으면 취합본에서 읽습니다.
- 멈추거나 남기는 곳 · 보정: 구조를 맞추다 지워야 하는 곳, 계획 오류, 미해결 자리가 있으면 2단계에서 멈춥니다. 겹침, 확인 필요, 표 구조가 다른 내용은 실패가 아니라 넣지 않고 남깁니다. 기관 문서마다 「남긴 것 보기」 목록이나 끌어 넣기로 보정합니다. 못 올린 문서는 「이어서」 를 눌러 다시 올립니다.
- 단계별(세부 작업): 패널 「작업 개요」 의 단계 묶음마다 세부 목록을 씁니다. 반영할 기관 지정, LLM 검토, 넣기 계획, 반영을 기관 문서마다 직접 보고 고르며 진행할 때(세부 작업 모드) 씁니다.
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/plan_merge.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 도구 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### 워크플로우를 시작할 때

시작 화면의 워크플로우 카드, 문서 목록, 대화창에서 문서를 올리기 전에 확인합니다. 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 워크플로우가 받는 형식(hwp · hwpx)인지 확인합니다.
  - 안 맞으면: 시작하지 않고 알립니다. docx 파일은 「워크플로우 없이 열기」로 열거나 「문서 서식 복사」 워크플로우에서 시작합니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 선택했는지 확인합니다. 파일이 하나면 그 파일을 목적 문서로 씁니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다. 시스템이 임의로 정하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **기관 문서 · 자동 진행** — 스크립트 → 사람. 목적 문서(취합본)가 아닌 문서는 기관 문서로 보고, hwp · hwpx 형식인지 확인합니다. 「자동 진행」 을 켰으면 기관 문서가 하나 이상 있는지도 확인합니다. 조건이 맞으면 확인 창 없이 끝까지 진행합니다.
  - 안 맞으면: docx 파일이 섞였거나 자동 진행인데 기관 문서가 없으면 시작하지 않고 알립니다. 「자동 진행」 을 끄면 문서를 올리고 등록만 합니다(세부 작업 모드).
  → 사양: spec_취합.md ② §8

### 문서를 올릴 때

문서를 올리면 자동으로 실행됩니다. 사람이 누를 필요가 없으며 유료 LLM을 쓰지 않습니다.

- **작업 만들기 · 같은 파일 고르기** — 스크립트. 올린 파일마다 작업 공간을 만들고, hwp 파일은 한글로 hwpx로 변환합니다. 같은 파일의 기존 작업이 있으면 열기 전에 선택 창을 띄웁니다. 같은 워크플로우 작업, 미지정 작업 순으로 「이어서」와 「초기화하고 열기」를 보이고, 아래에 프로젝트 칸과 「새 작업으로 시작」을 둡니다.
  - 안 맞으면: 다른 워크플로우, 프로젝트, 역할의 작업은 「그대로 열기」만 됩니다. 고르면 그 작업의 설정을 바꾸지 않고 열며, 현재 워크플로우 시작은 멈춥니다. 창을 닫으면 열지 않고, 올리지 못하면 원인을 알리고 시작하지 않습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§3-1·§15
- **양식 판정 · 문서 종류** — 스크립트. 목적 문서는 취합본(사업계획서)으로 적습니다.
  - 안 맞으면: 카드에 파일 하나만 올렸는데 양식 종류를 판정하지 못하면 사업계획서로 둡니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **워크플로우 · 프로젝트 · 라운드** — 스크립트. 작업에 현재 워크플로우를 지정합니다. 프로젝트 이름을 적었으면 해당 프로젝트의 다음 라운드로 시작합니다. 비우면 임시 이름(임시 프로젝트 N)으로 함께 올린 문서를 묶습니다.
  - 안 맞으면: 임시 이름은 문서를 연 뒤 「작업 개요」의 프로젝트 칸이나 작업 리스트의 「이름 정하기」에서 바꿀 수 있습니다. 이미 있는 프로젝트 이름을 적으면 문서가 모두 그 프로젝트로 옮겨집니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **기관 문서 올리기 · 등록 · 분석** — 스크립트. 함께 올린 기관 문서를 목록 순서대로 취합본에 등록하고, 문서마다 헤딩과 표를 스크립트로 분석합니다. 이 문서들은 화면에 열지 않습니다. 자동 진행이면 1~3단계를 이어서 끝까지 진행합니다. 반영할 기관은 파일 이름에서 먼저 찾고, 없으면 넣을 내용이 가장 많은 기관으로 정합니다.
  - 안 맞으면: 올리지 못한 문서는 남기고 알립니다. 「간단 모드 이어서」 를 누르면 다시 올립니다. 반영할 기관을 못 정한 문서는 넣지 않고 남깁니다.
  → 도구: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_취합.md ② §8
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 화면에서 제대로 읽었는지 기본 분석과 함께 검사합니다. 한글이나 Word가 있으면 PDF로 변환해 비교하며, 결과는 패널 상단 「검증」에 표시됩니다. 주의나 실패가 나오면 「LLM 검토」가 자동으로 한 번 실행되어 실제 오류인지 PDF 변환 차이인지 구분합니다.
  - 안 맞으면: LLM을 쓸 수 없거나 호출에 실패하면 스크립트 판정 결과를 유지하고 「LLM 검토」 단계에 원인을 기록합니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 hwpx 문서의 헤딩 그래프와 표 구조를 스크립트로 한 번 분석합니다. 이미 결과가 있는 단계는 건너뛰며, 이어서 연 작업에서는 실행되지 않습니다.
  - 안 맞으면: 시작하지 못하면 문서 이름 줄에 「헤딩 없음 · 표 없음」이 표시되고, 도중 실패하면 해당 단계가 「실패」로 뜹니다. 이름 줄의 「분석」 단추로 다시 실행합니다.
  → 도구: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 분석 항목(헤딩, 템플릿, 서식, 표)과 LLM 검증·보완, 구분 기준 검토 상태가 표시됩니다. 어느 워크플로우나 같으며 누르면 진행표가 열립니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **편집 구역의 기준 적기** — 스크립트. 시작 화면 문서 목록의 「편집 구역」에서 기준(기관, 단계, 차년도)을 선택했으면, 워크플로우 설정 시 해당 묶음의 옵션으로 함께 저장합니다.
  - 안 맞으면: 따로 선택하지 않으면 기본값(취합은 기관 켜짐, 나머지는 꺼짐)으로 시작합니다. 문서를 연 뒤 「편집 구역」 줄에서 바꿀 수 있습니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1

### 워크플로우 화면을 열 때

패널 「작업 개요」와 에이전트 시작 안내가 현재 상태를 확인합니다. 부족한 항목이 사전 준비 대상입니다.

- **에이전트의 시작 턴** — 스크립트 → LLM. LLM을 쓸 수 있으면 상단 바의 에이전트 창(또는 패널 탭)이 열리며 시작 안내가 한 번 실행됩니다. 사전 준비, 현재 진행 상태, 다음 단계를 설명하고 다음 작업을 제안합니다. 같은 작업과 워크플로우에 이미 진행 기록이 있으면 다시 실행되지 않습니다.
  - 안 맞으면: LLM이 꺼져 있으면 패널 「작업 개요」가 열립니다. 이때도 에이전트 보기의 「작업 설명 듣기」로 스크립트 안내를 볼 수 있습니다.
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §1
- **취합본이 있는가 · 지금 문서가 취합본인가** — 스크립트. 취합본(목적 문서)을 골랐는지 확인합니다. 지금 연 문서가 취합본인지 기관 문서인지도 확인합니다.
  - 안 맞으면: 취합본이 없으면 패널 「작업 개요」 에서 고르도록 안내합니다. 기관 문서를 열었으면 실행 대신 「취합본 열기」 카드를 보입니다. 기관 문서는 바뀌지 않습니다.
  → 도구: 에이전트 보기 | 사양: spec_취합.md ② §5
- **프로젝트 구성 확정** — 스크립트. 취합본의 프로젝트 구성을 확정해 저장했는지 확인합니다.
  - 안 맞으면: 값이 없으면 취합본에서 추출하거나 불러오도록 안내합니다. 확정해야 2단계로 넘어갑니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §18
- **취합본의 구조** — 스크립트. 확정한 프로젝트 구성이 취합본에 반영됐는지 확인합니다. 구조가 이미 맞으면 확인만 합니다. 자동 반영을 지원하는 양식인지도 확인합니다.
  - 안 맞으면: 아직 반영하지 않았으면 「변경 계획 보기」 가 다음 차례입니다. 연구개발계획서 양식만 자동 반영을 지원하며, 다른 양식은 자동 반영하지 않습니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_취합.md ② §3
- **배포 기준본** — 스크립트. 배포 기준본이 있는지 확인합니다. 기준본을 만든 뒤 프로젝트 구성을 다시 반영해 낡았는지도 확인합니다.
  - 안 맞으면: 기준본이 없거나 낡았으면 기관 문서 줄이 열리지 않으므로 새로 만들어야 합니다. 낡은 기준본으로 작성된 기관 문서는 자동으로 넣지 않습니다.
  → 사양: spec_취합.md ② §3
- **기관 문서마다** — 스크립트. 기관 문서마다 반영할 기관을 정했는지와 자리 연결을 막는 문제(다른 판 기준본, 분석 없음 등)가 있는지 확인합니다. 넣을 내용이 남았는지와 겹침 · 확인 필요 · 표 구조 다름으로 남긴 곳의 수도 셉니다.
  - 안 맞으면: 기관 미지정인 문서는 넣지 않고 다른 문서만 그대로 진행합니다. 남긴 내용이 있으면 에이전트가 최대 3개 문서까지 「남긴 것 보기」 를 안내합니다.
  → 도구: 에이전트 보기 | 사양: spec_취합.md ② §4-1·§5
- **간단 모드의 끝** — 스크립트. 첫 화면에서 실행한 간단 모드가 중간에 멈췄는지, 올리지 못한 문서가 남았는지 확인합니다.
  - 안 맞으면: 남은 작업이 있으면 「간단 모드 이어서」 실행 카드를 보입니다. 앞서 이미 넣은 내용은 다시 넣지 않습니다.
  → 도구: 에이전트 보기 | 사양: spec_취합.md ② §8
- **편집 구역 — 보일 기준과 구역 읽기** — 스크립트. 이 묶음(프로젝트 · 워크플로우 · 라운드)의 편집 구역에서 보일 기준(기관, 단계, 차년도)을 확인합니다. 켠 기준이 있으면 문단과 표, 표 칸이 어디에 속하는지 스크립트로 읽어 색 띠와 이름표로 표시합니다. 취합은 기관 기준이 기본으로 켜져 있어 기관 구역과 기관 문서에서 넣은 내용이 바로 보입니다.
  - 안 맞으면: 켠 기준이 없으면 구역을 읽지 않으며, 패널 「작업 개요」의 「편집 구역」 줄에서 켤 수 있습니다. 프로젝트 구성 값이 없으면 계산할 수 없다고 알립니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1·§6
- **지금 도는 실행** — 스크립트. 이 문서에서 「한 번에 진행」(간단 모드, 묶음, 실행 카드)이 실행 중인지 확인합니다.
  - 안 맞으면: 실행 중에는 에이전트가 새 실행이나 저장을 제안하지 않고 진행 카드만 표시합니다. 끝나면 이어서 안내합니다.
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7

### 저절로 돌지 않는 것

자동으로 실행되지 않고 사람이 단추를 눌러 실행하는 항목입니다. 유료 LLM을 씁니다.

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 문서를 올릴 때는 실행되지 않으며, 사람이 직접 실행합니다. 「헤딩 추출」과 「테이블」 탭의 「단계별 실행 ▾」에서 단계를 골라 「고른 n개 실행」하거나, 「추출·설정」 하위 탭의 단계 카드를 씁니다. 「헤딩 추출」 탭의 「전체 실행」(조정까지 실행), 「조정」 끝의 「LLM 판정」(판정 전 문서), 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」로도 실행합니다. 헤딩 판정 시 스크립트가 못 맞췄거나 충돌한 첫머리 묶음도 함께 봅니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **구분 기준 LLM 검토** — 사람 → LLM. 선택 기능입니다. 문서 이름 줄의 「구분 기준」 표시나 프로젝트 구성의 「LLM 검토」를 연 뒤, 「LLM 검토 실행」을 눌러 실행합니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §20
- **편집 구역 LLM 검토** — 사람 → LLM. 선택 기능이며 유료입니다. 「편집 구역」 줄의 「LLM 검토」를 눌러 실행합니다. 스크립트가 기관이나 차년도를 못 정한 자리를 LLM이 판별해 「LLM」 지정으로 표시합니다. 문서는 바뀌지 않습니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §8
- **이 워크플로우의 LLM 검토** — 사람 → LLM. 기관 작성 내용의 LLM 검토(유료): 기관 문서 줄의 「LLM 검토」 단추나 확인을 받은 「한 번에 진행」, 간단 모드에서 돕니다. 문서를 올리거나 여는 것만으로는 실행되지 않습니다.
  → 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 자동/필수/선택/준비 중 · 하는 문서. 하는 일`(하는 문서 = 문서 여럿인 워크플로우의 단계만 — 원본 문서 · 목적 문서 · 두 문서 · 원본 → 목적 · 워크플로우 전체 · 원본 문서가 여럿이면 「원본 문서마다」 · 「원본 문서마다 → 목적」), 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 도구 | 코드(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 1단계 프로젝트 구성 — 단계 · 차년도 · 기관 구성을 정해 프로젝트에 확정(문서는 안 바뀜)

- **준비** — 사람 · 문서 안 바뀜 · 필수 · 워크플로우 전체. 사업계획서(취합본)를 올리거나 같은 프로젝트의 문서에서 고릅니다. LLM을 쓸 수 있으면 상단 바의 에이전트 창이 열려 사전 준비와 다음 단계를 안내합니다.
  - 하려면: 프로젝트 이름. 없으면 문서는 올릴 수 있지만 같은 프로젝트의 다른 문서는 못 고릅니다.
  - 끝난 것으로 보는 때: 취합본을 골랐을 때.
  → 도구: 문서 올리기 · 첫 분석 · 에이전트 보기 | 사양: spec_작업.md ② §10·§17
- **프로젝트 구성 추출** — 스크립트 → 사람 · 저장만 · 필수 · 워크플로우 전체. 취합본에서 단계 · 차년도 · 기관 구성을 추출해 확인한 뒤 프로젝트에 확정합니다. 이미 확정한 구성이 있으면 그대로 쓰며, 문서는 바뀌지 않습니다.
  - 하려면: 준비가 끝난 뒤.
  - 끝난 것으로 보는 때: 프로젝트에 이미 확정한 구성이 있거나, 값을 확정한 뒤 변경 사항이 없을 때.
  - 멈추는 때: 취합본에 저장된 값이 없으면 문서에서 읽어 확인받은 뒤 확정하며, 읽지 못하면 직접 묻습니다. 확정 후 값을 바꾸면 다시 확정해야 2단계로 넘어갑니다.
  → 확정한 프로젝트 구성 | 도구: 프로젝트 구성(구분 기준) | 코드: `division_model` · `projects` | 사양: spec_작업.md ② §18

### 2단계 문서 프레임 작성 — 취합본의 구조를 프로젝트 구성에 맞추고, 기관에 나눠 줄 배포 기준본을 만듦

- **① 프로젝트 구성 반영** — 스크립트 → 사람 · 문서 바뀜 · 필수 · 목적 문서. 확정한 프로젝트 구성에 맞춰 취합본의 변경 계획(바뀔 자리)을 확인한 뒤 반영합니다. 절과 표의 행 · 열 구조만 늘리고 줄입니다.
  - 하려면: 1단계 확정과 프로젝트 구성 자동 반영을 지원하는 연구개발계획서 양식.
  - 끝난 것으로 보는 때: 확정한 값이 취합본에 반영됐거나, 구조가 이미 값에 맞아 확인만 했을 때.
  - 멈추는 때: 계획을 세우지 못했거나 계획 오류, 미해결 자리가 있으면 「한 번에 진행」 이 반영하지 않고 멈춥니다. 기관 순서가 마지막 반영과 달라도 멈춥니다. 간단 모드는 구조를 맞추다 글을 지워야 하는 곳이 있어도 멈춥니다.
  - 남기는 것 · 보정: 지원 안 되는 자리는 그대로 둡니다.
  → 구조를 맞춘 취합본 | 도구: 프로젝트 구성(구분 기준) | 코드: `division_plan` · `division_model` | 사양: spec_취합.md ② §3
- **◆ 배포 기준본 만들기** — 스크립트 → 사람 · 저장만 · 필수 · 목적 문서. 구조를 맞춘 취합본 파일과 자리 정보(기관, 차년도 구분, 헤딩, 표, 서식)를 배포 기준본으로 고정합니다. 헤딩 · 표 분석이 최신이 아니면 먼저 다시 분석합니다. 프로젝트 구성을 다시 반영하면 기준본이 낡으므로 새로 만듭니다.
  - 하려면: ① 프로젝트 구성 반영이 끝난 취합본.
  - 끝난 것으로 보는 때: 최신 배포 기준본이 있을 때. 프로젝트 구성을 다시 반영하면 기준본이 낡아 새로 만들어야 합니다.
  - 남기는 것 · 보정: 낡은 기준본으로 작성된 기관 문서는 자동으로 넣지 않습니다. 간단 모드에서는 기준본이 없으면 현재 취합본을 기준본으로 봅니다.
  → 배포 기준본(hwpx) + 자리 정보 | 도구: 헤딩 추출 | 코드: `merge_gather_frame` · `merge_gather_api` | 사양: spec_취합.md ② §3
- **기관에 배포 · 회수** — 사람 · 문서 안 바뀜 · 필수 · 목적 문서. 기준본을 내려받아 각 기관에 나눠 줍니다. 각 기관이 자기 몫만 채워 돌려주는 앱 밖의 작업입니다.
  - 하려면: 배포 기준본(「기준본 내려받기」).
  - 끝난 것으로 보는 때: 앱 밖의 일이라 완료 여부를 세지 않습니다. 기관 문서가 들어오면 3단계로 진행합니다.
  → 기관 문서들

### 3단계 내용 매핑 — 기관 문서가 들어올 때마다 내용을 취합본의 같은 자리에 넣음(기관 문서마다 반복)

- **기관 문서 올리기 · 반영할 기관 지정** — 사람 · 저장만 · 필수 · 원본 문서마다. 기관 문서를 올리고 어느 기관의 문서인지 지정합니다. 지정하지 않은 문서는 넣지 않고 다른 문서만 그대로 진행합니다.
  - 하려면: 최신 배포 기준본. 기준본이 없거나 낡으면 기관 문서 줄이 열리지 않습니다.
  - 끝난 것으로 보는 때: 그 문서의 반영할 기관을 정했을 때.
  - 남기는 것 · 보정: 기관 미지정 문서는 넣지 않고 다른 문서만 그대로 진행합니다.
  → 도구: 문서 올리기 · 첫 분석 | 코드: `merge_gather_api` | 사양: spec_취합.md ② §2·§5
- **헤딩 · 표 분석** — 스크립트 · 저장만 · 자동 · 원본 문서마다. 기관 문서를 올릴 때 스크립트로 헤딩 그래프와 표 구조를 분석합니다(LLM 호출 없음). 이 결과는 서식 맞춤, LLM 검토, 끌어 넣기 범위 계산에 씁니다. 자리 연결은 이 분석 대신 문서 블록을 순서대로 비교해 찾습니다.
  - 하려면: 올린 기관 문서(hwpx).
  - 끝난 것으로 보는 때: 그 기관 문서에 헤딩 · 표 분석이 있을 때.
  - 멈추는 때: 분석 결과가 없으면 자리 연결을 할 수 없습니다. 해당 줄의 「헤딩·표 분석」 을 눌러 스크립트로 다시 실행합니다.
  → 도구: 헤딩 추출 | 코드: `heading_runs` | 사양: spec_취합.md ② §4-1
- **② 자리 연결 · 기관 작성 내용 판정** — 스크립트 · 문서 안 바뀜 · 필수 · 원본 문서마다 → 목적. 기준본, 기관 문서, 취합본을 비교해 기관이 새로 쓰거나 고친 내용(기관 작성 내용)을 찾아 취합본의 같은 자리에 연결합니다. 기준본에 원래 있던 제목 줄, 빈 틀, 안내 글과 서식만 바뀐 내용은 제외합니다.
  - 하려면: 최신 배포 기준본, 반영할 기관 지정, 기관 문서의 분석 결과. 기준본이 없거나 낡았거나 판이 다르면 진행할 수 없습니다.
  - 끝난 것으로 보는 때: 기준본과 비교해 기관 작성 내용 목록이 만들어졌을 때.
  - 남기는 것 · 보정: 기준본과 자리를 충분히 확인하지 못한 문서는 진행을 막지 않고, 「기관 작성 내용」 에서 사람이 직접 켠 항목만 넣습니다. 기준본과 맞는 자리를 아예 찾지 못한 문서는 끌어 넣기만 가능합니다.
  → 기관 작성 내용 목록 | 코드: `merge_gather` · `merge_gather_frame` | 사양: spec_취합.md ② §4-1·§4-2
- **LLM 검토** — LLM · 저장만 · 선택 · 원본 문서마다 → 목적. 넣기로 한 기관 작성 내용이 실제로 기관이 쓴 글인지, 양식의 안내 글이나 빈 틀인지 취합본의 장별로 검토합니다. 불필요한 항목을 걸러 내기만 하며, 건너뛰어도 넣기 계획을 세울 수 있습니다.
  - 하려면: 넣을 수 있는 기관 작성 내용과 LLM 연결(유료). 단추를 누르거나 확인을 받은 「한 번에 진행」 에서 돕니다.
  - 끝난 것으로 보는 때: 검토를 한 번 마쳤을 때. 건너뛰어도 넣기 계획을 세울 수 있습니다.
  - 남기는 것 · 보정: LLM 은 불필요한 항목을 빼기만 합니다. 판단을 보류한 항목은 확인 필요로 남깁니다. 스크립트가 막은 항목을 넣게 하거나 사람이 고른 선택은 바꾸지 않습니다.
  → 에이전트: 12 취합 검토 | 코드: `merge_gather_llm` · `merge_guides` · `job_prompts` | 사양: spec_취합.md ② §4-3
- **③ 넣기 계획** — 스크립트 · 문서 안 바뀜 · 필수 · 원본 문서마다 → 목적. 취합본에 넣을 문단과 표 · 그림, 표 칸과 행의 수를 셉니다. 이미 내용이 있는 자리는 넣지 않고 「겹침」 으로 표시합니다. 문서는 바뀌지 않습니다.
  - 하려면: 자리 연결이 끝난 기관 문서.
  - 끝난 것으로 보는 때: 해당 문서의 넣기 계획이 만들어졌을 때. 그 뒤 문서나 설정이 바뀌면 다시 계획합니다.
  - 남기는 것 · 보정: 겹치는 자리는 넣지 않고 「겹침」 으로 둡니다.
  → 넣기 계획 | 코드: `merge_gather` | 사양: spec_취합.md ② §4-4
- **④ 내용 반영 · 틀 맞춤** — 사람 → 스크립트 · 문서 바뀜 · 필수 · 원본 문서마다 → 목적. 「계획 보기」 에서 확인하고 「반영」 을 누르면 내용이 취합본에 들어갑니다. 서식은 취합본의 틀에 맞추고, 틀보다 깊게 쓴 개요는 넘친 개요 레벨로 처리합니다.
  - 하려면: 넣을 내용이 있는 넣기 계획. 「계획 보기」 에서 확인하고 「반영」 을 누릅니다.
  - 끝난 것으로 보는 때: 그 기관 문서에서 더 넣을 내용이 없을 때(반영 완료 또는 이미 들어 있음).
  - 남기는 것 · 보정: 겹침, 확인 필요, 표 구조가 다른 내용은 실패가 아니라 넣지 않고 남깁니다. 기관 문서마다 「남긴 것 보기」 목록이나 끌어 넣기로 보정합니다.
  → 내용이 들어간 취합본 | 코드: `merge_gather` · `merge_gather_fit` · `merge_over` | 사양: spec_취합.md ② §4-4
- **끌어 넣기** — 사람 · 문서 바뀜 · 선택 · 원본 문서마다 → 목적. 배포 기준본에서 만들지 않은 문서나 겹친 내용은 옆에 띄운 기관 문서의 절(제목 줄과 아래 내용)을 끌어와 취합본의 원하는 자리에 놓습니다.
  - 하려면: 취합본 옆에 띄운 기관 문서.
  - 끝난 것으로 보는 때: 선택 단계이므로 완료 여부를 따로 세지 않습니다.
  → 코드: `merge_gather_drop` | 사양: spec_취합.md ② §4-6

## 쓰는 도구

단계가 「도구」 로 가리키는 과정 — 그 과정의 단계는 [워크플로우 전체 지도](../workflow.md) 의 「도구」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 워크플로우든 문서를 올리면 먼저 거치는 과정입니다. 문서마다 작업 공간이 생기고, 새 문서이면 스크립트로 헤딩과 표 기본 분석이 저절로 돕니다. 진행 상태는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 대화하는 창이며, 어느 워크플로우의 문서에서나 엽니다. 워크플로우를 시작하면 사전 준비와 진행 상황을 안내하고 다음 단계를 제안·실행합니다. 글로 요청하면 글 작성, 새 표, 표 채우기 · 서식 입히기, 서식 복사 같은 제안을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 비어 있을 때는 「지금 할 수 있는 일」 에서 현재 작업 진행 현황 보고(스크립트), 남은 헤딩·표 LLM 검토(유료), 서식 반영을 바로 고를 수 있습니다.
- **프로젝트 구성(구분 기준)**(`division`) — 단계, 기관, 차년도 값에 맞춰 문서의 절과 표 행·열을 늘리고 줄입니다. 프로젝트 구성 값은 프로젝트당 하나이며 같은 프로젝트의 워크플로우가 함께 씁니다.
- **헤딩 추출**(`headings`) — 문서의 개요(헤딩)와 표 구조를 뽑아 뼈대를 만듭니다. 자리 연결, 넣기, 서식 후보, 템플릿 관계가 이 뼈대를 쓰며 문서는 바꾸지 않습니다. 진행 상태는 탭 위 진행 줄에 스크립트(문단, 헤딩 그래프, 표 구조), LLM(규칙 보강, 헤딩 판정, 표 판정), 조정 세 층으로 보입니다. LLM 이 구간과 표를 판정할 때는 양식의 작성 지침(작성 요령 표, 참고 자료, 안내, 각주 작성 요령)도 함께 읽습니다. 「작성요령 삭제」 뒤에는 저장해 둔 지침을 씁니다. LLM 칸(✓)을 누르면 문서 옆 열 「LLM 이 바꾼 것」 에서 스크립트와 달라진 판정 결과를 볼 수 있습니다. LLM 판정만으로는 문서가 바뀌지 않습니다. 진행 줄 「조정」 에는 템플릿 조정(레터가 다른 줄을 서식 종속 템플릿으로 분리), 서식 조정(같은 템플릿 줄을 대표 서식에 맞추기와 자리 맞춤), 「모두 반영」 이 있습니다. 두 칸을 누르면 받아 둔 계획을 보고, 「모두 반영」 을 눌러야 문서 서식이 바뀝니다. 헤딩 판정(LLM)을 아직 안 했으면 줄 끝에 「계획 받기」 대신 「LLM 판정」 단추가 뜹니다(헤딩과 템플릿, 표, 서식 정리 계획을 차례로 받음 · 유료 · 문서는 안 바뀜). 「계획 받기」 는 판정을 마친 뒤에 뜹니다. 「모두 반영」 은 계획을 적용한 뒤 레터 뒤 빈칸을 묶음 빈칸으로 맞추고 둘째 줄을 글 시작에 정렬합니다. 계획이 없어도 자리가 안 맞은 줄이 있으면 뜹니다. 대표만 바꾸는 계획도 반영합니다. 반영 뒤 에이전트가 답하지 못한 줄이 남으면 「서식 조정」 칸에 「답 없음 n줄」 로 남습니다. 이런 줄은 계획을 다시 받거나 「템플릿 관계」 에서 손으로 맞춥니다. 형광펜이나 필드 표지가 든 줄은 글을 못 바꾸면 모양만 맞추고 남깁니다(「서식 조정 · 표지 n줄」). 한글의 자동 글머리표나 문단 번호가 붙은 헤딩 줄도 맞추면 대표의 레터가 글로 들어갑니다. 탭 머리에는 실행 단추가 둘 있습니다. 「단계별 실행 ▾」 은 고른 단계만 차례로 돌리며, 실패하거나 LLM 이 답하지 못하면 뒤 단계를 멈춥니다. 「전체 실행」 은 남은 단계를 조정까지 한 번에 돌립니다(유료 LLM · 문서가 바뀜 · 반영마다 실행 취소 1번). 대시보드의 2단계 「한 번에 진행」 은 끝나면 고친 문단을 확정합니다. 「전체 실행」 은 계획을 따로 묻지 않고 바로 반영하며, 멈추거나 실패하면 한 일과 남은 일을 알립니다. LLM 구간 검증 실패로 미판정이 있으면 반영하지 않고 남깁니다. 표 칸에 혼자 있는 레터(빈 값 「-」 나 번호 칸)는 헤딩 후보에서 뺍니다. 끝나면 「LLM 이 바꾼 것」 의 「반영 결과」 가 열려 바뀐 내용과 남긴 까닭을 보여 줍니다. 한 자리에만 매달린 가지 템플릿은 확실한 경우 종속 템플릿으로 자동 편입하고, 되돌린 뒤에도 줄이 그대로면 받아 둔 서식 계획을 다시 씁니다.
