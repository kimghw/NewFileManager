# 연차보고서 양식 맞추기 — `report_fit`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(워크플로우 상세 문서 — 화면 `/workflow` 의 이 워크플로우 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [워크플로우 전체 지도](../workflow.md) 가 모든 워크플로우의 차례를 보인다면 이 글은 이 워크플로우 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

단계·차년도·기관에 맞춰 양식의 절·표를 늘리고 줄입니다.

- 받는 문서: 연차보고서(국가R&D 양식, hwp · hwpx) + 프로젝트 구성(단계 · 차년도 · 기관)
- 산출물: 절, 표 행, 표 열을 프로젝트 구성에 맞춘 연차보고서
- 알아 둘 것: 본문 내용은 쓰지 않고 단계 · 차년도 · 기관 수에 맞게 양식의 자리만 늘리거나 줄입니다. 프로젝트 이름이 있으면 반영 뒤 문서 이름이 「연차보고서_<프로젝트>_프레임」이 됩니다. 이관과 달리 원본 문서나 내용 매핑이 필요하지 않습니다.
- 한 번에 진행: 에이전트가 문서에서 프로젝트 구성을 읽어 확정한 뒤 변경 계획까지 세웁니다. 값이 없으면 질문 카드로 묻습니다. 문서를 바꾸는 「반영」은 실행 카드에서 계획 요약을 확인한 뒤 실행합니다. 패널 「작업 개요」의 「한 번에 진행」은 확인 창 없이 계획과 반영을 이어서 하고 고친 문단을 확정합니다. 이전 상태는 「고친 문단」 탭의 확정 기록에서 복원합니다.
- 에이전트가 묻는 것: 단계 수, 단계별 차년도 수, 주관·공동기관, 당해 차년도 등 프로젝트 구성을 묻습니다. 문서에서 읽은 값이 있으면 그 값을 확인받습니다.
- 멈추거나 남기는 곳 · 보정: 계획 오류나 미해결 자리가 있거나 기관 순서가 마지막 반영과 다르면 자동으로 반영하지 않고 멈춥니다. 변경 계획 목록을 확인한 뒤 「② 반영」을 누릅니다. 지원하지 않는 자리는 그대로 둡니다.
- 단계별(세부 작업): 제외할 자리를 고르거나 바뀔 자리를 하나씩 확인할 때, 패널 「작업 개요」의 「① 변경 계획 보기 › ② 반영」을 씁니다.

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 도구 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### 워크플로우를 시작할 때

시작 화면의 워크플로우 카드, 문서 목록, 대화창에서 문서를 올리기 전에 확인합니다. 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 작업 문서의 확장자가 이 워크플로우가 받는 형식(hwp · hwpx)인지 확인합니다.
  - 안 맞으면: 시작하지 않고 알립니다. docx 파일은 「워크플로우 없이 열기」로 열거나 「문서 서식 복사」 워크플로우에서 시작합니다.
  → 사양: spec_작업.md ② §15
- **작업 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 작업 문서(이 워크플로우로 다룰 문서)를 선택했는지 확인합니다. 파일이 하나면 그 파일을 작업 문서로 씁니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다. 시스템이 임의로 정하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **나머지 문서** — 스크립트 → 사람. 이 워크플로우는 작업 문서 하나로 합니다. 목록에 다른 문서가 있으면 작업 문서만 올리고 나머지는 목록에 남길지 확인받습니다.
  - 안 맞으면: 확인하지 않으면 시작하지 않습니다.
  → 사양: spec_작업.md ② §15-1

### 문서를 올릴 때

문서를 올리면 자동으로 실행됩니다. 사람이 누를 필요가 없으며 유료 LLM을 쓰지 않습니다.

- **작업 만들기 · 같은 파일 고르기** — 스크립트. 올린 파일마다 작업 공간을 만들고, hwp 파일은 한글로 hwpx로 변환합니다. 같은 파일의 기존 작업이 있으면 열기 전에 선택 창을 띄웁니다. 같은 워크플로우 작업, 미지정 작업 순으로 「이어서」와 「초기화하고 열기」를 보이고, 아래에 프로젝트 칸과 「새 작업으로 시작」을 둡니다.
  - 안 맞으면: 다른 워크플로우, 프로젝트, 역할의 작업은 「그대로 열기」만 됩니다. 고르면 그 작업의 설정을 바꾸지 않고 열며, 현재 워크플로우 시작은 멈춥니다. 창을 닫으면 열지 않고, 올리지 못하면 원인을 알리고 시작하지 않습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§3-1·§15
- **양식 판정 · 문서 종류** — 스크립트. 문서가 연구개발계획서나 연차보고서 양식인지 확인해 문서 종류(사업계획서 · 연차보고서)를 정합니다.
  - 안 맞으면: 양식에서 종류를 판별하지 못하면 이 워크플로우의 기본 문서(연차보고서)로 지정합니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **워크플로우 · 프로젝트 · 라운드** — 스크립트. 작업에 현재 워크플로우를 지정합니다. 프로젝트 이름을 적었으면 해당 프로젝트의 다음 라운드로 시작합니다. 비우면 임시 이름(임시 프로젝트 N)으로 함께 올린 문서를 묶습니다.
  - 안 맞으면: 임시 이름은 문서를 연 뒤 「작업 개요」의 프로젝트 칸이나 작업 리스트의 「이름 정하기」에서 바꿀 수 있습니다. 이미 있는 프로젝트 이름을 적으면 문서가 모두 그 프로젝트로 옮겨집니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 화면에서 제대로 읽었는지 기본 분석과 함께 검사합니다. 한글이나 Word가 있으면 PDF로 변환해 비교하며, 결과는 패널 상단 「검증」에 표시됩니다. 주의나 실패가 나오면 「LLM 검토」가 자동으로 한 번 실행되어 실제 오류인지 PDF 변환 차이인지 구분합니다.
  - 안 맞으면: LLM을 쓸 수 없거나 호출에 실패하면 스크립트 판정 결과를 유지하고 「LLM 검토」 단계에 원인을 기록합니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 hwpx 문서의 헤딩 그래프와 표 구조를 스크립트로 한 번 분석합니다. 이미 결과가 있는 단계는 건너뛰며, 이어서 연 작업에서는 실행되지 않습니다.
  - 안 맞으면: 시작하지 못하면 문서 이름 줄에 「헤딩 없음 · 표 없음」이 표시되고, 도중 실패하면 해당 단계가 「실패」로 뜹니다. 이름 줄의 「분석」 단추로 다시 실행합니다.
  → 도구: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 분석 항목(헤딩, 템플릿, 서식, 표)과 LLM 검증·보완, 구분 기준 검토 상태가 표시됩니다. 어느 워크플로우나 같으며 누르면 진행표가 열립니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **편집 구역의 기준 적기** — 스크립트. 시작 화면 문서 목록의 「편집 구역」에서 기준(기관, 단계, 차년도)을 선택했으면, 워크플로우 설정 시 해당 묶음의 옵션으로 함께 저장합니다.
  - 안 맞으면: 따로 선택하지 않으면 기본값(취합은 기관 켜짐, 나머지는 꺼짐)으로 시작합니다. 문서를 연 뒤 「편집 구역」 줄에서 바꿀 수 있습니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1

### 워크플로우 화면을 열 때

패널 「작업 개요」와 에이전트 시작 안내가 현재 상태를 확인합니다. 부족한 항목이 사전 준비 대상입니다.

- **에이전트의 시작 턴** — 스크립트 → LLM. LLM을 쓸 수 있으면 상단 바의 에이전트 창(또는 패널 탭)이 열리며 시작 안내가 한 번 실행됩니다. 사전 준비, 현재 진행 상태, 다음 단계를 설명하고 다음 작업을 제안합니다. 같은 작업과 워크플로우에 이미 진행 기록이 있으면 다시 실행되지 않습니다.
  - 안 맞으면: LLM이 꺼져 있으면 패널 「작업 개요」가 열립니다. 이때도 에이전트 보기의 「작업 설명 듣기」로 스크립트 안내를 볼 수 있습니다.
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §1
- **지원 양식인가** — 스크립트. 이 문서의 양식이 프로젝트 구성 자동 반영을 지원하는지 확인합니다.
  - 안 맞으면: 「이 양식은 프로젝트 구성 자동 반영을 지원하지 않습니다」라고 알리며 변경 계획과 반영을 진행하지 않습니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_구분_기준.md ② §3
- **구분 기준 자리 찾기** — 스크립트. 프로젝트 구성 값만큼 되풀이될 자리(절 헤딩, 표 행, 표 열)를 찾아 문서 위에 표시합니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_구분_기준.md ② §3·§11
- **프로젝트 구성 값 · 확정** — 스크립트. 단계 · 차년도 · 기관 값이 입력되어 있는지, 확정 후 값이 바뀌지 않았는지 확인합니다.
  - 안 맞으면: 값이 없으면 에이전트가 문서에서 읽어오고, 프로젝트 구성 질문 카드로 확인받아 확정합니다. 전체 차년도가 20년을 넘으면 계획을 세우지 않습니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §19
- **변경 계획의 상태** — 스크립트. 변경 계획이 있는지, 계획 후 문서나 제외 자리가 바뀌어 낡았는지 확인합니다. 이미 구성에 맞는지와 마지막 반영 값이 현재 값과 같은지도 봅니다.
  - 안 맞으면: 낡은 계획은 쓰지 않고 새로 세웁니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_구분_기준.md ② §7·§22
- **사람이 봐야 할 것** — 스크립트. 계획 오류나 미해결 자리가 있는지, 기관 순서가 마지막 반영과 다른지 확인합니다.
  - 안 맞으면: 문제가 있으면 에이전트가 「문서에 반영」 대신 「변경 계획 목록 보기」를 제안합니다. 「한 번에 진행」도 여기서 멈춥니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업에이전트.md ② §7
- **편집 구역 — 보일 기준과 구역 읽기** — 스크립트. 이 묶음(프로젝트 · 워크플로우 · 라운드)의 편집 구역에서 보일 기준(기관, 단계, 차년도)을 확인합니다. 켠 기준이 있으면 문단과 표, 표 칸이 어디에 속하는지 스크립트로 읽어 색 띠와 이름표로 표시합니다.
  - 안 맞으면: 켠 기준이 없으면 구역을 읽지 않으며, 패널 「작업 개요」의 「편집 구역」 줄에서 켤 수 있습니다. 프로젝트 구성 값이 없으면 계산할 수 없다고 알립니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §1·§6
- **지금 도는 실행** — 스크립트. 이 문서에서 「한 번에 진행」(간단 모드, 묶음, 실행 카드)이 실행 중인지 확인합니다.
  - 안 맞으면: 실행 중에는 에이전트가 새 실행이나 저장을 제안하지 않고 진행 카드만 표시합니다. 끝나면 이어서 안내합니다.
  → 도구: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7

### 저절로 돌지 않는 것

자동으로 실행되지 않고 사람이 단추를 눌러 실행하는 항목입니다. 유료 LLM을 씁니다.

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 문서를 올릴 때는 실행되지 않으며, 사람이 직접 실행합니다. 「헤딩 추출」과 「테이블」 탭의 「단계별 실행 ▾」에서 단계를 골라 「고른 n개 실행」하거나, 「추출·설정」 하위 탭의 단계 카드를 씁니다. 「헤딩 추출」 탭의 「전체 실행」(조정까지 실행), 「조정」 끝의 「LLM 판정」(판정 전 문서), 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」로도 실행합니다. 헤딩 판정 시 스크립트가 못 맞췄거나 충돌한 첫머리 묶음도 함께 봅니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **구분 기준 LLM 검토** — 사람 → LLM. 선택 기능입니다. 문서 이름 줄의 「구분 기준」 표시나 프로젝트 구성의 「LLM 검토」를 연 뒤, 「LLM 검토 실행」을 눌러 실행합니다.
  → 도구: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §20
- **편집 구역 LLM 검토** — 사람 → LLM. 선택 기능이며 유료입니다. 「편집 구역」 줄의 「LLM 검토」를 눌러 실행합니다. 스크립트가 기관이나 차년도를 못 정한 자리를 LLM이 판별해 「LLM」 지정으로 표시합니다. 문서는 바뀌지 않습니다.
  → 도구: 편집 구역 | 사양: spec_구역.md ② §8

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 자동/필수/선택/준비 중. 하는 일`, 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 도구 | 코드(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 준비 — 문서를 올려 워크플로우를 시작

- **문서 올리기 · 첫 분석** — 사람 → 스크립트 · 저장만 · 필수. 연차보고서를 올리면 작업 공간이 생기고 기본 분석(헤딩 그래프 · 표 구조 — 스크립트)이 자동으로 실행됩니다. 구분 기준 LLM 검토는 선택 기능이라 자동으로 돌지 않습니다. LLM을 쓸 수 있으면 상단 바의 에이전트 창이 열려 사전 준비와 다음 단계를 안내합니다.
  - 하려면: 이 워크플로우가 지원하는 hwp 또는 hwpx 문서 하나.
  - 끝난 것으로 보는 때: 문서가 열리고 워크플로우가 지정되면 끝난 것으로 봅니다. 기본 분석은 함께 실행되며 완료를 기다리지 않습니다.
  → 도구: 문서 올리기 · 첫 분석 · 에이전트 보기 | 사양: spec_작업.md ② §9·§15·§20

### 프로젝트 구성 — 단계 · 차년도 · 기관 값을 정합니다(문서는 안 바뀜)

- **프로젝트 구성 값 정하기** — 사람 → 스크립트 · 저장만 · 필수. 문서에서 읽거나 불러오거나 직접 입력해 단계 · 차년도 · 기관을 정하고 프로젝트에 저장합니다. 문서는 바뀌지 않습니다.
  - 하려면: 문서를 열면 바로 진행할 수 있습니다. 값은 문서에서 읽거나 불러오거나 직접 입력합니다.
  - 끝난 것으로 보는 때: 값을 확정한 뒤 변경 사항이 없을 때. 값을 바꾸면 다시 확정해야 합니다.
  - 멈추는 때: 값이 없으면 에이전트가 문서에서 읽어 질문 카드로 확인받으며, 없는 값을 지어내지 않습니다. 확정한 뒤에만 변경 계획 단계로 넘어갑니다.
  → 도구: 프로젝트 구성(구분 기준) | 코드: `division_model` · `division_presets` · `projects` | 사양: spec_작업.md ② §19
- **구분 기준 자리 확인** — 스크립트 → LLM · 저장만 · 선택. 구성 값만큼 되풀이될 자리(절, 표 행, 표 열)를 문서 표시로 확인합니다. LLM이 빠진 자리 후보를 찾으면 「자리로 추가」로 등록합니다.
  - 하려면: 지원 양식의 문서. LLM 검토는 유료이며, LLM 연결 시 대시보드의 「LLM 검토 실행」 단추를 누르거나 「작업 개요」의 「LLM 검토」 결과 열에서 실행합니다.
  - 끝난 것으로 보는 때: 필수가 아니며 완료 수에 포함되지 않습니다. 대시보드에서는 LLM 검토를 마치고 「자리로 추가」 대기 후보나 미응답 검토가 없을 때 「끝남」으로 표시됩니다.
  - 남기는 것 · 보정: LLM이 찾은 빠진 자리 후보는 사람이 「자리로 추가」를 눌러야 반영 대상이 됩니다.
  → 에이전트: 07 구분 기준 자리 재검토 · 08 빠진 구분 기준 자리 검토 | 도구: 프로젝트 구성(구분 기준) | 코드: `division_model` · `division_llm` | 사양: spec_구분_기준.md ② §11·§13·§14

### 구조 반영 — 절, 표 행, 표 열을 구성 값에 맞춤(구조만)

- **① 변경 계획 보기** — 스크립트 · 문서 안 바뀜 · 필수. 프로젝트 구성에 맞춰 늘어나거나 줄어들 자리를 목록으로 미리 확인합니다. 문서는 바뀌지 않습니다.
  - 하려면: 지원 양식, 프로젝트 구성 값, 전체 차년도 20년 이하. 에이전트는 값을 확정한 뒤에 계획을 세웁니다.
  - 끝난 것으로 보는 때: 현재 문서에 맞는 계획(반영 가능, 바꿀 것 없음, 이미 반영함)이 있을 때. 계획 후 문서나 제외 자리를 바꾸면 낡은 계획이 되어 다시 세웁니다.
  → 변경 계획 | 도구: 프로젝트 구성(구분 기준) | 코드: `division_plan` | 사양: spec_구분_기준.md ② §3·§7·§22
- **② 반영** — 사람 → 스크립트 · 문서 바뀜 · 필수. 계획대로 절, 표 행, 표 열을 늘리거나 줄입니다. 「한 번에 진행」은 계획과 반영을 이어서 실행하며, 확인이 필요한 곳에서 멈춥니다.
  - 하려면: 낡지 않은 유효한 변경 계획.
  - 끝난 것으로 보는 때: 반영을 마쳤거나, 계획이 「현재 구성과 맞습니다」이거나, 마지막 반영 값이 현재 값과 같을 때.
  - 멈추는 때: 계획 오류나 미해결 자리가 있거나 기관 순서가 마지막 반영과 다르면 자동으로 반영하지 않습니다. 실행 카드 생성 뒤 계획이 바뀌면 실행하지 않고 새 계획으로 다시 묻습니다.
  - 남기는 것 · 보정: 지원하지 않는 자리는 그대로 두며 변경 계획 목록에서 확인합니다. 줄어드는 항목은 안의 글도 함께 지워지므로, 지워질 글이 있으면 목록을 먼저 보입니다.
  → 구조를 맞춘 연차보고서(프레임) | 도구: 프로젝트 구성(구분 기준) | 코드: `division_model` · `hwpx_struct` | 사양: spec_구분_기준.md ② §4·§22

## 쓰는 도구

단계가 「도구」 로 가리키는 과정 — 그 과정의 단계는 [워크플로우 전체 지도](../workflow.md) 의 「도구」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 워크플로우든 문서를 올리면 먼저 거치는 과정입니다. 문서마다 작업 공간이 생기고, 새 문서이면 스크립트로 헤딩과 표 기본 분석이 저절로 돕니다. 진행 상태는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 대화하는 창이며, 어느 워크플로우의 문서에서나 엽니다. 워크플로우를 시작하면 사전 준비와 진행 상황을 안내하고 다음 단계를 제안·실행합니다. 글로 요청하면 글 작성, 새 표, 표 채우기 · 서식 입히기, 서식 복사 같은 제안을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 비어 있을 때는 「지금 할 수 있는 일」 에서 현재 작업 진행 현황 보고(스크립트), 남은 헤딩·표 LLM 검토(유료), 서식 반영을 바로 고를 수 있습니다.
- **프로젝트 구성(구분 기준)**(`division`) — 단계, 기관, 차년도 값에 맞춰 문서의 절과 표 행·열을 늘리고 줄입니다. 프로젝트 구성 값은 프로젝트당 하나이며 같은 프로젝트의 워크플로우가 함께 씁니다.
