# 문서 일반 편집 — `doc_edit`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(TASK 문서 — 화면 `/workflow` 의 이 TASK 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [workflow.md](../workflow.md) 가 모든 TASK 의 차례를 보이는 **전체 지도**라면 이 글은 이 TASK 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

에이전트에 요청해 글·표를 쓰고, 표·글 서식을 보관함에 저장해 다시 씁니다.

- 받는 문서: 문서 하나(hwp · hwpx — 양식에 묶이지 않은 문서) + 사람의 요청 · 자료
- 산출물: 요청한 글 · 표가 더해진 같은 문서
- 알아 둘 것: 차례가 정해진 단계 묶음은 없습니다 — 요청 → 제안 → 반영을 되풀이합니다. 서식은 서식 관리자의 서식이나 이 문서의 서식만 쓰고(새 서식을 지어내지 않음), 표의 값은 받은 자료에 있는 것만 넣습니다.
- 한 번에 진행: 정해진 끝이 없습니다 — 요청마다 에이전트가 제안을 내고, 사람이 고른 제안만 문서에 반영합니다.
- 에이전트가 묻는 것: 넣을 자리(고른 문단 · 표) · 자료 · 서식(안 고르면 에이전트가 서식 관리자에서 고릅니다).
- 멈추거나 남기는 곳 · 보정: 자료에 없는 수 · 검산이 안 맞는 표 · 에이전트가 지은 글은 처음부터 고르지 않은 채로 보입니다 — 사람이 보고 고릅니다.
- 단계별(세부 작업): 표 손잡이 메뉴(엑셀식 보기 · 표 채우기 · 표 만들기)와 서식 관리자 — 표 하나 · 서식 하나를 직접 다룰 때.
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/doc_edit.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 공통 모듈 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### TASK 를 시작할 때

시작 화면의 TASK 카드 · 문서 목록 · 첫 화면 대화창에서, 문서를 올리기 전에 봅니다 — 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 TASK 가 받는 형식(hwp · hwpx)인지 봅니다.
  - 안 맞으면: 시작하지 않고 알립니다 — docx 는 「TASK 없이 열기」 로 열거나 TASK 「문서 서식 복사」 로 시작합니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 골랐는지 봅니다 — 하나면 그 파일이 목적 문서입니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다 — 어느 파일인지 짐작하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **나머지 문서** — 스크립트 → 사람. 이 TASK 는 목적 문서 하나로 합니다 — 목록에 다른 문서가 있으면 목적 문서만 올리고 나머지는 목록에 남긴다고 확인받습니다.
  - 안 맞으면: 확인하지 않으면 시작하지 않습니다.
  → 사양: spec_작업.md ② §15-1

### 문서를 올릴 때

올리면 저절로 도는 것입니다 — 사람이 누르지 않고, 유료 LLM 호출이 없습니다.

- **작업 만들기 · 이어 열기** — 스크립트. 올린 파일로 작업(문서마다의 저장 공간)을 만듭니다. 같은 파일로 하던 작업이 있으면 이 TASK 의 작업(가장 최근) → TASK 가 빈 작업 차례로 이어 엽니다. hwp 는 한글이 hwpx 로 바꿔 받습니다.
  - 안 맞으면: 다른 TASK 를 하던 작업뿐이면 그 작업은 그대로 두고 새 작업으로 열고 알립니다. 올리지 못하면 까닭을 알리고 시작하지 않습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§15
- **양식 판정 · 문서 종류** — 스크립트. 작업 종류를 일반 문서로 적습니다 — 문서 종류(사업계획서 · 연차보고서)는 정하지 않습니다.
  - 안 맞으면: 양식에 묶이지 않은 문서라 프로젝트 구성 · 구분 기준 항목이 없습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **TASK · 프로젝트 · 라운드** — 스크립트. 작업에 이 TASK 를 적습니다. 문서 목록에 프로젝트 이름을 적었으면 그 프로젝트의 이 TASK 다음 라운드로 시작합니다.
  - 안 맞으면: 프로젝트 이름을 비우면 프로젝트 없이 시작합니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 웹 화면이 제대로 읽었는지 검사합니다(한글 · Word 가 있으면 PDF 로 찍어 견줌) — 기본 분석과 함께 돌고, 결과는 패널 머리 「검증」 에 보입니다. 주의 · 실패가 나면 마지막 「LLM 검토」(LLM 호출 한 번)가 저절로 돌아 그 단계가 실제 문제인지 기준 PDF 쪽 사정인지 가립니다.
  - 안 맞으면: LLM 을 쓸 수 없거나 호출이 실패하면 스크립트 판정 그대로 두고 「LLM 검토」 단계에 까닭을 적습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 한 번, 헤딩 그래프 → 표 구조를 스크립트만으로 분석합니다(hwpx). 이미 결과가 있는 단계는 건너뛰고, 이어 연 작업에서는 돌지 않습니다.
  - 안 맞으면: 시작하지 못했으면 문서 이름 줄이 「헤딩 없음 · 표 없음」, 돌다 실패했으면 멈춘 단계가 「실패」 입니다 — 이름 줄의 「분석」 단추로 다시 돌립니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 헤딩 · 템플릿 · 서식 · 표 · LLM 검증·보완이 어디까지 됐는지 보입니다 — 어느 TASK 에서나 같은 꼴입니다(누르면 진행표)(일반 문서라 구분 기준 항목은 없습니다).
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20

### TASK 화면을 열 때

패널 「작업 내용」 과 에이전트의 시작 턴이 지금 상태를 셈합니다 — 여기서 모자란 것이 사전 준비입니다.

- **에이전트 보기 열기** — 스크립트. 문서를 열면 패널의 에이전트 보기가 열립니다 — 단계가 없는 TASK 라 작업 진행 에이전트의 시작 턴은 돌지 않고, 보낸 글은 바로 편집 요청이 됩니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_일반편집.md ② §11
- **LLM 을 쓸 수 있는가** — 스크립트. 제안은 LLM 이 냅니다 — 에이전트 보기가 LLM 연결을 읽어 둡니다.
  - 안 맞으면: 쓸 수 없으면 에이전트가 제안을 내지 못합니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_일반편집.md ② §8

### 저절로 돌지 않는 것

시작할 때 돌 것 같지만 사람이 단추로 돌려야 하는 것입니다(유료 LLM).

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 기본 분석과 따로이고 올릴 때 돌지 않습니다 — 「헤딩 추출」 · 「테이블」 탭 머리의 「단계별 실행 ▾」 메뉴(또는 하위 탭 「추출·설정」 의 단계 카드 · 헤딩 추출 탭의 「전체 실행」 은 조정까지 한 번에) · 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」(실행 카드)로 돌립니다. 헤딩의 LLM 판정은 스크립트가 판정하지 못한 첫머리 묶음(못 맞춤 · 충돌)도 함께 봅니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 저절로/안 해도 됨/준비 중. 하는 일`, 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 공통 모듈 | 모듈(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 준비 — 문서를 올려 TASK 를 시작

- **문서 올리기 · 첫 분석** — 사람 → 스크립트 · 저장만. 문서를 올리면 에이전트 보기가 열립니다. 기본 분석(헤딩 그래프 · 표 구조 — 스크립트)은 다른 TASK 와 같이 저절로 돕니다 — 구분 기준 항목은 없습니다(일반 문서).
  - 하려면: hwp · hwpx 문서 하나(양식에 묶이지 않은 문서).
  - 끝난 것으로 보는 때: 문서가 열리면 끝난 것으로 봅니다 — 에이전트 보기가 열립니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_일반편집.md ② §11

### 요청 → 제안 → 반영 — 에이전트에 요청하고, 제안을 골라 반영 — 되풀이

- **자료 주기** — 사람 · 저장만 · 안 해도 됨. 붙여 넣은 글이나 파일(txt · md · csv · xlsx · docx · hwpx · pdf)을 자료로 줍니다.
  - 하려면: 붙여 넣을 글이나 자료 파일.
  - 끝난 것으로 보는 때: 안 해도 됩니다 — 다만 표의 값은 받은 자료에 있는 것만 넣으므로, 표를 채우려면 자료가 있어야 합니다.
  → 모듈: `doc_agent_api` | 사양: spec_일반편집.md ② §10
- **요청 → 제안** — 사람 → LLM · 저장만. 오른쪽 에이전트 열에 글로 요청하면 에이전트가 제안을 냅니다 — 글 쓰기 · 표 구조 후보(1~3) · 표 채우기 · 서식 입히기. 문서는 바뀌지 않습니다.
  - 하려면: LLM 연결 · 글로 적은 요청(넣을 자리를 골랐으면 그 자리에).
  - 끝난 것으로 보는 때: 제안 카드가 나왔을 때 — 문서는 바뀌지 않습니다.
  → 제안 카드 | 에이전트: 16 문서 에이전트 · 14 표 채우기 | 공통 모듈: 에이전트 보기 | 모듈: `doc_agent` · `doc_agent_api` | 사양: spec_일반편집.md ② §8
- **스크립트 검사 · 엑셀 검증** — 스크립트 · 문서 안 바뀜 · 저절로. 제안의 수가 자료에 있는지와 합계 · 소계 · 비율 칸의 검산을 봅니다 — 경고가 있는 제안은 처음부터 고르지 않은 채로 보입니다.
  - 하려면: 에이전트가 낸 제안.
  - 끝난 것으로 보는 때: 제안마다 검사 결과가 붙었을 때 — 저절로 돕니다.
  - 남기는 것 · 보정: 자료에 없는 수 · 검산이 안 맞는 표 · 에이전트가 지은 글은 처음부터 고르지 않은 채로 보입니다 — 사람이 보고 고릅니다.
  → 공통 모듈: 에이전트 보기 · 표 도구 | 모듈: `doc_agent` · `table_excel` · `table_fill` | 사양: spec_일반편집.md ② §9
- **고른 제안 반영** — 사람 · 문서 바뀜. 「문서에 반영」 을 누른 제안만 문서에 들어갑니다(제안 하나 = 실행 취소 하나).
  - 하려면: 서버에 저장된 제안 — 제안을 낸 뒤 문서가 바뀌었으면 다시 요청합니다.
  - 끝난 것으로 보는 때: 「문서에 반영」 을 누른 제안이 문서에 들어갔을 때(제안 하나 = 실행 취소 하나).
  → 글 · 표가 더해진 문서 | 공통 모듈: 에이전트 보기 | 모듈: `doc_agent_api` · `style_apply` | 사양: spec_일반편집.md ② §9

### 서식 · 표 다시 쓰기 — 고른 서식을 저장해 재사용 · 표 도구

- **표 · 글 서식 저장** — 사람 → 스크립트 · 저장만 · 안 해도 됨. 반영한 표나 문서의 서식을 서식 관리자에 저장해 다른 문서에서 다시 씁니다.
  - 하려면: 반영한 표나 이 문서의 서식.
  - 끝난 것으로 보는 때: 안 해도 됩니다 — 끝남을 따로 세지 않습니다.
  → 공통 모듈: 서식 관리자(서식 보관함) | 모듈: `style_lib` · `style_carrier` · `style_extract` | 사양: spec_일반편집.md ② §2·§5
- **표 손보기** — 사람 · 문서 바뀜 · 안 해도 됨. 엑셀식 보기 · 표 채우기 · 표 만들기는 표 손잡이 메뉴에서도 엽니다.
  - 하려면: 문서의 표(표 손잡이 메뉴).
  - 끝난 것으로 보는 때: 안 해도 됩니다 — 끝남을 따로 세지 않습니다.
  → 공통 모듈: 표 도구 | 사양: spec_헤딩_추출.md ② §16

## 쓰는 공통 모듈

단계가 「공통 모듈」 로 가리키는 과정 — 그 과정의 단계는 [workflow.md](../workflow.md) 의 「공통 모듈」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 TASK 든 문서를 올리면 먼저 거치는 과정입니다 — 작업(문서마다의 저장 공간)이 생기고, 새 작업이면 기본 분석(헤딩 · 표 — 스크립트)이 저절로 돕니다. 어디까지 됐는지는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 주고받는 대화창입니다 — TASK 를 시작하면 에이전트가 사전 준비와 진행 상황을 설명하고 다음 단계를 제안·실행하며(작업 진행), 글로 요청하면 제안(글 · 새 표 · 표 채우기 · 서식 입히기 · 서식 복사)을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 빈 동안은 「지금 할 수 있는 일」 — 현재 작업 진행 현황 보고(스크립트 · 무료) · 남은 헤딩·표 LLM 검토(실행 카드 · 유료) · 서식 반영 — 을 고릅니다. 어느 TASK 의 문서에서나 엽니다.
- **표 도구**(`tables`) — 표 하나에 대한 일입니다 — 수식 검산 · 빈 칸 채우기 · 표 만들기 · 빈 필드 지우기.
- **서식 관리자(서식 보관함)**(`styles`) — 서버 전체에 저장해 둔 서식(표지 · 내용 · 테이블 · 문단)을 보고 문서에 씁니다. 서식을 뽑아 더하는 과정은 TASK 「문서 서식 복사」 입니다.
