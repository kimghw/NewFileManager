# 문서 일반 편집 — `doc_edit`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(워크플로우 상세 문서 — 화면 `/workflow` 의 이 워크플로우 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [워크플로우 전체 지도](../workflow.md) 가 모든 워크플로우의 차례를 보인다면 이 글은 이 워크플로우 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

에이전트에 요청해 글·표를 쓰고, 표·글 서식을 보관함에 저장해 다시 씁니다.

- 받는 문서: hwp · hwpx 문서 하나(양식 제한 없음) + 요청 내용과 참고 자료
- 산출물: 요청한 글과 표가 반영된 문서
- 알아 둘 것: 정해진 단계 순서 없이 요청 → 제안 → 반영을 반복합니다. 서식은 서식 관리자나 이 문서에 있는 것만 쓰며 새 서식을 임의로 만들지 않습니다. 표의 값도 받은 자료에 있는 내용만 넣습니다.
- 한 번에 진행: 정해진 종료 단계가 없습니다. 요청할 때마다 에이전트가 제안을 만들고, 사람이 고른 제안만 문서에 반영합니다.
- 에이전트가 묻는 것: 내용을 넣을 자리(선택한 문단이나 표), 참고 자료, 서식을 알려 줍니다. 서식을 고르지 않으면 에이전트가 서식 관리자에서 고릅니다.
- 멈추거나 남기는 곳 · 보정: 자료에 없는 숫자, 검산이 안 맞는 표, 에이전트가 새로 지은 글은 기본으로 선택 해제된 상태로 보입니다. 사람이 직접 확인한 뒤 고릅니다.
- 단계별(세부 작업): 표 하나나 서식 하나를 직접 다룰 때는 표 손잡이 메뉴(엑셀식 보기 · 표 채우기 · 표 만들기)와 서식 관리자를 씁니다.
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/doc_edit.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 도구 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### 워크플로우를 시작할 때

시작 화면의 워크플로우 카드, 문서 목록, 대화창에서 문서를 올리기 전에 확인합니다. 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 작업 문서의 확장자가 이 워크플로우가 받는 형식(hwp · hwpx)인지 확인합니다.
  - 안 맞으면: 시작하지 않고 알립니다. docx 파일은 「워크플로우 없이 열기」로 열거나 「문서 서식 복사」 워크플로우에서 시작합니다.
  → 사양: spec_작업.md ② §15
- **작업 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 작업 문서(이 워크플로우로 다룰 문서)를 선택했는지 확인합니다. 파일이 하나면 그 파일을 작업 문서로 씁니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다. 시스템이 임의로 정하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **나머지 문서** — 스크립트 → 사람. 이 워크플로우는 작업 문서 하나로 합니다. 목록에 다른 문서가 있으면 작업 문서만 올리고 나머지는 목록에 남길지 확인받습니다.
  - 안 맞으면: 확인하지 않으면 시작하지 않습니다.
  → 사양: spec_작업.md ② §15-1

### 문서를 올릴 때

문서를 올리면 자동으로 실행됩니다. 사람이 누를 필요가 없으며 유료 LLM을 쓰지 않습니다.

- **작업 만들기 · 같은 파일 고르기** — 스크립트. 올린 파일마다 작업 공간을 만들고, hwp 파일은 한글로 hwpx로 변환합니다. 같은 파일의 기존 작업이 있으면 열기 전에 선택 창을 띄웁니다. 같은 워크플로우 작업, 미지정 작업 순으로 「이어서」와 「초기화하고 열기」를 보이고, 아래에 프로젝트 칸과 「새 작업으로 시작」을 둡니다.
  - 안 맞으면: 다른 워크플로우, 프로젝트, 역할의 작업은 「그대로 열기」만 됩니다. 고르면 그 작업의 설정을 바꾸지 않고 열며, 현재 워크플로우 시작은 멈춥니다. 창을 닫으면 열지 않고, 올리지 못하면 원인을 알리고 시작하지 않습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§3-1·§15
- **양식 판정 · 문서 종류** — 스크립트. 작업 종류를 일반 문서로 지정합니다. 문서 종류(사업계획서 · 연차보고서)는 따로 정하지 않습니다.
  - 안 맞으면: 양식에 묶이지 않은 문서이므로 프로젝트 구성과 구분 기준 항목이 없습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **워크플로우 · 프로젝트 · 라운드** — 스크립트. 작업에 현재 워크플로우를 지정합니다. 프로젝트 이름을 적었으면 해당 프로젝트의 다음 라운드로 시작합니다. 비우면 임시 이름(임시 프로젝트 N)으로 함께 올린 문서를 묶습니다.
  - 안 맞으면: 임시 이름은 문서를 연 뒤 「작업 개요」의 프로젝트 칸이나 작업 리스트의 「이름 정하기」에서 바꿀 수 있습니다. 이미 있는 프로젝트 이름을 적으면 문서가 모두 그 프로젝트로 옮겨집니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 화면에서 제대로 읽었는지 기본 분석과 함께 검사합니다. 한글이나 Word가 있으면 PDF로 변환해 비교하며, 결과는 패널 상단 「검증」에 표시됩니다. 주의나 실패가 나오면 「LLM 검토」가 자동으로 한 번 실행되어 실제 오류인지 PDF 변환 차이인지 구분합니다.
  - 안 맞으면: LLM을 쓸 수 없거나 호출에 실패하면 스크립트 판정 결과를 유지하고 「LLM 검토」 단계에 원인을 기록합니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 hwpx 문서의 헤딩 그래프와 표 구조를 스크립트로 한 번 분석합니다. 이미 결과가 있는 단계는 건너뛰며, 이어서 연 작업에서는 실행되지 않습니다.
  - 안 맞으면: 시작하지 못하면 문서 이름 줄에 「헤딩 없음 · 표 없음」이 표시되고, 도중 실패하면 해당 단계가 「실패」로 뜹니다. 이름 줄의 「분석」 단추로 다시 실행합니다.
  → 도구: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 분석 항목(헤딩, 템플릿, 서식, 표)과 LLM 검증·보완 상태가 표시됩니다. 어느 워크플로우나 같으며 누르면 진행표가 열립니다. 일반 문서라 구분 기준 항목은 없습니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20

### 워크플로우 화면을 열 때

패널 「작업 개요」와 에이전트 시작 안내가 현재 상태를 확인합니다. 부족한 항목이 사전 준비 대상입니다.

- **에이전트 보기 열기** — 스크립트. 문서를 열면 패널의 에이전트 보기가 열립니다. 정해진 단계가 없는 워크플로우이므로 자동 안내 없이 입력한 글이 바로 편집 요청으로 처리됩니다.
  → 도구: 에이전트 보기 | 사양: spec_일반편집.md ② §11
- **LLM 을 쓸 수 있는가** — 스크립트. 에이전트가 제안을 만들 수 있도록 LLM 연결 상태를 확인합니다.
  - 안 맞으면: LLM 을 쓸 수 없으면 에이전트가 제안을 만들지 못합니다.
  → 도구: 에이전트 보기 | 사양: spec_일반편집.md ② §8

### 저절로 돌지 않는 것

자동으로 실행되지 않고 사람이 단추를 눌러 실행하는 항목입니다. 유료 LLM을 씁니다.

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 문서를 올릴 때는 실행되지 않으며, 사람이 직접 실행합니다. 「헤딩 추출」과 「테이블」 탭의 「단계별 실행 ▾」에서 단계를 골라 「고른 n개 실행」하거나, 「추출·설정」 하위 탭의 단계 카드를 씁니다. 「헤딩 추출」 탭의 「전체 실행」(조정까지 실행), 「조정」 끝의 「LLM 판정」(판정 전 문서), 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」로도 실행합니다. 헤딩 판정 시 스크립트가 못 맞췄거나 충돌한 첫머리 묶음도 함께 봅니다.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 자동/필수/선택/준비 중. 하는 일`, 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 도구 | 코드(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 준비 — 문서를 올려 워크플로우를 시작

- **문서 올리기 · 첫 분석** — 사람 → 스크립트 · 저장만 · 필수. 문서를 올리면 에이전트 보기가 열립니다. 기본 분석(헤딩 그래프 · 표 구조 — 스크립트)은 다른 워크플로우와 같이 자동으로 돕니다. 일반 문서이므로 구분 기준 항목은 없습니다.
  - 하려면: hwp · hwpx 문서 하나(양식 제한 없음).
  - 끝난 것으로 보는 때: 문서와 에이전트 보기가 열렸을 때.
  → 도구: 문서 올리기 · 첫 분석 | 사양: spec_일반편집.md ② §11

### 요청 → 제안 → 반영 — 에이전트에 요청하고 원하는 제안만 골라 반복 반영

- **자료 주기** — 사람 · 저장만 · 선택. 글을 붙여 넣거나 파일(txt, md, csv, xlsx, docx, hwpx, pdf)을 참고 자료로 올립니다.
  - 하려면: 붙여 넣을 글이나 자료 파일.
  - 끝난 것으로 보는 때: 선택 단계입니다. 다만 표의 값은 받은 자료에 있는 내용만 넣으므로, 표를 채우려면 자료가 필요합니다.
  → 코드: `doc_agent_api` | 사양: spec_일반편집.md ② §10
- **요청 → 제안** — 사람 → LLM · 저장만 · 필수. 오른쪽 에이전트 창에 글로 요청하면 에이전트가 제안을 만듭니다. 글 쓰기, 표 구조 후보(1~3개), 표 채우기, 서식 입히기를 제안하며 아직 문서는 바뀌지 않습니다.
  - 하려면: LLM 연결과 글로 적은 요청. 문서에서 자리를 미리 고르면 그 자리에 맞춰 제안합니다.
  - 끝난 것으로 보는 때: 제안 카드가 나왔을 때. 아직 문서는 바뀌지 않습니다.
  → 제안 카드 | 에이전트: 16 문서 에이전트 · 14 표 채우기 | 도구: 에이전트 보기 | 코드: `doc_agent` · `doc_agent_api` | 사양: spec_일반편집.md ② §8
- **스크립트 검사 · 엑셀 검증** — 스크립트 · 문서 안 바뀜 · 자동. 제안 속 숫자가 자료에 있는지 확인하고 합계 · 소계 · 비율의 검산을 봅니다. 경고가 있는 제안은 기본으로 선택 해제된 상태로 보입니다.
  - 하려면: 에이전트가 낸 제안.
  - 끝난 것으로 보는 때: 제안마다 검사 결과가 표시됐을 때(자동 실행).
  - 남기는 것 · 보정: 자료에 없는 숫자, 검산이 안 맞는 표, 에이전트가 지은 글은 기본으로 선택 해제됩니다. 사람이 확인한 뒤 직접 고릅니다.
  → 도구: 에이전트 보기 · 표 도구 | 코드: `doc_agent` · `table_excel` · `table_fill` | 사양: spec_일반편집.md ② §9
- **고른 제안 반영** — 사람 · 문서 바뀜 · 필수. 「문서에 반영」 을 누른 제안만 문서에 들어갑니다. 제안 하나마다 실행 취소 한 번으로 되돌릴 수 있습니다.
  - 하려면: 만들어진 제안. 제안을 받은 뒤 문서를 고쳤다면 다시 요청해야 합니다.
  - 끝난 것으로 보는 때: 「문서에 반영」 을 누른 제안이 문서에 반영됐을 때(제안 하나당 실행 취소 1회).
  → 글 · 표가 더해진 문서 | 도구: 에이전트 보기 | 코드: `doc_agent_api` · `style_apply` | 사양: spec_일반편집.md ② §9

### 서식 · 표 다시 쓰기 — 고른 서식을 저장해 다시 쓰고, 표 도구로 표를 손봄

- **표 · 글 서식 저장** — 사람 → 스크립트 · 저장만 · 선택. 반영한 표나 문서의 서식을 서식 관리자에 저장해 다른 문서에서 다시 씁니다.
  - 하려면: 반영한 표나 이 문서의 서식.
  - 끝난 것으로 보는 때: 선택 단계이므로 완료 여부를 따로 세지 않습니다.
  → 도구: 서식 관리자(서식 보관함) | 코드: `style_lib` · `style_carrier` · `style_extract` | 사양: spec_일반편집.md ② §2·§5
- **표 손보기** — 사람 · 문서 바뀜 · 선택. 엑셀식 보기 · 표 채우기 · 표 만들기는 표 손잡이 메뉴에서도 엽니다.
  - 하려면: 문서의 표(표 손잡이 메뉴).
  - 끝난 것으로 보는 때: 선택 단계이므로 완료 여부를 따로 세지 않습니다.
  → 도구: 표 도구 | 사양: spec_헤딩_추출.md ② §16

## 쓰는 도구

단계가 「도구」 로 가리키는 과정 — 그 과정의 단계는 [워크플로우 전체 지도](../workflow.md) 의 「도구」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 워크플로우든 문서를 올리면 먼저 거치는 과정입니다. 문서마다 작업 공간이 생기고, 새 문서이면 스크립트로 헤딩과 표 기본 분석이 저절로 돕니다. 진행 상태는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 대화하는 창이며, 어느 워크플로우의 문서에서나 엽니다. 워크플로우를 시작하면 사전 준비와 진행 상황을 안내하고 다음 단계를 제안·실행합니다. 글로 요청하면 글 작성, 새 표, 표 채우기 · 서식 입히기, 서식 복사 같은 제안을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 비어 있을 때는 「지금 할 수 있는 일」 에서 현재 작업 진행 현황 보고(스크립트), 남은 헤딩·표 LLM 검토(유료), 서식 반영을 바로 고를 수 있습니다.
- **표 도구**(`tables`) — 표 기능은 분석, 구성 개선, 매핑, 작성 네 묶음으로 나뉘며 필요한 기능을 골라 씁니다. 분석에서는 수식 검산, 병합 방식 보기, 키-값 보기, 양식의 표 판정을, 구성 개선에서는 표 서식 맞추기, 빈 필드 지우기, 프로젝트 구성에 맞추기를 합니다. 매핑은 다른 표의 값을 조건에 맞게 옮기거나 계산 칸을 다시 셈하고, 작성은 빈 칸 채우기와 표 만들기를 합니다. 각 칸이 헤더인지 값 칸인지는 현재 표를 다시 읽어 판단하며, 헤딩 추출의 표 판정은 표가 그대로일 때만 재사용합니다. 사람이 정한 헤더 지정이 늘 먼저입니다. 헤더 지정이 지금 표와 안 맞게 되면(지정한 칸의 자리나 글이 바뀜) 지정이 보류되고, 다시 지정하거나 풀 때까지 표 변경 도구가 멈춥니다.
- **서식 관리자(서식 보관함)**(`styles`) — 저장해 둔 표지, 내용, 테이블, 문단 서식을 보고 문서에 씁니다. 새 서식을 뽑아 추가하려면 「문서 서식 복사」 워크플로우를 씁니다.
