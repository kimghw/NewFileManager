# 사업계획서 양식 맞추기 — `plan_fit`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(TASK 문서 — 화면 `/workflow` 의 이 TASK 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [workflow.md](../workflow.md) 가 모든 TASK 의 차례를 보이는 **전체 지도**라면 이 글은 이 TASK 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

단계·차년도·기관에 맞춰 양식의 절·표를 늘리고 줄입니다.

- 받는 문서: 사업계획서(국가R&D 양식 — hwp · hwpx) + 프로젝트 구성(단계 · 차년도 · 기관)
- 산출물: 절 · 표 행 · 표 열을 프로젝트 구성에 맞춘 사업계획서
- 알아 둘 것: 내용은 쓰지 않습니다 — 단계 · 차년도 · 기관 수에 맞게 양식의 자리만 늘리고 줄입니다. 프로젝트 이름이 있으면 반영한 뒤 문서 이름이 「사업계획서_<프로젝트>_프레임」 이 됩니다.
- 한 번에 진행: 에이전트가 이끕니다 — 문서에서 프로젝트 구성을 읽고(값이 없으면 묻고) 확정한 뒤 변경 계획까지 바로 세웁니다. 문서를 바꾸는 「반영」 은 계획 요약을 보인 실행 카드에서 한 번 확인받습니다. 패널 「작업 내용」 의 「한 번에 진행」 은 누를 때 한 번 확인하고 계획 → 반영을 잇습니다.
- 에이전트가 묻는 것: 프로젝트 구성(단계 수 · 단계마다 차년도 수 · 주관기관 · 공동기관 · 당해 차년도) — 문서에서 읽은 값이 있으면 그 값을 확인받습니다.
- 멈추거나 남기는 곳 · 보정: 계획 오류 · 미해결 자리가 있거나 기관의 차례가 마지막 반영과 다르면 저절로 반영하지 않고 멈춥니다 — 변경 계획 목록에서 확인한 뒤 「② 반영」. 지원 안 되는 자리는 그대로 둡니다.
- 단계별(세부 작업): 패널 「작업 내용」 의 「① 변경 계획 보기 › ② 반영」 — 뺄 자리를 고르거나 바뀔 자리를 하나씩 확인하며 할 때.

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 공통 모듈 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### TASK 를 시작할 때

시작 화면의 TASK 카드 · 문서 목록 · 첫 화면 대화창에서, 문서를 올리기 전에 봅니다 — 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 TASK 가 받는 형식(hwp · hwpx)인지 봅니다.
  - 안 맞으면: 시작하지 않고 알립니다 — docx 는 「TASK 없이 열기」 로 열거나 TASK 「문서 서식 복사」 로 시작합니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 골랐는지 봅니다 — 하나면 그 파일이 목적 문서입니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다 — 어느 파일인지 짐작하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **나머지 문서** — 스크립트 → 사람. 이 TASK 는 목적 문서 하나로 합니다 — 목록에 다른 문서가 있으면 목적 문서만 올리고 나머지는 목록에 남긴다고 확인받습니다.
  - 안 맞으면: 확인하지 않으면 시작하지 않습니다.
  → 사양: spec_작업.md ② §15-1

### 문서를 올릴 때

올리면 저절로 도는 것입니다 — 사람이 누르지 않고, 유료 LLM 호출이 없습니다.

- **작업 만들기 · 이어 열기** — 스크립트. 올린 파일로 작업(문서마다의 저장 공간)을 만듭니다. 같은 파일로 하던 작업이 있으면 이 TASK 의 작업(가장 최근) → TASK 가 빈 작업 차례로 이어 엽니다. hwp 는 한글이 hwpx 로 바꿔 받습니다.
  - 안 맞으면: 다른 TASK 를 하던 작업뿐이면 그 작업은 그대로 두고 새 작업으로 열고 알립니다. 올리지 못하면 까닭을 알리고 시작하지 않습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§15
- **양식 판정 · 문서 종류** — 스크립트. 문서가 연구개발계획서 · 연차보고서 양식인지 보고 문서 종류(사업계획서 · 연차보고서)를 정합니다.
  - 안 맞으면: 양식 판정이 종류를 못 정하면 이 TASK 의 문서(사업계획서)로 둡니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **TASK · 프로젝트 · 라운드** — 스크립트. 작업에 이 TASK 를 적습니다. 문서 목록에 프로젝트 이름을 적었으면 그 프로젝트의 이 TASK 다음 라운드로 시작합니다.
  - 안 맞으면: 프로젝트 이름을 비우면 프로젝트 없이 시작합니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 웹 화면이 제대로 읽었는지 검사합니다(한글 · Word 가 있으면 PDF 로 찍어 견줌) — 기본 분석과 함께 돌고, 결과는 패널 머리 「검증」 에 보입니다. 주의 · 실패가 나면 마지막 「LLM 검토」(LLM 호출 한 번)가 저절로 돌아 그 단계가 실제 문제인지 기준 PDF 쪽 사정인지 가립니다.
  - 안 맞으면: LLM 을 쓸 수 없거나 호출이 실패하면 스크립트 판정 그대로 두고 「LLM 검토」 단계에 까닭을 적습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 한 번, 헤딩 그래프 → 표 구조를 스크립트만으로 분석합니다(hwpx). 이미 결과가 있는 단계는 건너뛰고, 이어 연 작업에서는 돌지 않습니다.
  - 안 맞으면: 시작하지 못했으면 문서 이름 줄이 「헤딩 없음 · 표 없음」, 돌다 실패했으면 멈춘 단계가 「실패」 입니다 — 이름 줄의 「분석」 단추로 다시 돌립니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 헤딩 · 템플릿 · 서식 · 표 · LLM 검증·보완 · 구분 기준 검토가 어디까지 됐는지 보입니다 — 어느 TASK 에서나 같은 꼴입니다(누르면 진행표).
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20

### TASK 화면을 열 때

패널 「작업 내용」 과 에이전트의 시작 턴이 지금 상태를 셈합니다 — 여기서 모자란 것이 사전 준비입니다.

- **에이전트의 시작 턴** — 스크립트 → LLM. LLM 을 쓸 수 있으면 패널 「에이전트」 로 옮겨 시작 턴이 돕니다(LLM 호출 한 번) — 이 TASK 의 사전 준비 · 지금까지 된 것 · 다음 단계를 설명하고 다음 행동을 제안합니다. 같은 작업 · 같은 TASK 에 진행 턴이 이미 있으면 다시 돌지 않습니다.
  - 안 맞으면: LLM 이 꺼져 있으면 옮기지 않고 패널 「작업 내용」 을 엽니다 — 에이전트 보기의 「작업 설명 듣기」 로 스크립트 설명을 볼 수 있습니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_작업에이전트.md ② §1
- **지원 양식인가** — 스크립트. 이 문서의 양식이 프로젝트 구성 자동 반영을 지원하는지 봅니다(양식 프로파일).
  - 안 맞으면: 변경 계획 · 반영을 할 수 없다고 알립니다(「이 양식은 프로젝트 구성 자동 반영을 지원하지 않습니다」).
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_구분_기준.md ② §3
- **구분 기준 자리 찾기** — 스크립트. 값만큼 되풀이될 자리(절 헤딩 · 표 행 · 표 열)를 양식 프로파일로 찾아 문서 위에 표시합니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_구분_기준.md ② §3·§11
- **프로젝트 구성 값 · 확정** — 스크립트. 단계 · 차년도 · 기관 값이 있는지, 확정했는지(확정한 뒤 값이 바뀌지 않았는지) 봅니다.
  - 안 맞으면: 값이 없으면 에이전트가 문서에서 읽고, 읽은 값은 질문 카드(프로젝트 구성 폼)로 확인받아 확정합니다. 전체 차년도가 20년을 넘으면 계획을 세우지 않습니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §19
- **변경 계획의 상태** — 스크립트. 계획이 있는지 · 낡았는지(계획 뒤 문서가 바뀜 · 뺄 자리를 바꿈) · 이미 구성에 맞는지 · 마지막으로 반영한 값이 지금 값과 같은지 봅니다.
  - 안 맞으면: 낡은 계획은 쓰지 않고 다시 세웁니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_구분_기준.md ② §7·§22
- **사람이 봐야 할 것** — 스크립트. 계획 오류 · 미해결 자리가 있는지, 기관의 차례가 마지막 반영과 다른지 봅니다.
  - 안 맞으면: 있으면 에이전트가 「문서에 반영」 을 다음 차례로 권하지 않고 「변경 계획 목록 보기」 를 냅니다 — 「한 번에 진행」 도 여기서 멈춥니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업에이전트.md ② §7
- **지금 도는 실행** — 스크립트. 이 문서에 「한 번에 진행」(간단 모드 · 묶음 · 실행 카드)이 도는 중인지 봅니다.
  - 안 맞으면: 도는 동안 에이전트는 실행 · 저장하는 행동을 내지 않고 진행 카드만 보입니다 — 끝나면 이어서 안내합니다.
  → 공통 모듈: 에이전트 보기 | 사양: spec_작업에이전트.md ② §7

### 저절로 돌지 않는 것

시작할 때 돌 것 같지만 사람이 단추로 돌려야 하는 것입니다(유료 LLM).

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 기본 분석과 따로이고 올릴 때 돌지 않습니다 — 「헤딩 추출」 · 「테이블」 탭 머리의 「단계별 실행 ▾」 메뉴(돌릴 단계를 여러 개 골라 「고른 n개 실행」 — 고른 것만 차례로 · 또는 하위 탭 「추출·설정」 의 단계 카드 · 헤딩 추출 탭의 「전체 실행」 은 조정까지 한 번에) · 헤딩 추출 탭 진행 줄 「조정」 끝의 「LLM 판정」(판정을 아직 안 한 문서) · 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」(실행 카드)로 돌립니다. 헤딩의 LLM 판정은 스크립트가 판정하지 못한 첫머리 묶음(못 맞춤 · 충돌)도 함께 봅니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **구분 기준 LLM 검토** — 사람 → LLM. 옵션입니다 — 문서 이름 줄의 「구분 기준」 표시나 프로젝트 구성의 「LLM 검토」 로 열어 「LLM 검토 실행」 을 눌러 돌립니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 사양: spec_작업.md ② §20

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 저절로/안 해도 됨/준비 중. 하는 일`, 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 공통 모듈 | 모듈(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 준비 — 문서를 올려 TASK 를 시작

- **문서 올리기 · 첫 분석** — 사람 → 스크립트 · 저장만. 사업계획서를 올리면 작업이 생기고 기본 분석(헤딩 그래프 · 표 구조 — 스크립트)이 저절로 돕니다. 구분 기준 LLM 검토는 옵션입니다(저절로 돌지 않음). LLM 을 쓸 수 있으면 패널 「에이전트」 가 열려 사전 준비와 다음 단계를 설명하고 진행합니다.
  - 하려면: 이 TASK 가 받는 형식(hwp · hwpx)의 문서 하나.
  - 끝난 것으로 보는 때: 문서가 열리면(작업이 생기고 TASK 가 적히면) 끝난 것으로 봅니다 — 기본 분석은 함께 돌고, 끝나기를 기다리지 않습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 에이전트 보기 | 사양: spec_작업.md ② §9·§15·§20

### 프로젝트 구성 — 단계 · 차년도 · 기관 값을 정함 — 문서는 안 바뀜

- **프로젝트 구성 값 정하기** — 사람 → 스크립트 · 저장만. 문서에서 읽거나 · 불러오거나 · 직접 입력해 단계 · 차년도 · 기관을 정하고 프로젝트에 저장합니다. 문서는 바뀌지 않습니다.
  - 하려면: 문서를 열면 바로 할 수 있습니다 — 값은 문서에서 읽거나 · 불러오거나 · 직접 입력합니다.
  - 끝난 것으로 보는 때: 값을 확정했고 확정한 뒤 값이 바뀌지 않았을 때 — 값을 바꾸면 다시 확정합니다.
  - 멈추는 때: 값이 없으면 에이전트가 문서에서 읽고, 읽은 값도 질문 카드로 확인받습니다(값을 지어내지 않습니다). 에이전트는 확정한 뒤에만 변경 계획으로 갑니다.
  → 공통 모듈: 프로젝트 구성(구분 기준) | 모듈: `division_model` · `division_presets` · `projects` | 사양: spec_작업.md ② §19
- **구분 기준 자리 확인** — 스크립트 → LLM · 저장만 · 안 해도 됨. 값만큼 되풀이될 자리(절 · 표 행 · 표 열)를 문서 위 표시로 확인합니다. LLM 검토가 빠진 자리 후보를 내면 사람이 「자리로 추가」 합니다.
  - 하려면: 지원 양식의 문서. LLM 검토는 LLM 을 쓸 수 있을 때 사람이 단추로 돌립니다(유료).
  - 끝난 것으로 보는 때: 안 해도 됩니다 — 끝남을 따로 세지 않습니다.
  - 남기는 것 · 보정: LLM 이 낸 빠진 자리 후보는 사람이 「자리로 추가」 해야 자리가 됩니다.

### 구조 반영 — 절 · 표 행 · 표 열을 값에 맞춤(구조만)

- **① 변경 계획 보기** — 스크립트 · 문서 안 바뀜. 값에 맞추면 바뀔 자리(늘어나는 것 · 줄어드는 것)를 목록으로 확인합니다. 문서는 바뀌지 않습니다.
  - 하려면: 지원 양식 · 프로젝트 구성 값 · 전체 차년도 20년 이하. 에이전트는 값을 확정한 뒤에 세웁니다.
  - 끝난 것으로 보는 때: 지금 문서에 맞는 계획이 있을 때(반영할 수 있음 · 바꿀 것 없음 · 이미 반영함). 계획 뒤 문서가 바뀌었거나 뺄 자리를 바꿨으면 낡은 계획입니다 — 다시 세웁니다.
  → 변경 계획 | 공통 모듈: 프로젝트 구성(구분 기준) | 모듈: `division_plan` | 사양: spec_구분_기준.md ② §3·§7·§22
- **② 반영** — 사람 → 스크립트 · 문서 바뀜. 계획대로 절 · 표 행 · 표 열을 늘리고 줄입니다. 「한 번에 진행」 은 계획 → 반영을 이어서 하고, 확인이 필요한 곳에서 멈춥니다.
  - 하려면: 반영할 수 있는(낡지 않은) 변경 계획.
  - 끝난 것으로 보는 때: 반영했거나 · 계획이 「현재 구성과 맞습니다」 이거나 · 마지막으로 반영한 값이 지금 값과 같을 때.
  - 멈추는 때: 계획 오류 · 미해결 자리가 있거나 기관의 차례가 마지막 반영과 다르면 저절로 반영하지 않습니다. 실행 카드를 낸 뒤 계획이 바뀌었으면 실행하지 않고 새 계획으로 다시 묻습니다.
  - 남기는 것 · 보정: 지원 안 되는 자리는 그대로 둡니다 — 변경 계획 목록에서 확인합니다. 줄어드는 항목은 그 안의 글과 함께 지워지므로, 지워지는 글이 있으면 목록을 보게 합니다.

## 쓰는 공통 모듈

단계가 「공통 모듈」 로 가리키는 과정 — 그 과정의 단계는 [workflow.md](../workflow.md) 의 「공통 모듈」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 TASK 든 문서를 올리면 먼저 거치는 과정입니다 — 작업(문서마다의 저장 공간)이 생기고, 새 작업이면 기본 분석(헤딩 · 표 — 스크립트)이 저절로 돕니다. 어디까지 됐는지는 문서 이름 줄에 보입니다.
- **에이전트 보기**(`agent`) — 에이전트와 글로 주고받는 대화창입니다 — TASK 를 시작하면 에이전트가 사전 준비와 진행 상황을 설명하고 다음 단계를 제안·실행하며(작업 진행), 글로 요청하면 제안(글 · 새 표 · 표 채우기 · 서식 입히기 · 서식 복사)을 내고 사람이 고른 것만 문서에 반영합니다. 대화가 빈 동안은 「지금 할 수 있는 일」 — 현재 작업 진행 현황 보고(스크립트 · 무료) · 남은 헤딩·표 LLM 검토(실행 카드 · 유료) · 서식 반영 — 을 고릅니다. 어느 TASK 의 문서에서나 엽니다.
- **프로젝트 구성(구분 기준)**(`division`) — 단계 · 차년도 · 기관 값(프로젝트 구성)에 맞춰 문서의 절 · 표 행 · 표 열을 늘리고 줄입니다. 값은 프로젝트에 하나이고 그 프로젝트의 TASK 들이 같이 씁니다.
