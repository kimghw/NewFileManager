# 문서 서식 복사 — `style_copy`

> 이 파일은 워크플로우 등록부 `app/workflow.py` 에서 **만든 글**이다(TASK 문서 — 화면 `/workflow` 의 이 TASK 절과 같은 내용) — 손으로 고치지 않는다.
> 등록부를 고치면 `python -X utf8 tools/workflow_md.py` 로 다시 만든다(안 맞으면 `tests/test_workflow.py` 가 떨어진다). 사양 [spec/spec_워크플로우.md](../spec/spec_워크플로우.md) ② §10.
>
> [workflow.md](../workflow.md) 가 모든 TASK 의 차례를 보이는 **전체 지도**라면 이 글은 이 TASK 하나의 **세부**다 — 시작할 때 저절로 확인하는 것(시작 점검)과 단계마다 조건을 함께 적는다.

문서에서 템플릿·문서 서식·테이블 서식을 뽑아 서식 관리자에 저장하고 PDF 로 검증합니다.

- 받는 문서: 문서 하나(hwp · hwpx · docx — 작업이 생김 / pdf — 작업 없이 후보만)
- 산출물: 서식 관리자의 서식(표지 · 내용 · 테이블 · 문단 — 서식마다 hwpx · docx 두 형식) + PDF 검증 기록
- 알아 둘 것: 문서는 바뀌지 않습니다. 서식 값(글꼴 · 크기 · 여백 · 괘선 · 레벨)은 스크립트가 읽고 LLM 은 검증 · 보완만 합니다. 「한 번에 진행」 은 ②③④ 를 차례로 하되 의심 · 고침이 없는 추천만 저장합니다.
- 한 번에 진행: 문서 옆 「서식 복사」 열의 「한 번에 진행」 — ② LLM 검토 → ③ 저장 → ④ PDF 검증을 잇습니다(문서는 바뀌지 않습니다). 도는 동안의 진행은 에이전트 보기의 진행 카드에도 보입니다.
- 에이전트가 묻는 것: 묻지 않습니다 — 의심 · 고침이 있는 후보는 저절로 저장하지 않고 남깁니다.
- 멈추거나 남기는 곳 · 보정: LLM 을 쓸 수 없으면 ② 에서 멈춥니다. 확인이 필요한 후보는 남깁니다 — 서식 견본 그림과 「자리로」 로 보고 골라 저장합니다.
- 단계별(세부 작업): 후보를 직접 골라 「고른 n개 저장」 · 서식 관리자에서 형식마다 검증 기록을 확인할 때.
- 전제(할 일 프롬프트 — 먼저 읽는 글): `jobs/style_copy.md`

## 시작 점검 — 시작할 때 저절로 확인하는 것

읽는 법 — 항목 = `이름 — 누가. 무엇을 확인하나`, 그 아래 `안 맞으면` = 그때 어떻게 되나, `→` 줄 = 공통 모듈 | 사양 자리. 사람이 누르지 않아도 보는 것만 적는다(끝의 「저절로 돌지 않는 것」 은 헷갈리기 쉬운 것을 따로 적은 것).

### TASK 를 시작할 때

시작 화면의 TASK 카드 · 문서 목록 · 첫 화면 대화창에서, 문서를 올리기 전에 봅니다 — 안 맞으면 시작하지 않고 알립니다.

- **문서 형식** — 스크립트. 목적 문서의 확장자가 이 TASK 가 받는 형식(hwp · hwpx · docx · pdf)인지 봅니다.
  - 안 맞으면: 시작하지 않고 알립니다 — pdf 는 문서 목록에 넣지 않고 이 카드에 하나씩 놓습니다: 작업을 만들지 않고 파일에서 서식 후보만 찾습니다.
  → 사양: spec_작업.md ② §15
- **목적 문서** — 스크립트. 문서 목록에 파일이 둘 이상이면 목적 문서(내용을 받는 문서)를 골랐는지 봅니다 — 하나면 그 파일이 목적 문서입니다.
  - 안 맞으면: 시작하지 않고 고르라고 알립니다 — 어느 파일인지 짐작하지 않습니다.
  → 사양: spec_작업.md ② §15-1
- **나머지 문서** — 스크립트 → 사람. 이 TASK 는 목적 문서 하나로 합니다 — 목록에 다른 문서가 있으면 목적 문서만 올리고 나머지는 목록에 남긴다고 확인받습니다.
  - 안 맞으면: 확인하지 않으면 시작하지 않습니다.
  → 사양: spec_작업.md ② §15-1

### 문서를 올릴 때

올리면 저절로 도는 것입니다 — 사람이 누르지 않고, 유료 LLM 호출이 없습니다.

- **작업 만들기 · 이어 열기** — 스크립트. 올린 파일로 작업(문서마다의 저장 공간)을 만듭니다. 같은 파일로 하던 작업이 있으면 이 TASK 의 작업(가장 최근) → TASK 가 빈 작업 차례로 이어 엽니다. hwp 는 한글이 hwpx 로 바꿔 받습니다.
  - 안 맞으면: 다른 TASK 를 하던 작업뿐이면 그 작업은 그대로 두고 새 작업으로 열고 알립니다. 올리지 못하면 까닭을 알리고 시작하지 않습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §1·§15
- **양식 판정 · 문서 종류** — 스크립트. 작업 종류를 일반 문서로 적습니다 — 문서 종류(사업계획서 · 연차보고서)는 정하지 않습니다.
  - 안 맞으면: 양식에 묶이지 않은 문서라 프로젝트 구성 · 구분 기준 항목이 없습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §10·§15
- **TASK · 프로젝트 · 라운드** — 스크립트. 작업에 이 TASK 를 적습니다. 문서 목록에 프로젝트 이름을 적었으면 그 프로젝트의 이 TASK 다음 라운드로 시작합니다.
  - 안 맞으면: 프로젝트 이름을 비우면 프로젝트 없이 시작합니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §15-1·§17
- **가져오기 검증** — 스크립트 → LLM. 올린 문서를 웹 화면이 제대로 읽었는지 검사합니다(한글 · Word 가 있으면 PDF 로 찍어 견줌) — 기본 분석과 함께 돌고, 결과는 패널 머리 「검증」 에 보입니다. 주의 · 실패가 나면 마지막 「LLM 검토」(LLM 호출 한 번)가 저절로 돌아 그 단계가 실제 문제인지 기준 PDF 쪽 사정인지 가립니다.
  - 안 맞으면: LLM 을 쓸 수 없거나 호출이 실패하면 스크립트 판정 그대로 두고 「LLM 검토」 단계에 까닭을 적습니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_hwpx_웹편집.md ② §3·§4-1
- **기본 분석 — 헤딩 그래프 · 표 구조** — 스크립트. 새 작업을 처음 열 때 한 번, 헤딩 그래프 → 표 구조를 스크립트만으로 분석합니다(hwpx). 이미 결과가 있는 단계는 건너뛰고, 이어 연 작업에서는 돌지 않습니다.
  - 안 맞으면: 시작하지 못했으면 문서 이름 줄이 「헤딩 없음 · 표 없음」, 돌다 실패했으면 멈춘 단계가 「실패」 입니다 — 이름 줄의 「분석」 단추로 다시 돌립니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 · 헤딩 추출 | 사양: spec_작업.md ② §9·§20
- **분석 상태 표시** — 스크립트. 문서 이름 줄에 헤딩 · 템플릿 · 서식 · 표 · LLM 검증·보완이 어디까지 됐는지 보입니다 — 어느 TASK 에서나 같은 꼴입니다(누르면 진행표)(일반 문서라 구분 기준 항목은 없습니다).
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20

### TASK 화면을 열 때

패널 「작업 내용」 과 에이전트의 시작 턴이 지금 상태를 셈합니다 — 여기서 모자란 것이 사전 준비입니다.

- **「서식 복사」 열 열기 · 후보 찾기** — 스크립트. 문서를 열면 문서 옆에 「서식 복사」 열이 열리고 ① 후보 찾기가 저절로 돕니다 — 표지 · 내용 · 테이블 · 문단 서식 후보를 스크립트가 뽑습니다(문서는 바뀌지 않습니다).
  - 안 맞으면: 후보를 찾다 오류가 나면 그 열에 까닭이 보이고 ① 이 끝난 것으로 치지 않습니다.
  → 공통 모듈: 서식 관리자(서식 보관함) · 헤딩 추출 | 사양: spec_서식복사.md ② §1·§6

### 저절로 돌지 않는 것

시작할 때 돌 것 같지만 사람이 단추로 돌려야 하는 것입니다(유료 LLM).

- **헤딩 · 표의 LLM 판정** — 사람 → LLM. 기본 분석과 따로이고 올릴 때 돌지 않습니다 — 「헤딩 추출」 · 「표」 탭 머리의 「실행 ▾」 메뉴(또는 하위 탭 「추출·설정」 의 단계 카드) · 에이전트 보기 빈 화면의 「헤딩·표 LLM 검토하기」(실행 카드)로 돌립니다. 헤딩의 LLM 판정은 스크립트가 판정하지 못한 첫머리 묶음(못 맞춤 · 충돌)도 함께 봅니다.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_작업.md ② §20
- **서식 후보의 LLM 검토** — 사람 → LLM. ② LLM 검토는 열기만 해서는 돌지 않습니다 — 「LLM 검토」 단추나 「한 번에 진행」 을 눌러야 돕니다.
  → 사양: spec_서식복사.md ② §15

## 단계마다 조건

읽는 법 — 단계 = `번호 이름 — 누가(차례대로) · 문서가 바뀌나 · 저절로/안 해도 됨/준비 중. 하는 일`, 그 아래 `하려면` · `끝난 것으로 보는 때` · `멈추는 때` · `남기는 것 · 보정`(적을 것이 있을 때만), `→` 줄 = 나오는 것 | 에이전트(작업 번호 이름) | 공통 모듈 | 모듈(`app/<이름>.py`) | 사양 자리.
「끝난 것으로 보는 때」 는 화면이 지금 문서의 상태로 셈한다 — 단추를 눌렀다는 사실로 끝남을 적지 않는다.

### 준비 — 서식을 뽑을 문서를 올림

- **문서 올리기 · 첫 분석** — 사람 → 스크립트 · 저장만. 문서를 올리면 문서 옆에 「서식 복사」 열이 열립니다. hwpx 는 기본 분석(헤딩 그래프 · 표 구조 — 스크립트)이 다른 TASK 와 같이 돌고, pdf 는 작업을 만들지 않고 파일에서 후보만 찾습니다.
  - 하려면: hwp · hwpx · docx 문서 하나(pdf 는 작업 없이 후보만).
  - 끝난 것으로 보는 때: 문서가 열리고 문서 옆 「서식 복사」 열이 열렸을 때.
  → 공통 모듈: 문서 올리기 · 첫 분석 | 사양: spec_서식복사.md ② §1

### 서식 복사 — 후보 찾기 → LLM 검토 → 저장 → PDF 검증

- **① 후보 찾기** — 스크립트 · 문서 안 바뀜 · 저절로. 문서에서 서식 후보를 뽑습니다 — 표지(첫 쪽의 배치) · 내용(개요템플릿 레벨마다의 글 서식 + 쪽 설정) · 테이블 · 문단. 글 후보는 헤딩 추출 결과를 씁니다.
  - 하려면: 연 문서(글 서식 후보는 헤딩 추출 결과를 씁니다).
  - 끝난 것으로 보는 때: 후보 목록이 나왔을 때 — 저절로 돕니다(오류면 끝난 것으로 치지 않습니다).
  → 서식 후보(종류마다) | 공통 모듈: 헤딩 추출 | 모듈: `style_extract` · `style_page` · `style_cover` | 사양: spec_서식복사.md ② §6·§12·§14
- **② LLM 검토** — LLM · 저장만 · 안 해도 됨. 후보마다 저장할 만한가 · 이름 · 역할(머리행 · 합계행 · 본문 바탕 글 …)을 검토하고, 확신이 없으면 고치지 않고 의심으로 표시합니다. 서식 값은 만들지 않습니다.
  - 하려면: 후보 목록 · LLM 연결(유료 — 「LLM 검토」 단추나 「한 번에 진행」).
  - 끝난 것으로 보는 때: 한 번 검토했을 때 — 안 해도 사람이 골라 저장할 수 있습니다.
  - 멈추는 때: LLM 을 쓸 수 없으면 「한 번에 진행」 은 여기서 멈춥니다.
  - 남기는 것 · 보정: 확신이 없는 후보는 고치지 않고 「확인」 으로 표시합니다.
  → 추천 · 의심 표시 | 에이전트: 17 서식 복사 검토 | 모듈: `style_extract` · `job_prompts` | 사양: spec_서식복사.md ② §15
- **③ 저장** — 사람 → 스크립트 · 저장만. 고른 후보를 서식 관리자에 저장합니다 — hwpx · docx 두 형식의 운반 문서와 원본 문서 기록(어느 문서에서 뽑았나). 글은 저장하지 않고 서식만 저장합니다.
  - 하려면: 고른 후보 — 「한 번에 진행」 은 추천이면서 「확인」 · 「LLM 고침」 · 띠 넓히기 제안이 없는 후보와 사람이 이미 고른 것만.
  - 끝난 것으로 보는 때: 이번에 저장한 서식이 있을 때.
  - 남기는 것 · 보정: 확인이 필요한 후보는 저절로 저장하지 않고 남깁니다 — 서식 견본 그림과 「자리로」 로 보고 골라 저장합니다.
  → 서식(hwpx · docx) | 모듈: `style_lib` · `style_carrier` · `style_docx` · `style_api` | 사양: spec_서식복사.md ② §4·§17
- **④ PDF 검증** — 스크립트 · 저장만. 저장한 서식을 한글 · Word 로 출력해 서식이 뜻한 값과 PDF 에서 잰 값을 견줍니다 — 재지 못한 것을 맞았다고 하지 않습니다.
  - 하려면: 저장한 서식 · 한글 · Word 의 PDF 출력.
  - 끝난 것으로 보는 때: 저장한 서식의 검증이 모두 끝났을 때(「한 번에 진행」 은 180초까지 기다립니다).
  - 남기는 것 · 보정: 늦게 끝나는 검증은 서식 관리자에서 확인합니다 — 재지 못한 것을 맞았다고 하지 않습니다.
  → 형식마다 검증 기록 | 모듈: `style_verify` · `pdf_render` | 사양: spec_서식복사.md ② §7

### 다시 쓰기 — 저장한 서식을 서식 관리자로 적용

- **다른 문서 · TASK 에서 쓰기** — 사람 · 문서 바뀜 · 안 해도 됨. 저장한 서식은 어느 TASK 의 문서에서나 서식 관리자로 적용합니다(그 TASK 의 원본 문서에는 적용하지 않음).
  - 하려면: 저장한 서식 · 적용할 문서(hwpx — 그 TASK 의 원본 문서가 아닌 것).
  - 끝난 것으로 보는 때: 안 해도 됩니다 — 끝남을 따로 세지 않습니다.

## 쓰는 공통 모듈

단계가 「공통 모듈」 로 가리키는 과정 — 그 과정의 단계는 [workflow.md](../workflow.md) 의 「공통 모듈」 절에 있다.

- **문서 올리기 · 첫 분석**(`intake`) — 어느 TASK 든 문서를 올리면 먼저 거치는 과정입니다 — 작업(문서마다의 저장 공간)이 생기고, 새 작업이면 기본 분석(헤딩 · 표 — 스크립트)이 저절로 돕니다. 어디까지 됐는지는 문서 이름 줄에 보입니다.
- **헤딩 추출**(`headings`) — 문서의 개요(헤딩)와 표의 구조를 뽑아 뼈대로 둡니다 — 자리 연결 · 넣기 · 서식 후보 · 템플릿 관계가 이 뼈대를 씁니다. 문서는 바꾸지 않습니다. 어디까지 했는지는 탭 위 진행 줄에 두 층으로 보입니다 — 스크립트(문단·라벨 · 헤딩 그래프 · 표 구조)와 LLM(규칙 보강 · 헤딩 판정 · 표 판정). LLM 칸(✓)을 누르면 문서 옆 열 「LLM 이 바꾼 것」 에 LLM 이 스크립트와 다르게 정한 것(규칙 · 노드 · 서식 쌍 판정 · 표 칸 역할 · 받아 둔 서식 계획)이 보입니다 — LLM 판정은 문서를 바꾸지 않습니다.
- **서식 관리자(서식 보관함)**(`styles`) — 서버 전체에 저장해 둔 서식(표지 · 내용 · 테이블 · 문단)을 보고 문서에 씁니다. 서식을 뽑아 더하는 과정은 TASK 「문서 서식 복사」 입니다.
